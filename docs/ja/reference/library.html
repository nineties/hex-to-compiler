ライブラリ

planck/lib のファイルは planck の構文で書かれ、use("name") で読み込みます。

リストは Cons{x, xs} と Nil{} です。文字コードは ord が返す整数です。

関数はモジュールの欄で、list.map(f, xs) のように呼びます。次の関数はモジュール名なしの名前でも呼べます。

  • base: panic assert
  • list: foldl reverse length append map filter concat_map each find member range
  • string: join

vector

ベクタは可変長の配列 Vector{a} です。v[i] と v[i] = x は vector.get と vector.set を呼びます。vector.push(v, x) は後ろに足して x を返し、vector.pop(v) は最後の要素を取り除いて返します。vector.get と vector.set は範囲外の添字でプログラムを止めます。

getopt

コマンドラインのオプションを GNU の getopt_long と同じ規則で読みます。オプションは Opt{short, long, takes} です。short は1文字の文字列、long は文字列で、どちらも "" にできます。takes は値を取るなら true です。getopt.parse(opts, args, from) は配列 args を添字 from から読みます。argv() を読むときは、先頭のプログラムのファイルを飛ばすために from を 1 にします。

  • 結果は Parsed{table, rest} です。table は指定されたオプションの名前（long、なければ short）から値への表で、値を取らないオプションの値は true です。同じオプションを複数回指定すると、最後の値が残ります。rest はオプションでない文字列を順に並べた配列です。
  • 読める形は -a・-abc（-a -b -c と同じ）・-o 値・-o値・--opt・--opt 値・--opt=値 です。値は - で始まってもかまいません。- だけの文字列はオプションではありません。-- より後は全部 rest に入ります。オプションとそうでない文字列は混ぜられます。
  • エラーはプログラムを止めず、値として返します。opts にないオプションは Unknown{name}、args の終わりで値が抜けたものは Missing{name}、値を取らないオプションへの --opt=値 は NoValue{name} です。name は書かれたとおりの "-x" や "--opt" です。長いオプションの省略形は受け付けません。

r_lib_getopt.pk

use("table")
use("getopt")
spec := [Opt{"a", "all", false}, Opt{"o", "output", true}, Opt{"", "level", true}]
use("list")
args := list.list_to_array(["prog", "-ao", "out.txt", "x", "--level=3", "--", "-y"])
r := getopt.parse(spec, args, 1)
println(head(r))
opts := arg(r, 0)
println(table.get(opts, "all", false))
println(table.get(opts, "output", none))
println(table.get(opts, "level", none))
rest := arg(r, 1)
println(array_len(rest))
println(rest[0])
println(rest[1])
println(getopt.parse(spec, list.list_to_array(["prog", "-ax"]), 1))
println(getopt.parse(spec, list.list_to_array(["prog", "-o"]), 1))

"out.txt"
"3"
2

table

table.new() は新しい表を作り、table.get(t, key, default) と table.set(t, key, value) で読み書きします。table.keys・table.values・table.items（[Tuple{key, value}, ...]）は不定の順序で項目を並べます。集合は値が true の表です。

r_lib_table.pk

use("list")
use("table")
use("pretty")
t := table.new()
table.set(t, 'a, 1)
table.set(t, 'b, 2)
put(f"{table.len(t)} {table.has(t, 'a)} {table.has(t, 'z)}\n")
put(f"{list.sort((a, b) -> a < b, table.values(t))}\n")
s := set.from_list([1, 2, 2, 3])
put(f"{set.len(s)} {set.has(s, 2)} {list.sort((a, b) -> a < b, set.to_list(s))}\n")

出力

2 true false
[1, 2]
3 true [1, 2, 3]

error

  • error.line_col(src, pos) はバイト位置 pos の Tuple{行, 列} です。どちらも1から数えます。error.line_text(src, line) は改行を除いたその行です。
  • error.loc_at(file, src, pos) は Loc{file, line, column} です。error.show_loc はそれを file:line:column と書きます。
  • error.at(loc, msg) は Error{loc, msg} を perform します。error.catch(f) は Ok{f()} です。f() が Error{loc, msg} を perform したら Err{loc, msg} です。
  • error.show(src, loc, msg) は file:line:column: msg・その行・列の下の ^ を並べた文字列です。

r_lib_error.pk

use("error")
src := "x := 1\ny := x +\n"
r := error.catch(() -> error.at(error.loc_at("a.pk", src, 12), "expected an expression"))
println(r)
put(error.show(src, arg(r, 0), arg(r, 1))); put("\n")
println(error.catch(() -> 42))

出力

Err{Loc{"a.pk", 2, 6}, "expected an expression"}
a.pk:2:6: expected an expression
  y := x +
       ^
Ok{42}

unparse

unparse.text(t) は規則 expr で読むと木 t になる文字列です。peg_sources の文法から作ります。unparse.text_as(rule, t) は任意の規則について同じことをし、文字列がなければプログラムを止めます。unparse.try_as は止まる代わりに none を返します。

  • 選択肢 Act{Seq{e1, ...}, Lambda{Tuple{Tuple{l1, ...}}, body}} は、body が準クオートで、その !x がラベル・Quote{c}・ラベル・Tuple{labels}・mexpr(h, args) のとき逆にたどれます。木を準クオートと照合し、ラベルに部分木を入れ、要素を順に書きます。文字列はそのまま、規則は unparse_as(rule, subtree) で書きます。いつも同じ文字列に合う要素（"+" や Same{}）にはラベル _ を使えます。要素は文字列・規則、または規則の Delimited・Delimited1・Many・Option です。
  • 木に合う選択肢のうち、準クオートの中で !x でない節が一番多いものを使います。
  • 弱い規則が求められている所に強い規則の選択肢を置くときは、文法の最初の "(" e ")"（動作は何でもよい）で囲みます。規則名だけの選択肢は、規則とそれがなりうる規則を結び、どの選択肢に括弧が要るかを決めます。より弱い規則で終わる選択肢（while (c) e は expr で終わる）も、それと同じかより弱い規則が求められているとき以外は括弧が要ります。
  • unparse.custom(owner, spec, tail, f) は規則 owner に選択肢を足します。f(t) は t の文字列か none、spec は準クオートとの順位付け、tail は文字列の最後の規則か none です。unparse は Do{...} を { } の中に1行1式、4つの空白で字下げして書き、If を if (c) a else b と書きます。どちらもこのやり方で足しています。
  • 文法で書かれない木の文字列は、コンストラクタの呼び出し Head{a, ...} です。識別子でないシンボルと、整数・文字列・シンボル・M式でない値には文字列がありません。

t6_unparse.pk

use("unparse")
t := '(if (n < 0) -n else n * (n + 1))
println(t)
put(unparse.text(t)); put("\n")

出力

If{Apply{_lt, Tuple{n, 0}}, Apply{_sub, Tuple{0, n}}, Apply{_mul, Tuple{n, Apply{_add, Tuple{n, 1}}}}}
if (n < 0) -n else n * (n + 1)

base

panic(msg) は msg を出力して終了状態1で止まります。assert(c, msg) は c が成り立たないときに panic(msg) を呼びます。

module でまとめたライブラリ

ライブラリを module でまとめて書くと、読み込んだあとに module の名前で呼べます。bitset が module bitset で書かれていれば、次のとおりです。

use("bitset")
s := bitset.new(100)
bitset.add(s, 3)

ライブラリの補助の関数は export を付けなければ外に出ません。補助の関数を呼ぶ試験は、module の中の test に書きます。

前処理したライブラリ

プログラム tools/preprocess.pk にライブラリの名前を引数で渡すと、指定したライブラリを前もって M式へ構文解析します。use("name") と同じように、それが使うライブラリとともに読み込み、各ライブラリの解析結果の M式を planck/lib/<name>.pkm に1行1式で書きます。

前もって評価するものはありません。use は planck/lib/<name>.pkm の M式を読んで1つずつ評価します。動作は use が planck/lib/<name>.pk を構文解析した場合と同じです。使える .pkm ファイルがなければ use はライブラリを構文解析します。

.pkm ファイルを使うのは、ライブラリの本文と文法がどちらもファイルを書いたときと同じ場合です。文法が同じとは、次の3つです。

  • planck/init.pk・planck/peg.pk・planck/syntax.pk の本文が同じ
  • 規則を宣言したライブラリが同じ本文で同じ順に並んでいる
  • ほかの規則が宣言されていない（peg_version が同じ）

M式として読めないファイルと、最後の式で終わっていないファイルは使われません。

この判定は、プログラムが parse や規則の動作が呼ぶ関数を差し替えたことを検出しません。解析結果に M式の文字列表現がない値（関数・配列）を含むライブラリは前処理できません。
