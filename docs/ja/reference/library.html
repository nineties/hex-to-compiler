ライブラリ

planck/lib のファイルは planck の構文で書かれ、use("name") で読み込みます。各ファイルは依存するファイルを use します。

リストは Cons{x, xs} と Nil{} です。文字コードは ord が返す整数です。

list

  • map(f, xs)・filter(p, xs)・each(f, xs) は最初の要素から最後の要素へ順に f を呼びます。
  • foldl(f, acc, xs) は f(f(acc, x1), x2) を計算します。foldr(f, init, xs) は f(x1, f(x2, init)) を計算します。
  • nth(xs, i) は0から数えます。take(xs, n) と drop(xs, n) は xs を n 個目のあとで分けた前半と後半です。
  • find(p, xs) は p(x) が成り立つ最初の要素で、なければ none です。index_of(x, xs) は x の位置で、なければ -1 です。
  • zip(xs, ys) は短いほうの長さの [Tuple{x, y}, ...] です。range(a, b) は [a, ..., b - 1] です。
  • list_to_array(xs) は xs の要素の配列です。
  • sort(less, xs) は less(a, b) による安定なマージソートです。例 sort((a, b) -> a < b, xs)。

r_lib_list.pk

use("list")
use("pretty")
xs := [3, 1, 4, 1, 5]
put(f"{length(xs)} {sum(xs)} {nth(xs, 2)} {last(xs)}\n")
put(f"{reverse(xs)} {append([0], xs)} {concat([[1], [2, 3]])}\n")
put(f"{take(xs, 2)} {drop(xs, 2)}\n")
put(f"{find(x -> x > 3, xs)} {any(x -> x > 4, xs)} {all(x -> x > 0, xs)}\n")
put(f"{member(4, xs)} {index_of(4, xs)} {index_of(9, xs)}\n")
put(f"{foldr((x, acc) -> x :: acc, [], xs)}\n")
put(f"{concat_map(x -> [x, x], [1, 2])}\n")
each(x -> put(f"<{x}>"), [1, 2, 3])
put("\n")

vector

ベクタは可変長の配列 Vector{a} です。v[i] と v[i] = x は vec_get と vec_set を呼びます。vec_push(v, x) は後ろに足して x を返します。vec_pop(v) は最後の要素を取り除いて返します。vec_get と vec_set は、範囲外の添字を渡すとプログラムを止めます。

string

  • chr(c) は文字コードが32から126・9・10・13のいずれかである1文字の文字列です。char_at(s, i) は i が s の範囲外なら "" です。
  • index_of_str(s, part, from) は、from 以降で part が最初に現れる位置で、なければ -1 です。
  • str_cmp(a, b) は文字コードの順で比べた -1・0・1 です。trim(s) は両端の空白を取り除きます。
  • str_to_int(s) は省略可能な - と10進の数字を読みます。読めなければ none です。
  • split(s, sep) は sep の間の部分のリストです。sep は空にできません。join(sep, xs) はその逆です。
  • 文字列バッファは文字列の断片を集めます。strbuf_add(b, s) で断片を足し、strbuf_str(b) で連結した文字列を得ます。断片を2つずつ連結するので、長い文字列を作っても同じバイトを何度もコピーしません。

r_lib_string.pk

use("string")
use("pretty")
put(f"{chr(65)} [{char_at("abc", 5)}] {ends_with("main.pk", ".pk")}\n")
put(f"{index_of_str("banana", "na", 3)} {str_repeat("ab", 3)}\n")
put(f"{str_cmp("a", "b")} {str_cmp("b", "b")} {str_less("b", "a")}\n")
put(f"{int_to_str(-42)} {str_to_int("x1")}\n")
put(f"{is_digit(ord("7", 0))} {is_alpha(ord("_", 0))} {is_ident_start(ord("_", 0))}\n")
b := strbuf_new()
strbuf_add(b, "plan")
strbuf_add(b, "ck")
put(strbuf_str(b)); put("\n")

出力

A [] true
4 ababab
-1 0 false
-42 none

u64

64ビットの値は、16ビットの4つの部分（下位から順）に分けた u16 配列です。作ったあとは変更しません。

  • u64(n) は整数 n の値で、負なら符号拡張します。u64_limbs(l3, l2, l1, l0) は16ビットの部分から、u64_hex("0x...") は16進の文字列（16桁まで、_ は無視）から作ります。u64_to_hex(a) は 0x と16桁の文字列、u64_to_int(a) は a の符号つきの値です。
  • u64_add・u64_sub・u64_neg は2の64乗を法とする計算です。u64_and・u64_or・u64_xor・u64_not はビットごとの演算です。
  • u64_shl(a, k)・u64_shr(a, k)・u64_sar(a, k) は k（0から63）ビットの左シフト・論理右シフト・算術右シフトです。
  • u64_eq(a, b) は等しいかどうかを返します。u64_ucmp(a, b) と u64_scmp(a, b) は符号なし・符号つきで比べた -1・0・1 です。u64_ult と u64_slt は a が小さいかどうかを返します。
  • u64_write_le(buf, off, a) は a の8バイトを下位のバイトから順に u8 配列 buf の off 以降へ書きます。u64_write_be は上位のバイトから順に書きます。u64_read_le(buf, off) はその逆で、u64_bytes_le(a) は8バイトの u8 配列です。

r_lib_u64.pk

use("u64")
a := u64_hex("0xffffffffffffffff")
b := u64_add(a, u64(2))
println(u64_to_hex(b))
println(u64_to_hex(u64_shl(u64_hex("0x0123456789abcdef"), 36)))
println(u64_to_hex(u64_sar(u64_hex("0x8000000000000000"), 60)))
println(u64_ucmp(u64(-1), u64(1)))
println(u64_scmp(u64(-1), u64(1)))
buf := u8_array(8)
u64_write_le(buf, 0, u64_hex("0x0102030405060708"))
println(buf[0])
println(buf[7])

出力

"0x0000000000000001"
"0x9abcdef000000000"
"0xfffffffffffffff8"
1
-1

getopt

コマンドラインのオプションを GNU の getopt_long と同じ規則で読みます。オプションは Opt{short, long, takes} です。short は1文字の文字列、long は文字列（どちらも "" にできます）、takes は値を取るなら true です。getopt(opts, args, from) は配列 args を添字 from から読みます。argv() を読むときは、先頭のプログラムのファイルを飛ばすために from を 1 にします。

  • 結果は Parsed{table, rest} です。table は指定されたオプションの名前（long、なければ short）から値への表です。値を取らないオプションの値は true で、同じオプションを複数回指定すると最後の値が残ります。rest はオプションでない文字列を順に並べた配列です。
  • 読める形は -a・-abc（-a -b -c と同じ）・-o 値・-o値・--opt・--opt 値・--opt=値 です。値は - で始まってもかまいません。- だけの文字列はオプションではありません。-- より後は全部 rest に入ります。オプションとそうでない文字列は混ぜられます。
  • エラーはプログラムを止めず、値として返します。opts にないオプションは Unknown{name}、args の終わりで値が抜けたものは Missing{name}、値を取らないオプションへの --opt=値 は NoValue{name} です。name は書かれたとおりの "-x" や "--opt" です。長いオプションの省略形は受け付けません。

r_lib_getopt.pk

use("getopt")
spec := [Opt{"a", "all", false}, Opt{"o", "output", true}, Opt{"", "level", true}]
use("list")
args := list_to_array(["prog", "-ao", "out.txt", "x", "--level=3", "--", "-y"])
r := getopt(spec, args, 1)
println(head(r))
opts := arg(r, 0)
println(table_get(opts, "all", false))
println(table_get(opts, "output", none))
println(table_get(opts, "level", none))
rest := arg(r, 1)
println(array_len(rest))
println(rest[0])
println(rest[1])
println(getopt(spec, list_to_array(["prog", "-ax"]), 1))
println(getopt(spec, list_to_array(["prog", "-o"]), 1))

2

"-y"

table

table_keys・table_values・table_items（[Tuple{key, value}, ...]）は不定の順序で項目を並べます。集合は値が true の表です。

r_lib_table.pk

use("list")
use("table")
use("pretty")
t := table()
table_set(t, 'a, 1)
table_set(t, 'b, 2)
put(f"{table_len(t)} {table_has(t, 'a)} {table_has(t, 'z)}\n")
put(f"{sort((a, b) -> a < b, table_values(t))}\n")
s := set_from_list([1, 2, 2, 3])
put(f"{set_len(s)} {set_has(s, 2)} {sort((a, b) -> a < b, set_to_list(s))}\n")

出力

2 true false
[1, 2]
3 true [1, 2, 3]

error

  • line_col(src, pos) はバイト位置 pos の Tuple{行, 列} です。どちらも1から数えます。line_text(src, line) は改行を除いたその行です。
  • loc_at(file, src, pos) は Loc{file, line, column} で、show_loc はそれを file:line:column と書きます。
  • error_at(loc, msg) は Error{loc, msg} を perform します。catch_error(f) は Ok{f()} です。f() が Error{loc, msg} を perform したら Err{loc, msg} です。
  • show_error(src, loc, msg) は file:line:column: msg・その行・列の下の ^ を並べた文字列です。

r_lib_error.pk

use("error")
src := "x := 1\ny := x +\n"
r := catch_error(() -> error_at(loc_at("a.pk", src, 12), "expected an expression"))
println(r)
put(show_error(src, arg(r, 0), arg(r, 1))); put("\n")
println(catch_error(() -> 42))

出力

Err{Loc{"a.pk", 2, 6}, "expected an expression"}
a.pk:2:6: expected an expression
  y := x +
       ^
Ok{42}

pretty

show(x) は print が出力する文字列で、リストは [a, b] になります。pretty(x, width) は、width 桁に収まる部分を1行にし、収まらない部分は要素を1つずつ別の行に2つの空白で字下げして置きます。pprint(x) は幅60でそれを出力します。

put(show(["a", 'b, F{1}])); put("\n")
put(quote_str("say \"hi\"")); put("\n")
pprint(Node{Node{Leaf{}, "left", Leaf{}}, "root", Node{Leaf{}, "a long right branch", Leaf{}}})

unparse

unparse(t) は規則 expr で読むと木 t になる文字列です。peg_sources の文法から作ります。unparse_as(rule, t) は任意の規則について同じことをし、文字列がなければプログラムを止めます。unparse_try は止まる代わりに none を返します。

  • 選択肢 Act{Seq{e1, ...}, Lambda{Tuple{Tuple{l1, ...}}, body}} は、body が準クオートで、その !x がラベル・Quote{c}・ラベル・Tuple{labels}・mexpr(h, args) のとき逆にたどれます。木を準クオートと照合し、ラベルに部分木を入れ、要素を順に書きます。文字列はそのまま、規則は unparse_as(rule, subtree) で書きます。いつも同じ文字列に合う要素（"+" や Same{}）にはラベル _ を使えます。要素は文字列・規則、または規則の Delimited・Delimited1・Many・Option です。
  • 木に合う選択肢のうち、準クオートの中で !x でない節が一番多いものを使います。
  • 弱い規則が求められている所に強い規則の選択肢を置くときは、文法の最初の "(" e ")"（動作は何でもよい）で囲みます。規則名だけの選択肢は、規則とそれがなりうる規則を結び、どの選択肢に括弧が要るかを決めます。より弱い規則で終わる選択肢（while (c) e は expr で終わる）も、それと同じかより弱い規則が求められているとき以外は括弧が要ります。
  • unparse_custom(owner, spec, tail, f) は規則 owner に選択肢を足します。f(t) は t の文字列か none、spec は準クオートとの順位付け、tail は文字列の最後の規則か none です。unparse は Do{...} を { } の中に1行1式、4つの空白で字下げして書き、If を if (c) a else b と書きます。どちらもこのやり方で足しています。
  • 文法で書かれない木の文字列は、コンストラクタの呼び出し Head{a, ...} です。識別子でないシンボルと、整数・文字列・シンボル・M式でない値には文字列がありません。

t6_unparse.pk

use("unparse")
t := '(if (n < 0) -n else n * (n + 1))
println(t)
put(unparse(t)); put("\n")

出力

If{Apply{_lt, Tuple{n, 0}}, Apply{_sub, Tuple{0, n}}, Apply{_mul, Tuple{n, Apply{_add, Tuple{n, 1}}}}}
if (n < 0) -n else n * (n + 1)

module でまとめたライブラリ

ライブラリを module でまとめて書くと、読み込んだあとに module の名前で呼べます。bitset が module bitset で書かれていれば、次のとおりです。

use("bitset")
s := bitset.new(100)
bitset.add(s, 3)

ライブラリの中の補助の関数は export を付けなければ外に出ません。試験で補助の関数を呼びたいときは、export module internal { ... } にまとめます。bitset の本体の末尾に次を足すと、bitset.internal.word(65) で補助の関数 helper の結果を試験できます。

    export module internal {
        export word(i) := helper(i)
    }

前処理したライブラリ

プログラム tools/preprocess.pk にライブラリの名前を引数で渡すと、指定したライブラリを前もって M式へ構文解析します。このプログラムは指定されたライブラリを use("name") と同じように、それが使うライブラリとともに読み込み、各ライブラリの解析結果の M式を planck/lib/<name>.pkm に1行1式で書きます。

前もって評価するものはありません。use は planck/lib/<name>.pkm の M式を読んで1つずつ評価するので、プログラムの動作は use が planck/lib/<name>.pk を構文解析した場合と同じです。使える .pkm ファイルがなければ use はライブラリを構文解析します。

.pkm ファイルを使うのは、ライブラリの本文と文法がどちらもファイルを書いたときと同じ場合です。文法が同じとは、planck/init.pk・planck/peg.pk・planck/syntax.pk の本文が同じで、規則を宣言したライブラリが同じ本文で同じ順に並び、ほかの規則が宣言されていない（peg_version が同じ）ことです。M式として読めないファイルと、最後の式で終わっていないファイルも使いません。

この判定は、プログラムが parse や規則の動作が呼ぶ関数を差し替えたことを検出しません。.pkm ファイルはいつ消してもかまいません。解析結果に M式の文字列表現がない値（関数・配列）を含むライブラリは前処理できません。
