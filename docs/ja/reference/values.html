値・パターン・M式

評価の対象は M式です。特殊形式の頭を持たない M式は構築子で、引数を評価した同じ頭の M式になります。パターンは構築子と同じ形で書き、合えば変数を束縛します。数は型が混ざると高いほうに揃え、誤りは実行時エラーです。以下は原則から外れる所です。値の種類はデータ型にあります。

M式

true・false・none は、同じ名前のシンボルを値とするリテラルです。変数ではないので、Def{true, e}・Set{true, e}・Declare{true} は実行前にプログラムを止めます。トップレベルの文字列は効果を持たず、コメントになります。

数

  • 整数どうしの割り算は3つあります。_div は0方向へ切り捨て、_quo（//）は負の無限大方向へ丸めます（-7 // 2 は -4）。_mod(a, b) は a - b * (a // b) で、符号は除数と同じです。
  • 除数が0なら実行時エラーです。ただし浮動小数点数か複素数を含む _div は止まらず、無限大か NaN（複素数は成分ごと）になります。
  • _lt _le _gt _ge は整数と浮動小数点数を、型を揃えず数学的な値で比べます。NaN を含むと false で、複素数は実行時エラーです。
  • _eq は型が違っても値が同じ数を等しいとします（1 == 1.0）。複素数は両成分が等しいときに等しく、NaN は自分自身とも等しくありません。
  • 整数は最も近い浮動小数点数に丸めて揃え、範囲外は実行時エラーです。

特殊形式

  • Def{x, e}：右辺から x より前の変数が見えます。Set{x, e} は代入です。
  • Declare{x}：Def{x, none} と同じです。ただし Def{x, e} が x を定義する場所に x がすでにあれば何もしません。
  • If{c, a, b}：c が false のときだけ b です。
  • Fusion{f, g}：f のどのパターンも合わなければ g を試します。Fusion{none, g} は g です。

t2_mexpr.pk

p := Point{3, 4}
println(p)
println(head(p))
println(arity(p))
println(arg(p, 1))
println(Point{1, 2} == Point{1, 2})
println(push(p, 5))

出力

Point{3, 4}
Point
2
4
true
Point{3, 4, 5}

パターン

  • _：何にでも合い、何も束縛しません。
  • Head{p, ..., _Rest{x}}：引数が _Rest の前の数以上ある M式に合い、残りの Tuple を x に束縛します。
  • _TypeOf{p, type}：値の type が type で p が合う値に合います。

t3_type.pk

describe := (n @ int) -> f"integer {n}"
          | (s @ string) -> f"string {s}"
          | (_) -> "other"
put(describe(1)); put("\n")
put(describe("abc")); put("\n")
put(describe('x)); put("\n")

出力

integer 1
string abc
other

部分関数と融合

関数はパターンで引数を取るので、合わない引数があり得る部分関数です。Fusion{f, g}（構文は f | g）は、まず f を試し、どのパターンも合わなければ（ガードが偽のときも）g を試します。つないだ順に試すので、f(0) := ... のように同じ場所に続けて書いた定義も、書いた順に試す1つの関数です。

f := (0) -> "zero" | (1) -> "one"
f(1)   // "one"
f(7)   // どの腕にも合わず、プログラムが止まる

どの腕にも合わなかった関数呼び出し・match・融合の最後のつなぎ先は、止まる代わりに MatchingFailed{f, args, loc} を Perform します。match e { f } は f(e) と同じ呼び出しです。受け手のハンドラが無ければ、エラーのメッセージ（matching failed）を出してプログラムが止まります。unhandled effect にはなりません。

フィールド中身
f呼ばれた関数（融合なら融合全体）
args合わなかった引数の Tuple{...}
loc失敗した呼び出しや match のソース上の位置。Loc{file, line, column}
a := handle f(7) with (MatchingFailed{_, Tuple{n}, _}, k) -> n
println(a)
7

ハンドラの値が Handle の値になります。f(7) を呼んだ式の値にはなりません。

融合の次のつなぎ先は、入口のパターンとガードだけで決まります。腕の入口が合えば、その腕の本体の奥で起きた MatchingFailed は次のつなぎ先へ移らず、外側へ伝わります。

g(0) := "zero"
h := (x) -> g(x) | (x) -> "second arm"

r := handle h(5) with (MatchingFailed{f, _, _}, k) -> "failed in g"
println(r)
"failed in g"

h(5) は1つ目の腕に入り、その中の g(5) が合わずに MatchingFailed になります。2つ目の腕には移りません。

Perform は、Handle のハンドラのどのパターンにも合わなければ、さらに外側のハンドラを探します。Return{v} や Break{} だけを受けるハンドラは通り抜け、どのパターンにも合う (e, k) -> ... のハンドラは MatchingFailed も受けます。MatchingFailed 以外の Perform は、受け手が無ければ unhandled effect で止まります。

代数的エフェクト

Perform{v} は、合うパターンを持つ一番近い handler(v, k) を呼びます。ハンドラは継続の中でも有効です。k は通常の関数で、Handle が値を返したあとでも何度でも呼べます。

継続を捕捉した時点で定義済みの変数は、再開した計算のあいだで共有されます。再開のあとに定義した変数は別です。

t5_resume.pk

ask() := perform Ask{}

with_answer(v, f) := handle f() with (Ask{}, k) -> k(v)

println(with_answer(21, () -> ask() * 2))
println(with_answer(5, () -> ask() + ask()))

出力

42
10

MatchingFailed のハンドラも k で再開できます。k(x) の x が、失敗した関数呼び出しや match の値になります。

b := handle [f(7), 1] with (MatchingFailed{_, _, _}, k) -> k("other")
println(b)
Cons{"other", Cons{1, Nil{}}}

ハンドラは再開した続きの中でも有効なので、再開後に2回目の失敗が起きても同じハンドラが受けます。

c := handle [f(8), f(9)] with (MatchingFailed{_, Tuple{n}, _}, k) -> k(n)
println(c)
Cons{8, Cons{9, Nil{}}}

トップレベル

式を読むたびに大域変数 parse と eval を引き直すので、差し替えると次の式から新しい定義で処理されます。Apply{eval, ...} も差し替えた eval を呼びます。

  • parse：文字列 -> Tuple{M式, 文字列の残り}。空白しか残っていなければ Tuple{Eof{}, ""} を返し、差し替える parse は Eof{} をそのまま通します。
  • eval：M式 -> 値。

t6_eval.pk

old_eval := eval
eval = e -> {
    v := old_eval(e)
    put("=> ")
    println(v)
    v
}
1 + 2
'(a + b)
Point{1, 2}

出力

=> 3
=> Apply{_add, Tuple{a, b}}
=> Point{1, 2}
