planckvm の内部仕様

planckvm の実装の中の設計を説明します。VM の利用者が頼ってよい約束は、外部仕様のplanckvm: 実行モデルと値とplanckvm の命令に書きます。

方針

  • 評価器はバイトコードインタプリタです。式を命令に変換して命令ループで実行し、式を閉包に変換する方式は採りません。
  • 評価器は独自のガベージコレクタを備えます。方式は世代別コピー GC で、値のヒープと根は評価器が持ちます。
  • 評価器はホストのエフェクト、継続、M式の読み取りを使いません。これらは評価器の一部として planck で書きます。
  • 命令ループは自分を再帰呼び出ししません。planck の呼び出しの状態はレジスタスタックとフレームスタックだけにあります。

スタック

評価器はレジスタスタックとフレームスタックの2つの連続した領域を持ちます。どちらも GC の根で、満杯になると stack overflow で止まります。レジスタスタックは起動時に全要素を none で埋めます。

呼び出しと復帰

  • CALL A B C が Lambda を選んだら、現在のフレームの pc を保存し、新しいフレームを base = 現在の base + B + 1、env = fn の環境、ret = A で積みます。窓が base + nregs まで収まることを確かめます。引数は動かしません。
  • HANDLE A B は同じように base = 現在の base + B + 2、ret の kind = 1、reg = A のフレームを積み、R[B] の Lambda を引数なしで実行します。
  • RET A は値を読み、フレームを捨て、捨てたフレームの ret のとおりに呼び出し元へ渡します。
  • TCALL B C は R[B] から R[B+C] を R[-1] から R[C-1] へ移し、現在のフレームを置き換えます。ret の mode と reg は保ち、kind は 0 にします。組み込みを呼んだときは結果を RET と同じように渡します。
  • alts の中身は下の Fusion の形です。NEXT は next から順に、引数の個数が合う選択肢を選びます。Lambda ならフレームの fn と env を置き換え、pc を 0 にします。窓は変えません。組み込みなら結果を RET と同じように渡し、継続なら TCALL と同じように再開します。
  • 選択肢が尽きたとき、kind が 2 なら転送に進み、それ以外なら matching failed で止まります。
  • 組み込みのセルが上書きされているときの呼び出しは、R[nregs] に関数、その上に引数を置いて CALL と同じように行います。ret は命令の種類で決まり、条件の命令なら mode は k + 1、ASET PLAINSET なら 3、それ以外なら 0 で reg = A です。窓の検査は nregs に呼び出しの分を足した大きさで行います。

上書きの判定

評価器は語 guard を1つ持ち、命令の組み込みの欄の名前ごとに1ビットを割り当てます。組み込みの欄を持つ命令は、まず guard が 0 かを見て、0 でなければ自分のビットを見ます。この名前のセルには印があり、SETGLOBAL は印のあるセルに書くときにビットを更新します（値が元の組み込みなら 0、それ以外なら 1）。

継続

継続はヒープ上のオブジェクトで、フレームスタックの切片とレジスタスタックの切片のコピーです。継続の実現にホストのエフェクトは使いません。

  1. PERFORM A B: 現在のフレームから下へたどって kind が 1 のフレーム F を探します。無ければ unhandled effect で止まります。
  2. 現在のフレームの pc を保存し、F から現在のフレームまでのフレームと、F.base - 2 から現在のフレームの R[nregs-1] までのレジスタをコピーして継続を作ります。コピーの base はレジスタの切片の先頭からの差にし、A を継続の欄 reg に入れます。この2つの切片の確保が S です。
  3. F より上を捨て、F と同じ位置に kind = 2、ret の mode と reg は F のまま、base = F.base のフレームを作ります。R[0] に送られた値、R[1] に継続を入れて、ハンドラを引数 2 個で選びます。
  4. 転送: フレームの下から次の kind が 1 のフレーム G を探します。無ければ unhandled effect で止まります。G からこのフレームの1つ下までの切片の後ろに元の継続の切片をつないだ新しい継続を作り、G について手順 3 を行います。元の継続のレジスタの切片は F.base - 2 の位置に続くので隙間はできません。元の切片のフレームの base には F.base - G.base を足します。
  5. 再開: CALL A B 1 の関数が継続なら、引数を先に読み、切片を 現在の base + B + 1 の位置にコピーし、各フレームの base にその位置を足します。切片の最初のフレーム（境界）の ret の mode と reg は CALL の A にします。切片の最後のフレームを現在のフレームにし、その R[reg] に引数を入れ、保存した pc から続けます。
  6. TCALL の関数が継続なら、引数を先に読み、切片を現在のフレームの base - 1 の位置にコピーし、最初のフレームの ret の mode と reg は現在のフレームのものにします。

GC は kind を見て値の語だけをたどります。大きな整数、浮動小数点数、複素数、文字列、plain 配列の中身はたどりません。コードは命令列をとばして定数表をたどります。継続のフレームは fn env alts だけをたどり、レジスタはすべてたどります。

FUSION は R[B] と R[C] の選択肢を連結して新しい Fusion を作ります。

世代

  • GC は若い世代と古い世代の2世代のコピー GC で、評価器の一部として planck で書きます。vasm のランタイムに足すものではありません。
  • 確保は若い世代から行います。若い世代に収まらないオブジェクトは古い世代に直接確保します。
  • 若い世代が満杯になると、根と記憶集合からたどれる若いオブジェクトをすべて古い世代へコピーし、若い世代を空にします。
  • 古い世代が満杯になると、古い世代を2つの半空間の間でコピーします。

確保とセーフポイント

  • 命令の表で S の付いた命令はメモリを確保する可能性があり、その確保で GC が走ることを許します。
  • GC は命令の副作用より前に走ります。命令の入力は GC の間もレジスタに残り、GC によって更新されます。命令は GC の後で入力を読み直します。
  • 実行中の値はすべて、レジスタスタック、フレームスタック、環境、セル、評価器の状態のいずれかからたどれます。評価器のローカル変数にだけ存在する値はありません。組み込みが確保をまたいで持つ値は評価器の状態の一時スロットに置きます。
  • 確保しない命令（JMP MOVE ENVGET など）では GC は走りません。ループの途中にセーフポイントは置きません。

レジスタの生死の表は持ちません。レジスタスタックの要素は常に有効な値か none です。これを次のように保ちます。

  • 起動時に全要素を none で埋めます。
  • GC は、この範囲より上で前回の GC の後に使われた範囲を none で埋めます。範囲の上端は窓を作るときに更新する語 high で持ちます。

呼び出し元の R[B] より上は呼ばれた側の窓に重なり、R[B] より下は生きている値か過去の値です。過去の値は上書きされるまで生き残りますが、誤った参照にはなりません。pc は添字なので、コードが移動しても影響を受けません。

ライトバリア

方式は記憶集合（古い世代のオブジェクトのリスト）です。古い世代のオブジェクトに若い世代のオブジェクトへの参照を書き込むとき、ヘッダの r が 0 ならその古いオブジェクトを記録して r を 1 にします。対象の命令は ENVSET SETGLOBAL ASET です。plain 配列は参照を持たないので記録しません。若い世代に確保したオブジェクトの初期化は記録しません。古い世代に直接確保したオブジェクトは、初期化で若い参照を書いたら記録します。レジスタスタックとフレームスタックへの書き込みは、毎回根としてたどるので記録しません。

同一性

配列、plain 配列、関数は同一性（EQ と HASH）を持ちます。同一性はアドレスでは表さず、最初の HASH のときにオブジェクトの番号の語へ番号を割り当てます（0 は未割り当て）。シンボルの番号は名前から、M式と文字列の番号は中身から、数の番号は値から決まります。

数と plain 配列の表現

  • 整数どうしの結果が小さい整数に収まるなら、確保せずに済ませてかまいません。確保が起きるのは桁が増えたときと、浮動小数点数や複素数の結果を作るときです。大きな整数の結果が 31 ビットに収まるときは必ず即値にします。
  • 浮動小数点数と複素数はヒープ上の不変のボックスです。vasm では複素数を浮動小数点数2つの組で表します。
  • plain 配列の要素はタグを持ちません。plain 配列は参照を持たないので、GC は中を走査せず、書き込みも記録しません。複素数の要素も plain 配列の中では2つの数であり、ボックスではありません。

部分評価との関係

planckvm の目的は planck で書いた評価器を部分評価して planck の vasm 実装を得ることです。次の性質はこの目的のために設計しました。

  • 命令列は作成後に変わらず、レジスタ番号とジャンプの差は即値です。コードが静的なら、命令の読み出しと次の命令の選択を展開でき、レジスタの添字も静的に決まります。
  • パターン照合は呼ばれる側のコードの中にあります。関数ごとに照合を特化でき、データの木をたどる照合器は要りません。
  • 継続はフレームの複製で実現し、ホストのエフェクトを使いません。評価器が Perform を使わないので、planck/lib/pe.pk にある継続の制限に当たりません。
  • 動的な間接呼び出しは CALL の呼び出し先だけです。呼ばれる可能性のあるコードの集合が閉じていれば、コードごとの関数に分割できます。
  • 組み込みの上書きの判定は語 guard を読むだけなので、guard が静的なら畳み込めます。大域変数は書き換え可能なセルなので、書き換えられる大域変数は静的に扱えません。
  • PLAINGET と PLAINSET は要素をボックス化しない数として読み書きします。
