構文の定義

planck/syntax.pk は、planck の構文を packrat パーサの規則として定義します。構文は処理系に組み込まれず、planck のプログラムです。すべての構文は M式の木に読み替えられ、ファイルの途中で parse を差し替えると有効になります。

  • 差し替えるまでは、字句・動作が呼ぶ関数・文法の文法を M式で書きます。
  • 差し替えたあとは、planck の構文を ::= で宣言します。

字句

識別子・整数・文字列などの字句は、読めたら次の位置を返す関数で書き、_define_rule にそのまま渡します。

planck/syntax.pk: Def{peg_tok_ident

Def{peg_tok_ident, Lambda{Tuple{p}, Apply{peg_scan_ident, Tuple{p, true}}}}
Def{peg_tok_rule_name, Lambda{Tuple{p}, Apply{peg_scan_ident, Tuple{p, false}}}}

動作は規則を定義するときにコンパイルされるので、動作が呼ぶ関数 peg_* は文法の規則より前に置きます。

文法の宣言

::= は規則 syntax_decl が読み、_define_rule を呼ぶ木にします。syntax_decl が使う g_choice・g_alt・g_item・g_suffix・g_primary が文法の文法で、宣言が作る形のとおりに、まず M式で書きます。

planck/syntax.pk: Apply{_define_rule, Tuple{Quote{syntax_decl}

Apply{_define_rule, Tuple{Quote{syntax_decl}, Quote{
    Act{Seq{rule_name, "::=", g_choice},
        Lambda{Tuple{Tuple{n, _, e}},
            Do{QuasiQuote{Apply{_define_rule, Tuple{Quote{UnQuote{n}}, Quote{UnQuote{e}}}}}}}}}}}

Apply{_define_rule, Tuple{Quote{g_choice}, Quote{
    Act{Seq{Delimited1{g_alt, "|"}},
        Lambda{Tuple{Tuple{es}}, Do{Apply{peg_choice, Tuple{es}}}}}}}}

Apply{_define_rule, Tuple{Quote{g_alt}, Quote{Choice{
    Act{Seq{"..."}, Lambda{Tuple{Tuple{_}}, Do{Quote{Prev{}}}}},
    Act{Seq{Many1{g_item}, Option{Seq{same, block}}},
        Lambda{Tuple{Tuple{items, act}}, Do{Apply{peg_alt, Tuple{items, act}}}}}}}}}

選択肢のラベルは、動作の無名関数の引数パターンになります。syntax_decl は expr の最初の選択肢なので、::= は式を書ける所ならどこにでも書け、次のトップレベルの式から新しい規則で読まれます。

i_decl.pk

use("pretty")
pretty.print('(pair ::= a:integer "," b:integer { (a, b) }))

出力

Apply{
  _define_rule,
  Tuple{
    Quote{pair},
    Quote{
      Act{
        Seq{integer, ",", integer},
        Lambda{Tuple{Tuple{a, _, b}}, Do{Tuple{a, b}}}
      }
    }
  }
}

parse の差し替え

動作を書く式の構文は最小のものです（M式・呼び出し・準クオート・ブロック）。そのあとで parse を切り替え、文法の文法自体も ::= で宣言し直します。

planck/syntax.pk: Def{parse_mexpr, parse}

Def{parse_mexpr, parse}
Set{parse, Lambda{Tuple{s}, Apply{peg_parse, Tuple{Quote{toplevel}, s}}}}

M式のリーダを parse_mexpr として残し、parse を規則 toplevel で1式読む関数にします。差し替えは Def でなく Set です。load が使う parse はすでに決まった変数なので、Def では新しい変数が増えるだけで、ライブラリは古い parse で読まれます。

式

規則は結合の強い順に宣言し、宣言済みの規則だけを参照します。

planck/syntax.pk: add_expr ::= a:add_expr "+

add_expr ::= a:add_expr "+" b:mul_expr { `_add(!a, !b) }
           | a:add_expr minus b:mul_expr { `_sub(!a, !b) }
           | mul_expr

add_expr は直接左再帰なので左結合です。動作は準クオートで、1 + 2 は Apply{_add, Tuple{1, 2}} になります。行頭の -1 が新しい式になるのは、minus の same が同じ行の字句にだけ成功するからです。

関数の定義も規則 expr の選択肢です。

  • fun f: Def{f, none}
  • f(p, ...) = e: Set{f, Fusion{f, Lambda{...}}}
  • f(p, ...) := e: Do{Declare{f}, Set{f, Fusion{f, Lambda{...}}}}。f がすでにその場所の変数なら f に定義を足します。

添字と置き換え

a[i] は _index_get、a[i] = e は _index_set の呼び出しになります（[ は a に空白なしで続けます）。

_index_get と _index_set は、種類ごとの Lambda（表は Table{t}、リストは Cons と Nil）を Fusion でつないだ関数です。利用者が _index_get = (K{...}, i) -> ... | _index_get と代入すると、新しい種類が元の関数の前に入ります。

関数 f を添字にすると subst(t, f) を呼びます。f の最後に「peg_skip を返す」腕を足して、木の各部分に当てます。peg_skip 以外が返った部分は置き換えて内側を試さず、返った部分は引数ごとに再帰します。

return と break

return・break・continue はエフェクトに読み替えます。関数の木を作るとき、return を読んでいれば本体を Handle で包みます。

i_return.pk

use("pretty")
pretty.print('(f(xs) := { for (x in xs) if (x > 0) return x; 0 }))

出力

Do{
  Declare{f},
  Set{
    f,
    Fusion{
      f,
      Lambda{
        Tuple{xs},
        Handle{
          Do{
            Apply{
              peg_for,
              Tuple{
                xs,
                Lambda{
                  Tuple{x},
                  If{
                    Apply{_gt, Tuple{x, 0}},
                    Perform{Return{x}},
                    none
                  }
                }
              }
            },
            0
          },
          Lambda{Tuple{Return{v}, k}, v}
        }
      }
    }
  }
}

規則で読む文字列

name{| text |} は、関数で書いた規則 embed が読みます。規則 name をその位置から呼び、続く |} を読んで、値を Quote{v} として木に入れます（planck/syntax.pk: Def{peg_tok_embed）。
