planckvm: 実行モデルと値

planckvm は planck の全体を実行するバイトコードです。planck で書いた評価器が式を planckvm の命令に変換し、命令ループで実行します。この頁は planckvm の設計で、機械・値・数・ガベージコレクタを書きます。命令はplanckvm の命令にあります。

状態。planckvm はこれから実装する設計です。今動いているのは planck0（planck0）と、リファレンスの vasm です。この頁が planck/SPEC.rst と違う点はSPEC との違いにまとめます。

方針

  • 評価器はバイトコードインタプリタです。式を命令に変換し、命令ループで実行します。式を閉包に変換する形は採りません。
  • 評価器は自前のガベージコレクタを持ちます。方式は世代別コピー GC で、値のヒープと根は評価器が持ちます。
  • 多倍長整数・浮動小数点・複素数は機械のプリミティブです。
  • 組み込み関数を一律に命令にはしません。他の命令と planck の式では書けないものだけを命令にします（組み込みと命令）。
  • 評価器はホストのエフェクト・継続・M式の読み取りを使いません。これらは評価器の一部として planck で書きます。

実行モデル

機械の形はスタック機械です。式の途中の値は、フレームごとのオペランドスタックに積みます。

名前中身
コード（code）1つの Lambda または1つのトップレベルの式の命令列。不変
フレーム1回の呼び出しの状態。フレームスタックに積む
環境（env）1回の呼び出しの変数の置き場。ヒープにあり、呼び出しごとに作る
セル大域変数1つ。値と名前を持つヒープの物
ヒープ評価器が持ち、GC が管理する

コード

欄意味
arity引数の個数
nslots環境のスロット数
params引数のパターンの木。実行には使わず、関数の表示と照合失敗の文に使う
instrs命令列。作った後は変えない
consts定数表。リテラル・シンボル・セル・入れ子のコード
  • 命令列は整数の列です。1命令は命令番号とそのオペランドです。
  • ジャンプ先 L と pc は命令列の添字で持ちます。GC が物を動かすので、アドレスでは持ちません。
  • コードを作るときに検査します。オペランドスタックの高さが全命令で一意に決まること、ジャンプ先が命令の先頭であること、スタックが負にならないことです。最大の高さも求めます。
  • MATCH* の失敗先 L の高さは 0 です。

フレーム

欄意味
呼び出し元値を返す先のフレーム。トップレベルの入口では無し
code, pc, env実行中のコードと次の命令と環境
残りの選択肢f | g のうち、まだ試していない関数。無ければ none
境界handler の関数。HANDLE が作ったフレームだけが持つ
転送の印PERFORM が handler を呼ぶフレームだけが持つ。選択肢が尽きたとき外側の境界へ進む指定
引数呼び出しの n 個の値。入口の照合が済むまで残す
オペランドスタック式の途中の値。高さはコード側で決まる最大値まで

フレームは連続した領域（フレームスタック）に積みます。領域は評価器が持ち、GC の根になります。満杯になると stack overflow で止まります。

環境と変数

  • 環境は | 親の環境 | スロット0 | スロット1 | ... | です。1回の呼び出しで1つ作り、スロットの初期値は none です。
  • 変数は書いた場所で決まり、コンパイル時に（深さ d, スロット i）に解決されます。d は親をたどる回数です。名前の解決はコンパイル時に終わり、実行時に未定義という状態はありません。
  • Lambda は作られた場所の環境を持ちます。環境は共有されるので、作った後の代入は関数から見えます。
  • 継続を再開しても環境は複製しません。再開した複数のコピーが同じ変数を共有します（SPEC の規則）。
  • 大域変数はセルで、初期値は none です。Def は新しいセルを作り、その後にコンパイルした式は新しいセルを指します。前にコンパイルした式は古いセルを指し続けます。Set は同じセルに書きます。

呼び出し

CALL n はスタックの f a1 ... an を取ります。関数 f は次のように選びます。

f選ぶ条件
Lambdaコードの arity が n
Fusion a | ba を先に試し、尽きたら b
組み込み引数の個数が合うとき。フレームは作らず、結果をその場で返す（EVAL だけはフレームを作る）
継続n が 1 のとき再開する
その他not a function で止まる

Lambda が選ばれたら、フレームと環境を作り、引数をフレームに置いて、コードの先頭から実行します。入口の命令列がパターンを照合します。不一致になると NEXT が同じ引数のまま次の選択肢を試します。選択肢が尽きると matching failed で止まります。

継続と handler

  • HANDLE は本体を境界フレームで実行します。本体が普通に終われば、その値が Handle の値です。
  • PERFORM v は呼び出し元をたどって最も内側の境界を探し、そこまでのフレームを複製して継続 k を作ります。境界の handler を引数 (v, k) で呼び、結果を境界の呼び出し元に返します。
  • handler の選択肢が全て合わなければ、次に外側の境界へ進みます。そのとき k は外側の境界までの複製に作り直します。内側の境界も複製に含まれます。
  • 境界が無ければ unhandled effect: v で止まります。
  • k を呼ぶと、複製したフレームを呼び出し元の上に複製し直します。境界の handler は残ります（deep）。最も内側のフレームで、引数を PERFORM の値として積んで続けます。本体が終わった値は k を呼んだ側に返ります。
  • 複製は捕捉時と再開時の2回です。k は何度でも呼べます。
  • 継続の実現にホストのエフェクトを使いません。フレームはデータとして複製します。

止まる

実行時の誤りは、文面を標準エラーに書き、終了状態 1 で終わります。捕まえる手段はありません。error_at の Error エフェクトはこの種の誤りではなく、通常の PERFORM です。

トップレベル

  • トップレベルの式1つが、arity 0 のコード1つです。ブロックの中の局所変数は、このコードの環境に置きます。
  • 式を読んで実行する繰り返しは評価器の入口で、命令ではありません。式ごとに大域変数 parse と eval のセルを読んで呼びます。
  • eval(e) も同じ形のコードを作って実行します。

  • 偽として扱う値はシンボル false だけです。

数

  • 整数は多倍長です。小さい整数は即値で持ち、大きい整数は桁の配列で持ちます。言語の整数は 1 種類で、範囲外の整数という状態は無く、巻き戻りも切り詰めもありません。
  • 浮動小数点は IEEE 754 の binary64 で、丸めは最近接偶数です。複素数は浮動小数点 2 つの組です。
  • ADD SUB MUL DIV は引数の型を見る 1 命令で、整数・浮動小数点・複素数を受けます。型が混ざったら、整数→浮動小数点→複素数の順に高い方へ揃えて計算し、結果の型も揃えた型になります。
  • 整数を浮動小数点に揃えると、最も近い値に丸まります。2^53 を超える整数は精度が落ちます（2^53 + 1 + 0.0 は浮動小数点の 2^53）。浮動小数点で表せる範囲（約 1.8 x 10^308）を超える整数を揃えようとすると誤りです。
  • 整数どうしの DIV は 0 方向へ切り捨てる商で、除数が 0 なら誤りです。浮動小数点か複素数が絡む割り算は 0 で割っても止まりません。浮動小数点なら無限大か NaN、複素数なら成分に同じ規則を当てた値になります。
  • LT は整数と浮動小数点を混ぜても型を揃えず、数学的な値で比べます。NaN が絡めば false です。複素数には順序が無いので、LT が複素数を受けたら誤りです。
  • EQ は型が違っても値が同じなら等しくなります（1 == 1.0 1 == 1+0j）。NaN は自分とも等しくありません。複素数は実部と虚部の両方が等しいとき等しくなります。
  • ビット演算は整数だけを受けます。負の数を含めて無限桁の 2 の補数として扱います。
  • 浮動小数点の例外は止めません。数学関数は exp・log・sin・cos・pow・atan2 の 6 つだけです。
  • 複素数は complex(re, im) で作ります。リテラルはありません。vasm には浮動小数点の型と演算を足しますが、複素数の型は足さず、浮動小数点 2 つの組で持ちます。

ヒープとガベージコレクション

値とヒープ

  • 値は 1 語のタグ付きです。小さい整数は即値で持ち、他はヒープへの参照です。浮動小数点・複素数・大きな整数・文字列・M式・配列はヒープの物です。
  • ヒープは 1 つの整数配列の上に作る、世代ごとの領域です。
  • GC は世代別コピー GC で、評価器の一部として planck で書きます。vasm の実行時に足すものではありません。

確保と安全点

  • 命令の表で S の印が付いた命令は確保しうる命令で、確保で GC が走ってよいことにします。
  • GC は命令の副作用の前に走ります。命令の入力は GC の間もオペランドスタックに残り、GC で更新されます。命令は GC の後に入力を読み直します。
  • 実行中の値は、フレームスタック・環境・セルから辿れます。評価器のローカルにだけ持つ値はありません。
  • 確保の無い命令（JMP LOAD POP など）では GC は走りません。ループの途中で止める安全点は置きません。

根

根内容
フレームスタック全フレームの env, code, 引数, オペランドスタック（保存した高さまで）
セル大域変数
評価器の状態シンボル表、定数表、コンパイル中の状態

フレームの欄は全て値かヘッダの整数で、タグから辿れます。スタックマップは持ちません。pc は添字なので、コードの移動に影響されません。定数表はコードの一部として辿ります。

書き込み記録

方式は記憶集合（古い世代の物のリスト）です。古い世代の物へ、若い世代の物への参照を書くとき、その物を記録します。対象は STORE GSET ASET です。plain 配列は参照を持たないので記録しません。新しく確保した物の初期化は記録せず、フレームスタックへの書き込みも記録しません（根として毎回辿るため）。

同一性

配列・plain 配列・関数は同一性（EQ と HASH）を持ちます。アドレスでは持たず、最初の HASH で番号を割り当てます。シンボルは名前から決まる番号を持ち、M式と文字列は中身から、数は値から決まる番号を持ちます。

継続

PERFORM はフレームを複製するので確保をします。継続の中のフレームは通常のフレームと同じ形で、同じように辿れます。

部分評価との関係

planckvm の目的は、planck で書いた評価器を部分評価して、planck の vasm 実装を得ることです。次の設計の性質は、このために置いています。

  • 命令列は作った後に変わらず、ジャンプ先は即値です。コードが静的なら、命令の読み出しと次の命令の選択を展開できます。
  • 各 pc でオペランドスタックの高さが決まるので、スタックを静的な並びとして持てます。
  • パターン照合は呼ばれるコードの中にあります。関数ごとに照合を特化でき、データの木をたどる照合器は要りません。
  • 継続はフレームの複製で、ホストの効果を使いません。評価器が Perform を使わないので、planck/lib/pe.pk にある継続の制限に当たりません。
  • 動的な間接呼び出しは CALL の先の関数だけです。呼ばれうるコードの集合が閉じていれば、コードごとの関数に分けられます。
  • CALLP の守りは、セルが静的で不変なら畳めます。大域変数は可変のセルなので、書き換えられる大域は静的に扱えません。
  • PLAINGET と PLAINSET は、要素を箱なしの数として読み書きします。

部分評価機そのものは planck/lib/pe.pk にあります。整数の型は I32{} と I64{} で、多倍長の型はありません。多倍長整数の静的な畳み込みと vasm の浮動小数点の演算は、必要になったときに足します。
