planckvm: 実行モデルと値

planckvm は planck の全機能を実行するバイトコードです。planck で書いた評価器が式を planckvm の命令に変換し、命令ループで実行します。この頁とplanckvm の命令が外部仕様で、VM の利用者や planck からコードを生成する側が頼ってよい約束を書きます。この頁では機械、値、数を説明します。実装の中の設計はplanckvm の内部仕様に書きます。planck/SPEC.rst との相違はSPEC との違いにまとめました。

方針

  • 多倍長整数、浮動小数点数、複素数は機械のプリミティブです。
  • 組み込み関数を一律に命令にはしません。高頻度で呼ばれるものだけを命令にします（組み込みと命令）。

実行モデル

機械はスタック機械です。式の評価途中の値は、フレームごとのオペランドスタックに積みます。

名前中身
コード（code）1つの Lambda または1つのトップレベルの式の命令列。不変
フレーム1回の呼び出しの状態。フレームスタックに積む
環境（env）1回の呼び出しの変数を置く領域。呼び出しごとに作る
セル大域変数1つを表すオブジェクト。値と名前を持つ

コード

欄意味
arity引数の個数
nslots環境のスロット数
params引数のパターンの木。実行には使わず、関数の表示と照合失敗のメッセージに使う
instrs命令列。作成後は変更しない
consts定数表。リテラル、シンボル、セル、入れ子のコードを持つ
  • 命令列は整数の列です。1命令は命令番号とそれに続くオペランドからなります。
  • ジャンプ先 L と pc は命令列の添字で表します。
  • コードの作成時に、オペランドスタックの高さが全命令で一意に決まること、ジャンプ先が命令の先頭であること、スタックの高さが負にならないことを検査します。高さの最大値もこのときに求めます。
  • MATCH* の失敗先 L では、スタックの高さは 0 です。

フレーム

フレームは1回の呼び出しの状態で、フレームスタックに積みます。フレームスタックが満杯になると stack overflow で止まります。

環境と変数

  • 環境は1回の呼び出しにつき1つ作り、スロットの初期値は none です。
  • 変数の指す先は書かれた位置で決まり、コンパイル時に（深さ d, スロット i）へ解決されます。d は親をたどる回数です。名前の解決はコンパイル時に終わるので、実行時に未定義の変数は生じません。
  • Lambda は作られた場所の環境を保持します。環境は共有されるので、Lambda の作成後に行った代入もその関数から見えます。
  • 継続を再開しても環境は複製しません。再開した複数のコピーは同じ変数を共有します（SPEC の規則）。
  • 大域変数はセルで表し、初期値は none です。Def は新しいセルを作り、それ以降にコンパイルした式は新しいセルを指します。それ以前にコンパイルした式は古いセルを指したままです。Set は同じセルに書き込みます。

呼び出し

CALL n はスタックから f a1 ... an を取り出します。関数は f の種類に応じて次のように選びます。

f選ぶ条件
Lambdaコードの arity が n に等しいとき
Fusion a | ba を先に試し、尽きたら b を試す
組み込み引数の個数が合うとき。フレームは作らず、結果をその場で返す（eval だけはフレームを作る）
継続n が 1 のとき再開する
その他not a function で止まる

Lambda を選んだら、フレームと環境を作り、引数をフレームに置いて、コードの先頭から実行します。入口の命令列がパターンを照合し、一致しなければ NEXT が同じ引数で次の選択肢を試します。選択肢が尽きると matching failed で止まります。

継続とハンドラ

  • HANDLE は本体を境界フレームで実行します。本体が正常に終わると、その値が Handle の値になります。
  • PERFORM v は呼び出し元をたどって最も内側の境界を探し、そこまでのフレームを複製して継続 k を作ります。次に境界のハンドラを引数 (v, k) で呼び、結果を境界の呼び出し元に返します。
  • ハンドラのどの選択肢にも一致しなければ、次に外側の境界へ進みます。このとき k は外側の境界までの複製として作り直します。内側の境界もこの複製に含まれます。
  • 境界が見つからなければ unhandled effect: v で止まります。
  • k を呼ぶと、複製してあるフレームを呼び出し元の上に再び複製します。境界のハンドラは残ります（deep）。最も内側のフレームでは、k の引数を PERFORM の値として積んで実行を続けます。本体が終わると、その値は k を呼んだ側に返ります。
  • k は何度でも呼べます。

実行時エラー

実行時エラーが起きると、メッセージを標準エラー出力に書き、終了状態 1 で終了します。捕捉する手段はありません。error_at の Error エフェクトはこの種のエラーではなく、通常の PERFORM です。

トップレベル

  • トップレベルの式1つが arity 0 のコード1つになります。ブロック内の局所変数はこのコードの環境に置きます。
  • 式を読んで実行するループは評価器の入口にあり、命令ではありません。式ごとに大域変数 parse と eval のセルを読んで呼び出します。
  • eval(e) も同じ形のコードを作って実行します。

  • 偽として扱う値はシンボル false だけです。

  • HASH は EQ で等しい値に同じ値を返します。整数に等しい浮動小数点数と、虚部が 0 で実部が整数に等しい複素数には、その整数と同じ値を返します。配列、関数、plain 配列には、オブジェクトごとに変わらない番号を割り当てます。

数

  • 整数は多倍長です。言語の整数は1種類で、範囲外の整数はなく、ラップアラウンドも切り詰めも起きません。
  • 浮動小数点数は IEEE 754 の binary64 で、丸めは最近接偶数です。複素数は浮動小数点数2つの組です。
  • ADD SUB MUL DIV はそれぞれ引数の型を見て動く1つの命令で、整数、浮動小数点数、複素数を受け取ります。型が混在するときは、整数→浮動小数点数→複素数の順で高い方の型に揃えて計算し、結果もその型になります。
  • 整数を浮動小数点数に揃えると、最も近い値に丸められます。2^53 を超える整数は精度が落ちます（2^53 + 1 + 0.0 は浮動小数点数の 2^53）。浮動小数点数で表せる範囲（約 1.8 x 10^308）を超える整数を揃えようとするとエラーです。
  • 整数どうしの DIV は 0 方向へ切り捨てた商を返し、除数が 0 ならエラーです。浮動小数点数か複素数を含む割り算は、0 で割っても止まりません。浮動小数点数なら無限大か NaN になり、複素数なら各成分に同じ規則を適用した値になります。
  • LT と GE は整数と浮動小数点数が混在しても型を揃えず、数学的な値で比べます。NaN を含むと false です。複素数には順序がないので、LT と GE に複素数を渡すとエラーです。
  • EQ では型が違っても値が同じなら等しくなります（1 == 1.0 1 == 1+0j）。NaN は自分自身とも等しくありません。複素数は実部と虚部がともに等しいときに等しくなります。
  • ビット演算は整数だけを受け取ります。負の数も含めて無限桁の2の補数として扱います。
  • 浮動小数点例外が起きても止めません。数学関数は exp・log・sin・cos・pow・atan2 の6つだけです。
  • 複素数は complex(re, im) で作ります。リテラルはありません。
