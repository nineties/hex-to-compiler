planckvm: 実行モデルと値

planckvm は planck の全機能を実行するレジスタマシンのバイトコードです。変数はコンパイル時にセル・環境・レジスタへ解決され、実行時に名前は引きません。呼び出しは呼び出し元のレジスタに窓を重ね、引数をコピーしません。外部仕様はこの頁と命令、実装の設計は内部仕様です。

実行モデル

命令は現在のフレームのレジスタ R[0] 〜 R[nregs-1] を読み書きします。コード（命令列と定数表）は不変で、1つの Lambda かトップレベルの式が1つのコードです（フォーマット）。環境は変数を置くヒープ上の領域で、セルは大域変数1つを表します。

レジスタの窓

フレームのレジスタは1本のレジスタスタックの上にあり、その範囲を窓と呼びます。CALL A B C で呼ばれた Lambda の窓は呼び出し元の R[B+1] から始まるので、引数 R[B+1] 〜 R[B+C] が呼ばれた側の R[0] 〜 R[C-1] になります。

  • 呼び出しの間、R[B] には呼ばれた関数が入ったままです。R[B] より上の値は失われるので、呼び出しをまたいで使う値は R[B] より下に置きます。

変数の置き場所

変数は書かれた位置で決まります。

  • 大域変数の初期値は none です。Def は新しいセルを作り、Set は同じセルに書き込みます。Def の前にコンパイルした式は古いセルを指したままです。
  • true false none はリテラルで、Def Set Declare の対象に書くとコンパイルエラーです。

呼び出し

CALL A B C は f = R[B] を C 個の引数で呼びます。Lambda は arity が C に等しければ新しいフレームで実行します。Fusion a | b は a を先に試し、尽きたら b を試します。組み込みは引数の個数が合えばフレームを作らず結果をその場で受け取ります（eval だけは arity 0 のコードをフレームで実行します）。継続は C が 1 のとき再開し、それ以外の値は not a function で止まります。

  • コードの入口の命令列がパターンを照合します。一致しなければ NEXT が同じ引数で次の選択肢を試し、尽きると MatchingFailed{f, args, loc} を Perform します（f は呼ばれた関数、args は引数の Tuple、loc は none です）。引数の個数に合う選択肢がない呼び出しも同じです。受け手がなければ matching failed で止まります。入口の命令列は引数のレジスタを書き換えません。
  • 呼ばれた側の RET の値は、条件の命令（TEST から TGEI まで）なら false 以外を真として扱い、ASET PLAINSET なら捨て、それ以外は R[A] に入れます。
  • 命令の表の「組み込み」の欄に名前のある命令は、その名前が局所変数でなければ、大域変数に同じ名前を定義していても表の動作をします。

継続とハンドラ

HANDLE は本体を境界フレームで実行し、本体の値が Handle の値になります。PERFORM A B は、最も内側の境界までのフレームとレジスタを複製して継続 k を作り、境界より上を捨てて、境界のハンドラを (R[B], k) で呼びます。ハンドラの結果が Handle の値です。どの選択肢にも一致しなければ外側の境界へ進み、見つからなければ unhandled effect: v で止まります（MatchingFailed は matching failed で止まります）。ハンドラが返した値は、失敗した呼び出しの値ではなく Handle の値で、失敗した呼び出しの値は k に渡した値です。

k は通常の関数で、何度でも呼べます。呼ぶと複製を呼び出した窓の上に再び複製し、境界のハンドラを残したまま（deep）続けます。PERFORM の R[A] には k の引数が入ります。

再開しても環境とセルは複製しないので、その変数は複数のコピーで共有されます。レジスタの変数は値を複製するので、再開のあとの x := e はコピーごとに別の変数です。

実行時エラーとトップレベル

実行時エラーは、起こしたフレームでエフェクト Error{none, メッセージ} を Perform します。Error のハンドラが捕まえると、その継続は、失敗した命令が書くレジスタに値を渡します。ハンドラが無ければ、メッセージを標準エラー出力に書いて終了状態 1 で終了します。命令のエラー、関数でないものの呼び出し、組み込み put・substr・_strcat・mexpr・intern・symname・exit とシステムの組み込みのエラーがこのエフェクトです。ほかの実行時エラーは、メッセージを書いて終了状態 1 で終了します。トップレベルの式1つが arity 0 のコード1つで、式ごとに parse と eval のセルを読んで呼ぶループは評価器の入口にあります。入口のコードは CALL R0 R0 n と HALT R0 の2語です。

値

値の type は Int・Float・Complex・String・Symbol・Expr・Array・Plain・Function で、どれも型 Type の値です。同じ名前の大域変数がそれを持ちます。整数は多倍長、浮動小数点数と複素数は binary64 で不変、文字列は 0 バイトも含められる不変のバイト列、シンボルは名前ごとに一意、M式は immutable です。配列は値の、plain 配列は1つの型の要素の、書き換え可能な列です。関数は Lambda・Fusion・組み込み・継続です。

  • シンボル false だけが偽で、それ以外はすべて真です。
  • EQ は、数は値で、文字列は中身で、M式とシンボルは同一性で比べます（M式は intern するので、頭と引数が同じ M式は同じオブジェクトです）。配列と plain 配列は、同一のオブジェクトなら等しく、そうでなければ要素ごとに比べます（plain 配列は読み出した値で比べるので、型が違っても要素が等しければ等しくなります）。関数とユーザーデータは同一のオブジェクトだけが等しくなります。等しい値の HASH は同じです（データ型）。

数

整数は多倍長で、ラップアラウンドも切り詰めも起きません。浮動小数点数は binary64 で丸めは最近接偶数です。複素数は complex(re, im) で作ります。ADD SUB MUL DIV は型を見て動く1つの命令で、型が混在すれば整数→浮動小数点数→複素数の順で高いほうに揃えます。原則から外れるのは次の所です。

  • 整数を浮動小数点数に揃えるときは最も近い値に丸めます。浮動小数点数の範囲を超える整数はエラーです。
  • 整数どうしの DIV は 0 方向へ切り捨てた商で、除数が 0 ならエラーです。浮動小数点数か複素数を含む割り算は、0 で割っても止まらず、無限大か NaN（複素数は各成分）になります。
  • LT と GE は整数と浮動小数点数を、型を揃えず数学的な値で比べます。NaN を含むと false で、複素数はエラーです。
  • EQ は型が違っても値が同じなら等しく（1 == 1.0）、NaN は自分自身とも等しくありません。

plain 配列

要素の型は、'bool、符号付き整数 'i8 'i16 'i32 'i64、符号なし整数 'u8 〜 'u64、浮動小数点数 'f16 'f32 'f64（binary16・binary32・binary64）、複素数 'c64 'c128（実部と虚部が binary32・binary64）です。読み出した要素は言語の値になり、'f16 と 'f32 は値を変えずに binary64 へ広がります。

PLAINSET は、型に収まる数だけを書けます。収まらない値は止まります。

  • 整数型へは、範囲内の整数をそのまま格納します。範囲外はエラーで、ラップアラウンドしません。浮動小数点数は 0 方向へ切り捨ててから範囲を検査します（255.9 は 255）。NaN・無限大・複素数はエラーです。
  • 浮動小数点型へは、最も近い値に丸めます。'f32 'f16 の最大値を超えると同じ符号の無限大です。複素数型へは実部に格納します。
  • 'bool へは、0 以外の数が true、0 0.0 -0.0 が false です。数値型へ true false を書くと 1 0 です。
  • 数でない値（文字列・none・M式・配列・関数）と、binary64 の範囲を超える整数の浮動小数点型・複素数型への書き込みはエラーです。
