packrat パーサ

planck/peg.pk は PEG の文法を解釈するパーサです。文法はただのデータ（M式）で、規則の結果は位置ごとに覚えておきます。M式で 316 行あります。

文法はデータ

構文解析式（規則の右辺）は M式です。どんな形があるかはファイルの先頭にまとまっています。

planck/peg.pk:4–21

" A grammar is data. A parsing expression is one of "
"   \"text\"          the text, after blanks and comments "
"   Tight{\"text\"}   the text, without skipping blanks "
"   Key{\"word\"}     the word, not followed by a letter, a digit or _ "
"   name            the rule name (a symbol) "
"   f               a function: f(p) returns the new position or -1, and sets peg_pv "
"   Seq{e, ...}     sequence. The value is Tuple{v, ...} "
"   Choice{e, ...}  ordered choice "
"   Many{e}, Many1{e}, Option{e}  the values are Tuple{v, ...}, Option gives Tuple{} or Tuple{v} "
"   And{e}, Not{e}  lookahead "
"   Delimited{e, sep}, Delimited1{e, sep}  e separated by sep. The value is Tuple{v, ...} "
"   Same{}          succeeds when the next token is on the same line "
"   Act{e, f}       applies f to the value of e. f is an expression evaluated by define_rule "
"   Prev{}          the previous definition of the rule (only as an alternative of define_rule) "
"   Fail{}          never matches "

" Results of rules are memoized for each position. "
" Direct left recursion (sum ::= sum \"+\" term | term) is handled by growing the seed. "

たとえば「"7" が 1 回以上」は Many1{"7"}、「読めたら個数を数える」は Act{Many1{"7"}, t -> arity(t)} です。define_rule で名前を付けると、そのまま規則として使えます。

i_define.pk

define_rule('sevens, 'Act{Many1{"7"}, t -> arity(t)})
println(peg_parse('sevens, "7 7 7 rest"))
println(sevens{| 7 7 7 7 |})

出力

Tuple{3, "rest"}
4

::= を使わずに規則を作りましたが、sevens{| ... |} でも読めます。::= も結局はこの define_rule の呼び出しになります（構文を planck で書く）。

式を解釈する

peg_px(e, p) は、構文解析式 e を位置 p から試します。成功すれば次の位置を返して値を peg_pv に置き、失敗すれば -1 を返します。

planck/peg.pk:207–212

Def{peg_px, Lambda{Tuple{e, p}, Do{
    Def{t, Apply{typeof, Tuple{e}}},
    If{Apply{eq, Tuple{t, Quote{string}}}, Apply{peg_lit, Tuple{e, Apply{peg_skip_ws, Tuple{p}}}},
    If{Apply{eq, Tuple{t, Quote{symbol}}}, Apply{peg_call_rule, Tuple{e, p}},
    If{Apply{eq, Tuple{t, Quote{function}}}, Apply{e, Tuple{p}},
        Apply{Apply{table_get, Tuple{peg_handlers, Apply{head, Tuple{e}}, none}}, Tuple{e, p}}}}}}}}

文字列なら空白を飛ばしてから照合し、シンボルなら規則を呼び、関数ならその関数に任せます。Seq や Choice のような M式は、頭ごとの処理を表 peg_handlers から引きます（planck/peg.pk:170–205）。字句（識別子や整数）は関数で書けるので、構文の側で速い関数を用意しています。

失敗したときは、一番先まで進んだ位置を peg_far に覚えておきます（planck/peg.pk:57–59）。構文エラーはその位置で知らせます。

メモ化と左再帰

同じ規則を同じ位置で何度試しても、結果は同じです。だから位置ごとに規則の結果を覚えておきます。これが packrat 構文解析です。後戻りしても、同じ仕事をくり返さずにすみます。

planck/peg.pk:214–220

" === Rules and memoization === "
" The memo of position p is the array peg_memo[p] (made when first used), which holds "
" three slots for each rule id: end position, value and left-recursion flag. "
" The end position is none before the rule runs, -1 for failure and -2 while the rule is running. "
" On left recursion (the rule is called again at the same position while it runs), "
" the inner call fails, which is the seed. Then the rule is run again "
" while it consumes more than the last result. "

メモは位置ごとの配列で、規則ごとに「終わりの位置・値・左再帰の印」の 3 つの欄を持ちます。規則を呼ぶ peg_call_rule はまずメモを見ます（planck/peg.pk:229–245）。

左再帰（sum ::= sum "+" term | term）もこのメモで扱います。規則の実行中にメモの欄を「実行中」にしておき、同じ位置で自分がもう一度呼ばれたら失敗を返します。これが最初の種です。種で 1 回目の結果ができたら、その結果をメモに置いてもう一度規則を動かします。前より長く読めた間は、これをくり返します。

planck/peg.pk:247–265

Def{peg_run_rule, Lambda{Tuple{r, p, row, b}, Do{
    Def{body, Apply{table_get, Tuple{peg_rules, r, none}}},
    Def{b1, Apply{add, Tuple{b, 1}}},
    Apply{array_set, Tuple{row, b, -2}},
    Def{q, Apply{peg_px, Tuple{body, p}}},
    Apply{array_set, Tuple{row, b, q}},
    Apply{array_set, Tuple{row, b1, peg_pv}},
    If{Apply{eq, Tuple{Apply{array_get, Tuple{row, Apply{add, Tuple{b, 2}}}}, true}}, Do{
        Def{go, Apply{ge, Tuple{q, 0}}},
        While{go, Do{
            Set{q, Apply{peg_px, Tuple{body, p}}},
            If{Apply{gt, Tuple{q, Apply{array_get, Tuple{row, b}}}},
                Do{
                    Apply{array_set, Tuple{row, b, q}},
                    Apply{array_set, Tuple{row, b1, peg_pv}}},
                Set{go, false}}}},
        Set{peg_pv, Apply{array_get, Tuple{row, b1}}},
        Apply{array_get, Tuple{row, b}}},
    q}}}}

こうして 1 - 2 - 3 は (1 - 2) - 3 のように左から積み上がります。

規則を定義する

planck/peg.pk:282–291

" define_rule(name, e) defines or replaces the rule "
Def{define_rule, Lambda{Tuple{name, e}, Do{
    If{Apply{eq, Tuple{Apply{table_get, Tuple{peg_ids, name, none}}, none}}, Do{
        Apply{table_set, Tuple{peg_ids, name, peg_nrules}},
        Set{peg_nrules, Apply{peg_inc, Tuple{peg_nrules}}}}, none},
    Def{old, Apply{table_get, Tuple{peg_rules, name, Fail{}}}},
    Apply{table_set, Tuple{peg_sources, name, Apply{peg_subst_prev, Tuple{e, Apply{table_get, Tuple{peg_sources, name, Fail{}}}}}}},
    Set{peg_version, Apply{peg_inc, Tuple{peg_version}}},
    Apply{table_set, Tuple{peg_rules, name, Apply{peg_subst_prev, Tuple{Apply{peg_prepare, Tuple{e}}, old}}}},
    name}}}

define_rule は規則に番号を振り、構文解析式の中の動作 Act{e, f} の f を評価してから表に入れます。選択肢の Prev{} は、その規則のそれまでの定義に置き換えます。::= の ... はこれになります。

評価する前の形は peg_sources にも残します。文法を読む道具、たとえば木を文字列に戻す unparse は、この表を読んで動きます。

入口

peg_parse(rule, s) は、メモを新しく作ってから規則を呼びます（planck/peg.pk:300–316）。結果は Tuple{値, 残り} です。読めなかったときは peg_far の位置から行の終わりまでを添えて SyntaxError{...} を返します。
