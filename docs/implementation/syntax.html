構文の定義

planck/syntax.pk は、planck の構文を packrat パーサの規則として定義し、最後に parse を差し替えます。構文は処理系に組み込まれておらず、planck のプログラムの一部です。

字句

識別子・整数・文字列などの字句は、構文解析式でなく関数で書きます。読めたら次の位置を返す関数です。

planck/syntax.pk:28–42

" identifier: [A-Za-z_][A-Za-z0-9_]* except the peg_reserved words and the f of f\"...\" "
Def{peg_tok_ident, Lambda{Tuple{p}, Do{
    Set{p, Apply{peg_skip_ws, Tuple{p}}},
    Def{q, Apply{peg_inc, Tuple{p}}},
    Def{name, ""},
    If{Apply{peg_is_alpha, Tuple{Apply{peg_char_at, Tuple{p}}}}, Do{
        While{Apply{peg_is_alnum, Tuple{Apply{peg_char_at, Tuple{q}}}}, Set{q, Apply{peg_inc, Tuple{q}}}},
        Set{name, Apply{substr, Tuple{peg_src, p, q}}},
        If{If{Apply{table_get, Tuple{peg_reserved, name, false}}, true,
              If{Apply{_eq, Tuple{q, Apply{_add, Tuple{p, 1}}}},
                 If{Apply{_eq, Tuple{Apply{peg_char_at, Tuple{p}}, 102}}, Apply{_eq, Tuple{Apply{peg_char_at, Tuple{q}}, 34}}, false},
                 false}},
            Apply{peg_fail, Tuple{p}},
            Do{Set{peg_pv, Apply{intern, Tuple{name}}}, q}}},
        Apply{peg_fail, Tuple{p}}}}}}

予約語の表 peg_reserved の単語と f" の f は識別子になりません（planck/syntax.pk:10–26）。関数は _define_rule にそのまま渡せば規則になります（planck/syntax.pk:123–126）。

式

規則は結合の弱い順に expr・union・arrow・ternary・or_expr と続き、primary で終わります（planck/syntax.pk:145–328）。加減算の規則は次のとおりです。

planck/syntax.pk:237–243

" a binary - must be on the same line as its left operand "
Apply{_define_rule, Tuple{Quote{minus}, Quote{Seq{Same{}, "-", Not{Tight{">"}}}}}}

Apply{_define_rule, Tuple{Quote{add_expr}, Quote{Choice{
    Act{Seq{add_expr, "+", mul_expr}, Apply{peg_binop, Tuple{Quote{_add}}}},
    Act{Seq{add_expr, minus, mul_expr}, Apply{peg_binop, Tuple{Quote{_sub}}}},
    mul_expr}}}}

add_expr は直接左再帰なので左結合です。動作 peg_binop は（左, 演算子, 右）を Apply{_add, Tuple{a, b}} にします（planck/syntax.pk:130–132）。二項の - の前の Same{} は次の字句が同じ行にあるときだけ成功するので、行頭の -1 は新しい式になります。

動作が返すのは評価器が受け取る M式そのものです。1 + 2 は Apply{_add, Tuple{1, 2}} になり、M式で直接書いた場合と同じ木です。

planck/syntax.pk:306–328

Apply{_define_rule, Tuple{Quote{primary}, Quote{Choice{
    if_expr,
    Act{Seq{Key{"while"}, "(", expr, ")", expr},
        Lambda{Tuple{Tuple{_, _, c, _, b}}, Apply{peg_while, Tuple{c, b}}}},
    Act{Seq{Key{"handle"}, expr, Key{"with"}, union},
        Lambda{Tuple{Tuple{_, b, _, h}}, QuasiQuote{Handle{UnQuote{b}, UnQuote{h}}}}},
    Act{Seq{Key{"perform"}, unary},
        Lambda{Tuple{Tuple{_, v}}, QuasiQuote{Perform{UnQuote{v}}}}},
    block,
    embed,
    Act{Seq{ident, Tight{"{"}, Delimited{expr, ","}, "}"},
        Lambda{Tuple{Tuple{h, _, args, _}}, Apply{mexpr, Tuple{h, args}}}},
    Act{Seq{istr_open, Many{Seq{istr_text, istr_hole, expr, "}"}}, istr_text, istr_close},
        Lambda{Tuple{Tuple{_, parts, last, _}}, Apply{peg_interp, Tuple{parts, last}}}},
    ident,
    integer,
    string,
    Act{Seq{"(", ")"}, Lambda{Tuple{_}, Quote{Tuple{}}}},
    Act{Seq{"(", Delimited1{expr, ","}, ")"},
        Lambda{Tuple{Tuple{_, es, _}}, If{Apply{_eq, Tuple{Apply{arity, Tuple{es}}, 1}}, Apply{peg_first, Tuple{es}}, es}}},
    Act{Seq{"[", Delimited{expr, ","}, "]"},
        Lambda{Tuple{Tuple{_, es, _}}, Apply{peg_to_list, Tuple{es}}}},
    sugar_primary}}}}

primary の最後の選択肢 sugar_primary が match・return・break・continue・for を持ちます（planck/syntax.pk:1254–1276）。

添字と置き換え

a[i] は規則 postfix の選択肢です。[ は a に空白なしで続け、] のあとが代入の = のときは読みません（planck/syntax.pk:262–271）。a[i] = e は規則 expr の選択肢が _index_set の呼び出しにします（planck/syntax.pk:161–162）。

[ ] の中は規則 index で、式1つです（planck/syntax.pk:278–280）。t[p -> e | q if c -> g] のようにガードのある腕を含む関数は、_peg_rewrite が peg_fuse で最後に peg_skip を返す腕を足し、どの腕も当てはまらないときに peg_skip を返すようにします（planck/syntax.pk:589–598）。

_index_get と _index_set は、種類ごとの Lambda を Fusion でつないだ関数です（planck/syntax.pk:1387–1443・planck/syntax.pk:1472–1524）。表は Table{t}、リストは Cons{x, xs} と Nil{} の頭で選ぶので、パターンだけで種類が決まります。関数 f を添字にすると subst(t, f) を呼びます（planck/syntax.pk:1308–1355）。subst は f の最後に「peg_skip を返す」腕を足し、それ以外の値が返った部分は置き換えて内側を試さず、peg_skip が返った部分は引数ごとに自分を呼びます。

利用者が _index_get = (K{...}, i) -> ... | _index_get と代入すると、新しい種類が元の関数の前に入ります。planck/lib/vector.pk の末尾はこの書き方です。

文法の宣言

::= も規則 syntax_decl が読み、_define_rule を呼ぶ木にします。

planck/syntax.pk:409–413

Apply{_define_rule, Tuple{Quote{syntax_decl}, Quote{
    Act{Seq{ident, "::=", g_choice},
        Lambda{Tuple{Tuple{n, _, e}},
            QuasiQuote{Apply{_define_rule, Tuple{UnQuote{Apply{mexpr, Tuple{Quote{Quote}, Tuple{n}}}},
                                                UnQuote{Apply{mexpr, Tuple{Quote{Quote}, Tuple{e}}}}}}}}}}}}

選択肢の項目と動作は g_alt が Act{Seq{...}, Lambda{Tuple{Tuple{ラベル, ...}}, 動作}} に組み替えます（planck/syntax.pk:420–430）。ラベルは動作の無名関数の引数パターンになります。

i_decl.pk

use("pretty")
pprint('(pair ::= a:integer "," b:integer { (a, b) }))

出力

Apply{
  _define_rule,
  Tuple{
    Quote{pair},
    Quote{
      Act{
        Seq{integer, ",", integer},
        Lambda{Tuple{Tuple{a, _, b}}, Do{Tuple{a, b}}}
      }
    }
  }
}

syntax_decl は expr の最初の選択肢なので、::= は式を書ける所ならどこにでも書けます。新しい規則は次のトップレベルの式から効きます。

return と break の読み替え

return・break・continue はエフェクトに読み替えます。return を読むたびに数を数え、関数の木を作るときに数が増えていれば本体を Handle で包みます（planck/syntax.pk:1081–1103）。

i_return.pk

use("pretty")
pprint('(f(xs) := { for (x in xs) if (x > 0) return x; 0 }))

出力

Def{
  f,
  Lambda{
    Tuple{xs},
    Handle{
      Do{
        Apply{
          peg_for,
          Tuple{
            xs,
            Lambda{
              Tuple{x},
              If{
                Apply{_gt, Tuple{x, 0}},
                Perform{Return{x}},
                none
              }
            }
          }
        },
        0
      },
      Lambda{Tuple{Return{v}, k}, v}
    }
  }
}

for の本体の return x は Perform{Return{x}} になり、関数の本体全体が Handle{..., (Return{v}, k) -> v} で包まれます。for は peg_for の呼び出しです。

規則で読む文字列

name{| text |} は関数で書いた規則 embed が読みます（planck/syntax.pk:1536–1561）。name と {| のあと規則 name をその位置から呼び、続く |} を求めます。規則の値は Quote{v} として木に入ります。

parse の差し替え

末尾の2行で切り替えます。

planck/syntax.pk:1542–1544

    Set{p, Apply{peg_skip_ws, Tuple{p}}},
    Def{q, p},
    Def{r, none},

M式のリーダを parse_mexpr として残し、parse を規則 toplevel で1式読む関数にします。planck0 は式ごとに parse を引き直すので（planck0）、syntax.pk の次の式から planck の構文で読まれます。toplevel は expr を1つ読み、;・改行・次の式の始まりのどれかを確かめます（planck/syntax.pk:149–151）。

primary に ident{expr, ...} の選択肢があるので、M式もそのまま式として読めます。
