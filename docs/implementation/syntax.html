構文を planck で書く

planck/syntax.pk は、planck の構文を packrat パーサの規則として定義し、最後に parse を差し替えます。構文は処理系に埋め込まれておらず、planck のプログラムの一部です。

字句は関数で

識別子・整数・文字列のような字句は、構文解析式ではなく関数で書いています。1 文字ずつ見て、読めたら次の位置を返します。

planck/syntax.pk:28–42

" identifier: [A-Za-z_][A-Za-z0-9_]* except the peg_reserved words and the f of f\"...\" "
Def{peg_tok_ident, Lambda{Tuple{p}, Do{
    Set{p, Apply{peg_skip_ws, Tuple{p}}},
    Def{q, Apply{peg_inc, Tuple{p}}},
    Def{name, ""},
    If{Apply{peg_is_alpha, Tuple{Apply{peg_char_at, Tuple{p}}}}, Do{
        While{Apply{peg_is_alnum, Tuple{Apply{peg_char_at, Tuple{q}}}}, Set{q, Apply{peg_inc, Tuple{q}}}},
        Set{name, Apply{substr, Tuple{peg_src, p, q}}},
        If{If{Apply{table_get, Tuple{peg_reserved, name, false}}, true,
              If{Apply{eq, Tuple{q, Apply{add, Tuple{p, 1}}}},
                 If{Apply{eq, Tuple{Apply{peg_char_at, Tuple{p}}, 102}}, Apply{eq, Tuple{Apply{peg_char_at, Tuple{q}}, 34}}, false},
                 false}},
            Apply{peg_fail, Tuple{p}},
            Do{Set{peg_pv, Apply{intern, Tuple{name}}}, q}}},
        Apply{peg_fail, Tuple{p}}}}}}

予約語の表 peg_reserved に入っている単語は識別子になりません（planck/syntax.pk:10–26）。f" の f も識別子にしません。関数を規則にするのは define_rule に関数をそのまま渡すだけです（planck/syntax.pk:123–126）。

式の規則

式は結合の弱いほうから順に規則を並べます。expr・union・arrow・ternary・or_expr と続き、primary で終わります（planck/syntax.pk:145–290）。たとえばたし算とひき算の規則はこうです。

planck/syntax.pk:214–220

" a binary - must be on the same line as its left operand "
Apply{define_rule, Tuple{Quote{minus}, Quote{Seq{Same{}, "-", Not{Tight{">"}}}}}}

Apply{define_rule, Tuple{Quote{add_expr}, Quote{Choice{
    Act{Seq{add_expr, "+", mul_expr}, Apply{peg_binop, Tuple{Quote{add}}}},
    Act{Seq{add_expr, minus, mul_expr}, Apply{peg_binop, Tuple{Quote{sub}}}},
    mul_expr}}}}

add_expr は自分自身から始まる左再帰なので、左から結合します。動作 peg_binop は「左・演算子・右」の組を Apply{add, Tuple{a, b}} の木にします（planck/syntax.pk:130–132）。2 項の - の前に Same{} があるので、行の頭の -1 は新しい式になります。

規則の動作が返すのは、評価器がそのまま受け取る M式です。1 + 2 を読んだ結果は Apply{add, Tuple{1, 2}} で、これを M式で直接書いても同じ木になります。

planck/syntax.pk:268–290

Apply{define_rule, Tuple{Quote{primary}, Quote{Choice{
    if_expr,
    Act{Seq{Key{"while"}, "(", expr, ")", expr},
        Lambda{Tuple{Tuple{_, _, c, _, b}}, Apply{peg_while, Tuple{c, b}}}},
    Act{Seq{Key{"handle"}, expr, Key{"with"}, union},
        Lambda{Tuple{Tuple{_, b, _, h}}, QuasiQuote{Handle{UnQuote{b}, UnQuote{h}}}}},
    Act{Seq{Key{"perform"}, unary},
        Lambda{Tuple{Tuple{_, v}}, QuasiQuote{Perform{UnQuote{v}}}}},
    block,
    embed,
    Act{Seq{ident, Tight{"{"}, Delimited{expr, ","}, "}"},
        Lambda{Tuple{Tuple{h, _, args, _}}, Apply{mexpr, Tuple{h, args}}}},
    Act{Seq{istr_open, Many{Seq{istr_text, istr_hole, expr, "}"}}, istr_text, istr_close},
        Lambda{Tuple{Tuple{_, parts, last, _}}, Apply{peg_interp, Tuple{parts, last}}}},
    ident,
    integer,
    string,
    Act{Seq{"(", ")"}, Lambda{Tuple{_}, Quote{Tuple{}}}},
    Act{Seq{"(", Delimited1{expr, ","}, ")"},
        Lambda{Tuple{Tuple{_, es, _}}, If{Apply{eq, Tuple{Apply{arity, Tuple{es}}, 1}}, Apply{peg_first, Tuple{es}}, es}}},
    Act{Seq{"[", Delimited{expr, ","}, "]"},
        Lambda{Tuple{Tuple{_, es, _}}, Apply{peg_to_list, Tuple{es}}}},
    sugar_primary}}}}

primary の最後の選択肢 sugar_primary には、match・return・break・continue・for が入っています（planck/syntax.pk:1100–1122）。

文法の宣言を読む規則

::= を読むのも規則です。syntax_decl は name ::= ... を読み、define_rule を呼ぶ木を作ります。

planck/syntax.pk:298–302

Apply{define_rule, Tuple{Quote{syntax_decl}, Quote{
    Act{Seq{ident, "::=", g_choice},
        Lambda{Tuple{Tuple{n, _, e}},
            QuasiQuote{Apply{define_rule, Tuple{UnQuote{Apply{mexpr, Tuple{Quote{Quote}, Tuple{n}}}},
                                                UnQuote{Apply{mexpr, Tuple{Quote{Quote}, Tuple{e}}}}}}}}}}}}

選択肢の項目と動作のブロックは、g_alt が Act{Seq{...}, Lambda{Tuple{Tuple{ラベル, ...}}, 動作}} に組み替えます（planck/syntax.pk:309–319）。ラベルが動作の関数の引数になるので、動作の中でラベルを変数として使えます。

i_decl.pk

use("pretty")
pprint('(pair ::= a:integer "," b:integer { (a, b) }))

出力

Apply{
  define_rule,
  Tuple{
    Quote{pair},
    Quote{
      Act{
        Seq{integer, ",", integer},
        Lambda{Tuple{Tuple{a, _, b}}, Do{Tuple{a, b}}}
      }
    }
  }
}

syntax_decl は expr の最初の選択肢です。だから ::= はどこにでも書ける式で、読まれた次の式から新しい規則が効きます。

return と break を読み替える

return・break・continue はエフェクトとして読みます。return を読むと数を数えておき、関数の木を作るときにその数を見ます。return があれば、本体を Handle で包みます（planck/syntax.pk:927–950）。

i_return.pk

use("pretty")
pprint('(f(xs) := { for (x in xs) if (x > 0) return x; 0 }))

出力

Def{
  f,
  Lambda{
    Tuple{xs},
    Handle{
      Do{
        Apply{
          peg_for,
          Tuple{
            xs,
            Lambda{
              Tuple{x},
              If{
                Apply{gt, Tuple{x, 0}},
                Perform{Return{x}},
                none
              }
            }
          }
        },
        0
      },
      Lambda{Tuple{Return{v}, k}, v}
    }
  }
}

for の本体の中の return x が Perform{Return{x}} になり、関数の本体全体が Handle{..., (Return{v}, k) -> v} で包まれています。for は peg_for の呼び出しになります。

規則で読む文字列

name{| text |} を読む embed も関数で書いた規則です（planck/syntax.pk:1124–1149）。name と {| を見つけたら、規則 name をその位置から呼び、そのあとに |} を求めます。規則の値は Quote{v} にして、定数として木に入れます。

parse を差し替える

最後の 2 行で切り替えます。

planck/syntax.pk:1151–1153

" === Switch to the new syntax === "
Def{parse_mexpr, parse}
Def{parse, Lambda{Tuple{s}, Apply{peg_parse, Tuple{Quote{toplevel}, s}}}}

元の M式のリーダは parse_mexpr として残し、parse を「規則 toplevel で 1 つ読む関数」にします。planck0 は式ごとに parse を引き直すので（planck0 の中身）、syntax.pk の次の式からは planck の構文で読まれます。toplevel は expr を 1 つ読み、;・改行・次の式の始まりのどれかを確かめます（planck/syntax.pk:149–151）。

M式も構文の一部です。primary に ident{expr, ...} の選択肢があるので、Def{x, 1} と書けばそのまま M式として読まれます。
