vasmc

planck/vasmc.pk は vasm と native のソースファイルから Linux の実行ファイルを作ります。ソースを単位に分けて結合したプログラムは、すべてのソースを一度にコンパイルしたプログラムと同じに動きます。コマンドは planck のプログラム planck/vasmc.pk への引数の形で書き、実行のしかたは処理系の実装にあります。

ソースファイルと対象

名前が .native で終わるファイルは native のソースで、先に vasm に展開されます。それ以外は vasm のソースです。誤りは file:line:column: message の形でソースファイルの位置を示し、コンパイルは止まります。

対象は機械で、今あるのは x86_64 だけです（指定しなければこれになります）。機械ごとの部分は命令の選択より後にあります。システムコールは対象の OS の部分が呼ぶので、プログラムには書きません。

1つのファイルから1つの実行ファイル

ソースには引数を取らない関数 main が必要です。その結果がプログラムの終了コードになります。

単位

ソースを単独でコンパイルした結果が単位ファイルです。単位ファイルには、下の形に落とした関数とインタフェース（本体を除く構造体と関数の宣言）が入り、機械語は入りません。命令の選択は、結合するときにプログラム全体に対して1回行います。

  • unit は1つのソースを単位ファイル output にします。import は単位ファイルで、その関数と構造体はソースの中で宣言されているかのように使え、インタフェースに対して検査されます。単位にするソースに main は要りません。
  • 単位の名前は、ソースのファイル名からディレクトリと拡張子を除いたものです（lib.native は lib）。
  • link は単位ファイルを与えた順に結合して実行ファイル output にします。ちょうど1つの単位が main を持ちます。
  • 単位ファイルは同じ語の幅の対象にだけ結合できます。2つの単位が同じ関数や構造体を定義すると結合できません。
  • import の import は取り込まれません。単位が使えるのは、自分のコマンドに挙げた単位ファイルの項目だけです。

native の単位

native のソースは、使う単位をファイルの先頭の import で挙げます。見えるのはこう挙げた単位の関数と構造体だけで、名前に修飾は付きません（import lib のあと、twice(3) は lib の twice を呼びます）。単位ファイルをコマンドに渡していない単位を import すると誤りです。vasm のソースには import がなく、渡した単位ファイルがすべて見えます。

native_compile.compile_with(m, imports) と native_compile.compile_all_with(m, imports) には、単位のインタフェース（vasm のモジュールの vasm_unit.iface）を項目の並びとして渡します。compile_all_with は誤りをモジュールとあわせて返します。展開されたモジュールには import の項目は入りません。
