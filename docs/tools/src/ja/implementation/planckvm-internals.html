planckvm の内部仕様

実装の中の設計。planck の呼び出しの状態はレジスタスタックとフレームスタックだけに置きます。継続はその複製、GC は評価器自身が持ち、すべて部分評価できる形にします。外部仕様はplanckvm: 実行モデルと値とplanckvm の命令です。

方針

  • 評価器はバイトコードインタプリタです。式を命令に変換し、命令ループで実行します。
  • GC は評価器の独自の世代別コピー GC で、値のヒープと根も評価器が管理します。
  • ホストのエフェクト、継続、M式の読み取りは使いません。同じ機能は、評価器の一部として planck で書きます。
  • 命令ループは自分を再帰呼び出ししません。

スタック

スタックは、レジスタスタックとフレームスタックの2つの連続した領域です。どちらも GC の根で、満杯になると stack overflow で止まります。レジスタスタックの全要素は、起動時に none で埋めます。

フレームは 7 語です。

呼び出しと復帰

  • CALL A B C が Lambda を選ぶと、現在のフレームの pc を保存して新しいフレームを積みます。新しいフレームは base = 現在の base + B + 1、env = fn の環境、ret = A です。窓が base + nregs まで収まることを確かめ、引数は動かしません。
  • HANDLE A B は同じように base = 現在の base + B + 2、ret の kind = 1、reg = A のフレームを積み、R[B] の Lambda を引数なしで実行します。
  • RET A は値を読み、フレームを捨て、捨てたフレームの ret のとおりに呼び出し元へ渡します。
  • TCALL B C は R[B] から R[B+C] を R[-1] から R[C-1] へ移して、現在のフレームを置き換えます。ret の mode と reg は変わらず、kind だけ 0 になります。組み込みの結果は RET と同じ扱いで渡します。
  • alts の中身は下の Fusion の形です。NEXT は next から順に、引数の個数が合う選択肢を選びます。選択肢が Lambda なら、フレームの fn と env を置き換えて pc を 0 にし、窓は変えません。組み込みなら結果を RET と同じ扱いで渡し、継続なら TCALL と同じ扱いで再開します。
  • 選択肢が尽きたとき、kind が 2 なら転送に進み、それ以外なら matching failed で止まります。
  • 組み込みのセルが上書きされているときは、R[nregs] に関数、その上に引数を置いて CALL と同じ扱いで呼びます。ret は命令の種類で決まります。条件の命令なら mode は k + 1、ASET PLAINSET なら 3、それ以外なら 0 で reg = A です。窓の検査では、nregs に呼び出しの分を足した大きさを使います。

上書きの判定

語 guard の各ビットは、命令の組み込みの欄の名前に1つずつ対応します。組み込みの欄を持つ命令は、まず guard が 0 かを見て、0 でなければ自分のビットを見ます。この名前のセルには印があり、SETGLOBAL が印のあるセルに書くときにビットを更新します（値が元の組み込みなら 0、それ以外なら 1）。

継続

継続はヒープ上のオブジェクトで、フレームスタックの切片とレジスタスタックの切片のコピーです。

  1. PERFORM A B: 現在のフレームから下へたどって kind が 1 のフレーム F を探します。無ければ unhandled effect で止まります。
  2. 現在のフレームの pc を保存します。次に、F から現在のフレームまでのフレームと、F.base - 2 から現在のフレームの R[nregs-1] までのレジスタをコピーして、継続を作ります。コピーの base はレジスタの切片の先頭からの差で、A は継続の欄 reg に入ります。命令の表の S は、この2つの切片の確保を指します。
  3. F より上を捨て、F と同じ位置に kind = 2、ret の mode と reg は F のまま、base = F.base のフレームを作ります。R[0] に送られた値、R[1] に継続を入れて、ハンドラを引数 2 個で選びます。
  4. 転送: このフレームの下から次の kind が 1 のフレーム G を探します。無ければ unhandled effect で止まります。G からこのフレームの1つ下までの切片の後ろに元の継続の切片をつないだ新しい継続を作り、G について手順 3 を行います。元の継続のレジスタの切片は F.base - 2 の位置に続くので隙間はできません。元の切片のフレームの base には F.base - G.base を足します。
  5. 再開: CALL A B 1 の関数が継続なら、引数を先に読み、切片を 現在の base + B + 1 の位置にコピーし、各フレームの base にその位置を足します。切片の最初のフレーム（境界）の ret は、CALL が積むフレームと同じく、mode と reg が A から決まります。切片の最後のフレームを現在のフレームにし、その R[reg] に引数を入れ、保存した pc から続けます。
  6. TCALL の関数が継続なら、引数を先に読み、切片を現在のフレームの base - 1 の位置にコピーし、最初のフレームの ret の mode と reg は現在のフレームのものにします。

ヒープとガベージコレクション

値の word、オブジェクトのヘッダ、種類ごとの中身はplanckvm の内部表現にあります。ヒープは 32 ビットの word の array で、世代ごとの領域をその上に取ります。

世代

  • GC は若い世代と古い世代の2世代のコピー GC で、評価器の一部として planck で書き、vasm のランタイムには含めません。
  • 確保は若い世代から行い、若い世代に収まらないオブジェクトだけを古い世代に直接確保します。
  • 若い世代が満杯になると、根と記憶集合からたどれる若いオブジェクトをすべて古い世代へコピーし、若い世代は空になります。
  • 古い世代が満杯になったときは、古い世代を2つの半空間の間でコピーします。

確保とセーフポイント

  • 命令の表で S の付いた命令はメモリを確保する可能性があり、その確保で GC が走ることがあります。
  • GC は命令の副作用より前に走ります。命令の入力は GC の間もレジスタに残って GC が更新するので、命令は GC の後で入力を読み直します。
  • 実行中の値はすべて、レジスタスタック、フレームスタック、環境、セル、評価器の状態のいずれかからたどれます。評価器のローカル変数にだけ存在する値はありません。組み込みが確保をまたいで保持する値は評価器の状態の一時スロットに置きます。
  • 確保しない命令（JMP MOVE ENVGET など）では GC は走らず、ループの途中に置くセーフポイントもありません。

レジスタの生死の表は持ちません。レジスタスタックの要素は常に有効な値か none です。この状態を次の2つで保ちます。

  • 起動時に全要素を none で埋めること。
  • GC が、根の範囲より上で前回の GC の後に使われた範囲を none で埋めること。範囲の上端は、窓を作るときに更新する語 high に記録する。

呼び出し元の R[B] より上は呼ばれた側の窓に重なり、R[B] より下は生きている値か過去の値です。過去の値は上書きされるまで生き残りますが、誤った参照にはなりません。

ライトバリア

方式は記憶集合（古い世代のオブジェクトのリスト）です。古い世代のオブジェクトに若い世代のオブジェクトへの参照を書き込むとき、ヘッダの r が 0 ならそのオブジェクトを記録して r を 1 にします。

  • 対象の命令は ENVSET SETGLOBAL ASET です。
  • 古い世代に直接確保したオブジェクトは、初期化で若い参照を書いたら記録します。
  • 記録しない書き込み: plain 配列（参照を持たない）、若い世代に確保したオブジェクトの初期化、レジスタスタックとフレームスタックへの書き込み（毎回根としてたどる）。

identity

配列、plain 配列、関数は identity（EQ と HASH）を持ちます。identity はアドレスでは表さず、最初の HASH のときにオブジェクトの番号の語へ番号を割り当てます（0 は未割り当て）。シンボルの番号は名前から、M式と文字列の番号は中身から、数の番号は値から決まります。

数と plain 配列の表現

  • 整数どうしの結果が小さい整数に収まるなら、確保せずに済ませてかまいません。確保が起きるのは桁が増えたときと、浮動小数点数や複素数の結果を作るときです。大きな整数の結果が 31 ビットに収まるときは必ず即値にします。
  • 浮動小数点数と複素数はヒープ上の不変のボックスです。vasm では複素数を浮動小数点数2つの組で表します。
  • plain 配列の要素はタグを持ちません。複素数の要素は2つの数で並べます。

部分評価との関係

planckvm の目的は planck で書いた評価器を部分評価して planck の vasm 実装を得ることです。次の性質はこの目的のために設計しました。

  • 命令列は作成後に変わらず、レジスタ番号とジャンプの差は即値です。コードが静的なら、命令の読み出しと次の命令の選択を展開でき、レジスタの添字も静的に決まります。
  • パターン照合は呼ばれる側のコードの中にあります。関数ごとに照合を特化でき、データの木をたどる照合器は要りません。
  • 継続はフレームの複製で実現し、ホストのエフェクトを使いません。評価器が Perform を使わないので、planck/lib/partial_eval.pk にある継続の制限に当たりません。
  • 動的な間接呼び出しは CALL の呼び出し先だけです。呼ばれる可能性のあるコードの集合が閉じていれば、コードごとの関数に分割できます。
  • 組み込みの上書きの判定は語 guard を読むだけなので、guard が静的なら畳み込めます。大域変数は書き換え可能なセルなので、書き換えられる大域変数は静的に扱えません。
  • PLAINGET と PLAINSET は要素をボックス化しない数として読み書きします。
