planckvm の内部仕様

planckvm の実装の中の設計を説明します。VM の利用者が頼ってよい約束は、外部仕様のplanckvm: 実行モデルと値とplanckvm の命令に書きます。

方針

  • 評価器はバイトコードインタプリタです。式を命令に変換して命令ループで実行し、式を閉包に変換する方式は採りません。
  • 評価器は独自のガベージコレクタを備えます。方式は世代別コピー GC で、値のヒープと根は評価器が持ちます。
  • 評価器はホストのエフェクト、継続、M式の読み取りを使いません。これらは評価器の一部として planck で書きます。

コードとフレーム

  • ジャンプ先と pc は命令列の添字で、アドレスは使いません。GC がオブジェクトを移動するためです。
  • コードの作成時に、オペランドスタックの高さの最大値を求めます。

フレーム

欄意味
呼び出し元値を返す先のフレーム。トップレベルの入口には無い
code, pc, env実行中のコード、次の命令、環境
残りの選択肢f | g のうちまだ試していない関数。無ければ none
境界ハンドラの関数。HANDLE が作ったフレームだけが持つ
転送の印PERFORM がハンドラを呼ぶフレームだけが持つ。選択肢が尽きたときに外側の境界へ進むことを示す
引数呼び出しの n 個の値。入口の照合が終わるまで保持する
オペランドスタック式の評価途中の値。高さの上限はコードごとに決まる

フレームは連続した領域（フレームスタック）に積みます。この領域は評価器が持ち、GC の根になります。領域が満杯になると stack overflow で止まります。

環境

環境の形は | 親の環境 | スロット0 | スロット1 | ... | です。ヒープ上に呼び出しごとに作ります。

ヒープとガベージコレクション

値とヒープ

  • 値はタグ付きの1語です。小さい整数は即値で、それ以外はヒープへの参照です。浮動小数点数、複素数、大きな整数、文字列、M式、配列はヒープ上のオブジェクトです。
  • ヒープは1つの整数配列の上に世代ごとの領域を取ったものです。
  • GC は世代別コピー GC で、評価器の一部として planck で書きます。vasm のランタイムに足すものではありません。

確保とセーフポイント

  • 命令の表で S の付いた命令はメモリを確保する可能性があり、その確保で GC が走ることを許します。
  • GC は命令の副作用より前に走ります。命令の入力は GC の間もオペランドスタックに残り、GC によって更新されます。命令は GC の後で入力を読み直します。
  • 実行中の値はすべて、フレームスタック、環境、セルのいずれかからたどれます。評価器のローカル変数にだけ存在する値はありません。
  • 確保しない命令（JMP LOAD POP など）では GC は走りません。ループの途中にセーフポイントは置きません。

根

根内容
フレームスタック全フレームの env, code, 引数, オペランドスタック（保存した高さまで）
セル大域変数
評価器の状態シンボル表、定数表、コンパイル中の状態

フレームの欄はすべて値かヘッダの整数で、タグを見てたどれます。スタックマップは持ちません。pc は添字なので、コードが移動しても影響を受けません。定数表はコードの一部としてたどります。

ライトバリア

方式は記憶集合（古い世代のオブジェクトのリスト）です。古い世代のオブジェクトに若い世代のオブジェクトへの参照を書き込むとき、その古いオブジェクトを記録します。対象の命令は STORE GSET ASET です。plain 配列は参照を持たないので記録しません。新しく確保したオブジェクトの初期化は記録せず、フレームスタックへの書き込みも記録しません（毎回根としてたどるため）。

同一性

配列、plain 配列、関数は同一性（EQ と HASH）を持ちます。同一性はアドレスでは表さず、最初の HASH のときに番号を割り当てます。シンボルの番号は名前から、M式と文字列の番号は中身から、数の番号は値から決まります。

継続

PERFORM はフレームを複製するのでメモリを確保します。フレームの複製は捕捉時と再開時の2回です。継続の実現にホストのエフェクトは使いません。フレームをデータとして複製します。継続の中のフレームは通常のフレームと同じ形をしており、同じようにたどれます。

数と plain 配列の表現

  • 小さい整数は即値で、大きい整数は桁の配列で表します。
  • 整数どうしの結果が小さい整数に収まるなら、確保せずに済ませてかまいません。確保が起きるのは桁が増えたときと、浮動小数点数や複素数の結果を作るときです。
  • 浮動小数点数と複素数はヒープ上の不変のボックスです。vasm では複素数を浮動小数点数2つの組で表します。
  • plain 配列の要素はタグを持ちません。plain 配列は参照を持たないので、GC は中を走査せず、書き込みも記録しません。複素数の要素も plain 配列の中では2つの数であり、ボックスではありません。

部分評価との関係

planckvm の目的は planck で書いた評価器を部分評価して planck の vasm 実装を得ることです。次の性質はこの目的のために設計しました。

  • 命令列は作成後に変わらず、ジャンプ先は即値です。コードが静的なら、命令の読み出しと次の命令の選択を展開できます。
  • pc ごとにオペランドスタックの高さが決まるので、スタックを静的な並びとして扱えます。
  • パターン照合は呼ばれる側のコードの中にあります。関数ごとに照合を特化でき、データの木をたどる照合器は要りません。
  • 継続はフレームの複製で実現し、ホストのエフェクトを使いません。評価器が Perform を使わないので、planck/lib/pe.pk にある継続の制限に当たりません。
  • 動的な間接呼び出しは CALL の呼び出し先だけです。呼ばれる可能性のあるコードの集合が閉じていれば、コードごとの関数に分割できます。
  • CALLP のガードはセルが静的で不変なら畳み込めます。大域変数は書き換え可能なセルなので、書き換えられる大域変数は静的に扱えません。
  • PLAINGET と PLAINSET は要素をボックス化しない数として読み書きします。
