機械語から planck0 まで

16進ダンプ1枚の Forth から、sasm で書いた planck0 ができるまでです。

pforth

pforth.xxd は201行の16進ダンプで、右側の注釈は xxd -r -c 8 が無視します。戻したバイト列がそのまま32ビット x86 Linux の ELF 実行ファイルです。

辞書の初期状態は1文字の名前の組み込み語だけです。k は1文字読む、t は1文字書く、f は文字から語を引く、x は語を実行する、などです。

最初の解釈器は k・f・x を繰り返すだけです。この段階の Hello World は次のとおりです。

plisp

plisp.fs は pforth への入力です。先頭は1文字の語だけで書いた列で、空白と改行を何もしない語として、\ を行コメントの語として登録します（[[plisp.fs#1-15]]）。以降は自己拡張で Forth を組み立てます。

  • 2番目の解釈器。名前で語を引き、コンパイル状態を持つ（[[plisp.fs#335-358]]）。
  • 条件分岐・ループ・再帰・構造体などの通常の Forth の語（[[plisp.fs#498-1380]]）。
  • 3番目の解釈器。辞書にない語を数として読み、数でもなければエラーを出して止まる（[[plisp.fs#1386-1447]]）。

その Forth で Lisp インタプリタを書きます（[[plisp.fs#1684]] 以降）。リスト、ノード、リーダとプリンタ、評価器の順で、最後に plisp/init.lisp を読みます（[[plisp.fs#2435]]）。次のステージがアセンブラとコンパイラなので、構文木を直接扱えて内部 DSL を作りやすい Lisp を選んでいます。

asm と sasm

どちらも plisp の上で動く、次のステージへ渡るための道具です。性能と安全性より実装の単純さを優先しています。

asm/core.lisp は x86 32ビットのアセンブラです。S式の命令列から ELF を直接書き出し、ヘッダ・コード・データを読み書き実行可能な1つの PT_LOAD に置きます。

sasm/core.lisp は構造化アセンブリ言語 sasm のコンパイラです。sasm は型のない C 風の言語で、変数・関数・if・while を持ち、plisp の内部 DSL として実装されています。レジスタ割り付けはせず、スタックへの push と pop を繰り返すコードを出して asm で機械語にします。

plisp2

Forth の上の plisp は以降のステージには遅すぎるため、同じ Lisp を sasm で書き直したのが plisp2.sv です。メモリ確保（[[plisp2.sv#6]]）、ノード（[[plisp2.sv#54]]）、リーダとプリンタ（[[plisp2.sv#302]]）、評価器（[[plisp2.sv#586]]）、組み込み関数（[[plisp2.sv#828]]）の順に並んでいます。

plisp2 は plisp の上の sasm でコンパイルし、できた plisp2 の上で同じ sasm が planck0.sv をコンパイルします。

planck0

planck0.sv（2684行）も sasm で書かれています。中身はplanck0の頁にあります。
