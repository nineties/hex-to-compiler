planck0

planck0 は M式だけを読む処理系です。トップレベルの M式を1つ読むたびにバイトコードにコンパイルし、専用のフレームスタックにフレームを置く仮想機械で実行します。ソースは planck0.sv の1ファイルです。

トップレベル

main は状態を初期化してから planck/init.pk を読み、続いて最初の引数のプログラムファイルを読みます。

ファイルは interpret_file が読みます（[[bootstrap/planck0.sv fun interpret_file]]）。式ごとに大域変数 parse と eval を call_global で呼び出します。call_global は Apply{名前, Tuple{引数}} を組み立ててコンパイルし、実行します（[[bootstrap/planck0.sv fun call_global]]）。このためプログラムが parse を差し替えると次の式から新しい parse で読みます。planck の構文はこの仕組みで導入します。

値の表現

値は32ビットの1語です。最下位ビットが1なら1ビット左シフトした整数、0ならヒープ上のオブジェクトへのポインタです。オブジェクトは先頭の1語のヘッダに種類と長さを持ちます。

シンボルと M式は intern します。同じ構造の M式はメモリ上に1つしかないので、等価性はポインタの比較で判定します（[[bootstrap/planck0.sv ; intern a temporary m-expr object]]）。

ヒープは起動時に mmap2 で確保する固定の領域です。ヒープにはヘッダ1語を持つチャンクが並び、オブジェクトのチャンクの先頭をビットマップに記録します（[[bootstrap/planck0.sv ; The heap is a fixed area .. ; === data layout (planck0)]]）。

GC はオブジェクトを動かさない stop-the-world の mark-sweep で、到達できないオブジェクトを解放します（[[bootstrap/planck0.sv ; === Garbage Collection .. fun main]]）。この GC は保守的です。根（planck0 自身の大域変数・フレームスタック・機械のスタック）の語か印を付けたオブジェクトの語がオブジェクトの内部を指していれば、指す位置が先頭でなくてもそのオブジェクトを解放しません。sweep は隣り合う空きチャンクを連結し、allocate はその中から first fit で取ります。前回の GC のあとに確保した量が前回の GC で生きていた量に達すると、次の GC を始めます。

M式のリーダ

組み込みの parse が読むのは、シンボル・整数・文字列と、シンボルに { が続く Head{...} の4種類です（[[bootstrap/planck0.sv fun parse_mexpr .. ; === Bytecode VM]]）。M式の引数は64個までです。

planck の構文を導入したあとも、このリーダは parse_mexpr として残ります。

コンパイラ

compile は整数と文字列を定数に、シンボルを変数の参照にし、M式を compile_mexpr に渡します（[[bootstrap/planck0.sv fun compile]]）。

compile_mexpr は頭で分岐します（[[bootstrap/planck0.sv fun compile_mexpr]]）。Apply・Def・Declare・Set・Do・If・While・Lambda・Fusion・Quote・QuasiQuote・Handle・Perform が特殊形式で、それ以外の頭は引数を評価して同じ頭の M式を作るコンストラクタになります。

局所変数はコンパイル時に（環境の深さ, 位置）の組に解決します。大域変数はセル（値・名前・定義したファイルの3語）で表し、コンパイラは名前から最新のセルを引く表 global_table を持ちます。トップレベルの Def は新しいセルを作って表の項目を差し替え（[[bootstrap/planck0.sv fun define_global]]）、命令 GLOAD・GDEF・GSET には名前でなくセルを埋め込みます（[[bootstrap/planck0.sv fun global_cell .. ; allocate slots for variables in a pattern]]）。このため名前の指す変数は式を実行する前に決まり、前にコンパイルした関数は前のセルを指したままです。Set は今のセルに書き込みます。局所にも大域にも見つからない名前があると、その式を実行する前にメッセージを出して止まります。

Def は右辺をコンパイルしたあとにセルを作るので、右辺からは前の変数が見えます。関数が自分自身を参照できるのは、構文が関数定義を Declare{f} で先にセルを作り Set で関数を入れる形に読み替えるからです。Set の前に関数を呼ぶと none を呼ぶことになって止まります。

Declare{f} が Def{f, none} としてコンパイルされるのは、f がまだその場所の変数でないときだけです。トップレベルでは global_table を引いて、セルのファイルを読み込み中のファイル cur_file と比べます。cur_file は interpret_file と、load が呼ぶ _set_file が設定します。関数の中ではコンパイル時の環境からその関数の深さの項目を探します（[[bootstrap/planck0.sv fun defined_here]]・[[bootstrap/planck0.sv if (== head DeclareS)]]）。

仮想機械

仮想機械の設計はソースのコメントに書いてあります。

フレームは機械のスタックでなく、専用のフレームスタックに置きます。フレームは呼び出し元のすぐ上に置き、戻ると捨てます。仮想機械は自分自身を再帰呼び出ししません。計算の状態は現在のフレームからトップレベルまでのフレームの鎖だけで表せるので、継続はこの鎖の複製で済みます。

呼び出しとパターン照合

呼び出しでは select が引数に合う関数を選びます（[[bootstrap/planck0.sv fun select]]）。Fusion は左の関数を試し、失敗すれば右の関数を試します。Lambda は引数の数を比べてからパターンを順に照合します。

match_pat は変数なら新しい環境の次の位置に値を書き、Quote なら等価性を比べ、_TypeOf なら種類を確かめてから内側を照合します。M式のパターンは頭と引数の数を比べ、引数ごとに再帰します。合う関数がなければ matching failed で止まります（[[bootstrap/planck0.sv fun match_error]]）。

組み込みの eval は M式をトップレベルの式としてコンパイルし、新しいフレームで実行します（[[bootstrap/planck0.sv if (== (get callee 3) PRIM_EVAL)]]）。

組み込み関数

init_prims は defprim で大域の表にセルを作り、組み込み関数を登録します。defprim には名前・引数の数・実装の関数・種類を渡します（[[bootstrap/planck0.sv fun defprim]]）。演算子と文字列の連結は構文糖衣が呼ぶ名前で登録します。これらの名前は _add・_sub・_mul・_div・_quo・_mod・_lt・_le・_gt・_ge・_eq・_ne・_strcat のように _ で始まります（[[bootstrap/planck0.sv fun init_prims]]）。_ のない add や strcat は登録しないので、プログラムが同名の変数を定義しても演算子の意味は変わりません。

エフェクト

Handle は本体を新しいフレームで実行し、そのフレームにハンドラを記録します（[[bootstrap/planck0.sv fun op_handle]]）。Perform は現在のフレームから呼び出し元へ鎖をたどり、ハンドラを持つフレームを探します。

見つけたら継続 k（現在のフレームから境界のフレームまでの鎖の、ヒープ上の複製）を作り、ハンドラを (v, k) で照合します。合わなければさらに外側を探します。ハンドラの値は境界のフレームの呼び出し元に返り、Handle 式の値になります。

k を呼ぶと、k の鎖をフレームスタックに複製し、複製を実行します（resume、[[bootstrap/planck0.sv fun resume]]）。元のフレームは実行しないので、同じ k を何度でも呼べます（マルチショット継続）。
