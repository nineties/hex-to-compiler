planck0

planck0 は M式だけを読む処理系です。トップレベルの M式を1つ読むたびにバイトコードにコンパイルし、専用のフレームスタックにフレームを置く仮想機械で実行します。ソースは planck0.sv の1本です。

トップレベル

main は準備をしてから planck/init.pk を読み、続いて最初の引数のプログラムファイルを読みます。

ファイルは interpret_file が読みます（[[bootstrap/planck0.sv fun interpret_file]]）。式ごとに大域変数 parse と eval を call_global で呼び直します。call_global は Apply{名前, Tuple{引数}} を組み立ててコンパイルし、実行します（[[bootstrap/planck0.sv fun call_global]]）。このため parse を差し替えると次の式から新しい parse で読まれ、planck の構文はこの仕組みで入ります。

値の表現

値は32ビットの1語です。最下位ビットが1なら1ビット左シフトした整数、0ならヒープ上のオブジェクトへのポインタです。オブジェクトは先頭の1語のヘッダに種類と長さを持ちます。

シンボルと M式は intern します。同じ構造の M式はメモリ上で1つなので、等価性はポインタの比較です（[[bootstrap/planck0.sv ; intern a temporary m-expr object]]）。

ヒープは起動時に mmap2 で確保する固定の領域です。ヘッダの1語を持つチャンクが並び、オブジェクトのチャンクの先頭をビットマップに記録します（[[bootstrap/planck0.sv ; The heap is a fixed area .. ; === data layout (planck0)]]）。GC はオブジェクトを動かない mark-sweep で、全体を止めて、到達できないオブジェクトを解放します（[[bootstrap/planck0.sv ; === Garbage Collection .. fun main]]）。保守的で、根（大域変数・フレームスタック・機械のスタック）や印を付けたオブジェクトの語のうち、オブジェクトの中を指すものは、先頭でなくてもそのオブジェクトを残します。掃除では隣り合う空きチャンクをつなぎ、allocate はその中から first fit で取ります。前回の GC のあとに確保した量が前回の生きている量に達すると GC を始めます。

M式のリーダ

組み込みの parse が読むのは、シンボル・整数・文字列と、シンボルの直後に { が続く Head{...} の4種類です（[[bootstrap/planck0.sv fun parse_mexpr .. ; === Bytecode VM]]）。M式の引数は64個までです。

planck の構文が入ったあとも、このリーダは parse_mexpr として残ります。

コンパイラ

compile は整数と文字列を定数に、シンボルを変数の参照にし、M式を compile_mexpr に渡します（[[bootstrap/planck0.sv fun compile]]）。

compile_mexpr は頭で分岐します（[[bootstrap/planck0.sv fun compile_mexpr]]）。Apply・Def・Declare・Set・Do・If・While・Lambda・Fusion・Quote・QuasiQuote・Handle・Perform が特殊形式で、それ以外の頭は引数を評価して同じ頭の M式を作るコンストラクタになります。

局所変数はコンパイル時に（環境の深さ, 位置）の組に解決します。大域変数は欄（値・名前・定義したファイルの3語）で、コンパイラは名前から最新の欄を引く表 global_table を持ちます。トップレベルの Def は新しい欄を作って表の項目を差し替え（[[bootstrap/planck0.sv fun define_global]]）、命令 GLOAD・GDEF・GSET には名前でなく欄を埋め込みます（[[bootstrap/planck0.sv fun global_cell .. ; allocate slots for variables in a pattern]]）。名前が指す変数は式を実行する前に決まり、前にコンパイルした関数は前の欄を指したままです。Set は今の欄に書き込みます。局所にも大域にも見つからない名前は、その式を実行する前にメッセージを出して止まります。

Def は右辺をコンパイルしたあとに欄を作るので、右辺からは前の変数が見えます。関数が自分自身を参照できるのは、構文が Declare{f} で先に欄を作り、Set で関数を入れる形に読み替えるからです。埋める前に呼ぶと none を呼ぶことになって止まります。Declare{f} が Def{f, none} としてコンパイルされるのは、f がまだその場所の変数でないときだけです。トップレベルでは global_table を引いて、欄のファイルを読み込み中のファイル cur_file と比べます。cur_file は interpret_file と、load が呼ぶ _set_file が設定します。関数の中ではコンパイル時の環境からその関数の深さの項目を探します（[[bootstrap/planck0.sv fun defined_here]]・[[bootstrap/planck0.sv if (== head DeclareS)]]）。

仮想機械

仮想機械の設計はソース中の注釈にあります。

フレームは機械のスタックでなく、専用のフレームスタックに置きます。フレームは呼び出し元のすぐ上に置き、戻ると捨てます。仮想機械は自分自身を再帰呼び出ししません。計算の状態は現在のフレームからトップレベルまでのフレームの鎖だけで表せるので、継続はこの鎖の複製で済みます。

呼び出しとパターン照合

呼び出しでは select が引数に合う関数を選びます（[[bootstrap/planck0.sv fun select]]）。Fusion は左、失敗すれば右を試します。Lambda は引数の数を比べてからパターンを順に照合します。

match_pat は、変数なら新しい環境の次の位置に値を書き、Quote なら等価性を比べ、_TypeOf なら種類を確かめてから内側を照合します。M式のパターンは頭と引数の数を比べ、引数ごとに再帰します。合う関数がなければ matching failed で止まります（[[bootstrap/planck0.sv fun match_error]]）。

組み込みの eval は、M式をトップレベルの式としてコンパイルし、新しいフレームで実行します（[[bootstrap/planck0.sv if (== (get callee 3) PRIM_EVAL)]]）。

組み込み関数

組み込み関数は init_prims が defprim で大域の表に欄を作って登録します。名前・引数の数・実装の関数・種類を渡します（[[bootstrap/planck0.sv fun defprim]]）。演算子と文字列の連結は糖衣の呼ぶ名前で登録され、_add・_sub・_mul・_div・_mod・_lt・_le・_gt・_ge・_eq・_ne・_strcat のように _ で始まります（[[bootstrap/planck0.sv fun init_prims]]）。_ のない add や strcat は登録しないので、プログラムの同名の変数が演算子の意味を変えません。

エフェクト

Handle は本体を新しいフレームで実行し、そのフレームにハンドラを記録します（[[bootstrap/planck0.sv fun op_handle]]）。Perform は現在のフレームから呼び出し元へ鎖をたどり、ハンドラを持つフレームを探します。

見つけたら継続 k（現在のフレームから境界のフレームまでの鎖の、ヒープ上の複製）を作り、ハンドラを (v, k) で照合します。合わなければさらに外側を探します。ハンドラの値は境界のフレームの呼び出し元に返り、Handle 式の値になります。

k を呼ぶと、k の鎖をフレームスタックに複製し、複製を実行します（resume、[[bootstrap/planck0.sv fun resume]]）。元のフレームは実行しないので、同じ k を何度でも呼べます（多重継続）。
