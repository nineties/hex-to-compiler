構文の定義

planck/syntax.pk は、planck の構文を packrat パーサの規則として定義し、ファイルの途中で parse を差し替えます。構文は処理系に組み込まれておらず、planck のプログラムの一部です。

ファイルは2つの部分に分かれます。parse を差し替えるまでは、字句・動作が呼ぶ関数・文法の文法を M式で書きます。差し替えたあとの残りはその規則で読まれ、planck の構文を ::= で宣言します。

字句

識別子・整数・文字列などの字句は、構文解析式でなく関数で書きます。読めたら次の位置を返す関数です。

予約語の表 peg_reserved の単語と f" の f は識別子になりません（[[planck/syntax.pk#12-28]]）。関数は _define_rule にそのまま渡せば規則になります（[[planck/syntax.pk#125-128]]）。

規則の動作は、規則を定義するときにコンパイルされます。名前はコンパイル時に決まるので、動作が呼ぶ関数 peg_* は規則より前に定義します。このため peg_* の定義（[[planck/syntax.pk#143-894]]）は文法の規則（[[planck/syntax.pk#1305-1529]]）より前にあります。

文法の宣言

::= は規則 syntax_decl が読み、_define_rule を呼ぶ木にします。使う規則 g_choice・g_alt・g_item・g_suffix・g_primary が文法の文法で、宣言が作る形のとおりに、最初に M式で書きます（[[planck/syntax.pk#1192-1263]]）。

選択肢の項目と動作は g_alt が peg_alt で Act{Seq{...}, Lambda{Tuple{Tuple{ラベル, ...}}, 動作}} に組み替えます（[[planck/syntax.pk#1213-1221]]）。ラベルは動作の無名関数の引数パターンになります。

syntax_decl は expr の最初の選択肢なので、::= は式を書ける所ならどこにでも書けます。新しい規則は次のトップレベルの式から効きます。

parse の差し替え

動作を書く式は、planck の規則に足りる最小の構文です。M式・呼び出し・`e・'e・!e・ブロックを読みます（[[planck/syntax.pk#1265-1298]]）。そのあとの2行で切り替えます。

M式のリーダを parse_mexpr として残し、parse を規則 toplevel で1式読む関数にします。差し替えは Def でなく Set です。init.pk の load は先に parse の変数を決めてあるので、Def では新しい変数が増えるだけで、load が読むライブラリは古い parse のままになります。planck0 は式ごとに parse を引き直すので（planck0）、切り替えたあとの式は上の規則で読まれます。toplevel は expr を1つ読み、;・改行・次の式の始まりのどれかを確かめます（[[planck/syntax.pk#1529]]）。

primary に ident{expr, ...} の選択肢があるので、M式もそのまま式として読めます。

続いて文法の文法が自分自身を ::= で宣言し直します（[[planck/syntax.pk#1305-1332]]）。宣言し直した規則は同じ名前の規則を置き換え、2つの書き方が作る規則は同じです。ここから先の planck の規則は ::= で書きます。

式

規則は結合の強い順に宣言し、どの規則も宣言済みの規則だけを参照するようにします。unary・postfix・mul_expr・add_expr から ternary まで、続いてパターン、arrow・union・primary・expr の順です（[[planck/syntax.pk#1334-1529]]）。宣言した規則は、それまでの規則が読むのに使っていた同じ名前の小さな規則を置き換えます。加減算の規則は次のとおりです。

add_expr は直接左再帰なので左結合です。動作は準クオートで、!a と !b がラベルの値になり、Apply{_add, Tuple{a, b}} を作ります。minus の中の same は次の字句が同じ行にあるときだけ成功するので、行頭の -1 は新しい式になります（[[planck/syntax.pk#1340]]）。

動作が返すのは評価器が受け取る M式そのものです。1 + 2 は Apply{_add, Tuple{1, 2}} になり、M式で直接書いた場合と同じ木です。

primary の最後の選択肢 sugar_primary が match・return・break・continue・for を持ちます（[[planck/syntax.pk#1487-1491]]）。

fun f と f(p, ...) = e も規則 expr の選択肢で、Def{f, none} と Set{f, Fusion{f, Lambda{...}}} にします（[[planck/syntax.pk#1514-1526]]）。f(p, ...) := e は Do{Declare{f}, Set{f, Fusion{f, Lambda{...}}}} に読み替えるので、f がすでにその場所の変数なら f に足します。本体の Lambda は peg_lambda が作ります。ブロックは Do に包むだけで、中の定義を先頭へ移すことはしません。

添字と置き換え

a[i] は規則 postfix の選択肢です。[ は a に空白なしで続け、] のあとが代入の = のときは読みません（[[planck/syntax.pk#1358]]）。a[i] = e は規則 expr の選択肢が _index_set の呼び出しにします（[[planck/syntax.pk#1524]]）。

[ ] の中は規則 index で、式1つです（[[planck/syntax.pk#1347]]）。t[p -> e | q if c -> g] のようにガードのある腕を含む関数は、_peg_rewrite が peg_fuse で最後に peg_skip を返す腕を足し、どの腕も当てはまらないときに peg_skip を返すようにします（[[planck/syntax.pk#400-409]]）。

_index_get と _index_set は、種類ごとの Lambda を Fusion でつないだ関数です（[[planck/syntax.pk#1002-1070]]・[[planck/syntax.pk#1073-1150]]）。表は Table{t}、リストは Cons{x, xs} と Nil{} の頭で選ぶので、パターンだけで種類が決まります。関数 f を添字にすると subst(t, f) を呼びます（[[planck/syntax.pk#922-972]]）。subst は f の最後に「peg_skip を返す」腕を足し、それ以外の値が返った部分は置き換えて内側を試さず、peg_skip が返った部分は引数ごとに自分を呼びます。

利用者が _index_get = (K{...}, i) -> ... | _index_get と代入すると、新しい種類が元の関数の前に入ります。planck/lib/vector.pk の末尾はこの書き方です。

return と break の読み替え

return・break・continue はエフェクトに読み替えます。return を読むたびに数を数え、関数の木を作るときに数が増えていれば本体を Handle で包みます（[[planck/syntax.pk#278-294]]）。

for の本体の return x は Perform{Return{x}} になり、関数の本体全体が Handle{..., (Return{v}, k) -> v} で包まれます。for は peg_for の呼び出しです。

規則で読む文字列

name{| text |} は関数で書いた規則 embed が読みます（[[planck/syntax.pk#1158-1178]]）。name と {| のあと規則 name をその位置から呼び、続く |} を求めます。規則の値は Quote{v} として木に入ります。
