9. 変数の範囲

名前がどの変数を指すかは、プログラムの書かれた位置から、式を実行する前に決まります。関数の定義 f(p, ...) := e は、同じ場所に f があるかどうかで、場合を足すか新しい f を作るかが変わります。

名前の解決

変数の範囲は字句的で、名前がどの変数を指すかは、式を実行する前に、プログラムの書かれた位置から決まります。関数の本体から見えるのは、その関数と外側の関数の引数と変数、およびトップレベルでそれより前に定義した変数です。呼んだ側の変数は見えません。read_n() は caller の中の n ではなく、トップレベルの n を読みます。

同じ名前を := でもう一度定義すると新しい変数ができ、前に作った関数は前の変数を指したままです。get は最初の x を指すので、x = 10 が代入する新しい x は見えません。

どの変数も指さない名前があると、その式を実行する前にメッセージを出してプログラムが止まります。later は3行目で定義されていて、2行目からは見えません。1行目は先に実行されるので "start" は出ます。

定義が足すとき・隠すとき

f(p, ...) := e は、同じ場所に f が定義済みなら場合を足し、なければ新しい f を定義します。場所は、トップレベルでは同じファイル、関数の中ではその関数の引数と、その関数でそれより前に定義した変数です。外の name は inner の中の場所の変数ではないので、inner の中の name(0) := "inner" は新しい name を定義し、外の name は変わりません。

別のファイルで定義した関数と組み込み関数も、プログラムのトップレベルでは同じ場所の変数ではありません。sum(xs) := ... は新しい sum を定義して use("list") の sum を隠します。ライブラリの関数に場合を足すときは last(Tuple{a, b}) = b のように = で書き、足した場合は元の場合のあとに試されます。

規則の全体はリファレンスの変数の範囲にあります。
