vasmc

planck/vasmc.pk は vasm と native のソースファイルから Linux の実行ファイルを作ります。手順は、プログラムの検査、下の形への変換、機械の命令の選択、実行ファイルの書き出しです。ソースを単位に分けて結合したプログラムは、すべてのソースを一度にコンパイルしたプログラムと同じに動きます。

ソースファイルと対象

名前が .native で終わるファイルは native のソースで、先に vasm に展開されます。それ以外は vasm のソースです。誤りは file:line:column: message の形で、位置はソースファイルのものを示し、コンパイルは止まります。

対象は機械です。今ある対象は x86_64 で、対象を指定しなければこれになります。命令の選択までは、語の幅を除いてどの対象でも同じで、機械ごとの部分は命令の選択より後にあります。システムコールは対象の OS の部分が呼ぶので、プログラムには書きません。

1つのファイルから1つの実行ファイル

ソースには引数を取らない関数 main が必要です。その結果がプログラムの終了コードになります。

単位

プログラムを複数のソースファイルに分けて、1つずつコンパイルできます。ファイルを単独でコンパイルした結果が単位ファイルです。単位ファイルには、そのファイルの下の形に落とした関数とインタフェース（構造体と関数の宣言。本体は除く）が入ります。機械語は入らないので、命令の選択は単位を結合するときに、プログラム全体に対して1回行われます。

  • unit は1つのソースファイルを単位ファイル output にします。import は単位ファイルです。import の関数と構造体は、ソースの中で宣言されているかのように使え、インタフェースに対して検査されます。単位にするソースに main は要りません。
  • 単位の名前は、ソースのファイル名からディレクトリと拡張子を除いたものです。lib.native は単位 lib です。
  • link は単位ファイルを与えた順に結合して実行ファイル output にします。単位のうちちょうど1つが、引数を取らない関数 main を持ちます。
  • 単位ファイルは対象の語の幅に合わせて作られ、同じ幅の対象にだけ結合できます。2つの単位が同じ関数や構造体を定義すると、結合できません。
  • import の import は取り込まれません。単位が使えるのは、自分のコマンドに挙げた単位ファイルの項目だけです。

native の単位

native のソースは、使う単位をファイルの先頭の import で挙げます。見えるのは、こう挙げた単位の関数と構造体だけです。コマンドに別の単位ファイルを渡していても、その単位の名前は未定義の名前になります。名前に修飾は付きません。import lib のあと、twice(3) は lib の関数 twice を呼びます。単位ファイルをコマンドに渡していない単位を import すると誤りです。vasm のソースには import がなく、渡した単位ファイルがすべて見えます。

native_compile.compile_with(m, imports) と native_compile.compile_all_with(m, imports) に項目の並びとして渡します。compile_all_with は native_compile.compile_all と同じく、誤りをモジュールとあわせて返します。imports は単位のインタフェース（vasm のモジュールの vasm_unit.iface）です。展開されたモジュールには import の項目は入りません。
