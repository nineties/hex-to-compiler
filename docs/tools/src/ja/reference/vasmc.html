vasmc

planck/vasmc.pk は vasm と native のソースファイルを Linux の実行ファイルにします。プログラムを検査し、下の形に落とし、機械の命令を選び、実行ファイルを書きます。ほかの系のアセンブラやリンカは要りません。

ソースファイルと対象

名前が .native で終わるファイルは native で書かれていて、先に vasm に展開されます。それ以外のファイルは vasm で書かれています。誤りは file:line:column: message の形で、位置はソースファイルのものとして書かれ、コンパイルは止まります。

対象は機械です。今ある対象は x86_64 で、対象を指定しなければこれになります。命令の選択までは、語の幅を除いてどの対象でも同じで、機械ごとの部分は命令の選択より後にあります。システムコールは対象の OS の部分が呼ぶので、プログラムには書きません。

1つのファイルから1つの実行ファイル

ソースには引数を取らない関数 main が必要です。その結果がプログラムの終了コードになります。

単位

プログラムを複数のソースファイルに分けて、1つずつコンパイルできます。ファイルを単独でコンパイルした結果が単位ファイルです。単位ファイルは、そのファイルの下の形に落とした関数とインタフェース（構造体と関数の宣言。本体は除く）を持ちます。機械語は持たないので、命令の選択は単位を結合するときに、プログラム全体に対して1回行われます。

  • unit は1つのソースファイルを単位ファイル output にします。import は単位ファイルです。import の関数と構造体は、ソースの中で宣言されているかのように使え、インタフェースに対して検査されます。単位にするソースに main は要りません。
  • link は単位ファイルを与えた順に結合して実行ファイル output にします。単位のうちちょうど1つが、引数を取らない関数 main を持ちます。
  • 単位ファイルは対象の語の幅に合わせて作られ、同じ幅の対象にだけ結合できます。2つの単位が同じ関数や構造体を定義することはできません。
  • import の import は取り込まれません。単位が使えるのは、自分のコマンドに挙げた単位ファイルの項目だけです。
  • 単位から結合したプログラムは、すべてのソースを一度にコンパイルしたプログラムと同じに動きます。

例では、lib.native に main がなく、main.native がその関数と構造体を使います。

native の単位

native では、import の関数と構造体を同じファイルのもののように使えます。native_expand.expand_with(m, imports) と native_expand.expand_all_with(m, imports) に項目の並びとして渡します。expand_all_with は native_expand.expand_all と同じく、誤りをモジュールとあわせて返します。imports は単位のインタフェース（vasm のモジュールの vasm_unit.iface）です。展開されたモジュールには import の項目は入りません。
