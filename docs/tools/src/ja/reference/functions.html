部分関数と融合

関数はパターンで引数を取ります。パターンは構築子と同じ形で書き、合えば変数を束縛します。f | g（融合）で場合分けを書きます。

部分関数と融合

関数はパターンで引数を取るので、合わない引数があり得る部分関数です。Fusion{f, g}（構文は f | g）は、まず f を試し、どのパターンも合わなければ（ガードが偽のときも）g を試します。つないだ順に試すので、f(0) := ... のように同じ場所に続けて書いた定義も、書いた順に試す1つの関数です。

f := (0) -> "zero" | (1) -> "one"
f(1)   // "one"
f(7)   // どの腕にも合わず、プログラムが止まる

どの腕にも合わなかった関数呼び出し・match・融合の最後のつなぎ先は、止まる代わりに MatchingFailed{f, args, loc} を Perform します。match e { f } は f(e) と同じ呼び出しです。受け手のハンドラが無ければ、エラーのメッセージ（matching failed）を出してプログラムが止まります。unhandled effect にはなりません。

フィールド中身
f呼ばれた関数（融合なら融合全体）
args合わなかった引数の Tuple{...}
loc失敗した呼び出しや match のソース上の位置。Loc{file, line, column}
a := handle f(7) with (MatchingFailed{_, Tuple{n}, _}, k) -> n
println(a)
7

ハンドラの値が Handle の値になります。f(7) を呼んだ式の値にはなりません。

融合の次のつなぎ先は、入口のパターンとガードだけで決まります。腕の入口が合えば、その腕の本体の奥で起きた MatchingFailed は次のつなぎ先へ移らず、外側へ伝わります。

g(0) := "zero"
h := (x) -> g(x) | (x) -> "second arm"

r := handle h(5) with (MatchingFailed{f, _, _}, k) -> "failed in g"
println(r)
"failed in g"

h(5) は1つ目の腕に入り、その中の g(5) が合わずに MatchingFailed になります。2つ目の腕には移りません。

Perform は、Handle のハンドラのどのパターンにも合わなければ、さらに外側のハンドラを探します。Return{v} や Break{} だけを受けるハンドラは通り抜け、どのパターンにも合う (e, k) -> ... のハンドラは MatchingFailed も受けます。MatchingFailed 以外の Perform は、受け手が無ければ unhandled effect で止まります。

パターン

  • _：何にでも合い、何も束縛しません。
  • Head{p, ..., _Rest{x}}：引数が _Rest の前の数以上ある M式に合い、残りの Tuple を x に束縛します。
  • _TypeOf{p, type}：値の type が type で p が合う値に合います。

引数のパターン

引数 p と for のパターンは、or の階層までの式として書きます。表の M式にしたうえで、パターンとして照合します。原則は、式と同じ書き方で、識別子が変数になることです。例外は次のとおりです。

  • 演算子と呼ばれる関数の名前はシンボルです。x + 1 は Apply{Quote{_add}, Tuple{x, 1}}、f(p, ...) は Apply{Quote{f}, Tuple{p, ...}} の木に合います。呼ばれる関数を変数にするには (f)(p, ...) と書きます（Apply{f, Tuple{p, ...}}）。
  • 'e は Quote{e}、p @ type は型の検査、x... は最後の引数の残りです。
  • 同じ名前を2回書く f(a, a) は、2つの値が == で等しいときだけ合います。
  • p or q はどちらかに合います。変数を書けるのは、どの枝も同じ変数を束縛するときだけです（f((x, 0) or (0, x)) := x）。式の or の M式 If{a, true, b} に合わせるには If{a, 'true, b} と書きます。
  • 書ける形は、演算子（or and not == != <= >= < > :: + - * / %、単項の - と '）・f(p, ...)・Head{p, ...}・識別子・true false none・整数・文字列・組・リストです。結合は式と同じです。

残りの引数

関数の最後の引数は x... と書けます。x は残りの引数の Tuple（なければ Tuple{}）に束縛されます。関数 f(p, x...) := e・(p, x...) -> e とパターン Head{p, x...} の最後の引数にだけ書けて、前の引数の数より少ない呼び出しは合いません。最後以外・呼び出しの引数・ガード付きの関数に書くと、式を実行する前にメッセージを出して止まります。

関数に定義が加わるとき

関数の定義 f(p, ...) := e は、書いた場所の変数に f があるかで読み方が変わります。あれば f(p, ...) = e と同じで、なければ新しい f をその場所で定義します（fun f のあとに f(p, ...) = e）。同じ場所に続けて書いた f の定義は1つの関数になり、書いた順に試されます。

書いた場所の変数は、トップレベルでは同じファイルで定義した大域変数、関数の中ではその関数の引数とそれより前に定義した変数、トップレベルの if の枝や while の本体ではその中でそれより前に定義した変数です。外側の関数の変数、関数の中から見た大域変数、別のファイル（use で読んだライブラリや planck/init.pk）の大域変数や組み込み関数は、書いた場所の変数ではありません。これらと同じ名前の f(p, ...) := e は、隠す新しい f を定義し、外の f を変えません。別のファイルの f に定義を追加するときは f(p, ...) = e と書きます。

ガードは定義にも付けられます。f(p, ...) if c := e は、引数が合って c が真のときに e を返す腕を足します。偽のときと合わないときは、同じ場所に続けて書いた次の定義を試します（間に別の式があると続きません）。f(x) if x > 0 := "正" のあとに f(_) := "それ以外" と書けば、f(-1) は "それ以外" です。export を付けた定義と f(p, ...) = e にはガードを付けられません。

互いに呼び合う関数

先に fun f で名前だけを宣言し（値は none）、あとで f(p, ...) = e で埋めます。f(p, ...) = e は f = f | (p, ...) -> e で、f の関数の後ろに足します。none | g は g なので、最初の f(p, ...) = e は関数そのものを代入します。埋める前に呼ぶと none を呼ぶことになって止まります。

値がガード付きの関数のとき（f = (n) if n > 0 -> 1 のあと）、ガードが偽でも f(p, ...) = e で追加した関数は呼ばれません。変数で渡したガード付きの関数は、あとにつないだ | g を呼ばないのと同じです。
