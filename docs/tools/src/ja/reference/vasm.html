vasm

use("vasm/check") が定義する低級言語です。vasm{| ... |} に書いた関数と構造体を、所有と借用の規則で検査します。解放後の使用・二重の解放・借用の違反・未初期化の読み出しは誤りです。検査は型の規則だけで行い、検査を無効にする手段はありません。

プログラム

プログラムは構造体と関数の並びで、どちらもモジュールのどこに書いても全体から見えます。文は改行か ; で区切ります。

関数の [r, ...] は領域の引数で、呼び出しの引数の借用から決まります。決まらなければ誤りです。構造体の名前や関数の名前に、組み込みの関数と同じものは使えません。

値と初期化

  • 読み出せるのは初期化済みのレジスタだけです。if の後は両方の分岐で初期化したものだけ、while の後はループの前の状態です。
  • 整数の演算の両辺は同じ型です。幅や符号の違う整数は混ぜられず、as で合わせます。広げるときは元の型の符号に応じて符号拡張かゼロ拡張をし、狭めるときは下位のビットを残します。
  • 整数のリテラルは、代入先・引数・相手の項の型の範囲に入るかを検査します。リテラル1つで書けるのは -32768 から 32767 までです。大きな値は m = 0x7F45、m = m << 16、m = m | 0x4C46 のように組み立てます。
  • 文字列リテラル "..." は、読み取り専用のデータに置いた u8 の配列です。エスケープは planck の文字列と同じで、バイトはソースのとおり、終端はありません。バイト数は len で分かります。型は &static [u8] で、write(1, "hello\n")・return "name"・s = "abc" のように、項を取る所に書けます。同じリテラルは1つだけ置かれます。共有の借用なので、要素は書き換えられません。
  • 配列の添字は i64 です。添字の範囲は実行時に検査し、検査器は型と所有だけを見ます。配列を *p で丸ごと読み書きすることはできません。
  • 構造体の値は、own を持たなければ整数と同じくコピーされ、own を持てば move されます。s.f は、s が構造体のレジスタならその値のフィールド、構造体を指すポインタなら指す先のフィールドです。

所有

  • own の値は、move するか free するかのどちらかを高々1回します。
  • 持ち主がなくなる時点で、残っている own は自動的に解放されます。該当するのは、ブロックや関数の終わりと return、上書き（p = box(2)・*p = v・p[i] = v・s.f = v の前の値）、文として捨てた関数の結果、free した値の中に残ったものです。箱の中身・構造体のフィールド・配列の要素のうち、取り出されていないものが解放されます。
  • 解放した値を使う・もう一度解放する・move した値を使うのは誤りです。
  • 片方の分岐だけで move や解放をした値は、その後に持ち主かどうかが決まらないので誤りです。ループは中で move した値を、次の周の前に入れ直す必要があります。
  • 関数は move された引数の持ち主になります。呼び出し元は渡した値をそのあと使えません。

own を持つ値の取り出し

  • x = *p は、中身が own を持つとき中身を move して取り出します。p は借用されていない own でなければなりません。取り出したあとの p は中身の無い箱で、*p = v で入れ直すか free(p) するまで読むことも move することも借用することもできません。借用からは取り出せません。
  • 構造体のレジスタ s からは x = s.f で own を持つフィールドを move して取り出せます。取り出したフィールドを読むことも、もう一度取り出すことも誤りです。s.f = v で入れ直せます。取り出したあとの s は丸ごとは使えず、残ったフィールドは s がなくなる時点で解放されます。
  • 配列の要素やポインタの指す構造体のフィールドは、swap(p[i], v)・swap(p.f, v) で入れ替えて取り出します。*p も swap(*p, v) で入れ替えられます。場所は借用されていない own か &mut から書けるものです。
  • own を持つ値を、配列の要素・ポインタの指す先・借用からコピーして読むことはできません。

val

val の値は種類の情報を実行時に保持します。検査器は val とほかの型を区別するだけで、種類を検査しません。種類が違う値を操作すると実行時に異常終了します。配列の添字の範囲と同じ扱いです。

  • レジスタの val は整数と同じくコピーされます。move も借用もありません。
  • 値ごとに持ち主の数を数え、持ち主がなくなると値を解放します。持ち主がなくなる時点は own の自動解放と同じです。自分自身を要素に持つ配列は解放されません。
  • 構造体のフィールド・箱の中身・own の配列の要素に入れた val は own と同じ扱いで、swap や move で取り出します。

借用と領域

  • x = &r p は、p が r より前に宣言され、r の終わりまで有効であることを求めます。借用されている間、p を move・解放・代入することはできません。&mut で借用されている間は *p・p[i]・p.f も読めません。借用は r の終わりで解消します。
  • 共有の借用は複製され、いくつでも持てます。&mut はレジスタの間で使うと move されます。
  • 関数の借用の引数に渡した &mut は、呼び出しの間だけ借り直され、move されません。同じ呼び出しの別の引数にもう一度渡すことはできません。関数の結果の型が借用した領域を含むときは、結果に借用が残るので借り直しにならず、move されます。
  • &mut は & の引数に渡せます（呼び出しの間だけ共有で借り直す）。
  • 外の領域 q の借用は、q の内側に開いた領域 r の借用の所に渡せます。代入・return・引数のどれでも同じです。関数の領域の引数どうしには内外の関係が無く、関数の領域は関数の中で開いた領域より外です。
  • 関数の領域の引数は、渡された借用の領域のうち一番内側のものに決まります（ほかが全部それより外であること）。
  • 領域 static はほかのどの領域より長く続きます。static の借用は、どの領域の借用を期待する所にも置け、領域の引数にも渡せます（ほかに渡す借用がなければ、その領域の引数は static になります）。ほかの領域の借用を &static を期待する所に置くことはできません。static は領域や変数の名前にできず、その借用を作るのは文字列リテラルだけです。
  • 型 &r T は r の中でしか書けません。r の外のレジスタに入れることも r の外へ返すことも誤りです。

誤りの種類

vasm_errors(file, m) は VasmErr{kind, loc, msg} のリストを返します。kind は次のシンボルです。構造体と関数のそれぞれで、最初の誤り1件だけを返します。

kind誤り
'type型が合わない。整数の幅や符号の違い、リテラルの範囲、フィールドの不足
'undefined定義のない関数や構造体
'uninit初期化前の読み出し
'movedmove した値、取り出した中身やフィールドの使用
'freed解放した値の使用、二重の解放
'borrowed借りている間の move・解放・代入・読み書き、借用の重なり
'ownerown を持つ値を持ち主でない場所からコピーする
'region領域が開いていない・すでに開いている・決まらない
'escape借用が領域の外に出る
'branch分岐の後で所有の状態が揃わない
'loopループで move した値を入れ直さない

例は実装の vasm の検査器にあります。vasm_report(file, m) は誤りを file:行:列: メッセージ で書き、誤りがなければ ok を書きます。
