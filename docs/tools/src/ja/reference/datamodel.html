データモデル

値は M式か atom のどちらかです。

M式

M式は Head{a, b, ...} と書く値で、head（symbol）と引数の列を持ちます。組は Tuple、リストは Cons と Nil を head とします。

  • 型は Expr で、immutable です。
  • 引数の数に限度はありません。mutable な値と NaN は引数に入れられず、作るときに実行時エラーです。
  • head(x) は M式だけに使えます。

atom

M式でない値が atom です。ユーザーデータで新しい型も作れます。

型は値（型の値）で、type(x) が返します。type(1) は Int、type(Int) は Type です。

array と plain array は array_set・plain_set で書き換えます。範囲外と、plain array に入らない値はエラーです。

equality

_eq(a, b) は値として等しい（equal）かを調べます。

  • 整数・float・complex は、型が違っても値が同じなら equal です。NaN はどの値とも equal ではありません。
  • M式は head と引数が equal なら equal です。
  • array と plain array は、identical なら equal で、そうでなければ要素ごとに比べます。
  • hash(x) は 0 以上の整数で、equal な値は同じ値です。

identity

_is(a, b) は同じ物（identical）なら true です。identical な値は必ず equal です。型が違う値は identical ではなく、整数 1 と float 1.0 は equal でも identical ではありません。

intern は、equal な値を1つの object にまとめることです。intern する型では equal な値が identical で、_is は O(1) です（多倍長整数を除く）。

ユーザーデータ

  • 組み込み関数で作り、immutable か mutable かを必ず指定します。
  • immutable なユーザーデータは mutable な値を中身に持てず、作るときに実行時エラーです。
  • 型は作るたびに別の値です。名前は表示にしか使わず、同じ名前の型は _is で区別します。
  • 作るときに equal と hash の関数をまとめて渡せます。_is(a, b) なら _eq(a, b)、equal なら hash が同じであることは、作る人が守ります。
  • 渡さない型の hash は、immutable なら中身、mutable なら object で決まります。

数

型が混ざる演算は、高い型に揃えます。

  • _div は0方向へ切り捨て、_quo は負の無限大方向へ丸めます。_mod(a, b) は _sub(a, _mul(b, _quo(a, b))) で、符号は除数と同じです。
  • 除数が0なら実行時エラーです。float か complex を含む _div は無限大か NaN（complex は成分ごと）になります。
  • _lt _le _gt _ge は整数と float を数学的な値で比べます。NaN があれば false、complex は実行時エラーです。
  • 整数を float に揃えると最も近い float になり、範囲外は実行時エラーです。

リテラル

true・false・none は同じ名前の symbol を値とするリテラルで、変数ではありません。

record

_record_declare(Quote{T}, Quote{Tuple{f, g, ...}}) は、T{a, b, ...} の引数に欄の名前を付けます。_record_get(t, Quote{f}) は f の位置の引数で、_record_with(t, Quote{f}, e) は欄を替えた新しい値です。

  • head が違えば同じ名前の欄を持てます。同じ T を宣言し直すと名前が置き換わります。
  • 宣言のない head や、欄がない値に _record_get を使うと、メッセージを出して止まります。
