9. Scope of variables

Which variable a name refers to is decided from the place where the program is written, before the expression runs. A function definition f(p, ...) := e adds a case or defines a new f depending on whether f is in the same place.

Resolving names

Scope is lexical: which variable a name refers to is decided before the expression runs, from the place where the program is written. The body of a function sees the parameters and variables of that function and of the functions around it, and the variables defined before it at the top level. The variables of the caller are not visible. read_n() reads the top-level n, not the n inside caller.

Defining the same name again with := makes a new variable, and the functions made before keep referring to the old one. get refers to the first x, so it does not see the new x that x = 10 assigns.

If a name refers to no variable, the program stops with a message before the expression runs. later is defined on the third line and is not visible to the second line. The first line runs earlier, so "start" is written.

Adding to a function and hiding it

f(p, ...) := e adds a case when f is already defined in the same place, and otherwise defines a new f. The place is the same file at the top level, and in a function the parameters of the function and the variables defined before it in the function. The outer name is not a variable of the place inside inner, so name(0) := "inner" in inner defines a new name and does not change the outer one.

A function defined by another file and a builtin function are not variables of the same place at the top level of a program either. sum(xs) := ... defines a new sum that hides the sum of use("list"). To add a case to a library function, write it with = as in last(Tuple{a, b}) = b. The added case is tried after the original cases.

The whole rules are in Scope of variables in the reference.
