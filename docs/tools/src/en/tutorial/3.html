3. Patterns and fusion

The parameters of a lambda are patterns. f | g (fusion) is a function that tries g when no pattern of f matches. Case analysis is written with it.

| associates to the right. Fusion tries the lambdas from the left and calls the first one that matches. When none matches, the program stops with matching failed.

f(p, ...) = e is f = f | (p, ...) -> e, which adds a case after f. The same function can be written with one line per case. The lines are tried in the order they are written.

When f is already defined in the same place, f(p, ...) := e also adds a case to f. So all the lines may be written with :=.

Patterns

Adding cases by fusion

A fusion is a value. So a case can be put in front of an existing function, and the result assigned back.

Adding to a function and hiding it

f(p, ...) := e adds a case to f when f is already defined in the same place. Otherwise it defines a new f.

The place is the same file at the top level. In a function, it is the parameters of the function and the variables defined earlier in the function. The outer name is not a variable of the place inside inner. So name(0) := "inner" in inner defines a new name and does not change the outer one.

At the top level of a program, a function defined by another file and a builtin function are not variables of the same place either. So reverse(xs) := ... defines a new reverse that hides the reverse of use("list").

To add a case to a library function, write it with =, as in foldl(f, acc, Tuple{a, b}) = f(f(acc, a), b). Chapter 9 describes which variable a name refers to.

match

match e { f } evaluates e once and calls the function f with the value. f is the arms joined by |, and the arms are tried from the top. In a guard p if c -> a, the next arm is tried when c is false.

Symbolic differentiation

'Add{x, 3} is a quotation. It passes the M-expression as it is, without evaluating it (chapter 6). A version with simplification is planck/examples/deriv.pk.
