native

use("native/expand") defines a systems language. Its meaning is that of vasm, with a higher-level notation: expressions nest, and let, for, compound assignments, the short-circuit and and or, and large integer literals are available. native_expand.expand expands the functions and structs written in native{| ... |} to a vasm module. Ownership and borrowing are checked on the expanded vasm.

Programs

A program is a list of structs and functions, which can follow import lines. import lib names the unit lib, and only the structs and functions of the units named so can be used from other units; see vasmc. The imports come first in the file, one on each line. Types, structs and function declarations are written as in vasm. The body of a function is a list of statements, separated by newlines or ;.

The value of native{| ... |} is PModule{[...]}; its list starts with PImport{at, name} for each import. native_expand.expand(m) is the vasm Module{[...]}, which vasm_check and vasm_build take as it is. native_expand.expand_all(m) is Tuple{module, errors}. The errors are VasmErr{kind, loc, msg}, the first one of each function. native_expand.errors(file, errors) gives the positions as Loc of the file. A function can call the functions and use the structs of other units: see vasmc.

Expressions nest. The precedence grows from the top to the bottom.

If the last statement of the body of a function that gives a value is an expression, its value is the result.

How types are fixed

  • The type of an expression comes from the declarations of the variables and functions and from the types of the built-in functions. Types are written only at let, var, parameters, results of functions and as.
  • An integer literal alone has no type. The type of the place it is put in, of the parameter, of the other operand or of the result of the function is its type. A literal that has nothing to fix its type, as in let x = 5, is an error. Write let x: i64 = 5 or 5 as i64.
  • The type of the variable of for i in a..b is the type of whichever of a and b is not a literal. If both are literals it is an error; give one of them a type, as in 0 as i64..10.
  • The type of a call whose result holds a borrow is inferred only when the region of the result is fixed by the arguments to one. Otherwise write let x: T = f(...).
  • The index of an array is i64. An index of another integer type gets as i64.
  • A name can be declared again. The earlier variable is hidden.

Large literals

A literal of vasm is from -32768 to 32767. native accepts an integer literal beyond it. A literal outside the range of its type is an error.

The expansion makes the value from parts of 15 bits, the greatest first, joined by << and |. A negative value is subtracted from 0 at the end.

Errors

The kind of an error of the expansion is 'type (the type is not known, a literal is outside the range of its type, a statement that is an expression is not a call) or 'undefined (a variable, function or struct that is not declared). Ownership, borrowing and initialization are not checked by the expansion; vasm_check.check checks the expanded vasm. The positions of the errors are those of the native source.
