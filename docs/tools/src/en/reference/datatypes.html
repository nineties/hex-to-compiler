Data types

Types of values, immutability, equality and identity.

Types of values

There are eight builtin types. A user can make new types (user data).

The type of a value is told by head. The pattern x @ Int matches a value whose head is Int.

Notes on each type

integer

  • Arbitrary precision. No limit on the range.
  • Arbitrary precision integers are also identical if the values are the same.

float

  • IEEE 754 binary64.
  • NaN is not equal to anything, itself included, and not identical to anything either. If x is NaN, x == x and x is x are both false.
  • NaN cannot be a table key. Using a NaN as a key is an error.
  • A different object with the same value is not identical.
  • The hash of a float equal to an integer is the same as the integer. Otherwise it is decided by the contents.

string

  • A sequence of bytes, including 0 bytes. Up to 65535 bytes.
  • Strings with the same bytes over the whole length, 0 bytes included, are identical. == and is are the same test.
  • a[i] can be read (a string of length 1).

symbol

  • Unique for each name. == and is are the same test. A name that starts with a letter, _ or %. For true, false and none, see Lexical rules.

M-expression

  • A head symbol and any number of arguments.
  • Sugar: (a, b) (Tuple), [a, b] and :: (Cons), [] (Nil).
  • A mutable value cannot be an argument. Neither can immutable user data that holds a mutable value. Neither can a NaN. Making such an M-expression is a runtime error.
  • == and is are the same test, and O(1). Equality across numeric types applies only to the numbers themselves, so f{1} and f{1.0} are not equal.
  • a[i] can be read.

function

  • Lambda, Fusion, builtin function, continuation.
  • Equal only when identical.
  • The hash is decided for each object and does not change while the object lives.

array

  • Fixed length. All elements are none at first. Made by array(n).
  • A different array with the same contents is equal but not identical.
  • a[i] = e works. An error when out of range.

plain array

  • All elements have one type. The element type is 'bool, 'i8 to 'u64, 'f16 to 'f64, 'c64 or 'c128.
  • Made by plain_array(kind, n), u8_array(n) and so on.
  • A different plain array with the same contents is equal but not identical.
  • a[i] = e works. An error when out of range or when the value cannot be converted.

user data

  • Made by a builtin function. Whether it is immutable or mutable must be specified when it is made. There is no default.
  • Making user data whose type name is the same as a builtin type name or another user data type name is an error. The symbols of the eight builtin type names and of user data type names cannot be the head of an M-expression.
  • The type name of a type made inside a module is the name of the module put before it (Set in the module bitset is bitset.Set). A type made outside a module gets no prefix. The error for the same type name above is checked with the name after the prefix is put.
  • A function for == and a function for hash can be given when the type is made. If given, give both. A type with == given is not interned, and is compares objects. == and hash are the given functions.
  • For the given functions, the person who makes the type must keep these: if a is b then a == b, and equal values have the same hash.
  • For a type without them, the hash of immutable user data is decided by the contents and the hash of mutable user data is decided for each object. == is identity.

Equality

Equality is tested by a == b (_eq). a != b (_ne) is its opposite.

Equality across number types

Integers, floats and complex numbers are equal if the values are the same, even when the types differ. 1 == 1.0 and 1 == complex(1, 0) are true, and the hash is the same.

Where equality is used

  • A pattern that writes the same name twice (f(a, a)) matches only when the two values are equal by ==. User data uses the given ==.
  • The builtin table (table_get, table_set and t[key]) treats two keys as the same if they are identical or equal. User data uses the given == and hash. An array, a plain array or a NaN as the key is an error.
  • hash(x) is an integer of 0 or more. Values that are equal by == give the same value. For user data with == given, it is the value of the given hash. The exact values of hash are not defined.

Identity and is

a is b is true if a and b are identical, and false otherwise. Its negation is written a is not b. It has the same precedence as ==, at the level of the comparison operators. Like the comparisons it does not group, so a is b is c is an error. is cannot be written in a pattern.

  • Identical values are always equal: if a is b, then a == b. A NaN is not identical even to itself.
  • Integers, strings, symbols, M-expressions and immutable user data without == given are interned. Floats, functions, arrays, plain arrays, mutable user data and user data with == given are objects.
  • Interning means that equal values are made into one object, so making the same value twice returns the same object. For an interned type, equal values are identical. User data with == given is not interned, so equal values are not always identical. So == is the same test as is, and O(1).
  • Values of different types are not identical. 1 == 1.0 is true, but 1 is 1.0 is false.
  • Testing whether values are identical is O(1) except for arbitrary precision integers.
