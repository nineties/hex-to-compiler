Data types

M-expressions and atoms, the types of atoms, equality and identity. == tests whether values are equal, and is whether they are the same thing (identical). Identical values are always equal, and for an interned type equal values are identical.

M-expressions and atoms

A value is an M-expression or an atom. An atom is a value that is not an M-expression: an integer, a float, a complex number, a string, a symbol, a function, an array, a plain array, a type value or user data.

  • The head of an M-expression is a symbol. Two libraries can use the same head. A head is not registered, so values with the same head are treated as values of the same form. A pattern such as Set{...} reads the head.
  • Every value has a type, which is itself a value (a type value). type(x) returns it: Expr for an M-expression, Symbol for a symbol, Int for 1, and Type for Int itself. Expr is also a builtin type value, and type(Expr) is Type.
  • head(x) is for M-expressions only. It returns the head symbol, and is an error if x is an atom.
  • Int, String, Expr and the other names of the builtin types are variables that hold type values. x @ T reads the variable T and compares it with type(x), so x @ Expr matches every M-expression and x @ Int matches an integer.

The M-expression Set{1} and a type whose name is Set are different things, so a name never collides with the head of an M-expression.

M-expressions

  • Has a head symbol and any number of arguments. The type is Expr.
  • Immutable. The literal is Head{a, b}. The sugar is (a, b) (Tuple), [a, b] and :: (Cons), and [] (Nil).
  • The following cannot be an argument. Making an M-expression with one of them is a runtime error.
    • A mutable value
    • Immutable user data that holds a mutable value
    • A NaN
  • Interned. == and is are the same test, and O(1). f{1} and f{1.0} are not equal.
  • Can be a table key. a[i] can be read.

Notes on each type

integer

  • Arbitrary precision. No limit on the range.
  • Arbitrary precision integers are also identical if the values are the same.

float

  • IEEE 754 binary64.
  • NaN is not equal to anything, itself included, and not identical to anything either. If x is NaN, x == x and x is x are both false.
  • NaN cannot be a table key. Using a NaN as a key is an error.
  • A different object with the same value is not identical.
  • The hash of a float equal to an integer is the same as the integer. Otherwise it is decided by the contents.

complex number

  • Equal to an integer or a float with the same value.

string

  • A sequence of bytes, 0 bytes included. Up to 65535 bytes.
  • Strings with the same bytes over the whole length, 0 bytes included, are identical. == and is are the same test.
  • a[i] can be read (a string of length 1).

symbol

  • Unique for each name. == and is are the same test. The name starts with a letter, _ or %. For true, false and none, see Lexical rules.

function

  • Lambda, Fusion, builtin function, continuation.
  • Equal only when identical.
  • The hash is decided for each object and does not change while the object lives.

array

  • Fixed length. All elements are none at first. Made by array(n).
  • A different array with the same contents is equal but not identical.
  • == first returns true if the two are identical. Otherwise it compares element by element. So if a holds a NaN, a == a is true. A different array b that holds the same NaN object is not equal to a, because the NaN elements are not equal: a == b is false.
  • a[i] = e works. An error when out of range.

plain array

  • All elements have one type. The element type is 'bool, 'i8 to 'u64, 'f16 to 'f64, 'c64 or 'c128.
  • A different plain array with the same contents is equal but not identical.
  • == first returns true if the two are identical. Otherwise it compares element by element, as for an array.
  • a[i] = e works. An error when out of range or when the value cannot be converted.

type value

  • The type of every value. Held by variables such as Int and String.
  • Shown by the name of the type. Different types with the same name are shown the same and are told apart by is.

user data

  • Made by a builtin function. You must specify whether it is immutable or mutable when you make it. There is no default.
  • Each type of user data is a unique value made each time a type is made. Its name is only used for display. A type with the same name made elsewhere is a different type.
  • You may give a function for == and a function for hash when you make the type; if you give one, give both. A type with == given is not interned, and is compares objects. == and hash use the given functions.
  • The author of the type must make the given functions keep two rules: if a is b then a == b, and equal values have the same hash.
  • For a type without them, == is identity. The hash of immutable user data is decided by the contents, and the hash of mutable user data by the object.

Equality

Equality is tested by a == b (_eq). a != b (_ne) is its opposite.

Equality across number types

Integers, floats and complex numbers are equal if the values are the same, even when the types differ. 1 == 1.0 and 1 == complex(1, 0) are true, and the hash is the same.

Where equality is used

  • A pattern that writes the same name twice (f(a, a)) matches only when the two values are equal by ==. User data uses the given ==.
  • The builtin table (table_get, table_set and t[key]) treats two keys as the same if they are identical or equal. User data uses the given == and hash. An array, a plain array or a NaN as the key is an error. A type value can be a key.
  • hash(x) is an integer of 0 or more. Values that are equal by == give the same value. For user data with == given, it is the value of the given hash. The exact values of hash are not defined.

Identity and is

a is b is true if a and b are identical, and false otherwise. Its negation is written a is not b. It has the same precedence as ==, at the level of the comparison operators. Like the comparisons it does not group, so a is b is c is an error. is cannot be written in a pattern.

  • Identical values are always equal: if a is b, then a == b. A NaN is not identical even to itself.
  • M-expressions, integers, strings, symbols and immutable user data without == given are interned. Floats, functions, arrays, plain arrays, mutable user data and user data with == given are objects.
  • Interning means that equal values are made into one object. For an interned type, equal values are identical. User data with == given is not interned, so equal values are not always identical. So == is the same test as is, and O(1).
  • Values of different types are not identical. 1 == 1.0 is true, but 1 is 1.0 is false.
  • The test for identical is O(1), except for arbitrary precision integers.
