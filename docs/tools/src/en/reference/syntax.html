Grammar

The standard syntax is sugar. It is expanded into the M-expressions of the core language in the table below and then evaluated.

Lexical rules

  • An identifier is [A-Za-z_][A-Za-z0-9_]*[?!]?, except the literals true false none and the reserved words if else while and or handle with perform match record for in return break continue fun macro module export import is.
  • An integer is decimal, 0x1f, 0o17 or 0b101; a float is 1.5e-3; a complex literal is 2i.
  • A string is "..." on one line, with the escapes \0 \a \b \t \n \v \f \r \" \' \\. f"...{e}..." embeds the value of e, and {{ and }} are one brace each.
  • A comment runs from # to the end of the line. A top-level string is also a comment.
  • No space goes before the (, [ or { of f(a), a[i] and Head{a}.
  • Expressions in a block are separated by ; or a newline. A binary - is on the same line as its left operand, so a line that starts with -1 is a new expression. Other binary operators can start a line.

Associativity

  • Right: |, ->, ::. Left: + - * / %. Comparisons and is do not chain: a < b < c is a syntax error. is has the precedence of == and cannot be written in a pattern.
  • :: binds tighter than comparisons and looser than + -. .. binds looser than + - and does not chain.
  • The condition cond of if and while is in parentheses, and a branch and a body are expressions without |. Write several expressions as a block { ... }. else belongs to the nearest if that has no else.

Rules by syntax

Patterns in parameters

A parameter p and the pattern of for are written as expressions up to the level of or, turned into a pattern of the core language, and matched. They are written like expressions, with identifiers as variables. The exceptions are:

  • The names of operators and called functions are symbols. x + 1 matches the tree Apply{Quote{_add}, Tuple{x, 1}} and f(p, ...) matches Apply{Quote{f}, Tuple{p, ...}}. To make the called function a variable, write (f)(p, ...).
  • 'e is Quote{e}, p @ type is _TypeOf{p, type}, and x... is the rest of the last parameter, _Rest{x}.
  • Writing the same name twice, as in f(a, a), matches only when the two values are equal.
  • p or q matches either. Variables are allowed only when every branch binds the same variables (f((x, 0) or (0, x)) := x). To match the M-expression If{a, true, b} of an expression or, write If{a, 'true, b}.
  • Allowed forms: operators (or and not == != <= >= < > :: + - * / %, unary - and '), f(p, ...), Head{p, ...}, identifiers, true false none, integers, strings, tuples and lists.
  • Writing x... in a guarded function stops the program with a message before the code runs.
  • When the value of f is a guarded function, a function added by f(p, ...) = body is not called even if the guard is false, just as a following | g is not called for a guarded function passed through a variable.

Definitions in a row

  • Definitions f(0) := ... written one after another in the same place form one function, tried in the order written.
  • f(p, ...) if cond := body returns body only when the arguments match and cond is true. Otherwise the next definition written right after it is tried (a different expression in between breaks the chain).
  • A definition with export and f(p, ...) = body cannot have a guard.

Compound assignment and splitting a tuple

x += e is the same as x = x + e, and -=, *=, /= and %= have the same form. a[i] += e evaluates a and i once. The left side is a variable or a[i]; t.f += e is not allowed.

Splitting a tuple

(a, b) := e defines variables from the elements of the tuple e, and (a, b) = e assigns to defined variables. The right side is evaluated completely first, so (a, b) = (b, a) swaps.

A tuple whose number of elements differs from the number of names, and a value that is not a tuple, are errors.

record and with

The . follows its left operand with no space. The fields of with are replaced from the left, and a right-hand side can refer to the fields of the original t. with { ... } can follow another one.

for, and return, break and continue

return e ends the call of the enclosing function with the value e (none without e), break ends the innermost while or for, and continue goes to its next round.

  • e starts on the same line as return.
  • A return in the body of a for or in an arm of a match ends the function around them. A return in a function written inside ends that function.
  • A continue outside a loop stops with unhandled effect: Continue{}.

match

match e { f } evaluates e once and calls the function f with the value. f is usually one-argument functions joined by |, and each is an arm. The first arm with a pattern that matches e is chosen; if none matches, MatchingFailed is performed. A | can start a line.

  • An arm has one argument. To take a tuple, write ((a, b)) -> x.
  • The guard cond of (p, ...) if cond -> body | g is evaluated after the arguments match, with their variables. When it is false, or the arguments do not match, g is called with the same arguments. g is the expression joined after the function by | in the source, even inside parentheses.
  • The guard and body are expressions up to the level of or, so put an anonymous function in parentheses.

module

module m { body } puts the definitions of the body under the name m. The value the body returns is the module value, and the definitions marked export are its fields. Reading a name that is not a field with . is an error.

  • The scope of the body is that of the body of a function with no parameters. To call something defined later from earlier code, use fun f and f(p, ...) = body (Mutual recursion).
  • The definitions of the body are variables of the body, not global variables. They cannot be assigned from outside and do not hide a same name outside. To let outside code add cases, export the function to add to (m.f(p, ...) = body is not allowed).
  • m is defined after the body is evaluated, so the body cannot see m.
  • Replacing parse inside the body does not affect the rest of the body. Replace a grammar outside the module.

export

  • export can be written only before f(p, ...) := body, x := e and module n { ... } directly in the body of a module. Anywhere else is a syntax error.
  • The field of export x := e is the value of x when the body returns, and later assignments do not change it. To show the current value, export a function that reads x (start and current above).
  • An inner module n { ... } defines the variable n of the body and is invisible from outside. To show it, write export module n { ... }. The inner body sees the variables the outer body defined earlier.

test

test { ... } can be written directly in the body of a module. Normally nothing runs. Running tools/test.pk <library> ... runs it, together with the test of the libraries they use.

  • The scope is that of the body of the module, so functions without export can be called.
  • A test runs while the body is being evaluated, so it sees the variables defined before it, and m is not defined yet.
  • assert(c, msg) writes msg and stops with status 1 unless c is true.
  • A block holds at most 64 expressions.

import

import a::b loads the same way as use("a/b"), and the same file is loaded once. The last name is the name of the module the file defines. How to take names follows the path. M is Apply{_import_module, Tuple{"a/b", Quote{b}}}.

import m only loads, and fields are read as m.f. as n adds n := m. (x, y) defines the named fields, (*) every field, and hiding (x, y) every field except x and y, as variables of the same names.

  • as n can come before (x, y), (*) and hiding (...). as, (...) and hiding are on the same line as m.
  • Naming a field that m lacks in (x, y) is the same error as reading it with ..
  • In a function, (*) and hiding define global variables, and (x, y) and as define local variables.

Indexing and rewriting

a[i] calls _index_get(a, i) and a[i] = e calls _index_set(a, i, e), whose value is e. The [ follows a with no space.

The function of each kind is tried in this order.

subst

t[f] is subst(t, f). It visits the tree t from the root and replaces each part that a pattern of f matches with the value of f, without visiting inside the replaced part. For a part that no pattern matches, it visits the arguments in order. The arms of f take guards (t[p if c -> a | q -> b]). The body of an arm is an expression up to the level of ->, so put a | inside it in parentheses. To rewrite a quoted tree, write ('e)[f].

Names the sugar calls

The functions the sugar is read into have names that start with _. Defining add in a program does not change a + b. To pass an operator as a function, use an anonymous function (sort((a, b) -> a < b, xs)).

Extending the grammar

::= defines the rules of a grammar. The syntax of planck is made of the same rules, so adding a rule extends the syntax of the following expressions.

::=

This example adds the syntax of unless.

  • name ::= alternative | ... defines the rule name, and replaces it if it already exists. The alternative ... stands for the previous definition of the rule.
  • An alternative is a sequence of items followed by an optional action { ... }. The items and the action are on the same line as ::= or |.
  • Alternatives are tried in order, and the result of a rule is memoized for each position (packrat).
  • The value of an alternative is the value of its action, the value of the item when there is one item, or Tuple{v, ...} of the items.

Texts, words, . and [set] skip blanks and comments first. A rule may be directly left recursive, which groups to the left.

Character classes

  • A letter, a digit or _ followed by - and a character is a range (a-z). Any other - is itself.
  • \n, \t, \a, \b, \f, \r, \v and \0 are control characters. Any other \x is the character x.
  • An empty set, a reversed range ([9-0]) and a range without its end ([a-]) are syntax errors.
  • At the end of the input none of ., [set] and [^set] matches.

Parsing with a rule

peg_parse

peg_parse(rule, s) parses a prefix of s by the rule and returns Tuple{value, rest}, Tuple{Eof{}, ""} when only blanks are left, or Tuple{SyntaxError{...}, ""}.

name{| text |}

When the expression is parsed, text is read by the rule name. The value is the value of the rule, as a constant.

  • There is no space between name and {|.
  • Define the rule in an expression that is evaluated before the expression with text is parsed.
  • The rule decides where text ends, and |} must follow, after blanks.
  • A failure of the rule or a missing |} is a syntax error, at the farthest position the rule reached in text.

peg_sources and peg_version

peg_sources is a table from a rule name to the parsing expression given to _define_rule. The actions are not evaluated (... is replaced by the previous definition). peg_version increases at every _define_rule.

macro

macro p := e adds a rule that rewrites trees before evaluation. p is written like a parameter pattern and describes the shape of a tree, and e is evaluated with the variables of p to give the new tree.

  • Before an expression is evaluated (also a tree given to eval), each part is rewritten from the root. Rules are tried from the last added, and a part that matches none stays.
  • A rewritten part gets the rules again until it no longer changes, and then its inside is rewritten. Applying more than 1000 rules to one expression stops with an error.
  • The inside of a quote 'e is not rewritten. In a quasi-quote `e only the inside of !e is.
  • The parameter patterns of functions and the names defined by Def, Set and Declare are not rewritten.
  • A rule is in effect from the position of the macro to the end of the innermost function or module body around it, or to all the following expressions if nothing surrounds it.
  • An export macro in a module is in effect also outside it, after the definition of that module.

Top level

The loop looks up the global variables parse and eval for every expression, so replacing them takes effect from the next expression. Apply{eval, ...} also calls the replaced eval.

  • parse: String -> Tuple{M-expression, rest String}. It returns Tuple{Eof{}, ""} when only blanks are left, and a replacement parse passes Eof{} through.
  • eval: M-expression -> value.
