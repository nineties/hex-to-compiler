vasmc

planck/vasmc.pk compiles vasm and native source files to executable files for Linux. It checks the program, lowers it, selects instructions for a machine, and writes the executable file. A program joined from units behaves as the program made from all the sources at once.

Source files and targets

A file whose name ends in .native is written in native and is expanded to vasm first. Any other file is written in vasm. An error is written as file:line:column: message, with the position in the source file, and stops the compilation.

A target is a machine. x86_64 is the only target, and the default when none is given. Every step before the choice of instructions is the same for all targets, except for the width of a word. The parts specific to a machine come after the choice of instructions. The operating-system part of the target makes system calls, so a program does not name them.

One file to one executable file

The source must have the function main, which takes no arguments. Its result is the exit status of the program.

Units

A program can be split in several source files and compiled one by one. The result of compiling a file apart is a unit file. It holds the lowered functions of the file and its interface: the structs and the functions of the file, with the bodies left out. It holds no machine code, so the instructions are chosen when units are joined, once for the whole program.

  • unit compiles one source file to the unit file output. Each import is a unit file. The functions and the structs of the imports can be used in the source as if they were declared in it; they are checked against the interfaces. A source file used for a unit need not have main.
  • A unit is named by the file name of its source without the directory and the extension: lib.native is the unit lib.
  • link joins the unit files in the order given into the executable file output. Exactly one of them has the function main, which takes no arguments.
  • A unit file is made for the width of a word of its target, and is joined only for a target of the same width. Two units cannot define the same function or struct.
  • The imports of an import are not imported: a unit uses only the items of the unit files named in its own command.

Units in native

A native source names the units it uses with import at the start of the file. Only the functions and the structs of the units named so are visible, even if other unit files are given on the command line; a name of another unit is an undefined name. The names are not qualified: after import lib, twice(3) calls the function twice of lib. It is an error to import a unit whose unit file is not given on the command line. A vasm source has no import, and it sees every unit file given.

native_compile.compile_with(m, imports) and native_compile.compile_all_with(m, imports) take them as a list of items; compile_all_with gives the errors with the module, as native_compile.compile_all does. imports is the interface of a unit (vasm_unit.iface of a vasm module). The expanded module does not hold them.
