vasmc

planck/vasmc.pk compiles vasm and native source files to executable files for Linux. A program joined from units behaves as the program made from all the sources at once. A command is written as the arguments to planck/vasmc.pk, a planck program, and Implementation shows how to run it.

Source files and targets

A file whose name ends in .native is written in native and is expanded to vasm first. Any other file is written in vasm. An error is written as file:line:column: message, with the position in the source file, and stops the compilation.

A target is a machine. x86_64 is the only one, and the default. The parts specific to a machine come after the choice of instructions. The operating-system part of the target makes system calls, so a program does not name them.

One file to one executable file

The source must have the function main, which takes no arguments. Its result is the exit status of the program.

Units

The result of compiling a source apart is a unit file. It holds the lowered functions and the interface (the structs and the functions, with the bodies left out), and no machine code. The instructions are chosen when units are joined, once for the whole program.

  • unit compiles one source to the unit file output. Each import is a unit file, and its functions and structs can be used as if they were declared in the source; they are checked against the interfaces. A source used for a unit need not have main.
  • A unit is named by the file name of its source without the directory and the extension (lib.native is lib).
  • link joins the unit files in the order given into the executable file output. Exactly one unit has main.
  • A unit file is joined only for a target with the same width of a word. Two units cannot define the same function or struct.
  • The imports of an import are not imported: a unit uses only the items of the unit files named in its own command.

Units in native

A native source names the units it uses with import at the start of the file. Only the functions and structs of the units named so are visible, and the names are not qualified (after import lib, twice(3) calls the twice of lib). It is an error to import a unit whose unit file is not given on the command line. A vasm source has no import, and sees every unit file given.

native_compile.compile_with(m, imports) and native_compile.compile_all_with(m, imports) take the interfaces of the units (vasm_unit.iface of a vasm module) as a list of items. compile_all_with gives the errors with the module. The expanded module does not hold the imports.
