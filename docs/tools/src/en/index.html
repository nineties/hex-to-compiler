hex-to-compiler

hex-to-compiler bootstraps a language implementation from hand-written hexadecimal machine code. Each stage uses only the artifacts of the earlier stages. It uses no external assembler, compiler, runtime or code generator.

The build needs only make and xxd. The current work is Stage 3: planck0, an implementation of the language planck.

Bootstrap stages

Three stages build the implementation and its tools in order. The text beside an arrow is the command that the Makefile runs. The color of an artifact is the language it is written in.

ArtifactSourceLanguageRole
pforthpforth.xxdMachine codeA Forth interpreter with one-letter words only. It grows by self-extension.
plispplisp.fs, plisp/init.lispForth, LispExtends pforth to a usable Forth, then builds on it a Lisp that handles syntax trees directly.
asmasm.lisp, asm/core.lispplispAn assembler. The current implementation writes x86 Linux ELF files directly and puts the header, code and data in one PT_LOAD (RWX).
sasmsasm.lisp, sasm/core.lisp, sasm/lib/std.svplispAn untyped C-like language. It is an internal DSL of plisp and emits stack-machine code without register allocation.
plisp2plisp2.svsasmA Lisp for the next stage, where the speed of plisp is not enough. It runs sasm to build planck0.
planck0planck0.svsasmA minimal subset of planck, a temporary implementation for the bootstrap. It has an M-expression reader, a bytecode compiler, a virtual machine and algebraic effects.
planckplanck/init.pk, peg.pk, syntax.pk, lib/M-expressions, planckA language whose syntax is a set of grammar rules that a program can extend.

asm and sasm are tools for crossing to the next stage. They favor a simple implementation over performance and safety. From machine code to planck0 describes each stage.

Build and test

$ git clone @REPO@.git
$ cd hex-to-compiler
$ make                  # pforth, plisp2, planck0
$ make test             # plisp tests: plisp/test.lisp
$ make test-planck0     # planck tests and examples
$ ./planck0 prog.pk

planck0 reads planck/init.pk by a relative path at startup, so run it at the top of the repository.

TargetAction
makeBuilds pforth, plisp2 and planck0, in this order.
make exampleBuilds asm/examples/*.s and sasm/examples/*.sv into executables.
make test./pforth < plisp.fs plisp/test.lisp
make test-planck0Runs planck/test.pk, test_syntax.pk, test_lib.pk and test_unparse.pk, and compares the output of planck/examples/*.pk with *.out.

On every push to main, CI (runtests.yaml) builds pforth, runs the plisp tests, builds plisp2, runs ./plisp2 plisp/test.lisp, builds planck0 and runs make test-planck0, in this order.

Status

  • planck0, the first implementation of Stage 3, is a subset of planck and a temporary implementation for the bootstrap ([[planck0.sv#4-5]]).
  • The language specification is planck/SPEC.rst. planck/lib has libraries for writing language implementations: lists, vectors, strings, tables, gensym, errors with locations, pretty printing, and an unparse made from the grammar.
  • planck/examples has 13 examples. They include the calculator calc.pk with a lexer, a parser, three-address code generation and a virtual machine, symbolic differentiation, N-queens with nondeterministic effects, and syntax tree rewriting.
  • The heap of planck0 is a fixed 1 GB region allocated at startup. There is no GC ([[planck0.sv#39-67]]).
