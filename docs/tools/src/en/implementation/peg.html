The packrat parser

planck/peg.pk (322 lines of M-expressions) is a parser that interprets a PEG. The grammar is M-expression data. The parser memoizes the result of each rule at each position.

The grammar as data

The forms of parsing expressions, the right-hand sides of rules, are at the top of the file.

One or more repetitions of "7" are Many1{"7"}. To take their count as the value, write Act{Many1{"7"}, t -> arity(t)}. Giving it a name with _define_rule makes it a rule.

A rule defined without ::= is also usable in sevens{| ... |}. ::= itself is translated to a call of _define_rule (Defining the syntax).

Interpretation

peg_px(e, p) tries the parsing expression e at the position p. On success it returns the next position and puts the value in peg_pv. A failure is -1. peg_px, peg_call_rule and peg_run_rule call each other, so their names are declared first with Def{name, none} and defined later with Set ([[planck/peg.pk#114-116]]).

A string is matched after skipping whitespace. A symbol is called as a rule. A function is called as it is. For M-expressions such as Seq and Choice, the table peg_handlers gives the handler for each head ([[planck/peg.pk#175-210]]). Tokens such as identifiers and integers are implemented as functions on the side of Defining the syntax.

At every failure, the parser records the farthest position reached in peg_far ([[planck/peg.pk#57-59]]) and reports a syntax error at that position.

Memoization and direct left recursion

The parser memoizes the result of a rule for each (position, rule) pair (packrat parsing). Backtracking does not recompute the same rule at the same position.

The memo is an array for each position. For each rule it has three fields: the end position, the value and a left-recursion mark. peg_call_rule first looks up the memo ([[planck/peg.pk#234-250]]).

The memo also handles direct left recursion (sum ::= sum "+" term | term). While a rule runs, its memo entry is marked as running, and a recursive call at the same position fails. The parser stores the result obtained with this failure as a seed in the memo and runs the rule again. It repeats this as long as the rule reads more than before (seed growing).

As a result, 1 - 2 - 3 is (1 - 2) - 3.

Defining a rule

_define_rule numbers the rule, evaluates f of the action Act{e, f}, and enters the rule in the table. Prev{} in an alternative is replaced by the previous definition of the rule. The ... of ::= is this Prev{}.

The form before evaluation is kept in peg_sources. Tools that read the grammar, such as unparse, use this table.

Entry point

peg_parse(rule, s) rebuilds the memo, calls the rule and returns Tuple{value, rest} ([[planck/peg.pk#306-322]]). On failure it returns SyntaxError{...} with the text from the position of peg_far to the end of the line.
