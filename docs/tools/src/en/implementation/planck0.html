planck0

planck0.sv is an implementation that reads only M-expressions, in one sasm file. It compiles each expression to bytecode as it reads it and runs it on a virtual machine with its own frame stack. Variables are resolved before the run, and a continuation is a copy of a chain of frames.

Top level

main reads planck/init.pk and the program file with interpret_file. For each expression, call_global looks up the global variables parse and eval again, so when a program replaces them the next expression is read with the new definitions.

Values and memory

A value is one 32-bit word. If the lowest bit is 1 it is an integer, and if 0 it is a pointer to an object on the heap. An object has a header that holds its kind and length.

Symbols and M-expressions are interned, so equality is a comparison of pointers. The heap is a fixed area allocated at start. The GC is a conservative mark-sweep that does not move objects, and an object is kept when any word points into it ([[bootstrap/planck0.sv ; === Garbage Collection .. fun main]]).

The M-expression reader

The builtin parse reads four kinds: a symbol, an integer, a string and Head{...}. It stays as parse_mexpr after the syntax is introduced.

The compiler

compile_mexpr branches on the head of the M-expression ([[bootstrap/planck0.sv fun compile_mexpr]]). A head other than the special forms is a constructor that evaluates its arguments and makes an M-expression with the same head.

Resolving variables

A local variable resolves to (depth of the environment, position), and a global variable to a cell. A top-level Def makes a new cell, and the instructions GLOAD, GDEF and GSET embed the cell ([[bootstrap/planck0.sv fun define_global]]). So a function compiled before keeps pointing to the old cell, and only Set writes the current cell.

Def and Declare

Def compiles the right-hand side before it makes the cell, so the right-hand side sees the previous variable. A function can refer to itself because the syntax reads a function definition as Declare{f}, which makes the cell first, and then Set, which puts the function in it.

Declare{f} becomes Def{f, none} only when f is not yet a variable of that place. At top level this checks whether the file that defined the cell is the file being loaded, cur_file. In a function it checks whether an item of that depth exists ([[bootstrap/planck0.sv fun defined_here]]).

The virtual machine

The virtual machine never calls itself recursively. The state of a computation is only the chain of frames, so a continuation is a copy of it.

Calls and pattern matching

select chooses the function that fits the arguments. A Fusion tries the left function and then the right, and the program stops with matching failed when none fits.

The names of builtins start with _, as in _add, _eq and _strcat ([[bootstrap/planck0.sv fun init_prims]]). add without the _ is not registered, so a program that defines a variable of that name does not change the meaning of an operator.

Effects

Handle runs its body in a new frame and records the handler in that frame. Perform follows the chain to the callers to find a frame with a handler, makes a continuation k (a copy on the heap of the chain up to there) and matches the handler with (v, k). When nothing matches, it looks further outside.

Calling k copies the chain onto the frame stack and runs it (resume). The original frames never run, so the same k can be called any number of times.
