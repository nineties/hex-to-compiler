From machine code to planck0

This page follows the path from a one-page hex dump of Forth to planck0, which is written in sasm.

pforth

pforth.xxd is a hex dump. xxd -r -c 8 ignores the annotations on the right. The restored bytes are an executable ELF file. The current implementation produces a 32-bit x86 Linux ELF.

The initial dictionary has only builtin words with one-letter names. k reads a character, t writes a character, f looks up a word from a character, x executes a word, and so on.

plisp

plisp.fs is the input to pforth. It begins with a sequence of one-letter words that registers whitespace and newlines as words that do nothing and \ as the word for a line comment ([[plisp.fs h@l@h@!h@C+h!k1k0-h@$k:k0 .. \ plancklisp -]]). The rest builds Forth by self-extension.

  • The second interpreter. It looks up words by name and has a compile state ([[plisp.fs \ The 2nd Phase Interpreter .. \ '\'' ( "name"]]).
  • The usual Forth words: conditionals, loops, recursion, structures ([[plisp.fs \ === Compilers === .. ( === 3rd Phase Interpreter === )]]).
  • The third interpreter. It reads a word that is not in the dictionary as a number, and stops with an error if it is not a number ([[plisp.fs ( === 3rd Phase Interpreter === ) .. ( === Do-loop === )]]).

A Lisp interpreter is written in that Forth ([[plisp.fs ( === Implementation of PlanckLISP === )]] onward). It is written in the order of lists, nodes, the reader and printer, and the evaluator. At the end it reads plisp/init.lisp ([[plisp.fs s" plisp/init.lisp" eval-file]]). The next stage is an assembler and a compiler, so the choice is a Lisp: it handles syntax trees directly and makes internal DSLs easy.

asm and sasm

Both run on plisp. They are tools for crossing to the next stage. They favor a simple implementation over performance and safety.

asm/core.lisp is an assembler for 32-bit x86. It writes an ELF file directly from a list of S-expression instructions, and puts the header, code and data in one readable, writable and executable PT_LOAD.

sasm/core.lisp is the compiler of the structured assembly language sasm. sasm is an untyped C-like language with variables, functions, if and while, and is implemented as an internal DSL of plisp. It does not allocate registers. It emits code that repeats pushes and pops on the stack, and asm turns the code into machine code.

plisp2

plisp on Forth is too slow for the later stages. plisp2.sv is the same Lisp rewritten in sasm. It has, in order, memory allocation ([[plisp2.sv ; === Memory Allocation .. ; === Utilities]]), nodes ([[plisp2.sv ; === Nodes .. ; === Parser and Printer]]), the reader and printer ([[plisp2.sv ; === Parser and Printer .. ; === Eval]]), the evaluator ([[plisp2.sv ; === Eval .. ; === Primitive Functions]]) and builtin functions ([[plisp2.sv ; === Primitive Functions ..]]).

plisp2 is compiled by sasm on plisp. The same sasm then compiles planck0.sv on the resulting plisp2.

planck0
