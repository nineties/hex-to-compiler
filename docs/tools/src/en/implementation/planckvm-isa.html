planckvm instructions

An instruction is one word, and only high-frequency operations are instructions. Everything else is a builtin function. The code generator keeps the code correct, and the evaluator does not check it. This page defines the bytecode format, the instructions, the builtins and the instructions for each feature of planck. The machine and the values are in planckvm: execution model and values, and the design inside an implementation is in planckvm internals.

Bytecode format

The basic unit is a 32-bit word, and bits are numbered from 0 at the least significant bit. One lambda or one top-level expression is one code. The code of a nested function lies in the constant table of the outer code.

nregs is the number of registers of the window, and every register number in the code is smaller than it. ninstrs and nconsts are the numbers of words of the instructions and of the constant table. params is the index of the tree of the parameter patterns in the constant table. It is used to print a function and in the message of a matching failure (0xFFFFFFFF for a top-level expression).

Instruction formats

An instruction is one word (two with a preceding EXT), and the low 8 bits are the opcode.

  • A, B, C and D are unsigned, and sB, sC and sD are the same fields in two's complement. R[A] means that A is a register number, and K[D] that D is an index of the constant table. k is 0 or 1 in the field C.
  • sJ is the difference in words from the pc after reading the instruction (the next word), and X is the unsigned 24 bits of EXT.

Extending operands

EXT widens the operands of the one instruction after it. X is split as below, and the parts are the high bits of the fields of that instruction.

  • A, B and C become 16 bits and D becomes 32 bits, and the signed fields grow in the same way. k is not widened.
  • Use it when a register number is over 255 or an index of the constant table is over the field. It cannot precede a J instruction or another EXT. A jump to a widened instruction goes to the EXT word.

Constant table and a correct code

An element of the constant table is one value word. LOADK takes literals, the content of a Quote and an M-expression of constants, MATCHHEAD and MATCHTYPE take symbols, GETGLOBAL and SETGLOBAL take cells, and CLOSURE takes a nested code. The code generator keeps the following.

  • A jump goes to the start of an instruction, and the last instruction is one of RET, TCALL, JMP, HALT and NEXT.
  • The word after a test instruction is JMP, and the word after an instruction that starts with MATCH is NEXT or JMP.
  • Local variables are in registers with smaller numbers than the temporaries. At a CALL or HANDLE, every live value is below R[B] (HANDLE also keeps R[B] and R[B+1]).
  • NEWENV runs once in a code, after all the pattern matches have succeeded. R[0] to R[arity-1] are not written until then.

Instructions

A field that the Format column does not list after its operands is 0. The marks are S, a safe point (the collector may run on an allocation), W, a write barrier, and T, the instruction stops when its conditions are not met. For an instruction with a name in the Builtin column, S and T apply while the cell is overwritten.

The test instructions (TEST to TGEI) make no value. When the condition equals k (true for k = 1, false for k = 0), the JMP in the next word runs. Otherwise it is skipped. With NaN, TLT and TGE are both false.

Arithmetic and comparison instructions stop on an argument that is not a number. An instruction with the mark T also stops on a wrong type or an out-of-range value (except the range of ORD).

Builtins and instructions

An operation that depends on the type is one instruction that looks at the type. When the f of Apply{f, Tuple{...}} resolves to the cell of a name in the Builtin column and the number of arguments fits, the compiler uses the instruction, whether or not the cell is overwritten.

The other builtins are machine builtins. The code reads the function into R[B] with GETGLOBAL, puts the arguments above it and calls it with CALL. Their allocation and errors are included in the S and T of that CALL.

  • eval(e): compile the M-expression e in the current global environment and run it. A compile error stops like a runtime error. The inner frames are ordinary frames, so they can be copied when a PERFORM happens inside eval.
  • _set_file(path): make path the file being loaded and return the previous value. It is used to decide where a global variable is defined.
  • Bit operations treat negative numbers as infinite two's complement.

Language features and instructions

The code generated for each row of the syntax. <e:d> is the instructions that put the value of e in R[d], and t is the lowest free temporary register.

  • A parameter whose pattern is a register variable is R[i]. The other register variables are assigned from R[arity] and are not reused after a block. Temporaries follow them like a stack.
  • For an operand <e:r>, when e is a register variable and the evaluation of the later operands does not write it, r is its register and no instruction is needed. Otherwise the value goes to t.
  • Features with no instruction of their own are a CALL of a planck function (_le, _gt, _index_get, _index_set, _record_get, peg_for, _strcat, _define_rule and so on).

Conditions

<c, L, k> is the instructions that jump to L when the truth of c equals k and go on otherwise.

  • a == b, a != b, a < b, a >= b: a test instruction (TEQ and so on) followed by JMP L. Use the immediate forms (TEQI, TLTI, TGEI) for an integer b from -128 to 127, and TEQK and TNEK for a constant b.
  • a and b is <a, L, 0> <b, L, 0> for k = 0, and <a, L1, 0> <b, L, 1> L1: for k = 1. or swaps 0 and 1.
  • Any other c is <c:r> TEST r k JMP L.

Patterns

The instructions of a pattern start with the value in R[r], and the word run on a failed match is NEXT. A variable that lives in an environment is kept in a register during the match, and ENVSET moves it after the NEWENV that follows a successful match.

  • _ needs none. A variable needs none as a parameter, and as an argument of an M-expression the destination of FIELD is its register.
  • An integer, a string, true, false, none and Quote{v} are MATCHEQ r k NEXT.
  • Head{p1, ..., pn} is MATCHHEAD r k n NEXT, then FIELD s r j and the instructions of p_j for each p_j that is not _. _TypeOf{p, type} is MATCHTYPE r k NEXT and then the instructions of p.
