planckvm instructions

The instructions of planckvm, how each feature of planck is translated into them, and which builtin functions are instructions. The machine and the values are in planckvm: execution model and values. planckvm is a design that is yet to be implemented.

Notation: the stack is written with the bottom at the left, and a b -> r pops two values and pushes one. Operands: k an index of the constant table, c a cell (a k), d i a depth and an index of the environment, L an index of the instructions, n a count, p the number of a builtin instruction. Marks: S a safe point where an allocation may run the collector, W a write that is recorded, T the program stops unless the condition holds.

Matching at the entry

The entry of a function has one instruction sequence for each pattern. When a match fails, the program goes to L and empties the operand stack. At L there is a NEXT. When an argument is bound to a variable of the pattern, STORE 0 i and POP write it into the environment. There is no instruction that fuses PARAM, STORE and POP.

An argument that is not a number is T (except for EQ). The mixing of types and the result type are in Numbers of the execution model.

Floats and complex numbers

The four operations and the comparisons belong to the instructions of Numbers. The instructions here are the functions, the conversions and the parts of complex numbers. An instruction that takes a float also takes an integer and raises it to a float. A complex number is T. The builtin is the lower case of the instruction name.

Builtins and instructions

A builtin becomes an instruction when it cannot be written with the other instructions and planck expressions. That is the case for anything that touches the representation of values, the heap, the operating system, the machine operations on numbers, or control. A builtin that can be written in planck is a planck function, and no instruction is added for it. Whether to promote a hot function to an instruction is decided separately, after measuring. An operation that differs by type is one instruction that looks at the type of its value.

Builtins that are not instructions

They are planck functions that use the instructions, and are part of the image of the evaluator. The names of the global variables and the behavior are the same as those of the builtins.

The name of a function in an error message can differ from the builtin that was called. For example the message for a non-integer argument of _mod names _div.

Names defined by planck code

The names in the table of builtin functions of the specification that are not builtins of the machine are defined by planck code and need no instruction: _define_rule _index_get _index_set _not _record_declare _record_get _to_text false load none parse_mexpr peg_for peg_parse subst table table_get table_set true use used_libs.

The new builtins that planckvm adds to the specification are plain_array, the float functions fsqrt ffloor ftoi ftobits bitstof ftos stof fexp flog fsin fcos fpow fatan2, the complex functions complex real imag, the array makers of each plain type, itof and conj.

Where the rules depend on the place

An instruction does not change its meaning with the place. The difference is in the instruction that the compiler picks.
