planckvm: execution model and values

planckvm is the bytecode of a register machine that runs all of planck. Every variable is resolved at compile time to a cell, an environment or a register, and no name is looked up at run time. A call overlaps a window on the registers of the caller and does not copy the arguments. This page and planckvm instructions are the external specification, and the design of an implementation is in planckvm internals.

Execution model

Instructions read and write the registers R[0] to R[nregs-1] of the current frame. A code (instructions and a constant table) is immutable, and one lambda or one top-level expression is one code (Bytecode format). An environment is a place on the heap for variables, and a cell is one global variable.

Register windows

The registers of the frames lie on one register stack, and the range of a frame is its window. The window of a lambda called by CALL A B C starts at R[B+1] of the caller, so the arguments R[B+1] to R[B+C] are R[0] to R[C-1] of the callee.

  • During the call, R[B] keeps the called function. The values above R[B] are lost, so a value used after the call is kept below R[B].

Calls

CALL A B C calls f = R[B] with C arguments. A lambda runs in a new frame when its arity is C. A Fusion a | b tries a first and then b when a runs out. A builtin whose number of arguments fits makes no frame and the result is received at once. A continuation resumes when C is 1. Anything else stops with not a function.

  • The instructions at the entry of a code match the patterns. When they do not match, NEXT tries the next alternative with the same arguments, and when none is left it performs MatchingFailed{f, args, loc} (f is the function that was called, args is a Tuple of the arguments and loc is the position of the failed call, or none when the position table has no entry for it). A call that no alternative takes by the number of arguments does the same. With no handler the program stops with matching failed. The entry instructions do not write the registers of the arguments.
  • The value of RET in the callee is, for a test instruction (TEST to TGEI), true when it is not false. For ASET and PLAINSET it is discarded, and otherwise it goes to R[A].
  • An instruction with a name in the Builtin column of the instruction table does the action of the table when the name is not a local variable, even if a global variable of the same name is defined.

Continuations and handlers

HANDLE runs its body in a boundary frame, and the value of the body is the value of the Handle. PERFORM A B copies the frames and registers up to the innermost boundary into a continuation k, drops what is above the boundary and calls the handler of the boundary with (R[B], k). The result is the value of the Handle. When no alternative matches, the effect goes to the next boundary outside, and with none the program stops with unhandled effect: v (MatchingFailed stops with matching failed). The value of the handler is the value of the Handle, and the value of the failed call is the value given to k.

k is an ordinary function and can be called any number of times. Calling it copies the saved frames and registers again above the window of the caller and goes on with the handler of the boundary still installed (deep). The argument of k goes to R[A] of the PERFORM.

Resuming copies neither environments nor cells, so the copies share the variables in them. A variable in a register is copied by value, so an x := e that runs after the resumption defines a separate variable in each copy.

Runtime errors and the top level

A runtime error performs the effect Error{none, message} in the frame that made it. A handler of Error catches it, and its continuation gives a value to the register that the failed instruction writes. With no handler, the message is written to the standard error and the program ends with status 1. The errors of the instructions, of a call of something that is not a function, and of the builtins put, substr, _strcat, mexpr, intern, symname, exit and the system builtins are this effect. The other runtime errors write the message and end the program with status 1. One top-level expression is one code of arity 0, and the loop that reads the cells of parse and eval for each expression and calls them is in the entry of the evaluator. The entry code is the two words CALL R0 R0 n and HALT R0.

Values

The type of a value is one of Int, Float, Complex, String, Symbol, Expr, Array, Plain and Function, and each of them is a value of the type Type. The global variables with these names have them. An integer has arbitrary precision. A float and a complex number are immutable binary64 (a complex number has a real and an imaginary part). A string is an immutable sequence of bytes that may contain 0, a symbol is unique for its name, and an M-expression is immutable. An array is a mutable sequence of values, and a plain array a mutable sequence of elements of one type. A function is a lambda, a Fusion, a builtin or a continuation.

  • Only the symbol false is false. Every other value is true.
  • EQ compares numbers by value, strings by contents, and M-expressions and symbols by identity (M-expressions are interned, so M-expressions with the same head and arguments are one object). An array or a plain array is equal to itself, and otherwise compared element by element (a plain array is compared by the values read from it, so plain arrays of different types are equal when their elements are equal). Functions and user data are equal only to themselves. Values equal by EQ have the same HASH (planckvm data types).

Numbers

Integers have arbitrary precision, and nothing wraps around or is truncated. A float is binary64 rounded to nearest even. A complex number is made by complex(re, im). ADD, SUB, MUL and DIV are one instruction each that looks at the types, and mixed types are raised to the higher one in the order integer, float, complex. These are the exceptions.

  • An integer raised to a float is rounded to the nearest value. An integer beyond the range of floats is an error.
  • DIV of two integers is the quotient truncated toward 0, and a zero divisor is an error. A division that involves a float or a complex number does not stop on a zero divisor. It gives an infinity or NaN (per component for a complex number).
  • LT and GE compare an integer and a float by their mathematical values without raising the type. They give false with NaN, and a complex number is an error.
  • EQ takes values of different types as equal when their values are the same (1 == 1.0), and NaN is not equal to itself.

Plain arrays

The element types are 'bool; the signed integers 'i8, 'i16, 'i32 and 'i64; the unsigned integers 'u8 to 'u64; the floats 'f16, 'f32 and 'f64 (binary16, binary32 and binary64); and the complex numbers 'c64 and 'c128 (real and imaginary parts of binary32 and binary64). A read element is a value of the language, and 'f16 and 'f32 widen to binary64 without changing the value.

PLAINSET can write only a number that fits the type. A value that does not fit stops the program.

  • To an integer type, an integer in range is stored as it is. One out of range is an error and never wraps around. A float is truncated toward 0 and then checked against the range (255.9 becomes 255). NaN, an infinity and a complex number are errors.
  • To a float type, the value is rounded to the nearest. Above the largest value of 'f32 or 'f16 it becomes an infinity of the same sign. To a complex type, it is stored as the real part.
  • To 'bool, a non-zero number is true, and 0, 0.0 and -0.0 are false. true and false written to a numeric type are 1 and 0.
  • A value that is not a number (a string, none, an M-expression, an array or a function), and an integer beyond binary64 written to a float or complex type, are errors.
