Defining the syntax

planck/syntax.pk defines the syntax of planck as rules of the packrat parser and replaces parse at the end. The syntax is not built into the implementation. It is a part of a planck program.

Tokens

Tokens such as identifiers, integers and strings are written as functions, not as parsing expressions. A token function returns the next position when it reads a token.

The words of the table of reserved words peg_reserved and the f of f" are not identifiers ([[planck/syntax.pk#10-25]]). A function becomes a rule when it is passed to _define_rule as it is ([[planck/syntax.pk#123-126]]).

Expressions

The rules run from the loosest binding: expr, union, arrow, ternary, or_expr, and so on up to primary ([[planck/syntax.pk#900-1087]]). The rules for addition and subtraction are as follows.

add_expr is directly left recursive, so it associates to the left. The action peg_binop turns (left, operator, right) into Apply{_add, Tuple{a, b}} ([[planck/syntax.pk#130-132]]). The Same{} before the binary - succeeds only when the next token is on the same line, so a line that starts with -1 is a new expression.

An action returns the M-expression that the evaluator receives. 1 + 2 becomes Apply{_add, Tuple{1, 2}}, the same tree as one written directly in M-expressions.

The last alternative of primary, sugar_primary, holds match, return, break, continue and for ([[planck/syntax.pk#1215-1237]]).

fun f and f(p, ...) = e are alternatives of the rule expr too, and make Def{f, none} and Set{f, Fusion{f, Lambda{...}}} ([[planck/syntax.pk#914-918]]). f(p, ...) := e is read as Do{Declare{f}, Set{f, Fusion{f, Lambda{...}}}}, so it adds to f when f is already a variable of the place. The Lambda of the body is made by peg_lambda. A block is only wrapped in Do; the definitions in it are not moved to the top.

The action of a rule is compiled when the rule is defined. Since names are resolved at compile time, the functions peg_* that an action calls are defined before the rule. That is why the definitions of peg_* ([[planck/syntax.pk#145-899]]) come before the rules of the grammar ([[planck/syntax.pk#900-1087]]).

Indexing and rewriting

a[i] is an alternative of the rule postfix. The [ follows a with no space, and the parser does not read it when the assignment = follows the ] ([[planck/syntax.pk#1021-1030]]). An alternative of the rule expr turns a[i] = e into a call of _index_set ([[planck/syntax.pk#920-921]]).

The inside of [ ] is the rule index: one expression ([[planck/syntax.pk#1037-1039]]). When the function, as in t[p -> e | q if c -> g], has an arm with a guard, _peg_rewrite adds with peg_fuse a last arm that returns peg_skip, so that the function returns peg_skip when no arm applies ([[planck/syntax.pk#402-411]]).

_index_get and _index_set are functions that join one Lambda for each kind with Fusion ([[planck/syntax.pk#1347-1403]], [[planck/syntax.pk#1432-1484]]). A table is selected by the head Table{t} and a list by the heads Cons{x, xs} and Nil{}, so the patterns alone decide the kind. A function f as the index calls subst(t, f) ([[planck/syntax.pk#1268-1315]]). subst adds to f a last arm that returns peg_skip. A part for which f returns any other value is replaced, and its inside is not tried. For a part for which f returns peg_skip, subst calls itself on each argument.

When a user assigns _index_get = (K{...}, i) -> ... | _index_get, the new kind comes before the original function. The end of planck/lib/vector.pk is written this way.

Grammar declarations

The rule syntax_decl reads ::= and turns it into a tree that calls _define_rule.

g_alt rearranges the items and the action of an alternative into Act{Seq{...}, Lambda{Tuple{Tuple{label, ...}}, action}} ([[planck/syntax.pk#1179-1189]]). The labels become the argument pattern of the anonymous function of the action.

syntax_decl is the first alternative of expr, so ::= can be written wherever an expression can. A new rule takes effect from the next top-level expression.

Translating return and break

return, break and continue are translated to effects. The parser counts each return it reads. When it builds the tree of a function and the count has increased, it wraps the body in a Handle ([[planck/syntax.pk#273-296]]).

A return x in the body of a for becomes Perform{Return{x}}, and the whole body of the function is wrapped in Handle{..., (Return{v}, k) -> v}. for is a call of peg_for.

Text read by a rule

name{| text |} is read by the rule embed, which is written as a function ([[planck/syntax.pk#1496-1521]]). After name and {|, it calls the rule name at that position and then requires |}. The value of the rule enters the tree as Quote{v}.

Replacing parse

The last two lines switch the syntax.

The M-expression reader remains as parse_mexpr, and parse becomes a function that reads one expression by the rule toplevel. The replacement is a Set, not a Def. load in init.pk has already fixed the variable parse, so a Def would only add a new variable and the libraries that load reads would still be read by the old parse. planck0 looks up parse again for every expression (planck0), so the expressions after syntax.pk are read in the syntax of planck. toplevel reads one expr and checks for one of ;, a newline, or the start of the next expression ([[planck/syntax.pk#904-906]]).

primary has the alternative ident{expr, ...}, so M-expressions are also read as expressions as they are.
