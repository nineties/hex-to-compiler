Defining the syntax

planck/syntax.pk defines the syntax of planck as rules of the packrat parser. The syntax is not built into the implementation. It is a planck program. Every syntax is translated into a tree of M-expressions, and it takes effect when parse is replaced in the middle of the file.

  • Until parse is replaced, tokens, the functions called by actions and the grammar of the grammar are written in M-expressions.
  • After that, the syntax of planck is declared with ::=.

Tokens

Tokens such as identifiers, integers and strings are written as functions that return the next position when they match, and are passed to _define_rule as they are.

The action of a rule is compiled when the rule is defined, so the functions peg_* that actions call come before the rules of the grammar.

Grammar declarations

::= is read by the rule syntax_decl and becomes a tree that calls _define_rule. The rules g_choice, g_alt, g_item, g_suffix and g_primary that syntax_decl uses are the grammar of the grammar. They are first written in M-expressions, in the shape that a declaration produces.

The labels of an alternative become the parameter patterns of the anonymous function of the action. syntax_decl is the first alternative of expr, so ::= can appear anywhere an expression can, and the next top-level expression is read with the new rules.

Replacing parse

The syntax of the expressions of actions is minimal (M-expressions, calls, quasiquotes and blocks). After it, parse is switched, and the grammar of the grammar is declared again with ::=.

The M-expression reader stays as parse_mexpr, and parse becomes a function that reads one expression with the rule toplevel. The replacement is a Set, not a Def. The parse that load uses is already a fixed variable, so a Def would only add a new variable and libraries would be read with the old parse.

Expressions

Rules are declared from the strongest binding, and each refers only to rules already declared.

add_expr is directly left-recursive, so it is left-associative. The action is a quasiquote, and 1 + 2 becomes Apply{_add, Tuple{1, 2}}. A -1 at the start of a line is a new expression because same in minus succeeds only for a token on the same line.

Function definitions are also alternatives of the rule expr.

  • fun f: Def{f, none}
  • f(p, ...) = e: Set{f, Fusion{f, Lambda{...}}}
  • f(p, ...) := e: Do{Declare{f}, Set{f, Fusion{f, Lambda{...}}}}. When f is already a variable of that place, the definition is added to it.

Indexing and rewriting

a[i] calls _index_get and a[i] = e calls _index_set (the [ follows a without a space).

_index_get and _index_set are functions that join one Lambda per kind with Fusion (Table{t} for tables, Cons and Nil for lists). When a user assigns _index_get = (K{...}, i) -> ... | _index_get, the new kind comes before the original function.

When a function f is used as an index, subst(t, f) is called. It adds to f a last arm that returns peg_skip and applies it to each part of the tree. A part for which something other than peg_skip comes back is replaced without looking inside, and a part that returns peg_skip is processed recursively argument by argument.

return and break

return, break and continue are translated into effects. When the tree of a function is built and it has read a return, the body is wrapped in a Handle.

Text read by a rule

name{| text |} is read by the rule embed, which is written as a function. It calls the rule name at that position, reads the following |} and puts the value in the tree as Quote{v} ([[planck/syntax.pk Def{peg_tok_embed .. " -> or the word if after]]).
