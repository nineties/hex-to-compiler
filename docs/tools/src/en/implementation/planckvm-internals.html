planckvm internals

The design inside an implementation. The state of a call is kept only in the register stack and the frame stack, a continuation is a copy of them, and the evaluator owns its GC. The goal is to partially evaluate an evaluator written in planck to get the vasm implementation of planck. The external specification is in execution model and values and instructions.

Policy

  • The evaluator is a bytecode interpreter that translates an expression into instructions and runs them in an instruction loop. The loop never calls itself, and host effects and continuations are not used.
  • The instructions never change after they are made, and pattern matching lies in the code of the callee. When the code is static, the reading of instructions and the matching can be unrolled.
  • The only dynamic indirect call is the target of CALL. Global variables can be written, so they are not treated as static.

Stacks

The register stack and the frame stack are contiguous areas and both are GC roots. A full stack stops the program with stack overflow.

Frames

A frame is 7 words: fn (the running lambda), env (the current environment), alts (the called Fusion, or none), next (the index of the next alternative to try), base (the index in the register stack of the start of the window), pc (the index of the next instruction while this frame calls another) and ret. next, base and pc are untagged integers.

  • kind: 0 is an ordinary frame. 1 is a boundary (the handler is in R[-1] and the body lambda in R[-2]). 2 is a transfer, the frame where PERFORM called the handler (R[0] is the sent value and R[1] the continuation).
  • mode: 0 puts the return value in R[reg] of the caller. 1 and 2 mean that the caller was a test instruction with k = 0 and k = 1. 3 discards the value.

Calls and returns

  • When CALL A B C chooses a lambda, it saves pc and pushes a frame with base = the current base + B + 1 and reg of ret = A. The arguments are not moved. HANDLE A B pushes a frame with base + B + 2 and kind = 1.
  • RET drops the frame and passes the value as its ret says. TCALL moves the arguments to R[-1] and on and replaces the current frame. It keeps ret and sets only kind to 0.
  • NEXT picks, from next on, the first alternative whose arity fits. For a lambda it replaces fn and env and sets pc to 0. When none is left, a frame with kind 2 goes on to the transfer and any other stops with matching failed.
  • An overwritten builtin is detected with the word guard, whose bits correspond one by one to the names in the Builtin column. SETGLOBAL updates the bit when it writes the cell of such a name, and an instruction first checks whether guard is 0. When the builtin is overwritten, the function goes to R[nregs] with the arguments above it, and it is called like CALL.

Continuations

A continuation is an object on the heap: a copy of a slice of the frame stack and a slice of the register stack.

  1. PERFORM A B looks down from the current frame for a frame F with kind = 1. With none, it stops with unhandled effect.
  2. It copies the frames from F to the current frame and the registers from F.base - 2 to R[nregs-1] of the current frame into a continuation. The base of a copy is the offset from the start of the slice.
  3. It drops what is above F, makes a frame with kind = 2 at the position of F, puts the sent value and the continuation in R[0] and R[1], and chooses a handler. When none matches, it makes a new continuation from the slice up to the next boundary G with the original slice appended, and repeats this for G.
  4. Resuming copies the slices above the window of the caller, adds that position to the base of each frame, makes the last frame current and goes on from the saved pc. The ret of the first frame (the boundary) is decided as for a frame that CALL pushes.

Heap and garbage collection

The words of values and the contents of objects are in planckvm internal representation. The GC is a copying collector of two generations, young and old, written in planck as a part of the evaluator. Allocation is from the young generation, and only an object that does not fit goes directly to the old one.

  • When the young generation is full, the young objects reachable from the roots and the remembered set are copied to the old generation. When the old generation is full, it is copied between two semispaces.
  • An instruction marked S in the instruction table may allocate and so may run the GC. The GC runs before the side effects of the instruction, and the inputs are read again from the registers, which the GC updates. There is no safe point in the middle of a loop.
  • Every live value is reachable from the register stack, the frame stack, the cells, the state of the evaluator (the symbol table and the temporary slots of builtins) or the remembered set. No value lives only in a local variable of the evaluator.

There is no table of live registers, and every element of the register stack is a valid value or none. It is filled with none at start, and the GC fills with none the used range above the roots. The top of that range is recorded in the word high, which is updated when a window is made.

When a reference to a young object is written into an old object (ENVSET, SETGLOBAL, ASET), the object is recorded in the remembered set if its header bit r is 0, and r becomes 1.

The identity of a function (EQ and HASH) is not its address. It is a number assigned at the first HASH.
