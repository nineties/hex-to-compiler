planckvm internals

The design inside an implementation of planckvm. What the user of the VM may rely on is in the external specification: planckvm: execution model and values and planckvm instructions.

Principles

  • The evaluator is a bytecode interpreter: an expression is translated into instructions, and an instruction loop runs them. An expression is not turned into a closure.
  • The evaluator has its own garbage collector, a generational copying collector. It owns the heap of values and the roots.
  • The evaluator does not use the effects, the continuations or the M-expression reader of the host. They are written in planck as parts of the evaluator.

Code and frames

  • A jump target and the pc are indices, not addresses, because the collector moves objects.
  • When a code is made, the maximum height of its operand stack is computed.

Frames

FieldMeaning
callerThe frame that receives the value. None for the entry of a top-level expression
code, pc, envThe running code, the next instruction and the environment
remaining alternativesThe functions of f | g that have not been tried yet, or none
boundaryThe handler function. Only a frame made by HANDLE has it
forwarding markOnly a frame that PERFORM uses to call a handler has it. It tells where to go to the outer boundary when the alternatives run out
argumentsThe n values of the call, kept until the matching at the entry is over
operand stackThe intermediate values. Its height is bounded by a maximum that the code determines

Frames are pushed on a contiguous region, the frame stack. The evaluator owns the region and it is a root of the collector. When it is full the program stops with stack overflow.

Environments

An environment is | parent environment | slot 0 | slot 1 | ... |. It is on the heap and made for each call.

Heap and garbage collection

Values and the heap

  • A value is one tagged word. A small integer is an immediate value and every other value is a reference into the heap. Floats, complex numbers, large integers, strings, M-expressions and arrays are objects on the heap.
  • The heap is built on one integer array, as regions for the generations.
  • The collector is a generational copying collector, written in planck as a part of the evaluator. It is not a runtime added to vasm.

Allocation and safe points

  • An instruction marked S in the instruction tables may allocate, and the collector may run when it allocates.
  • The collector runs before the side effects of the instruction. The inputs of the instruction remain on the operand stack during the collection and are updated by it. The instruction reads its inputs again after the collection.
  • Every running value can be reached from the frame stack, the environments or the cells. No value lives only in a local of the evaluator.
  • The collector does not run in an instruction that allocates nothing (JMP, LOAD, POP and so on). No safe point is placed in the middle of a loop.

Roots

RootContents
The frame stackThe env, code, arguments and operand stack (up to the saved height) of every frame
CellsThe global variables
The state of the evaluatorThe symbol table, the constant tables and the state during compilation

Every field of a frame is a value or an integer of a header, and can be followed from its tag. There is no stack map. The pc is an index, so a move of the code does not affect it. The constant table is followed as a part of the code.

The write record

The method is a remembered set: a list of old objects. When a reference to a young object is written into an old object, the old object is recorded. The targets are STORE, GSET and ASET. A plain array has no references and is not recorded. The initialization of a newly allocated object is not recorded, and neither is a write to the frame stack, because the frame stack is traced as a root every time.

Identity

Arrays, plain arrays and functions have identity (EQ and HASH). It is not held as an address. The first HASH assigns a number. A symbol has a number that comes from its name, an M-expression and a string have one from their contents, and a number has one from its value.

Continuations

PERFORM allocates, because it copies frames. The frames are copied twice: when k is captured and when it is resumed. Continuations do not use the effects of the host. The frames are data and are copied as data. The frames inside a continuation have the same form as ordinary frames and are traced in the same way.

Representation of numbers and plain arrays

  • A small integer is an immediate value and a large one is an array of digits.
  • When the result of two integers fits a small integer, the instruction need not allocate. An allocation happens when digits are added, and when the result is a float or a complex number.
  • Floats and complex numbers are immutable boxes on the heap. vasm holds a complex number as a pair of floats.
  • The elements of a plain array carry no tag. A plain array holds no references, so the collector does not scan it and writing to it is not recorded. A complex element is two numbers inside the array, not a box.

Partial evaluation

The purpose of planckvm is to partially evaluate an evaluator written in planck and to get an implementation of planck in vasm. The following properties of the design are meant to serve this.

  • The instructions do not change after a code is made and the jump targets are immediate, so for a static code the reading of instructions and the choice of the next one can be unrolled.
  • The height of the operand stack is determined at each pc, so the stack can be kept as a static sequence.
  • Pattern matching is in the code that is called. A match can be specialized for each function, and no matcher that walks a data tree is needed.
  • Continuations are copies of frames and use no effects of the host, so the evaluator does not use Perform and does not meet the limit on continuations in planck/lib/pe.pk.
  • A dynamic indirect call goes only to a function reached by CALL. If the set of codes that can be called is closed, each code can become one function.
  • The guard of CALLP can be folded when the cell is static and immutable. A global variable is a mutable cell, so a global that is assigned cannot be treated as static.
  • With PLAINGET and PLAINSET, the elements are read and written as numbers without boxes.
