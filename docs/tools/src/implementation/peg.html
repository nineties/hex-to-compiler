packrat パーサ

planck/peg.pk は PEG の文法を解釈するパーサです。文法はただのデータ（M式）で、規則の結果は位置ごとに覚えておきます。M式で 316 行あります。

文法はデータ

構文解析式（規則の右辺）は M式です。どんな形があるかはファイルの先頭にまとまっています。

たとえば「"7" が 1 回以上」は Many1{"7"}、「読めたら個数を数える」は Act{Many1{"7"}, t -> arity(t)} です。define_rule で名前を付けると、そのまま規則として使えます。

::= を使わずに規則を作りましたが、sevens{| ... |} でも読めます。::= も結局はこの define_rule の呼び出しになります（構文を planck で書く）。

式を解釈する

peg_px(e, p) は、構文解析式 e を位置 p から試します。成功すれば次の位置を返して値を peg_pv に置き、失敗すれば -1 を返します。

文字列なら空白を飛ばしてから照合し、シンボルなら規則を呼び、関数ならその関数に任せます。Seq や Choice のような M式は、頭ごとの処理を表 peg_handlers から引きます（[[planck/peg.pk#170-205]]）。字句（識別子や整数）は関数で書けるので、構文の側で速い関数を用意しています。

失敗したときは、一番先まで進んだ位置を peg_far に覚えておきます（[[planck/peg.pk#57-59]]）。構文エラーはその位置で知らせます。

メモ化と左再帰

同じ規則を同じ位置で何度試しても、結果は同じです。だから位置ごとに規則の結果を覚えておきます。これが packrat 構文解析です。後戻りしても、同じ仕事をくり返さずにすみます。

メモは位置ごとの配列で、規則ごとに「終わりの位置・値・左再帰の印」の 3 つの欄を持ちます。規則を呼ぶ peg_call_rule はまずメモを見ます（[[planck/peg.pk#229-245]]）。

左再帰（sum ::= sum "+" term | term）もこのメモで扱います。規則の実行中にメモの欄を「実行中」にしておき、同じ位置で自分がもう一度呼ばれたら失敗を返します。これが最初の種です。種で 1 回目の結果ができたら、その結果をメモに置いてもう一度規則を動かします。前より長く読めた間は、これをくり返します。

こうして 1 - 2 - 3 は (1 - 2) - 3 のように左から積み上がります。

規則を定義する

define_rule は規則に番号を振り、構文解析式の中の動作 Act{e, f} の f を評価してから表に入れます。選択肢の Prev{} は、その規則のそれまでの定義に置き換えます。::= の ... はこれになります。

評価する前の形は peg_sources にも残します。文法を読む道具、たとえば木を文字列に戻す unparse は、この表を読んで動きます。

入口

peg_parse(rule, s) は、メモを新しく作ってから規則を呼びます（[[planck/peg.pk#300-316]]）。結果は Tuple{値, 残り} です。読めなかったときは peg_far の位置から行の終わりまでを添えて SyntaxError{...} を返します。
