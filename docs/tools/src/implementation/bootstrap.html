機械語から planck0 まで

16 進で書いた 1 枚の機械語から、sasm で書いた planck0 ができるまでを順にたどります。

pforth：手書きの機械語

出発点は pforth.xxd です。201 行の 16 進ダンプで、各行の右に注釈が付いています。xxd -r -c 8 がこれをバイト列に戻すと、そのまま 32 ビット x86 の Linux で動く ELF の実行ファイルになります。

中身は小さな Forth です。最初に辞書にあるのは 1 文字の名前の語だけです。k は 1 文字読む、t は 1 文字書く、f は文字から語を探す、x は語を実行する、といった具合です。

はじめの解釈器は「k で 1 文字読み、f で語を探し、x で実行する」をくり返すだけです。1 文字の語だけでも、次のように Hello World が書けます。

plisp：Forth を育てて Lisp を作る

plisp.fs は pforth に食べさせる入力です。最初の数行は 1 文字の語だけで書かれた暗号のような列で、空白と改行を何もしない語にし、\ をコメントの語にします（[[plisp.fs#1-15]]）。15 行目で、やっとコメントが書けるようになります。

そこから少しずつ語を足して、Forth を使いやすくしていきます。

  • 2 段目の解釈器。名前で語を探し、コンパイルの状態を持ちます（[[plisp.fs#335-358]]）。
  • 条件分岐・ループ・再帰・構造体などのふつうの Forth の語（[[plisp.fs#498-1380]]）。
  • 3 段目の解釈器。辞書にない語は数として読み、数でもなければエラーの文を出して止まります（[[plisp.fs#1386-1447]]）。

Forth が十分に育ったら、その Forth で Lisp を書きます（[[plisp.fs#1684]] から）。リスト・ノード・パーサとプリンタ・評価器と続き、最後に plisp/init.lisp を読み込んで Lisp 側の準備をします（[[plisp.fs#2435]]）。

Lisp にしたのは、次の段がアセンブラやコンパイラだからです。木を直接いじれて、内部 DSL を作りやすい言語が向いています。

asm と sasm：機械語を書く道具

plisp の上で 2 つの道具を作ります。どちらも次の段へ渡るための使い捨ての道具で、速さや安全より作りやすさを優先しています。

asm/core.lisp は x86 のアセンブラです。S式で書いた命令を読み、ELF の実行ファイルを直接書き出します。対象は 32 ビットだけで、ヘッダもコードもデータも読み書き実行できる 1 つの PT_LOAD にまとめます。

sasm/core.lisp は構造化アセンブリ言語 sasm のコンパイラです。sasm は型のない C のような言語です。変数・関数・if・while が書け、plisp の内部 DSL として作られています。レジスタ割り付けはせず、値を毎回スタックに積んで降ろすコードを出し、asm で機械語にします。

plisp2：速い Lisp

Forth の上の plisp は、大きな仕事には遅すぎます。そこで同じ Lisp を sasm で書き直したのが plisp2.sv です。メモリの確保（[[plisp2.sv#6]]）・ノード（[[plisp2.sv#54]]）・パーサとプリンタ（[[plisp2.sv#302]]）・評価器（[[plisp2.sv#586]]）・組み込み関数（[[plisp2.sv#828]]）の順に並んでいます。

plisp2 は plisp の上の sasm で機械語になります。できた plisp2 が、今度は同じ sasm を動かして planck0.sv を機械語にします。
