native

use("native/compile") defines a systems language. Its meaning is that of vasm, with a higher-level notation. native_compile.compile expands the functions and structs written in native{| ... |} to a vasm module, and ownership and borrowing are checked on the expanded vasm. Types come from the declarations of variables and functions, and are written only there.

Programs

A program is a list of structs and functions. Types, structs and function declarations are written as in vasm. The body of a function is a list of statements, separated by newlines or ;. If the last statement of a function that gives a value is an expression, its value is the result.

To use other units, write import lib at the start of the file, one on each line (see vasmc). The value of native{| ... |} is PModule{[...]}; its list starts with PImport{at, name} for each import.

FunctionReturns
native_compile.compile(m)The vasm Module{[...]}, which vasm_check and vasm_build take as it is
native_compile.compile_all(m)Tuple{module, errors}. The errors are VasmErr{kind, loc, msg}, the first one of each function
native_compile.errors(file, errors)The errors, with the positions as Loc of the file

Expressions and statements

Precedence grows from the top row of the table to the bottom row. Arguments are computed from left to right.

FormMeaning
a or b a and bThe right side is not computed if the left decides
== != < <= > >=Comparison. The result is bool
| ^ &Bitwise or, xor, and, each tighter than the one before. and binds tighter than a comparison
<< >> + - * / %Shifts, addition and subtraction, multiplication and division, each tighter than the one before. A * is on the same line as its left operand
e as TChanges the integer type
-e not e *p &r y &mut r yNegation, logical not, the contents of a box, a borrow
a[i] s.f f(a, ...) S{f: a, ...}An element, a field, a call, a struct value

A struct value starts with a field, so it is told from the { that starts the body of an if or a for. 'name, "text", val H(a, ...), fn f(a, ...), true and false are values as in vasm.

  • let x = e, let x: T = e, var x: T (uninitialized). A name can be declared again, and the earlier variable is hidden.
  • Assignments x = e, *p = e, a[i] = e and s.f = e compute the right-hand side first. A compound assignment such as += reads the place on the left once.
  • if c {...} else if c {...} else {...} and while c {...}. The condition needs no parentheses.
  • for i in a..b {...}: i runs from a up to just before b, and is visible only in the body. b is computed once, at the start.
  • region r {...}, return and return e are as in vasm.

native_compile.pk

use("native/compile")
use("vasm/text")

m := native{|
    fn gcd(a: i64, b: i64) -> i64 {
        while b != 0 {
            let t = a % b
            a = b
            b = t
        }
        a
    }

    fn bump[r](m: &mut r [i32], n: i32) {
        for i in 0 as i32..n {
            m[i] += 1
        }
    }
|}
put(vasm_text.text(native_compile.compile(m)))

Output

fn gcd(a: i64, b: i64) -> i64 {
    while (b != 0) {
        var t: i64
        t = a % b
        a = b
        b = t
    }
    return a
}

fn bump[r](m: &mut r [i32], n: i32) {
    var t0: i32
    t0 = n
    var i: i32
    i = 0
    while (i < t0) {
        var t1: i64
        t1 = i as i64
        var t2: i32
        t2 = m[t1]
        t2 = t2 + 1
        m[t1] = t2
        i = i + 1
    }
}

How types are fixed

  • Types are written only at let, var, parameters, results of functions and as.
  • An integer literal alone has no type. It takes the type of the place it is put in, the parameter, the other operand or the result of the function. A literal with nothing to fix its type, as in let x = 5, is an error. Write let x: i64 = 5 or 5 as i64.
  • The type of i in for i in a..b is that of whichever of a and b is not a literal. If both are literals it is an error; give one a type, as in 0 as i64..10.
  • The index of an array is i64. An index of another integer type needs as i64.
  • The type of a call whose result holds a borrow is inferred only when the arguments fix the region of the result to one. Otherwise write let x: T = f(...).

Large literals

A literal of vasm is from -32768 to 32767, but native accepts an integer literal beyond it. A literal outside the range of its type is an error.

native_logic.pk

use("native/compile")
use("vasm/text")

m := native{|
    fn both(a: i64, b: i64) -> bool {
        a > 0 and b > 0
    }

    fn mask(x: i32) -> i32 {
        x & 0x3FFFFFF
    }
|}
put(vasm_text.text(native_compile.compile(m)))

Output

fn both(a: i64, b: i64) -> bool {
    var t0: bool
    t0 = a > 0
    var t1: bool
    t1 = t0
    if (t1) {
        var t2: bool
        t2 = b > 0
        t1 = t2
    }
    return t1
}

fn mask(x: i32) -> i32 {
    var t0: i32
    t0 = 2047
    t0 = t0 << 15
    t0 = t0 | 32767
    var t1: i32
    t1 = x & t0
    return t1
}

Errors

The kind of an error of the expansion is 'type (the type is not known, a literal is outside the range of its type, a statement that is an expression is not a call) or 'undefined (a variable, function or struct that is not declared). vasm_check.check checks ownership, borrowing and initialization on the expanded vasm. The positions of the errors are those of the native source.

native_errors.pk

use("native/compile")

m := native{|
    fn f(n: i64) {
        let x = 5
    }
    fn g(n: i64) {
        for i in 0..10 {
            n += 1
        }
    }
    fn h(n: i64) -> i64 {
        n + k
    }
|}
file := argv()[0]
each((VasmErr{_, Loc{_, l, c}, msg}) -> put(f"line {l}: {msg}\n"), native_compile.errors(file, arg(native_compile.compile_all(m), 1)))

Output

line 5: the type of this value is not known; write the type, as in let x: i32 = ... or e as i32
line 8: the type of the loop variable is not known; write one bound with its type, as in 0 as i64..n
line 13: k is not declared
