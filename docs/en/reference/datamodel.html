Data model

Every value has a type, and a value is an M-expression or an atom. The evaluator works on M-expressions. An M-expression whose head is not a special form is a constructor: its arguments are evaluated and an M-expression with the same head is built. == tests whether values are equal, and is whether they are the same thing (identical). Identical values are always equal, and for an interned type equal values are identical. Mixed number types are raised to the highest type, and mistakes are runtime errors. What follows are the differences between the types and the exceptions to these rules.

M-expressions and atoms

An atom is a value that is not an M-expression: an integer, a float, a complex number, a string, a symbol, a function, an array, a plain array, a type value or user data.

  • The head of an M-expression is a symbol. A head is not registered, so two libraries can use the same head. head(x) is for M-expressions only, and is an error for an atom.
  • A type is itself a value (a type value), which type(x) returns. type(1) is Int, and type(Int) is Type.
  • Int, String, Expr and the other type names are variables that hold type values. x @ T compares the variable T with type(x), so x @ Expr matches every M-expression.

The M-expression Set{1} and a type named Set are different things, so a name never collides with a head.

M-expressions

  • The type is Expr, and it is immutable. The literal is Head{a, b}. The sugar is (a, b) (Tuple), [a, b] and :: (Cons), and [] (Nil).
  • Interned. f{1} and f{1.0} are not equal.
  • A mutable value, immutable user data that holds a mutable value, and a NaN cannot be arguments. Making an M-expression with one is a runtime error.

Notes on each type

  • An integer has arbitrary precision. The range has no limit, and there is no wraparound or truncation.
  • A complex number is made with an imaginary literal (2i) or complex(re, im). It is equal to an integer or a float with the same value.
  • A float is an IEEE 754 binary64. A NaN is neither equal nor identical to anything, itself included (x == x and x is x are both false), and using it as a table key is an error.
  • A string is a sequence of bytes, 0 bytes included, up to 65535 bytes. a[i] returns a string of length 1.
  • A symbol name starts with a letter, _ or %. For true, false and none, see Lexical rules.
  • A function is a Lambda, a Fusion, a builtin function or a continuation. It is equal only when identical.
  • An array has a fixed length. array(n) makes one, with all elements none at first. All elements of a plain array have one type: 'bool, 'i8 to 'u64, 'f16 to 'f64, 'c64 or 'c128. Both can be changed by a[i] = e. It is an error when out of range (for a plain array, also when the value cannot be converted).
  • A different array or plain array with the same contents is equal but not identical. == first returns true if the two are identical, so if a holds a NaN, a == a is true. A different array b that holds the same NaN object gives a == b false.
  • A type value is shown by the name of the type. Different types with the same name are told apart by is.

User data

  • Made by a builtin function. You must specify whether it is immutable or mutable. There is no default.
  • Each type is a unique value made each time, and its name is only used for display. A type with the same name made elsewhere is a different type.
  • You may give a function for == and a function for hash, both together. A type with them is not interned, and is compares objects. The author of the type must keep two rules: if a is b then a == b, and equal values have the same hash.
  • For a type without them, == is identity, and the hash is decided by the contents if immutable and by the object if mutable.

Equality

Tested by a == b (_eq); a != b (_ne) is its opposite. Integers, floats and complex numbers are equal if the values are the same, even when the types differ, and the hash is the same too (1 == 1.0, 1 == complex(1, 0)).

  • A pattern that writes the same name twice (f(a, a)) matches only when the two values are equal.
  • A table (table_get, table_set and t[key]) treats two keys as the same if they are identical or equal. An array, a plain array or a NaN as the key is an error.
  • hash(x) is an integer of 0 or more, and equal values give the same value. The exact values are not defined.

Identity and is

a is b is true if a and b are identical. Its negation is a is not b, and its precedence is that of ==, at the level of the comparison operators. It does not group, so a is b is c is an error, and is cannot be written in a pattern.

  • Interning makes equal values into one object. Integers, strings, symbols, M-expressions and immutable user data without == given are interned, so == and is are the same test, and O(1) (except for arbitrary precision integers).
  • Floats, functions, arrays, plain arrays, mutable user data and user data with == given are objects. Equal values are not always identical.
  • Values of different types are not identical. 1 == 1.0 is true, but 1 is 1.0 is false.

Literals

true, false and none are literals whose value is the symbol of the same name. They are not variables, so Def{true, e}, Set{true, e} and Declare{true} stop the program before running. A top-level string is a comment.

Numbers

  • Integer division: _div truncates toward 0. _quo (the operator //) rounds toward minus infinity, so -7 // 2 is -4. _mod(a, b) is a - b * (a // b) and has the sign of the divisor.
  • A zero divisor is a runtime error, except for _div with a float or a complex number, which gives an infinity or NaN (per component for a complex number).
  • _lt _le _gt _ge compare an integer and a float by their mathematical values, without raising the type. They give false when NaN is involved and are a runtime error on a complex number.
  • _eq treats numbers of different types as equal when their values are the same (1 == 1.0). Complex numbers are equal when both components are equal. NaN is not equal to itself.
  • An integer is raised to the nearest float, and one beyond the range of floats is a runtime error.

Special forms

  • Def{x, e}: e sees the previous variables, up to but not including x. Set{x, e} assigns.
  • Declare{x}: the same as Def{x, none}, except that nothing happens when x is already a variable of the place where Def{x, e} defines x.
  • If{c, a, b}: b only when c is false.
  • Fusion{f, g}: tries g when no pattern of f matches. Fusion{none, g} is g.

record

record T(f, g, ...) names the arguments of the values T{a, b, ...}. Values are built as before. t.f is the argument of t at the position of f in the declaration for the head of t, and the . follows its left operand with no space.

  • Values with different heads can have fields of the same name. Declaring the same T again replaces the names.
  • Using .f on a value whose head is not declared, or that has no field f, stops the program with a message.
  • t with { f = e, g = e2 } is a new value with those fields replaced (t does not change). The fields are replaced from the left, so e can refer to the fields of the original t. with { ... } can follow another one.
