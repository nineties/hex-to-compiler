Variable binding

There are two kinds of binding: definition (:=) and assignment (=). Modules and imports, which group names, are also written here.

Definition and assignment

x := e defines a new variable where it is written. Defining the same name again also makes a new variable, and functions made earlier keep the earlier one. x = e assigns to the existing variable, so functions made earlier see the new value.

r_scope_redefine.pk

f(x) := 1
g() := f(0)
f := (x) -> 2
println(g())

h(x) := 1
k() := h(0)
h = (x) -> 2
println(k())

Output

1
2

The right side sees the earlier x; if there is none, it is undefined. Write a function that calls itself as f(p, ...) := e.

bd_recursion.pk

fact(n) := if (n == 0) 1 else n * fact(n - 1)
println(fact(5))

Output

120

e_bd_define_self.pk

x := x + 1

Output

undefined variable: x

Compound assignment and splitting a tuple

x += e is the same as x = x + e, and -=, *=, /= and %= have the same form. a[i] += e evaluates a and i once. The left side is a variable or a[i]; t.f += e is not allowed.

t1_compound.pk

# x += e is x = x + e. The same goes for -=, *=, /= and %=.

x := 10
x += 5
println(x)
x -= 3
println(x)
x *= 2
println(x)
x /= 4
println(x)
x %= 4
println(x)

# the element of an array
a := array(3)
a[0] = 1
a[1] = 2
a[2] = 3
a[1] *= 10
a[2] += a[1]
println(Tuple{a[0], a[1], a[2]})

# the index is evaluated once
n := 0
next() := {
    n += 1
    n - 1
}
a[next()] += 100
println(Tuple{a[0], a[1], n})

# in a loop
sum := 0
i := 1
while (i <= 10) {
    sum += i
    i += 1
}
println(sum)

Output

15
12
24
6
2
Tuple{1, 20, 23}
Tuple{101, 20, 1}

Splitting a tuple

(a, b) := e defines variables from the elements of the tuple e, and (a, b) = e assigns to defined variables. The right side is evaluated completely first, so (a, b) = (b, a) swaps.

t1_destructure.pk

# (a, b) := e defines several variables from the elements of a tuple

(a, b) := (1, 2)
println(a + b)

# swap
(a, b) = (b, a)
println(Tuple{a, b})

# a function that returns two values
divmod(x, y) := (x / y, x % y)
(q, r) := divmod(17, 5)
println(Tuple{q, r})

# in a function and in a loop
fib(n) := {
    (x, y) := (0, 1)
    i := 0
    while (i < n) {
        (x, y) = (y, x + y)
        i = i + 1
    }
    x
}
println(fib(10))

Output

3
Tuple{2, 1}
Tuple{3, 2}
55

A tuple whose number of elements differs from the number of names, and a value that is not a tuple, are errors.

e_bd_destructure_size.pk

Output

e_bd_destructure_atom.pk

module

module m { ... } puts the definitions of the body under the name m. The value the body returns is the module value, and the definitions marked export are its fields. Reading a name that is not a field with . is an error.

bd_module.pk

module counter {
    n := 0
    export start := n
    export next() := {
        n = n + 1
        n
    }
    export current() := n
}
counter.next()
counter.next()
println(counter.start)
println(counter.current())

module outer {
    module hidden {
        export f(x) := x + 1
    }
    export module inner {
        export g(x) := hidden.f(x) * 2
    }
}
println(outer.inner.g(3))

Output

0
2
8

e_bd_module_private.pk

module m {
    helper(i) := i / 30
    export f(i) := helper(i)
}
println(m.f(65))
println(m.helper(65))

Output

2
no field helper in Module{}
  • The scope of the body is that of the body of a function with no parameters. To call something defined later from earlier code, use fun f and f(p, ...) = e (Partial functions and fusion).
  • The definitions of the body are variables of the body, not global variables. They cannot be assigned from outside and do not hide a same name outside. To let outside code add cases, export the function to add to (m.f(p, ...) = e is not allowed).
  • m is defined after the body is evaluated, so the body cannot see m.
  • Replacing parse inside the body does not affect the rest of the body. Replace a grammar outside the module.

export

  • export can be written only before f(p, ...) := e, x := e and module n { ... } directly in the body of a module. Anywhere else is a syntax error.
  • The field of export x := e is the value of x when the body returns, and later assignments do not change it. To show the current value, export a function that reads x (start and current above).
  • An inner module n { ... } defines the variable n of the body and is invisible from outside. To show it, write export module n { ... }. The inner body sees the variables the outer body defined earlier.

test

test { ... } can be written directly in the body of a module. Normally nothing runs. planck0 tools/test.pk <library> ... runs it, together with the test of the libraries they use.

module bitset {
    export new(n) := i32_array(n / 30 + 1)
    helper(i) := i / 30
    export add(s, i) := {
        w := helper(i)
        s[w] = bit_or(s[w], bit_shl(1, i % 30))
    }
    test {
        assert(helper(65) == 2, "helper")
        s := new(100)
        add(s, 3)
        assert(s[0] == 8, "add")
    }
}
  • The scope is that of the body of the module, so functions without export can be called.
  • A test runs while the body is being evaluated, so it sees the variables defined before it, and m is not defined yet.
  • assert(c, msg) writes msg and stops with status 1 unless c is true.
  • A block holds at most 64 expressions.

import

import a::b loads the same way as use("a/b"), and the same file is loaded once. The last name is the name of the module the file defines. How to take names follows the path.

FormMeaning
import mOnly loads. Fields are read as m.f
import m as nAdds n := m
import m (x, y)Defines x := m.x and y := m.y
import m (*)Defines every field under the same name
import m hiding (x, y)Defines every field except x and y under the same name

i_import.pk

# import: the module of a library under the names that are chosen

import bitset as bs
s := bs.new(100)
bs.add(s, 3)
bs.add(s, 42)
println(bs.to_list(s))

# only the listed fields are defined
import bitset (has, count)
println(has(s, 42))
println(count(s))

# all the fields but the hidden ones
import bitset hiding (new, add)
println(to_list(s))

Output

Cons{3, Cons{42, Nil{}}}
true
2
Cons{3, Cons{42, Nil{}}}
  • as n can come before (x, y), (*) and hiding (...). as, (...) and hiding are on the same line as m.
  • Naming a field that m lacks in (x, y) is the same error as reading it with ..
  • In a function, (*) and hiding define global variables, and (x, y) and as define local variables.

!x on the left of a definition or an assignment

Inside a quasi-quote, the left side of x := e and x = e may be written !x, which is replaced by the symbol that x holds (Def{!x, e} and Set{!x, e}). When x holds 'i, `{ !x := 0; !x = !x + 1 } is Do{Def{i, 0}, Set{i, Apply{_add, Tuple{i, 1}}}}. When x holds 'true, it stops the program, as Def{true, e} does.
