Variable binding

There are two kinds of binding: definition (Def) and assignment (Set).

Definition and assignment

Def{x, e} defines a new variable where it is written. Defining the same name again also makes a new variable, and functions made earlier keep the earlier one. Set{x, e} assigns to the existing variable, so functions made earlier see the new value.

r_scope_redefine.pk

Def{f, Lambda{Tuple{x}, 1}}
Def{g, Lambda{Tuple{}, Apply{f, Tuple{0}}}}
Def{f, Lambda{Tuple{x}, 2}}
Apply{println, Tuple{Apply{g, Tuple{}}}}

Def{h, Lambda{Tuple{x}, 1}}
Def{k, Lambda{Tuple{}, Apply{h, Tuple{0}}}}
Set{h, Lambda{Tuple{x}, 2}}
Apply{println, Tuple{Apply{k, Tuple{}}}}

Output

1
2

The right side sees the earlier x; if there is none, it is undefined. A function that calls itself first creates the name with Declare{f}, and then adds the function with Set{f, Fusion{f, Lambda{...}}} (Adding a case).

bd_recursion.pk

Declare{fact}
Set{fact, Fusion{fact, Lambda{Tuple{n},
    If{Apply{_eq, Tuple{n, 0}}, 1,
        Apply{_mul, Tuple{n, Apply{fact, Tuple{Apply{_sub, Tuple{n, 1}}}}}}}}}}
Apply{println, Tuple{Apply{fact, Tuple{5}}}}

Output

120

e_bd_define_self.pk

Def{x, Apply{_add, Tuple{x, 1}}}

Output

undefined variable: x

UnQuote on the left of a definition or an assignment

Inside a QuasiQuote, the left side of Def and Set may be written UnQuote{x}, which is replaced by the symbol that x holds. When x holds Quote{true}, it stops the program, as Def{true, e} does.

bd_quasi.pk

Def{x, Quote{i}}
Apply{println, Tuple{QuasiQuote{Do{Def{UnQuote{x}, 0}, Set{UnQuote{x}, Apply{_add, Tuple{UnQuote{x}, 1}}}}}}}

Output

Do{Def{i, 0}, Set{i, Apply{_add, Tuple{i, 1}}}}
