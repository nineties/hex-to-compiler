Values, patterns, M-expressions

The evaluator works on M-expressions. An M-expression whose head is not a special form is a constructor: its arguments are evaluated and an M-expression with the same head is built. A pattern is written like a constructor and binds variables when it matches. Mixed number types are raised to the highest type, and mistakes are runtime errors. The kinds of values are in Data types.

M-expressions

true, false and none are literals whose value is the symbol of the same name. They are not variables, so Def{true, e}, Set{true, e} and Declare{true} stop the program before running. A top-level string is a comment.

Numbers

  • Integer division: _div truncates toward 0. _quo (the operator //) rounds toward minus infinity, so -7 // 2 is -4. _mod(a, b) is a - b * (a // b) and has the sign of the divisor.
  • A zero divisor is a runtime error, except for _div with a float or a complex number, which gives an infinity or NaN (per component for a complex number).
  • _lt _le _gt _ge compare an integer and a float by their mathematical values, without raising the type. They give false when NaN is involved and are a runtime error on a complex number.
  • _eq treats numbers of different types as equal when their values are the same (1 == 1.0). Complex numbers are equal when both components are equal. NaN is not equal to itself.
  • An integer is raised to the nearest float, and one beyond the range of floats is a runtime error.

Special forms

  • Def{x, e}: e sees the previous variables, up to but not including x. Set{x, e} assigns.
  • Declare{x}: the same as Def{x, none}, except that nothing happens when x is already a variable of the place where Def{x, e} defines x.
  • If{c, a, b}: b only when c is false.
  • Fusion{f, g}: tries g when no pattern of f matches. Fusion{none, g} is g.

t2_mexpr.pk

p := Point{3, 4}
println(p)
println(head(p))
println(arity(p))
println(arg(p, 1))
println(Point{1, 2} == Point{1, 2})
println(push(p, 5))

true

Patterns

  • _: matches anything and binds nothing.
  • Head{p, ..., _Rest{x}}: matches an M-expression with at least as many arguments as the patterns before _Rest, and binds x to a Tuple of the rest.
  • _TypeOf{p, type}: matches a value whose type is type and which p matches.

t3_type.pk

describe := (n @ int) -> f"integer {n}"
          | (s @ string) -> f"string {s}"
          | (_) -> "other"
put(describe(1)); put("\n")
put(describe("abc")); put("\n")
put(describe('x)); put("\n")

Output

integer 1
string abc
other

Partial functions and fusion

A function takes its arguments by patterns, so it is a partial function: some arguments may not match. Fusion{f, g} (written f | g) tries f first, and tries g if none of its patterns match (also when a guard is false). Functions are tried in the order they are joined, so definitions written one after another in the same place, such as f(0) := ..., form one function tried in the order written.

f := (0) -> "zero" | (1) -> "one"
f(1)   // "one"
f(7)   // matches no arm, and the program stops

When a function call, a match or the last function of a fusion has no arm that matches, it performs MatchingFailed{f, args, loc} instead of stopping. match e { f } is the same call as f(e). With no handler for it, the program prints an error message (matching failed) and stops. It does not become unhandled effect.

FieldContents
fthe function that was called (the whole fusion for a fusion)
argsa Tuple{...} of the arguments that did not match
locthe position in the source of the failed call or match: Loc{file, line, column}
a := handle f(7) with (MatchingFailed{_, Tuple{n}, _}, k) -> n
println(a)
7

The value of the handler is the value of the Handle, not the value of the expression that called f(7).

The next function of a fusion is chosen only by the entry patterns and guards. When the entry of an arm matches, a MatchingFailed raised deep in the body of that arm does not move on to the next function: it propagates outward.

g(0) := "zero"
h := (x) -> g(x) | (x) -> "second arm"

r := handle h(5) with (MatchingFailed{f, _, _}, k) -> "failed in g"
println(r)
"failed in g"

h(5) enters the first arm, and g(5) inside it fails with MatchingFailed. The second arm is not tried.

When no pattern of a handler of Handle matches a Perform, the next outer handler is searched. A handler that accepts only Return{v} or Break{} is passed through, and a handler (e, k) -> ... whose pattern matches anything also receives MatchingFailed. A Perform other than MatchingFailed with no handler stops with unhandled effect.

Algebraic effects

Perform{v} calls the nearest handler(v, k) that has a matching pattern. Handlers stay installed in the continuation. k is an ordinary function and can be called any number of times, even after Handle has returned.

Variables defined when the continuation is captured are shared between the resumed copies. Variables defined after the resumption are separate.

t5_resume.pk

ask() := perform Ask{}

with_answer(v, f) := handle f() with (Ask{}, k) -> k(v)

println(with_answer(21, () -> ask() * 2))
println(with_answer(5, () -> ask() + ask()))

Output

42
10

The handler of a MatchingFailed can also resume with k. The x of k(x) becomes the value of the failed function call or match.

b := handle [f(7), 1] with (MatchingFailed{_, _, _}, k) -> k("other")
println(b)
Cons{"other", Cons{1, Nil{}}}

The handler stays installed in the resumed continuation, so a second failure after the resumption is received by the same handler.

c := handle [f(8), f(9)] with (MatchingFailed{_, Tuple{n}, _}, k) -> k(n)
println(c)
Cons{8, Cons{9, Nil{}}}

Top level

The loop looks up the global variables parse and eval for every expression, so replacing them takes effect from the next expression. Apply{eval, ...} also calls the replaced eval.

  • parse: String -> Tuple{M-expression, rest String}. It returns Tuple{Eof{}, ""} when only blanks are left, and a replacement parse passes Eof{} through.
  • eval: M-expression -> value.

t6_eval.pk

old_eval := eval
eval = e -> {
    v := old_eval(e)
    put("=> ")
    println(v)
    v
}
1 + 2
'(a + b)
Point{1, 2}

Output

=> 3
=> Apply{_add, Tuple{a, b}}
=> Point{1, 2}
