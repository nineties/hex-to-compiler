Values, patterns, M-expressions

The evaluator works on M-expressions. This page defines the kinds of values, the special forms, patterns, effects and the top level.

M-expressions

An M-expression is a symbol (x), an integer (42, -1), a float (1.5), a string ("abc") or Head{a, b, ...}. A symbol is a letter, _ or % followed by letters, digits and _. A string is up to 65535 bytes and Head{...} has up to 64 arguments. A string at the top level has no effect, so it can be used as a comment.

true, false and none are literals. Each is the symbol of the same name, and its value is that symbol, so true and Quote{true} have the same value. They are not variables: Def{true, e}, Set{true, e} and Declare{true} stop the program with a message before the expression runs.

Arrays and plain arrays are the values that can be written. Numbers, strings, symbols and M-expressions are immutable. A list (Cons{x, xs}) and a tuple (Tuple{a, ...}) are M-expressions, so they are immutable too. A table Table{a} and a vector Vector{a} are M-expressions that hold an array, and a[i] = e writes them (see Indexing and rewriting).

Numbers

  • No integer is out of range, and nothing wraps around or is truncated.
  • Floats round to nearest even, and floating-point exceptions do not stop the program. A complex number is made by complex(re, im) and has no literal.
  • _add _sub _mul _div take integers, floats and complex numbers, and stop the program on any other value. When the types are mixed, the operands are raised to the higher type in the order integer, float, complex, and the result has that type.
  • An integer raised to a float is rounded to the nearest value. Raising an integer beyond the range of floats is a runtime error.
  • _div of two integers is the quotient truncated toward 0, and a zero divisor is a runtime error. A division that involves a float or a complex number does not stop on a zero divisor: a float gives an infinity or NaN, and a complex number gives the same rule applied to its components.
  • _mod(a, b) of two integers is a - b * (a / b), and a zero divisor is a runtime error.
  • _lt _le _gt _ge compare an integer and a float by their mathematical values without raising the type, and give false when NaN is involved. They stop the program on a value that is not a number and on a complex number.
  • _eq says that numbers of different types are equal when their values are the same (1 == 1.0). NaN is not equal to itself. Complex numbers are equal when both components are equal. _ne is the opposite of _eq.

An M-expression with any other head, such as Cons{x, y}, is a constructor: its arguments are evaluated and an M-expression with the same head is built.

t2_mexpr.pk

p := Point{3, 4}
println(p)
println(head(p))
println(arity(p))
println(arg(p, 1))
println(Point{1, 2} == Point{1, 2})
println(push(p, 5))

Patterns

A parameter pattern is one of:

  • a variable x, or _ (matches anything and binds nothing)
  • an integer, a string, true, false or none (matches an equal value and binds nothing)
  • Quote{v} (matches an equal value, e.g. Quote{x} matches the symbol x)
  • Head{p, ...} (matches an M-expression with the same head and arity)
  • _TypeOf{p, type} (p matches and the value has the type shown by typeof)

In the syntax, 'none is Quote{none}, x @ int is _TypeOf{x, int}, and x :: xs and [a, b] are patterns of Cons.

t3_type.pk

describe := (n @ int) -> f"integer {n}"
          | (s @ string) -> f"string {s}"
          | (_) -> "other"
put(describe(1)); put("\n")
put(describe("abc")); put("\n")
put(describe('x)); put("\n")

Output

integer 1
string abc
other

Algebraic effects

Handle{body, handler} evaluates body. Perform{v} calls the nearest handler(v, k) that has a matching pattern, where k is the continuation of the Perform. Handlers are deep: they stay installed in the continuation. When no pattern matches, the effect goes to the outer handler.

k is an ordinary function and can be called any number of times, even after Handle has returned. Variables that are defined when the continuation is captured are shared between the resumed copies. A variable defined by x := e after the resumption is defined separately in each copy, unless a function written inside refers to it.

t5_resume.pk

ask() := perform Ask{}

with_answer(v, f) := handle f() with (Ask{}, k) -> k(v)

println(with_answer(21, () -> ask() * 2))
println(with_answer(5, () -> ask() + ask()))

Output

42
10

Top level

The loop looks up the global variables parse and eval for every expression, so a program can replace them and the next expression is handled by the new definitions. Apply{eval, ...} in a program also calls the replaced eval.

  • parse: String -> Tuple{M-expression, rest String}. It skips blanks itself and returns Tuple{Eof{}, ""} when only blanks are left. A replacement parse passes Eof{} through.
  • eval: M-expression -> value.

t6_eval.pk

old_eval := eval
eval = e -> {
    v := old_eval(e)
    put("=> ")
    println(v)
    v
}
1 + 2
'(a + b)
Point{1, 2}

Output

=> 3
=> Apply{_add, Tuple{a, b}}
=> Point{1, 2}
