Syntax

An expression is translated to an M-expression before it is evaluated. An M-expression is also an expression of this syntax.

Associativity

  • |, -> and :: group to the right. + - * / % group to the left. Comparisons do not group: a < b < c is not an expression.
  • :: binds tighter than comparisons and looser than + -, so a + 1 :: b == c is Cons{a + 1, b} == c.
  • () groups an expression.

if and while

The condition of if and while is in parentheses. The body e of while is any expression, and the branches a and b of if are expressions without | outside of brackets, so if (c) a else b | g is (if (c) a else b) | g. A block { ... } is the usual body of several expressions.

else belongs to the nearest if that has no else, so if (a) if (b) x else y is if (a) { if (b) x else y }. else if (c) ... is else followed by an if expression. An if is an expression: y = if (c) 1 else 2.

record

record T(f, g, ...) declares the names of the fields of the values T{a, b, ...}, which are built as before. t.f is the argument of t at the position of the field f in the declaration for the head of t.

Values with different heads can have fields of the same name. Declaring T again replaces the names. A . follows its left operand with no space. A value whose head is not declared or has no field f stops the program with a message.

fun

fun f(p, ...) e declares a function in a block, as f(p, ...) := e does, but all the fun of a block are declared at its top, so each function can call the functions declared after it.

A function is assigned where its fun is, so it sees the variables declared before it in the block, and it can be called after that place. A fun is written only as an expression of a block. It is a variable of the function or the program that contains the block, like x := e.

Names the sugar calls

The functions a piece of sugar expands to have a name starting with _, and there is no function of the same name without _. A variable named add or index_get in a program therefore does not change the meaning of a + b or a[i].

Indexing and rewriting

a[i] is _index_get(a, i) and a[i] = e is _index_set(a, i, e), whose value is the value of e. The [ follows a with no space, so a followed by [1, 2] on the next line or after a space is two expressions. a is a postfix expression such as x, f(x), t.f or b[j]: a[i][j] = e is Apply{_index_set, Tuple{a[i], j, e}}.

_index_get and _index_set are functions joined by |, one for each kind of a, tried in this order:

A string, a list, a tuple and an M-expression are immutable: a[i] = e on them stops the program with a message such as cannot assign to an element of a string, which is immutable: .... A program adds a kind of its own in front of the others by assigning _index_get and _index_set:

_index_set = (Matrix{w, _, d}, (i, j), e) -> { d[i * w + j] = e } | _index_set
m := Matrix{2, 2, array(4)}

none

subst(t, f) rewrites the tree t with the function f. Each part of t is tried from the root down: when a pattern of f matches the part, the part is replaced by the value of f and the parts inside it are not tried; otherwise the arguments of the part are tried and its head is kept. A part that is not an M-expression has no parts.

t[p -> a | q -> b] is the expression p -> a | q -> b in brackets, so its arms are tried in order. An arm may have a guard as in match: in t[p if c -> a | q -> b] the arm applies when p matches and c is true, otherwise the next arm is tried, and a part that no arm applies to is gone into. The body of an arm is an expression up to ->, so | in a body needs parentheses. 't[f] quotes t[f]: a quoted tree to rewrite is written ('e)[f].

r_rewrite.pk

use("unparse")
t := '(x * 1 + 0 * y)
println(unparse(t[Apply{'_mul, Tuple{a, 1}} -> a | Apply{'_mul, Tuple{0, _}} -> 0]))
# with a guard: 1 * 2 is skipped and its parts are tried
u := '(1 * 2 + 3 * 4)
println(unparse(u[Apply{'_mul, Tuple{a @ int, b @ int}} if a > 1 -> a * b]))

Output

"x + 0"
"1 * 2 + 12"

for

for (p in e) a evaluates a for each element of the list or the vector e, with the elements matched by the pattern p, and has the value none. The variables of a outside the loop are shared, so a can assign them.

return, break and continue

return e ends the call of the function that contains it, with the value e (none without e; e must start on the same line and is an expression up to ->, without |, := and = outside of brackets). break ends the innermost while or for that contains it.

They are effects: the function is translated to Handle{body, (Return{v}, k) -> v} when its body has a return, and the loop to Handle{loop, (Break{}, k) -> none} when its body has a break. continue goes on to the next round of the innermost while or for that contains it: the body of the loop is translated to Handle{body, (Continue{}, k) -> none} when it has a continue. A continue outside of a loop stops the program with unhandled effect: Continue{}.

A return in a for body or in an arm of match belongs to the function around them, and one in a function written inside belongs to that function.

match

match e { f } evaluates e once and calls the function f with it. f is an expression up to |, usually functions of one parameter joined by |, the arms, so the first arm whose pattern matches e is selected. An arm takes one parameter: (a, b) -> x takes two, and ((a, b)) -> x takes a tuple. A | may start a line, and the arms after the first one are usually written so:

match e {
    p -> a
  | q -> b
}

The guard if c of (p, ...) if c -> e | g is evaluated after the parameters matched, with their variables. When it is false, or the arguments do not match the parameters, g is called with the same arguments, so g is the arms after it. Without | g the call fails as a call of a function with no matching pattern does. g is what is joined after the function by | in the text, also when the function is in parentheses: (p if c -> a) | g. A function with a guard that is given by a variable, as h | g after h := p if c -> a, does not call g. The guard and e of match are expressions up to ?:, so a lambda needs parentheses. The function binds variables whose names start with %, which no identifier can name.

Parameter patterns

Parameters p and the patterns of for are written as expressions up to or, and are the M-expressions of the table above, matched as the patterns of Values, patterns, M-expressions, with these rules:

  • The name of an operator or of a called function is a symbol: a + b is Apply{Quote{_add}, Tuple{a, b}}, -a is Apply{Quote{_sub}, Tuple{0, a}} and f(p, ...) is Apply{Quote{f}, Tuple{p, ...}}, so they match the trees of x + 1, -x and f(1). a and b and a or b are If{a, b, Quote{false}} and If{a, Quote{true}, b}.
  • The other identifiers are variables. The arguments of Head{p, ...} are patterns, so Apply{f, Tuple{x}} matches a call of any function with one argument and binds f.
  • 'e is Quote{e} for the expression e.
  • The forms are the operators or and not == != <= >= < > :: + - * / %, the unary - and ', f(p, ...), p @ type, Head{p, ...}, identifiers, integers, strings, (), (p), (p, q, ...) and [p, ...], with the same binding as in expressions: a @ int + b @ int is (a @ int) + (b @ int).

Lexical rules

  • Identifiers are [A-Za-z_][A-Za-z0-9_]* except the reserved words
    if else while and or handle with perform match record for in return break continue fun.
  • Integers are decimal (10, -3), 0x1f, 0o17 or 0b101.
  • Strings are "..." in one line with the escapes \a \b \t \n \v \f \r \" \' \\. f"...{e}..." embeds the value of the expression e, which may contain strings and f-strings; {{ and }} are the braces themselves. A string without the prefix f embeds nothing.
  • # starts a comment up to the end of the line.
  • There is no space between f and ( in f(a), between a and [ in a[i], and between Head and { in Head{a}.

r_strings.pk

put("tab:[\t] quote:[\"] backslash:[\\]\n")
x := 7
put(f"{{x}} = {x}\n")
put(f"{x * 6} {"inner"} {f"n{x}"}\n")

Output

tab:[	] quote:["] backslash:[\]

Separators

Expressions in a block are separated by ; or newlines. A top-level expression ends with ;, a newline or the start of another expression.

A binary - must be on the same line as its left operand, so a line starting with -1 is a new expression. Other binary operators may start a line.
