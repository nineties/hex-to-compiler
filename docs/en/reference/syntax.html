Syntax

An expression is translated to an M-expression before it is evaluated. An M-expression is also an expression of this syntax.

A row binds more weakly than the rows below it.

Associativity

  • |, -> and :: group to the right. + - * / % group to the left. Comparisons do not group: a < b < c is not an expression.
  • :: binds tighter than comparisons and looser than + -, so a + 1 :: b == c is Cons{a + 1, b} == c.
  • () groups an expression.

!x on the left of a definition or an assignment

The x of x := e and x = e may be !x, which is Def{!x, e} and Set{!x, e}. Inside a quasi-quote, !x is replaced by the symbol that x holds: with x holding 'i, `{ !x := 0; !x = !x + 1 } is Do{Def{i, 0}, Set{i, Apply{_add, Tuple{i, 1}}}}.

if and while

The condition of if and while is in parentheses. The body e of while is any expression, and the branches a and b of if are expressions without | outside of brackets, so if (c) a else b | g is (if (c) a else b) | g. A block { ... } is the usual body of several expressions.

else belongs to the nearest if that has no else, so if (a) if (b) x else y is if (a) { if (b) x else y }. else if (c) ... is else followed by an if expression. An if is an expression: y = if (c) 1 else 2.

record

record T(f, g, ...) declares the names of the fields of the values T{a, b, ...}, which are built as before. t.f is the argument of t at the position of the field f in the declaration for the head of t.

Values with different heads can have fields of the same name. Declaring T again replaces the names. A . follows its left operand with no space. A value whose head is not declared or has no field f stops the program with a message.

Scope of variables

true, false and none are literals, not identifiers, so they cannot name a variable: true := e, true = e, fun true and true(p) := e are syntax errors. As a parameter, true is a pattern that matches the value true and binds nothing. When x holds 'true, !x := e and !x = e stop the program as Def{true, e} and Set{true, e} do.

Variables have lexical scope, and the variable a name refers to is decided before the expression runs. A variable in the body of a function is a parameter of that function or of a function around it, or a variable defined before it in those functions, and otherwise a variable defined before it at the top level (a global variable). The variables of the caller are not visible. If a name refers to no variable, the program stops with a message before the expression runs. A function keeps the variables of the place where it was made, and they are shared locations: an assignment to them after the function was made is seen by the function.

n := 5

caller() := {

    read_n()
}
println(caller())

x := 1

x := x + 1
println(Tuple{x, get()})
x = 10
println(Tuple{x, get()})

Definition and assignment

The top-level definitions are resolved in the order they are written. A definition written later is not visible to the expressions before it. The body of a function definition f(p, ...) := e sees f itself.

Defining the same name again with x := e or fun f makes a new variable. The functions made before keep referring to the old variable, and only the expressions after the definition see the new one. To overwrite an existing variable, write x = e. It is an assignment to the same variable, so the functions made before also see the new value. In the first half of the example below, f := (x) -> 2 makes a new f and g() is 1. In the second half, h = (x) -> 2 assigns, and k() is 2.

r_scope_redefine.pk

f(x) := 1
g() := f(0)
f := (x) -> 2
println(g())

h(x) := 1
k() := h(0)
h = (x) -> 2
println(k())

Output

1
2

A variable definition x := e (also x := (p) -> e) is defined where it is written, and the expressions before it see the x outside. The right-hand side e sees the previous x too. The new x is made after the right-hand side is evaluated, so x in the right-hand side is undefined if there is no previous x. After x := 1, x := x + 1 makes x 2. A function that calls itself is written as f(p, ...) := e. This is the same at the top level and in a block. A variable of a block is a variable of the function or the program that contains the block.

A function definition that adds a case

A function definition f(p, ...) := e is f(p, ...) = e when f is already a variable of the place where it is written, and otherwise fun f followed by f(p, ...) = e, which defines a new f where it is written. Several definitions of f in one place make one function whose functions are tried in the order they are written.

The variables of the place are the global variables defined by the same file at the top level, and in a function the parameters of the function and the variables defined before it in the function. In a branch of if or the body of while at the top level, they are the variables defined before it in the branch or the body. A variable of a function around it, or a global variable seen from a function, is not of the place. So f(p, ...) := e there defines a new f and does not change the f outside.

fib(0) := 0
fib(1) := 1
fib(n) := fib(n - 1) + fib(n - 2)
println(fib(20))

x := 1
x := x + 1
println(x)

Functions that call each other

Functions that call each other first declare the name with fun f. fun f defines a variable f whose value is none where it is written, and f(p, ...) = e later fills it. f(p, ...) = e is the assignment f = f | (p, ...) -> e: it adds the function after the functions of f, so the functions are tried in the order they are written. none | g is g, so the first f(p, ...) = e after fun f assigns the function (p, ...) -> e itself. The functions may have different numbers of parameters. The functions written after the declaration see f.

r_scope_fun.pk

fun odd
even(n) := if (n == 0) true else odd(n - 1)
odd(n) = if (n == 0) false else even(n - 1)
println(Tuple{even(10), odd(7)})

fun fact
fact(0) = 1
fact(n) = n * fact(n - 1)
println(fact(5))

120

module

module m { ... } is an expression that gathers definitions under the name m. It can be read as sugar for m := (() -> { ... })(), except that the value the body returns is a module value, which has the definitions marked export as its fields.

module bitset {
    export new(n) := i32_array(n / 30 + 1)
    helper(i) := i / 30
    export add(s, i) := {
        w := helper(i)
        s[w] = bit_or(s[w], bit_shl(1, i % 30))
    }
}

The value of this bitset has the fields new and add. The user calls them with ., as in bitset.new(100).

Every module value has the same head Module, and the names and values of its fields are held in a table for each module value. Different modules therefore have different fields. The rule of . is the same as that of reading a field of any other record, and reading a name that is not a field, such as helper that is not marked export, prints a message and stops the program.

  • The scope in the body is that of the body of a function with no parameters. A variable in the body is a variable defined before it in the body, or a variable outside. To call a function defined later, declare it with fun f and add cases with f(p, ...) = e.
  • The definitions in the body are variables of the body and do not become global variables. They do not hide a variable of the same name outside, and the outside cannot assign to them. f(p, ...) := e in the body defines a new f of the body even if there is an f outside.
  • Like m := e, m is defined after the body has been evaluated. The body does not see m, and the functions in the body call each other by their names. Writing module m { ... } again with the same name makes a new variable, as x := e does.
  • The body is read as a whole. Replacing parse inside the body does not affect the rest of that body. To replace the grammar, write it outside the module.
  • module is one top-level expression. The table of global variables is not divided by file, and a file is read one expression at a time as before.

export

export can be written only before f(p, ...) := e, x := e and module n { ... } that stand directly in the body of a module. Writing it anywhere else, such as inside a function, in a branch of if, inside a block or at the top level, is a syntax error. The names of the definitions marked export become the fields of the module value, and a definition without it is not visible from outside.

The value of the field of export x := e is the value of x at the time the body returns. If a function of the body assigns to x later, the field does not change. To show the current value, export a function that reads x. In the following counter, counter.start stays 0 and counter.current() returns the current value.

module counter {
    n := 0
    export start := n
    export next() := {
        n = n + 1
        n
    }
    export current() := n
}

Nested modules

A module can be written inside the body of a module. The inner module n { ... } defines a variable n of the body and is not visible from outside. To show the inner one outside, write export module n { ... }. Then n is a field of the outer module, and its value is a module value too. The body of the inner module sees the variables defined before it in the body of the outer one.

module outer {
    module hidden {
        export f(x) := x + 1
    }
    export module inner {
        export g(x) := hidden.f(x) * 2
    }
}
outer.inner.g(3)

Adding definitions from outside a module

A case cannot be added to a function from outside a module by writing m.f(p, ...) = e. To let the outside add cases, export a function that adds them inside the module.

test

test { ... } can be written directly in the body of a module. test { e } is sugar for if (_testing) { e }, and the variable _testing is false at first. Nothing runs when a library is loaded as usual. planck0 tools/test.pk <library> ... sets _testing to true and then loads the libraries, and the expressions in test run. The test blocks of the libraries that a loaded library uses run too.

The inside of test has the scope of the module body, so the functions that are not marked export can be called. test runs while the body is being evaluated, so it sees the variables defined before it, and m is not defined yet. assert(c, msg) writes msg and stops with status 1 unless c is true. The { ... } of test is an ordinary block, so one block holds at most 64 expressions. Split test when there are more. test is a keyword only directly in the body of a module, and is an ordinary name elsewhere.

module bitset {
    export new(n) := i32_array(n / 30 + 1)
    helper(i) := i / 30
    export add(s, i) := {
        w := helper(i)
        s[w] = bit_or(s[w], bit_shl(1, i % 30))
    }
    test {
        assert(helper(65) == 2, "helper")
        s := new(100)
        add(s, 3)
        assert(s[0] == 8, "add")
    }
}

Indexing and rewriting

a[i] is _index_get(a, i) and a[i] = e is _index_set(a, i, e), whose value is the value of e. The [ follows a with no space, so a followed by [1, 2] on the next line or after a space is two expressions. a is a postfix expression such as x, f(x), t.f or b[j]: a[i][j] = e is Apply{_index_set, Tuple{a[i], j, e}}.

subst(t, f) rewrites the tree t with the function f. Each part of t is tried from the root down: when a pattern of f matches the part, the part is replaced by the value of f and the parts inside it are not tried; otherwise the arguments of the part are tried and its head is kept. A part that is not an M-expression has no parts.

t[p -> a | q -> b] is the expression p -> a | q -> b in brackets, so its arms are tried in order. An arm may have a guard as in match: in t[p if c -> a | q -> b] the arm applies when p matches and c is true, otherwise the next arm is tried, and a part that no arm applies to is gone into. The body of an arm is an expression up to ->, so | in a body needs parentheses. 't[f] quotes t[f]: a quoted tree to rewrite is written ('e)[f].

r_rewrite.pk

use("unparse")
t := '(x * 1 + 0 * y)
println(unparse.text(t[Apply{'_mul, Tuple{a, 1}} -> a | Apply{'_mul, Tuple{0, _}} -> 0]))
# with a guard: 1 * 2 is skipped and its parts are tried
u := '(1 * 2 + 3 * 4)
println(unparse.text(u[Apply{'_mul, Tuple{a @ int, b @ int}} if a > 1 -> a * b]))

Output

"x + 0"
"1 * 2 + 12"

for

for (p in e) a evaluates a for each element of the list or the vector e, with the elements matched by the pattern p, and has the value none. The variables of a outside the loop are shared, so a can assign them.

return, break and continue

return e ends the call of the function that contains it, with the value e (none without e; e must start on the same line and is an expression up to ->, without |, := and = outside of brackets). break ends the innermost while or for that contains it.

They are effects: the function is translated to Handle{body, (Return{v}, k) -> v} when its body has a return, and the loop to Handle{loop, (Break{}, k) -> none} when its body has a break. continue goes on to the next round of the innermost while or for that contains it: the body of the loop is translated to Handle{body, (Continue{}, k) -> none} when it has a continue. A continue outside of a loop stops the program with unhandled effect: Continue{}.

A return in a for body or in an arm of match belongs to the function around them, and one in a function written inside belongs to that function.

match

match e { f } evaluates e once and calls the function f with it. f is an expression up to |, usually functions of one parameter joined by |, the arms, so the first arm whose pattern matches e is selected. An arm takes one parameter: (a, b) -> x takes two, and ((a, b)) -> x takes a tuple. A | may start a line, and the arms after the first one are usually written so:

match e {
    p -> a
  | q -> b
}

The guard if c of (p, ...) if c -> e | g is evaluated after the parameters matched, with their variables. When it is false, or the arguments do not match the parameters, g is called with the same arguments, so g is the arms after it. Without | g the call fails as a call of a function with no matching pattern does. g is what is joined after the function by | in the text, also when the function is in parentheses: (p if c -> a) | g. A function with a guard that is given by a variable, as h | g after h := p if c -> a, does not call g. The guard and e of match are expressions up to ?:, so a lambda needs parentheses. The function binds variables whose names start with %, which no identifier can name.

Parameter patterns

Parameters p and the patterns of for are written as expressions up to or, and are the M-expressions of the table above, matched as the patterns of Values, patterns, M-expressions, with these rules:

  • The name of an operator or of a called function is a symbol: a + b is Apply{Quote{_add}, Tuple{a, b}}, -a is Apply{Quote{_sub}, Tuple{0, a}} and f(p, ...) is Apply{Quote{f}, Tuple{p, ...}}, so they match the trees of x + 1, -x and f(1).
  • The other identifiers are variables. The arguments of Head{p, ...} are patterns, so Apply{f, Tuple{x}} matches a call of any function with one argument and binds f.
  • (f)(p, ...) is Apply{f, Tuple{p, ...}}. The name in parentheses is a variable, not a symbol, so (f)(x) matches a call of any function with one argument and binds f.
  • 'e is Quote{e} for the expression e.
  • The forms are the operators or and not == != <= >= < > :: + - * / %, the unary - and ', f(p, ...), p @ type, Head{p, ...}, (f)(p, ...), identifiers, true, false, none, integers, strings, (), (p), (p, q, ...) and [p, ...], with the same binding as in expressions: a @ int + b @ int is (a @ int) + (b @ int).

Lexical rules

  • Identifiers are [A-Za-z_][A-Za-z0-9_]* except the reserved words
    if else while and or handle with perform match record for in return break continue fun module export
    and the literals true false none.
  • Integers are decimal (10, -3), 0x1f, 0o17 or 0b101.
  • Floats are decimal with a point, as 1.5.
  • Strings are "..." in one line with the escapes \a \b \t \n \v \f \r \" \' \\. f"...{e}..." embeds the value of the expression e, which may contain strings and f-strings; {{ and }} are the braces themselves. A string without the prefix f embeds nothing.
  • # starts a comment up to the end of the line.
  • There is no space between f and ( in f(a), between a and [ in a[i], and between Head and { in Head{a}.

put("tab:[\t] quote:[\"] backslash:[\\]\n")

Separators

Expressions in a block are separated by ; or newlines. A top-level expression ends with ;, a newline or the start of another expression.

A binary - must be on the same line as its left operand, so a line starting with -1 is a new expression. Other binary operators may start a line.
