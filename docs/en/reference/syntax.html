Syntax

The syntax is sugar. Each expression is read into the M-expression in the table below and then evaluated, and the M-expression decides its meaning. An M-expression is also an expression of this syntax. What follows covers what the table cannot: the scope of variables, how function definitions add up, modules and the writing of patterns.

Expressions and M-expressions

A row binds more weakly than the rows below it.

Associativity

  • |, -> and :: group to the right, and + - * / % to the left. Comparisons do not group, so a < b < c is not an expression.
  • :: binds tighter than comparisons and looser than + - (a + 1 :: b == c is Cons{a + 1, b} == c). .. binds tighter than :: and looser than + -, and does not chain (a + 1..b * 2 is Range{a + 1, b * 2}).
  • The condition of if and while is in parentheses. The branches of if are expressions without | outside brackets, so if (c) a else b | g is (if (c) a else b) | g. Write several expressions as a block { ... }. else belongs to the nearest if that has no else.

!x on the left of a definition or an assignment

The x of x := e and x = e may be written !x, which are Def{!x, e} and Set{!x, e}. Inside a quasi-quote, !x is replaced by the symbol that x holds. When x holds 'i, `{ !x := 0; !x = !x + 1 } is Do{Def{i, 0}, Set{i, Apply{_add, Tuple{i, 1}}}}. When x holds 'true, it stops the program, as Def{true, e} does.

record

record T(f, g, ...) names the arguments of the values T{a, b, ...}. Values are built as before. t.f is the argument of t at the position of f in the declaration for the head of t, and the . follows its left operand with no space.

  • Values with different heads can have fields of the same name. Declaring the same T again replaces the names.
  • Using .f on a value whose head is not declared, or that has no field f, stops the program with a message.
  • t with { f = e, g = e2 } is a new value with those fields replaced (t does not change). The fields are replaced from the left, so e can refer to the fields of the original t. with { ... } can follow another one.

t1_with.pk

record Point(x, y)

p := Point{1, 2}
q := p with { y = 5 }
println(p)
println(q)
println(p with { x = p.y, y = p.x })
println(p with { x = 7 } with { y = 8 })

Compound assignment and splitting a tuple

x += e is the same as x = x + e, and -=, *=, /= and %= have the same form. a[i] += e is the same as a[i] = a[i] + e, except that a and i are evaluated once. The left side is a variable or a[i]; t.f += e is not allowed.

Splitting a tuple

(a, b) := e defines variables from the elements of the tuple e, and (a, b) = e assigns to defined variables. The right side is evaluated completely first, so (a, b) = (b, a) swaps. A tuple whose number of elements differs from the number of names, and a value that is not a tuple, stop the program with a message.

t1_destructure.pk

# (a, b) := e defines several variables from the elements of a tuple

(a, b) := (1, 2)
println(a + b)

# swap
(a, b) = (b, a)
println(Tuple{a, b})

# a function that returns two values
divmod(x, y) := (x / y, x % y)
(q, r) := divmod(17, 5)
println(Tuple{q, r})

# in a function and in a loop
fib(n) := {
    (x, y) := (0, 1)
    i := 0
    while (i < n) {
        (x, y) = (y, x + y)
        i = i + 1
    }
    x
}

Scope of variables

The scope is static (lexical): which variable a name refers to is decided before the expression runs. A function refers to the variables of the place where it was made. Variables are shared, so an assignment made after the function was made is also seen by it. Variables of the caller are not visible. A name that refers to no variable stops the program with a message before the expression runs.

  • The function body sees the parameters of that function and of the outer functions, the variables defined earlier in those functions, and the variables defined earlier at the top level (global variables).
  • true, false and none are literals and cannot be variable names. true := e, fun true and true(p) := e are syntax errors. A true in a parameter is a pattern that matches the value true and binds nothing.

Definition and assignment

Defining the same name again by x := e or fun f makes a new variable. Functions made earlier keep the earlier variable. To overwrite an existing variable, write x = e: it assigns to the same variable, so functions made earlier see the new value.

r_scope_redefine.pk

g() := f(0)
f := (x) -> 2
println(g())

h(x) := 1
k() := h(0)
h = (x) -> 2
println(k())

Output

1
2

x := e defines the variable where it is written. The right side sees the earlier x, and if there is none, the x on the right side is undefined. Write a function that calls itself as f(p, ...) := e. This is the same at the top level and in a block.

A function definition that adds a case

How f(p, ...) := e is read depends on whether the variables at the place where it is written have f. If they do, it is the same as f(p, ...) = e. If not, it defines a new f there (fun f followed by f(p, ...) = e). Definitions of f written one after another in the same place form one function, tried in the order written.

The variables at the place are: at the top level, the global variables defined in the same file; in a function, its parameters and the variables defined earlier in it; in the branch of a top-level if or the body of a while, the variables defined earlier in it. Variables of an outer function, global variables seen from inside a function, and global variables or builtin functions of another file (a library loaded by use, or planck/init.pk) are not variables at the place. f(p, ...) := e with such a name defines a new f that hides the outer one and does not change it. To add a definition to an f of another file, write f(p, ...) = e.

A definition can have a guard. f(p, ...) if c := e adds an arm that returns e when the arguments match and c is true. When c is false or the arguments do not match, the next definition written right after it is tried (a different expression in between breaks the chain). After f(x) if x > 0 := "positive", writing f(_) := "other" makes f(-1) be "other". A definition with export and f(p, ...) = e cannot have a guard.

Functions that call each other

Declare the name first with fun f (its value is none) and fill it in later with f(p, ...) = e. That is f = f | (p, ...) -> e, which adds after the function of f. Since none | g is g, the first f(p, ...) = e assigns the function itself. Calling f before it is filled calls none and stops the program.

odd(n) = if (n == 0) false else even(n - 1)
println(Tuple{even(10), odd(7)})

fun fact
fact(0) = 1

When the value of f is a function with a guard (after f = (n) if n > 0 -> 1), a function added by f(p, ...) = e is not called even if the guard is false, just as a guarded function passed through a variable does not call a following | g.

for, and return, break and continue

for (p in e) a matches each element of the list, vector or range e against the pattern p and evaluates a. The value is none, and the variables outside the loop that a sees are shared.

return e ends the call of the function that contains it with the value e (none without e), and break and continue end the innermost while or for, or go to its next round. e starts on the same line as return. They are read as effects.

  • A function whose body has return becomes Handle{body, (Return{v}, k) -> v}, a loop with break becomes Handle{loop, (Break{}, k) -> none}, and a loop with continue has the body Handle{body, (Continue{}, k) -> none}.
  • A return in the body of a for or in an arm of a match ends the function around them. A return in a function written inside ends that function. A continue outside a loop stops the program with unhandled effect: Continue{}.

match

match e { f } evaluates e once and calls the function f with the value. f is usually one-argument functions joined by |. Each is an arm, and the first arm with a pattern that matches e is chosen. If no arm matches, the program stops, as for a function call (Partial functions and fusion). An arm has one argument; to take a tuple, write ((a, b)) -> x. A | can start a line.

match e {
    p -> a
  | q -> b
}

The guard c of (p, ...) if c -> e | g is evaluated after the arguments match, with their variables. When it is false, or the arguments do not match, g is called with the same arguments. g is the expression joined after the function by | in the source, even inside parentheses. A guarded function passed through a variable, as in h | g after h := p if c -> a, does not call g.

The guard and e of a match are expressions up to the level of or, so put an anonymous function in parentheses.

module

module m { ... } puts definitions together under the name m. The value the body returns is the module value, with the definitions marked export as fields. Reading a name that is not a field (a helper without export) with . stops the program with a message.

module bitset {
    export new(n) := i32_array(n / 30 + 1)
    helper(i) := i / 30
    export add(s, i) := {
        w := helper(i)
        s[w] = bit_or(s[w], bit_shl(1, i % 30))
    }
}

The fields of this bitset are new and add.

  • The scope of the body is that of the body of a function with no parameters. To call something defined later from earlier code, use fun f and f(p, ...) = e.
  • The definitions of the body are variables of the body, not global variables. They do not hide a same name outside, and cannot be assigned from outside. To let outside code add cases, export the function to add to (m.f(p, ...) = e is not allowed).
  • m is defined after the body is evaluated, so the body cannot see m. Functions in the body call each other by name.
  • The body is read as a whole, so replacing parse inside it does not affect the rest of the body. Replace a grammar outside the module.

export

export can be written only before f(p, ...) := e, x := e and module n { ... } directly in the body of a module; anywhere else is a syntax error. The field of export x := e is the value of x when the body returns, and later assignments do not change it. To show the current value, export a function that reads x.

module counter {
    n := 0
    export start := n
    export next() := {
        n = n + 1
        n
    }
    export current() := n
}

An inner module n { ... } defines the variable n of the body and is invisible from outside. To show it, write export module n { ... }. The inner body sees the variables the outer body defined earlier.

module outer {
    module hidden {
        export f(x) := x + 1
    }
    export module inner {
        export g(x) := hidden.f(x) * 2
    }
}
outer.inner.g(3)

test

test { ... } can be written directly in the body of a module. It is sugar for if (_testing) { ... }, and _testing is false at first, so nothing runs normally. planck0 tools/test.pk <library> ... sets _testing to true, loads the libraries, and runs the test of those and of the libraries they use.

The scope is that of the body of the module, so functions without export can be called. A test runs while the body is being evaluated, so it sees the variables defined before it, and m is not defined yet. assert(c, msg) writes msg and stops with status 1 unless c is true. A block holds at most 64 expressions, so split a long test.

module bitset {
    export new(n) := i32_array(n / 30 + 1)
    helper(i) := i / 30
    export add(s, i) := {
        w := helper(i)
        s[w] = bit_or(s[w], bit_shl(1, i % 30))
    }
    test {
        assert(helper(65) == 2, "helper")
        s := new(100)
        add(s, 3)
        assert(s[0] == 8, "add")
    }
}

import

import a::b loads the same way as use("a/b"), and the same file is loaded once. The last name is the name of the module the file defines. It can be written wherever an expression can. How to take names follows the path.

Indexing and rewriting

a[i] is _index_get(a, i) and a[i] = e is _index_set(a, i, e), whose value is that of e. The [ follows a with no space ([1, 2] after a space is a different expression). a[i][j] = e is Apply{_index_set, Tuple{a[i], j, e}}. They are functions for each kind joined by |, tried in this order.

subst(t, f) rewrites the tree t with the function f. It tries each part of t from the root: if a pattern of f matches, the part is replaced by the value of f and its inside is not tried. Otherwise the head is kept and the arguments are tried in order. A part that is not an M-expression is not taken apart.

t[p -> a | q -> b] tries the arms in order. Guards work as in match: t[p if c -> a | q -> b] uses the arm when p matches and c holds. For a part that no arm matches, its inside is tried. The body of an arm is an expression up to the level of ->, so put a | inside it in parentheses. 't[f] is the quote of t[f], so to rewrite a quoted tree write ('e)[f].

r_rewrite.pk

use("unparse")
t := '(x * 1 + 0 * y)
println(unparse.text(t[Apply{'_mul, Tuple{a, 1}} -> a | Apply{'_mul, Tuple{0, _}} -> 0]))
# with a guard: 1 * 2 is skipped and its parts are tried
u := '(1 * 2 + 3 * 4)
println(unparse.text(u[Apply{'_mul, Tuple{a @ int, b @ int}} if a > 1 -> a * b]))

"x + 0"

Rest arguments

The last parameter of a function can be written x.... x is bound to the Tuple of the remaining arguments (Tuple{} if none). It can be written only as the last parameter of a function f(p, x...) := e or (p, x...) -> e and of a pattern Head{p, x...}, and a call with fewer arguments than the preceding parameters does not match. Writing it anywhere else, as an argument of a call, or in a guarded function stops the program with a message before the expression runs.

r_rest.pk

# A rest parameter x... takes the remaining arguments as a Tuple

sum_tuple(t) := {
    s := 0
    i := 0
    while (i < arity(t)) {
        s = s + arg(t, i)
        i = i + 1
    }
    s
}

# the last parameter of a function
total(xs...) := sum_tuple(xs)
println(total())
println(total(1, 2, 3))

# after the fixed parameters
scale(k, xs...) := k * sum_tuple(xs)
println(scale(10, 1, 2, 3))

# in a function written with ->
count := (first, others...) -> 1 + arity(others)
println(count(7, 8, 9))

# arms with fewer parameters are chosen by the number of arguments
describe(a) := "one"
describe(a, b) := "two"
describe(a, b, c...) := "three or more"

Parameter patterns

A parameter p and the pattern of for are written as expressions up to the level of or. They are turned into the M-expression of the table and matched as patterns. The principle is that they are written like expressions, with identifiers as variables. The exceptions are:

  • The names of operators and called functions are symbols. x + 1 matches the tree Apply{Quote{_add}, Tuple{x, 1}} and f(p, ...) matches Apply{Quote{f}, Tuple{p, ...}}. To make the called function a variable, write (f)(p, ...) (Apply{f, Tuple{p, ...}}).
  • 'e is Quote{e}, p @ type checks a type, and x... is the rest of the last parameter.
  • Writing the same name twice, as in f(a, a), matches only when the two values are equal by ==.
  • p or q matches either. Variables are allowed only when every branch binds the same variables (f((x, 0) or (0, x)) := x). To match the M-expression If{a, true, b} of an expression or, write If{a, 'true, b}.
  • The forms allowed are operators (or and not == != <= >= < > :: + - * / %, unary - and '), f(p, ...), Head{p, ...}, identifiers, true false none, integers, strings, tuples and lists. Grouping is as in expressions.

r_pattern.pk

simp(e) := match e {
    a @ int + b @ int -> a + b
  | a + 0 -> a
  | x * y if x == y -> `sq(!x)
  | _ -> e
}
println(simp('(1 + 2)))
println(simp('(z + 0)))
println(simp('(z * z)))
swap(a + b) := `(!b + !a)
println(swap('(1 + 2)))
callee((f)(x)) := f
println(callee('g(1)))

macro

macro p := e adds a rule that rewrites trees before evaluation. p is written like a parameter pattern and describes the shape of a tree, and e is evaluated with the variables of p to give the new tree. It does not touch the syntax that turns strings into M-expressions.

r_macro.pk

macro Twice{x} := `(!x + !x)
macro unless(c, e) := `if (not !c) !e

println(Twice{21})
unless(1 > 2, println("shown"))
unless(1 < 2, println("not shown"))

# a quote is not rewritten
println('(Twice{1}))

Output

42
"shown"
Twice{1}
  • Before a parsed expression is evaluated (also a tree given to eval), each part is rewritten from the root. Rules are tried from the last added, and a part that matches none stays. A rewritten part gets the rules again until it no longer changes, and then its inside is rewritten.
  • The inside of a quote 'e is not rewritten. In a quasi-quote `e only the inside of !e is. The parameter patterns of functions and the names defined by Def, Set and Declare are not rewritten either.
  • Applying more than 1000 rules while rewriting one expression stops with an error (a rule that never ends stops too).
  • A rule is in effect from the position of the macro to the end of the innermost function or module body around it, or to all the following expressions if nothing surrounds it. An export macro in a module is in effect also outside it, after the definition of that module.

r_macro_module.pk

module shapes {
    macro Inside{x} := `(!x + 100)
    export macro Double{x} := `(!x * 2)
    export f() := Inside{1}
}
println(shapes.f())
println(Double{21})
println('(Inside{1}))

Lexical rules

  • An identifier is [A-Za-z_][A-Za-z0-9_]*[?!]?, except the reserved words if else while and or handle with perform match record for in return break continue fun macro module export import is and the literals true false none. A ? or ! right after a name with no space is part of the name (empty?(x); x!=y is x != y).
  • An integer is decimal, 0x1f, 0o17 or 0b101, with no limit on the digits. A float needs digits on both sides of the point and may have an exponent (1.5e-3, 6.02e23). An imaginary literal puts i right after the number (2i is complex(0, 2)).
  • A string is "..." on one line, with the escapes \0 \a \b \t \n \v \f \r \" \' \\. f"...{e}..." embeds the value of the expression e (which can contain strings and f-strings), and {{ and }} are one brace each.
  • A comment runs from # to the end of the line.
  • No space goes between the f and ( of f(a), the a and [ of a[i], or the Head and { of Head{a}.
  • Expressions in a block are separated by ; or a newline. A top-level expression ends at ;, a newline or the start of the next expression. A binary - is on the same line as its left operand, so a line that starts with -1 is a new expression. Other binary operators can start a line.
