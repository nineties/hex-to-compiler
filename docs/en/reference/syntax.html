Syntax

The syntax is sugar. Each expression is read into the M-expression in the table below and then evaluated, and the M-expression decides its meaning. An M-expression is also an expression of this syntax. The functions the sugar calls have names that start with _ (Names the sugar calls), so they never clash with names in a program.

A row binds more weakly than the rows below it.

Associativity

  • |, -> and :: group to the right. + - * / % group to the left. Comparisons do not group, so a < b < c is not an expression.
  • :: binds tighter than comparisons and looser than + -. So a + 1 :: b == c is Cons{a + 1, b} == c.
  • .. binds tighter than :: and looser than + -, and does not chain, so a..b..c is not an expression. a + 1..b * 2 is Range{a + 1, b * 2}.

!x on the left of a definition or an assignment

The x of x := e and x = e may be written !x. They are Def{!x, e} and Set{!x, e}. Inside a quasi-quote, !x is replaced by the symbol that x holds. For example, when x holds 'i, `{ !x := 0; !x = !x + 1 } is Do{Def{i, 0}, Set{i, Apply{_add, Tuple{i, 1}}}}.

if and while

The condition of if and while is in parentheses. The body e of while is any expression. The branches a and b of if are expressions without | outside brackets, so if (c) a else b | g is (if (c) a else b) | g. Write several expressions as a block { ... }.

else belongs to the nearest if that has no else, so if (a) if (b) x else y is if (a) { if (b) x else y }. else if (c) ... is else followed by an if expression.

record

record T(f, g, ...) declares names for the arguments of the values T{a, b, ...}. An argument with a name is a field. Values are built as before. t.f is the argument of t at the position of f in the declaration for the head of t.

  • Values with different heads can have fields of the same name.
  • Declaring the same T again replaces the names.
  • A . follows its left operand with no space.
  • Using .f on a value whose head is not declared, or that has no field f, stops the program with a message.

t with { f = e, g = e2 } is a new value in which the fields f and g of t are the values of e and e2. t does not change. The fields are replaced from the left, so e can refer to the fields of the original t.

t is a postfix expression such as x, f(x) or t.f, and with { ... } can follow another one (t with { f = 1 } with { g = 2 }). Using it on a value that is not an M-expression, or that has no such field, stops the program with a message.

p := Point{1, 2}

println(q)
println(p with { x = p.y, y = p.x })

Compound assignment

x += e is the same as x = x + e. -=, *=, /= and %= have the same form, with the operators -, *, / and %. a[i] += e is the same as a[i] = a[i] + e, except that a and i are evaluated once. The left side is a variable or a[i]; t.f += e is not allowed. The value is the assigned value.

Splitting a tuple

(a, b) := e defines a and b from the elements of the tuple e. (a, b) = e assigns them to the variables already defined. The left side is two or more names separated by , in parentheses. The right side is evaluated before any assignment, so (a, b) = (b, a) swaps the two values. A tuple whose number of elements differs from the number of names, and a value that is not a tuple, stop the program with a message.

t1_destructure.pk

# (a, b) := e defines several variables from the elements of a tuple

(a, b) := (1, 2)
println(a + b)

# swap

println(Tuple{a, b})

# a function that returns two values
divmod(x, y) := (x / y, x % y)
(q, r) := divmod(17, 5)
println(Tuple{q, r})

# in a function and in a loop
fib(n) := {
    (x, y) := (0, 1)
    i := 0
    while (i < n) {
        (x, y) = (y, x + y)
        i = i + 1
    }
    x
}

Scope of variables

true, false and none are literals, not identifiers, so they cannot name a variable: true := e, true = e, fun true and true(p) := e are syntax errors. As a parameter, true is a pattern that matches the value true and binds nothing. When x holds 'true, !x := e and !x = e stop the program, as Def{true, e} and Set{true, e} do.

Variables have lexical scope. Which variable a name refers to is decided before the expression runs.

  • A variable in the body of a function is a parameter of that function or of a function around it, or a variable defined earlier in those functions. Otherwise it is a variable defined earlier at the top level (a global variable).
  • The variables of the caller are not visible.
  • When a name refers to no variable, the program stops with a message before the expression runs.
  • A function refers to the variables of the place where it was made. They are shared, so an assignment made after the function was made is seen by the function.

Definition and assignment

Top-level definitions are resolved in the order they are written. A definition written later is not visible to the expressions before it. The body of a function definition f(p, ...) := e sees f itself.

Defining the same name again with x := e or fun f makes a new variable. The functions made before keep referring to the old variable, and only the expressions after the definition see the new one. To overwrite an existing variable, write x = e. It assigns to the same variable, so the functions made before also see the new value.

r_scope_redefine.pk

f(x) := 1
g() := f(0)

println(k())

A variable definition x := e (also x := (p) -> e) is defined where it is written, so the expressions before it see the x outside. The right-hand side e also sees the previous x. The new x is made after the right-hand side is evaluated, so x in the right-hand side is undefined when there is no previous x. Therefore a function that calls itself is written as f(p, ...) := e. This is the same at the top level and in a block. A variable of a block is a variable of the function or the program that contains the block.

A function definition that adds a case

How f(p, ...) := e is read depends on whether f is a variable of the place where it is written.

  • If it is, the definition is the same as f(p, ...) = e.
  • If it is not, the definition is fun f followed by f(p, ...) = e, which defines a new f where it is written.

Several definitions of f in one place make one function, and its cases are tried in the order they are written.

A definition can have a guard too. f(p, ...) if c := e adds to f an arm that gives e when the arguments match p, ... and c is true. When c is false, or the arguments do not match, the arms after it are tried with the same arguments. The arms after it are the definitions of f written after it in a row in the same place. A definition with another expression between does not follow. After f(x) if x > 0 := "positive", writing f(_) := "other" makes f(-1) return "other". A definition marked export and f(p, ...) = e cannot have a guard.

The variables of the place are these.

  • At the top level: the global variables defined by the same file.
  • In a function: the parameters of the function and the variables defined earlier in the function.
  • In a branch of if or the body of while at the top level: the variables defined earlier in the branch or the body.

A variable of a function around it, or a global variable seen from a function, is not a variable of the place. So f(p, ...) := e with the same name defines a new f and does not change the f outside.

Functions that call each other

Functions that call each other first declare the name with fun f, and fill it in later with f(p, ...) = e.

  • fun f defines a variable f whose value is none, where it is written.
  • f(p, ...) = e is the assignment f = f | (p, ...) -> e. It adds the function after the functions of f. The added functions are tried in the order they are written, and may have different numbers of parameters.
  • none | g is g, so the first f(p, ...) = e after fun f assigns the function (p, ...) -> e itself.

println(Tuple{even(10), odd(7)})

fact(0) = 1

module

module m { ... } is an expression that gathers definitions under the name m. It can be read as sugar for m := (() -> { ... })(), except that the body returns a module value, whose fields are the definitions marked export.

module bitset {
    export new(n) := i32_array(n / 30 + 1)
    helper(i) := i / 30
    export add(s, i) := {
        w := helper(i)
        s[w] = bit_or(s[w], bit_shl(1, i % 30))
    }
}

The value of this bitset has the fields new and add.

Every module value has the head Module, and its fields differ for each module value. . reads a field in the same way as for any other record. Reading a name that is not a field, such as helper that is not marked export, prints a message and stops the program.

  • The scope in the body is that of the body of a function with no parameters. A variable in the body is a variable defined earlier in the body, or a variable outside. To call a function defined later, declare it with fun f and add cases with f(p, ...) = e.
  • The definitions in the body are variables of the body and do not become global variables. They do not hide a variable of the same name outside, and the outside cannot assign to them. f(p, ...) := e in the body defines a new f of the body, even if there is an f outside.
  • Like m := e, m is defined after the body has been evaluated. The body does not see m, so the functions in the body call each other by their own names. Writing module m { ... } again with the same name makes a new variable, as x := e does.
  • The body is read as a whole. Replacing parse inside the body does not affect the rest of that body. To replace the grammar, write it outside the module.
  • module is one top-level expression.

export

export may be written only before f(p, ...) := e, x := e and module n { ... } that stand directly in the body of a module. Writing it anywhere else is a syntax error: inside a function, in a branch of if, inside a block, or at the top level. The names of the definitions marked export become the fields of the module value. A definition without export is not visible from outside.

The value of the field of export x := e is the value of x when the body returns. If a function of the body assigns to x later, the field does not change. To show the current value, export a function that reads x. In the following counter, counter.start stays 0 and counter.current() returns the current value.

module counter {
    n := 0
    export start := n
    export next() := {
        n = n + 1
        n
    }
    export current() := n
}

Nested modules

A module can be written inside the body of a module. The inner module n { ... } defines a variable n of the body, and is not visible from outside. To show the inner one outside, write export module n { ... }. Then n is a field of the outer module, and its value is a module value too. The body of the inner module sees the variables defined earlier in the body of the outer one.

module outer {
    module hidden {
        export f(x) := x + 1
    }
    export module inner {
        export g(x) := hidden.f(x) * 2
    }
}
outer.inner.g(3)

Adding definitions from outside a module

Writing m.f(p, ...) = e cannot add a case to a function from outside a module. To let the outside add cases, export a function that adds them inside the module.

test

test { ... } can be written directly in the body of a module. test { e } is sugar for if (_testing) { e }, and the variable _testing is false at first. Nothing runs when a library is loaded as usual. planck0 tools/test.pk <library> ... sets _testing to true and then loads the libraries, and the expressions in test run. The test blocks of the libraries that a loaded library uses run too.

The inside of test has the scope of the module body, so it can call functions that are not marked export. test runs while the body is being evaluated, so it sees the variables defined earlier, and m is not defined yet.

assert(c, msg) writes msg and stops with status 1 unless c is true. The { ... } of test is an ordinary block, so one block holds at most 64 expressions. Split test when there are more. test is a keyword only directly in the body of a module, and is an ordinary name elsewhere.

module bitset {
    export new(n) := i32_array(n / 30 + 1)
    helper(i) := i / 30
    export add(s, i) := {
        w := helper(i)
        s[w] = bit_or(s[w], bit_shl(1, i % 30))
    }
    test {
        assert(helper(65) == 2, "helper")
        s := new(100)
        add(s, 3)
        assert(s[0] == 8, "add")
    }
}

import

import a::b loads a file of a library. It loads as use("a/b") does, and a file is loaded once. The path is names separated by ::, and the last name is the name of the module that the file defines. import can be written wherever an expression can.

The forms after the path decide how the names are taken in.

FormMeaning
import mOnly loads the module m. A field is read as m.f.
import m as nAdds n := m.
import m (x, y)Defines the fields x and y as x := m.x and y := m.y.
import m (*)Defines all the fields under their own names.
import m hiding (x, y)Defines all the fields but x and y under their own names.
  • as n can come before (x, y), (*) and hiding (...).
  • as, (...) and hiding are written on the same line as m.
  • Naming a field that m does not have in (x, y) prints the same message as reading the field with ., and stops the program.
  • The names that (*) and hiding define are global variables, even when import is written in a function. The names that (x, y) and as define are local variables in a function.

Indexing and rewriting

a[i] is _index_get(a, i), and a[i] = e is _index_set(a, i, e), whose value is the value of e. The [ follows a with no space, so [1, 2] after a space or on the next line is a separate expression. a is a postfix expression such as x, f(x), t.f or b[j], so a[i][j] = e is Apply{_index_set, Tuple{a[i], j, e}}.

_index_get and _index_set are functions joined by |, one for each kind of a. They are tried in this order.

A string, a list, a tuple and an M-expression are immutable. a[i] = e on them stops the program with a message such as cannot assign to an element of a string, which is immutable: .... These stop the program with a message: an index outside a string, a list or the arguments of an M-expression, and an a[i] or a[i] = e that no kind accepts.

A program adds a kind of its own in front of the others by assigning _index_get and _index_set.

subst(t, f) rewrites the tree t with the function f. Each part of t is tried from the root down.

  • When a pattern of f matches the part, the part is replaced by the value of f, and the parts inside it are not tried.
  • Otherwise the arguments of the part are tried and its head is kept.
  • A part that is not an M-expression has no parts to try.

t[p -> a | q -> b] is the expression p -> a | q -> b in brackets, so its arms are tried in order. An arm may have a guard, as in match. In t[p if c -> a | q -> b], the arm applies when p matches and c is true. Otherwise the next arm is tried, and the inside of a part that no arm applies to is tried.

The body of an arm is an expression up to ->, so a | in a body needs parentheses. 't[f] is the quotation of t[f]. To rewrite a quoted tree, write ('e)[f].

r_rewrite.pk

use("unparse")
t := '(x * 1 + 0 * y)
println(unparse.text(t[Apply{'_mul, Tuple{a, 1}} -> a | Apply{'_mul, Tuple{0, _}} -> 0]))
# with a guard: 1 * 2 is skipped and its parts are tried
u := '(1 * 2 + 3 * 4)
println(unparse.text(u[Apply{'_mul, Tuple{a @ int, b @ int}} if a > 1 -> a * b]))

Output

"x + 0"
"1 * 2 + 12"

for

for (p in e) a evaluates a for each element of the list, the vector or the range e, with the element matched by the pattern p. Its value is none. The variables of a outside the loop are shared, so a can assign to them.

return, break and continue

return e ends the call of the function that contains it, with the value e (none without e). e starts on the same line as return and is an expression up to ->, without |, := and = outside brackets. break ends the innermost while or for that contains it.

They are effects, and are translated as follows.

  • A function whose body has a return becomes Handle{body, (Return{v}, k) -> v}.
  • A loop whose body has a break becomes Handle{loop, (Break{}, k) -> none}.
  • A loop whose body has a continue has its body translated to Handle{body, (Continue{}, k) -> none}.

continue goes on to the next round of the innermost while or for that contains it. A continue outside a loop stops the program with unhandled effect: Continue{}.

A return in a for body or in an arm of match ends the call of the function around them. A return in a function written inside ends the call of that function.

match

match e { f } evaluates e once and calls the function f with the value. f is an expression up to |, usually functions of one parameter joined by |. Each joined function is an arm, and the first arm whose pattern matches e is selected. An arm takes one parameter: (a, b) -> x takes two, and ((a, b)) -> x takes a tuple.

A | may start a line. The arms after the first one are usually written so:

match e {
    p -> a
  | q -> b
}

The guard if c of (p, ...) if c -> e | g is evaluated after the parameters matched, with their variables. When it is false, or the arguments do not match the parameters, g is called with the same arguments. Without | g, the call fails as a call of a function with no matching pattern does.

g is the arms after it. In the text, it is what is joined after the function by |, also when the function is in parentheses: (p if c -> a) | g. A function with a guard that is given by a variable, as h | g after h := p if c -> a, does not call g.

The guard and e of match are expressions up to or, so a lambda needs parentheses. The function binds variables whose names start with %, which no identifier can name.

Rest arguments

The last argument of a function can be written x.... x is bound to a Tuple of the arguments left after the preceding ones, and to Tuple{} when none are left. x... is the tree _Rest{x}.

  • It may be the last argument of a function f(p, x...) := e or (p, x...) -> e, and the last argument of a pattern Head{p, x...}.
  • A call with fewer arguments than the preceding ones does not match.
  • Writing x... anywhere but last, in the arguments of a call, or in a function with a guard stops the program with a message before the expression runs.

# A rest parameter x... takes the remaining arguments as a Tuple

sum_tuple(t) := {
    s := 0
    i := 0
    while (i < arity(t)) {
        s = s + arg(t, i)
        i = i + 1
    }

# the last parameter of a function

Parameter patterns

Parameters p and the patterns of for are written as expressions up to or. They become the M-expressions of the table above, and are matched as the patterns of Values, patterns, M-expressions. The rules are these.

  • The name of an operator or of a called function is a symbol. a + b is Apply{Quote{_add}, Tuple{a, b}}, -a is Apply{Quote{_sub}, Tuple{0, a}}, and f(p, ...) is Apply{Quote{f}, Tuple{p, ...}}. So they match the trees of x + 1, -x and f(1).
  • Other identifiers are variables. The arguments of Head{p, ...} are patterns, so Apply{f, Tuple{x}} matches a call of any function with one argument, and binds f.
  • (f)(p, ...) is Apply{f, Tuple{p, ...}}. The name in parentheses is a variable, not a symbol, so (f)(x) matches a call of any function with one argument and binds f.
  • 'e is Quote{e} for the expression e.
  • x... can be written only as the last argument (Rest arguments).
  • p or q matches what p or q matches. They can be written in a row, a or b or c, and anywhere in an argument (F{1 or 2, x}). When none matches, it is the same as a pattern that does not match.
  • An alternative of or can write variables only when every alternative binds the same variables (f((x, 0) or (0, x)) := x). Otherwise it is an error and the program stops.
  • A name written twice in the parameters, as in f(a, a), matches only two values that are equal by ==. f([1], [1]) matches.
  • To match the M-expression If{a, true, b} of an or expression, write If{a, 'true, b}.
  • The forms are listed below. They bind as in expressions, so a @ Int + b @ Int is (a @ Int) + (b @ Int).
    • Operators: or and not == != <= >= < > :: + - * / %, the unary - and '
    • Calls and types: f(p, ...), p @ type, Head{p, ...}, (f)(p, ...)
    • Values: identifiers, true, false, none, integers, strings
    • Tuples and lists: (), (p), (p, q, ...), [p, ...]

simp(e) := match e {
    a @ int + b @ int -> a + b

  | x * y if x == y -> `sq(!x)
  | _ -> e

macro

macro p := e adds a rule that rewrites a tree before it is evaluated. p is written as a parameter pattern and stands for the shape of a tree. e is evaluated with the variables of p, and its value is the new tree. macro turns an M-expression into another M-expression. It does not touch the syntax that turns a string into an M-expression.

r_macro.pk

macro Twice{x} := `(!x + !x)
macro unless(c, e) := `if (not !c) !e

println(Twice{21})
unless(1 > 2, println("shown"))
unless(1 < 2, println("not shown"))

# a quote is not rewritten
println('(Twice{1}))

Output

42
"shown"
Twice{1}

The rewriting is done after an expression is read and before it is evaluated. A tree given to eval is rewritten in the same way. It proceeds in this order.

  • Each part of the tree is rewritten by the rules from the root down. The rules added last are tried first, and a part that no rule matches stays as it is.
  • The rules are applied to a rewritten part until it no longer changes. Then the parts inside the result are rewritten.
  • The inside of a quote 'e is not rewritten. The inside of a quasi-quote `e is rewritten only where it is unquoted by !e.
  • The parameter patterns of a function and the names that Def, Set and Declare define are not rewritten. The body of a function is rewritten.

The rewriting stops with an error when the rules are applied more than 1000 times while one expression is rewritten. So a rule that never settles, such as macro A{x} := `A{!x + 1}`, stops too.

A rule is added from the place of the macro in the expression that was read. It applies to the end of the body of the innermost function or module around the macro, including the parts inside. When nothing surrounds it, it applies to all the expressions after it. export macro in a module also applies outside the module, after the definition of the module. macro is a reserved word.

r_macro_module.pk

module shapes {
    macro Inside{x} := `(!x + 100)
    export macro Double{x} := `(!x * 2)
    export f() := Inside{1}
}
println(shapes.f())
println(Double{21})
println('(Inside{1}))

Output

101
42
Inside{1}

Lexical rules

  • Identifiers are [A-Za-z_][A-Za-z0-9_]*[?!]?, except the reserved words
    if else while and or handle with perform match record for in return break continue fun macro module export import is
    and the literals true false none.
  • A ? or ! right after a name, with no space, is part of the name. empty?(x) and x? are names, and x!=y is x != y. In a grammar, a ? after the name of a rule is the optional item, as in x:digits?.
  • Integers are decimal (10, -3), 0x1f, 0o17 or 0b101. The number of digits is not limited.
  • Floats are decimal with a point (1.5, -0.25). Digits are needed on both sides of the point. e or E and an integer exponent, which may have a -, may follow (1.5e-3, 2.0E10, 6.02e23).
  • true, false and none are literals whose values are the symbols of the same names.
  • Imaginary literals are an integer or a float followed directly by i (2i, 1.5i). 2i is complex(0, 2).
  • Strings are "..." in one line with the escapes \0 \a \b \t \n \v \f \r \" \' \\. f"...{e}..." embeds the value of the expression e, which may contain strings and f-strings. {{ and }} are the braces themselves. A string without the prefix f embeds nothing.
  • # starts a comment that runs to the end of the line.
  • Do not put a space between f and ( in f(a), between a and [ in a[i], or between Head and { in Head{a}.

put("tab:[\t] quote:[\"] backslash:[\\]\n")

Separators

Expressions in a block are separated by ; or newlines. A top-level expression ends with ;, a newline or the start of another expression.

A binary - must be on the same line as its left operand, so a line starting with -1 is a new expression. Other binary operators may start a line.
