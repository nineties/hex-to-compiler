vasm

use("vasm/check") defines a low-level language. The functions and structs written in vasm{| ... |} are checked by the rules of ownership and borrowing. An own value has exactly one owner and is moved or freed at most once. A borrow is valid only inside its region, and while it is borrowed, the source cannot be touched.

Programs

A program is a list of structs and functions. Both are visible from everywhere in the module. Statements are separated by newlines or ;.

struct S { f: T, g: T }
fn f[r, ...](x: T, ...) -> T { ... }

The [r, ...] of a function are region parameters, fixed by the borrows of the arguments at a call. If one cannot be fixed, it is an error. A struct or a function cannot have the name of a built-in function.

Values and initialization

  • Only an initialized register can be read. After an if, only what both branches initialized is initialized; after a while, the state is the one before the loop.
  • Both operands of an integer operation have the same type; match different widths or signedness with as. Widening extends the sign or zero-extends according to the source, and narrowing keeps the low bits.
  • An integer literal is checked to be in the range of the type of its target, argument or other operand. A single literal ranges from -32768 to 32767. A larger value is built, as in m = 0x7F45, m = m << 16, m = m | 0x4C46.
  • A string literal is a &static [u8] in read-only data. It has the escapes of planck strings and no terminator: len gives the number of bytes. It can be written where an operand is taken (write(1, "hello\n")), and its elements cannot be written.
  • An index is an i64, and whether it is in range is left to a run-time check; the checker looks at types and ownership only. An array cannot be read or written as a whole through *p.
  • A struct value is copied like an integer unless it owns something, and is moved if it does. s.f is the field of the value if s is a struct register, and the field of the target if s is a pointer.

Ownership

  • An own value is moved or freed at most once. Using a released or moved value, and releasing it again, are errors.
  • When its owner goes away, what an own still holds is released automatically. This happens at the end of a block or a function and at return; at an overwrite (the previous value of p = box(2), *p = v, p[i] = v and s.f = v); when the result of a call is discarded as a statement; and for what is left in a value passed to free.
  • A value that is moved or freed in only one branch has no determined owner afterwards, which is an error. A loop must give back, before the next iteration, a value it moves.
  • A function takes the ownership of a moved argument. The caller cannot use the value afterwards.

Taking out what an own value holds

An own cannot be copied out of a borrow or an element of an array. Use one of these.

  • x = *p: moves the contents when they own something. p must be an own that is not borrowed. Afterwards p is a box without contents, and cannot be read, moved or borrowed until *p = v refills it or free(p).
  • x = s.f: moves a field that owns something out of the struct register s. The field cannot be read until s.f = v puts it back, and s cannot be used as a whole. The remaining fields are released when s goes away.
  • swap(p[i], v), swap(p.f, v), swap(*p, v): the place must be writable from an own that is not borrowed, or from a &mut.

val

A val keeps its kind at run time. The checker only tells val from the other types and does not check kinds; operating on a value of the wrong kind ends the program as failed. A val register is copied like an integer, with no move and no borrow.

The owners of each value are counted, and the value is released when none is left (at the same points as the automatic release of own). An array that holds itself is not released. A val in a field of a struct, the contents of a box or an element of an own array is treated like own and is taken out by swap or a move.

Borrows and regions

  • x = &r p requires that p is declared before r and valid to the end of r. The borrow ends with r.
  • While p is borrowed it cannot be moved, freed or assigned. While it is borrowed by &mut, *p, p[i] and p.f cannot be read either.
  • The type &r T can be written only inside r. Putting it in a register outside r or returning it outside is an error. A borrow of an outer region q can be given where a borrow of an inner region r is expected.
  • A shared borrow is duplicated, and any number can exist. A &mut used between registers is moved.
  • A &mut passed to a borrowed parameter is reborrowed for the call only and is not moved. It cannot be passed again to another argument of the same call. It can also go to a & parameter (shared for the call). But when the result type contains the borrowed region, the borrow remains in the result, so it is not a reborrow and the &mut is moved.
  • Region parameters of a function have no inner-outer relation to each other, and are outside the regions opened inside the function. A region parameter is the innermost of the regions of the borrows passed, provided all the others are outside it.
  • The region static outlasts every other region, so a static borrow can be put where a borrow of any region is expected. With no other borrow passed, a region parameter is static. A borrow of another region cannot be put where &static is expected. static cannot name a region or a variable, and only a string literal makes such a borrow.

Kinds of errors

vasm_check.errors(file, m) returns a list of VasmErr{kind, loc, msg}, only the first error of each struct and function. vasm_check.report(file, m) writes the errors as file:line:column: message, or ok when there are none. Examples are in the vasm checker of the implementation.

kindError
'type 'undefinedtypes do not match (width, signedness, literal range, missing fields); an undefined function or struct
'uninit 'moved 'freedreading before initialization; using a moved value or taken-out contents; using a released value, releasing twice
'borrowed 'ownermoving, freeing, assigning, reading or writing while borrowed, and overlapping borrows; copying a value that owns something from a place that is not its owner
'region 'escapea region that is not open, is already open or cannot be fixed; a borrow that leaves its region
'branch 'loopownership states that differ after a branch; a value moved in a loop and not given back
