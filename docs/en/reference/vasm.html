vasm

use("vasm") defines a low-level language. The functions and structs written in vasm{| ... |} are checked by the rules of ownership and borrowing. A use after free, a double free, a violation of borrowing and a read of an uninitialized register are errors. The check uses type rules alone and has no way to switch it off.

Programs

A program is a list of structs and functions. Both are visible from everywhere in the module. Statements are separated by newlines or ;.

struct S { f: T, g: T }
fn f[r, ...](x: T, ...) -> T { ... }

The [r, ...] of a function are region parameters, fixed by the borrows of the arguments at a call. If one cannot be fixed, it is an error. A struct or a function cannot have the name of a built-in function.

Values and initialization

  • Only an initialized register can be read. After an if, only what both branches initialized is initialized; after a while, the state is the one before the loop.
  • Both operands of an integer operation have the same type. Integers of different widths or signedness cannot be mixed; use as to match them. Widening extends the sign or zero-extends according to the source, and narrowing keeps the low bits.
  • An integer literal is checked to be in the range of the type of its target, argument or other operand. A single literal ranges from -32768 to 32767. A larger value is built, as in m = 0x7F45, m = m << 16, m = m | 0x4C46.
  • An index is an i64. Whether it is in range is left to a run-time check; the checker looks at types and ownership only. An array cannot be read or written as a whole through *p.
  • A struct value is copied like an integer unless it owns something, and is moved if it does. s.f is the field of the value if s is a struct register, and the field of the target if s is a pointer to a struct.

Ownership

  • An own value is moved or freed at most once.
  • Where its owner goes away, what an own still holds is released automatically: at the end of a block or a function and at return; when it is overwritten (the previous value of p = box(2), *p = v, p[i] = v and s.f = v); when the result of a call is discarded as a statement; and what is left in a value that is passed to free. The parts of a box, the fields of a struct and the elements of an array that have not been taken out are released.
  • Using a released value, releasing it again and using a moved value are errors.
  • A value that is moved or freed in only one branch has no determined owner afterwards, which is an error. A loop must give back, before the next iteration, a value it moves.
  • A function takes the ownership of a moved argument. The caller cannot use the value afterwards.

Taking out what an own value holds

  • When the contents hold own, x = *p moves them out. p must be an own and not borrowed. Afterwards p is an empty box: it cannot be read, moved or borrowed until *p = v puts contents in again or free(p) frees it. Nothing can be taken out of a borrow.
  • From a struct register s, x = s.f moves out a field that owns. Reading the field taken out or taking it out again is an error; s.f = v puts one back. Afterwards s cannot be used as a whole, and the remaining fields are released where s goes away.
  • An element of an array and a field of the struct that a pointer points to are exchanged with swap(p[i], v) and swap(p.f, v). *p is exchanged with swap(*p, v). The place must be writable from an own (not borrowed) or a &mut.
  • A value that owns something cannot be copied out of an array element, the target of a pointer or a borrow.

Borrows and regions

  • x = &r p requires p to be declared before r and to live in r. While it is borrowed, p can be neither moved, freed nor assigned. While it is borrowed by &mut, *p, p[i] and p.f cannot be read either. The loan ends at the end of r.
  • A shared borrow is copied, and any number can exist. A &mut is moved when it is used between registers.
  • A &mut passed to a borrowed parameter of a function is borrowed again for the call only and is not moved. It cannot be passed again to another argument of the same call. If the result type contains the region that was borrowed, the result carries the borrow out, so it is moved instead.
  • A &mut can be passed to a & parameter (it is borrowed again as shared for the call).
  • A borrow of an outer region q can be passed where a borrow of a region r opened inside q is expected, whether by assignment, return or an argument. The region parameters of a function have no inside-outside relation among them, and are outside the regions opened in the function.
  • A region parameter of a function is the innermost region of the borrows that are passed (all the others must be outside it).
  • The type &r T can be written only inside r. Putting it in a register outside r or returning it out of r is an error.

Kinds of errors

vasm_errors(file, m) returns a list of VasmErr{kind, loc, msg}, the first error of each struct and function. kind is one of the following symbols.

kindError
'typea type does not match: a width or a signedness, the range of a literal, a missing field
'undefinedan undefined function or struct
'uninita read before initialization
'moveduse of a moved value, or of contents or a field that was taken out
'freeduse of a freed value, a double free
'borroweda move, a free, an assignment or an access while borrowed; overlapping borrows
'ownercopying a value that owns something from a place that is not its owner
'regiona region that is not open, already open or not fixed
'escapea borrow that leaves its region
'branchthe ownership differs after the branches
'loopa value moved in a loop is not given back
