Libraries

The files of planck/lib are written in the syntax of planck and loaded by use("name"). Each file calls use for the files it depends on.

A list is Cons{x, xs} and Nil{}. The code of a character is the integer that ord returns.

list

  • map(f, xs), filter(p, xs) and each(f, xs) call f on the elements in order, from the first to the last.
  • foldl(f, acc, xs) is f(f(acc, x1), x2) and so on. foldr(f, init, xs) is f(x1, f(x2, init)).
  • nth(xs, i) counts from 0. take(xs, n) and drop(xs, n) split xs after n elements.
  • find(p, xs) is the first element with p(x) or none. index_of(x, xs) is the position or -1.
  • zip(xs, ys) is [Tuple{x, y}, ...] as long as the shorter list. range(a, b) is [a, ..., b - 1].
  • list_to_array(xs) is the array of the elements of xs.
  • sort(less, xs) is a stable merge sort by less(a, b), e.g. sort((a, b) -> a < b, xs).

r_lib_list.pk

use("list")
use("pretty")
xs := [3, 1, 4, 1, 5]
put(f"{length(xs)} {sum(xs)} {nth(xs, 2)} {last(xs)}\n")
put(f"{reverse(xs)} {append([0], xs)} {concat([[1], [2, 3]])}\n")
put(f"{take(xs, 2)} {drop(xs, 2)}\n")
put(f"{find(x -> x > 3, xs)} {any(x -> x > 4, xs)} {all(x -> x > 0, xs)}\n")
put(f"{member(4, xs)} {index_of(4, xs)} {index_of(9, xs)}\n")
put(f"{foldr((x, acc) -> x :: acc, [], xs)}\n")
put(f"{concat_map(x -> [x, x], [1, 2])}\n")
each(x -> put(f"<{x}>"), [1, 2, 3])
put("\n")

vector

A vector is a growable array Vector{a}. v[i] and v[i] = x call vec_get and vec_set. vec_push(v, x) appends and returns x, vec_pop(v) removes and returns the last element. vec_get and vec_set stop the program for an index outside the elements.

string

  • chr(c) is the one-character string for the codes 32 to 126, 9, 10 and 13. char_at(s, i) is "" outside s.
  • index_of_str(s, part, from) is the first position of part in s at or after from, or -1.
  • str_cmp(a, b) is -1, 0 or 1 by the order of the character codes. trim(s) removes the blanks at both ends.
  • str_to_int(s) reads an optional - and decimal digits. It is none when s is anything else.
  • split(s, sep) is the list of the parts between sep. sep cannot be empty. join(sep, xs) is the inverse.
  • A string buffer collects pieces: strbuf_add(b, s) and strbuf_str(b). The pieces are joined two at a time, so a long string does not copy the same bytes many times.

r_lib_string.pk

use("string")
use("pretty")
put(f"{chr(65)} [{char_at("abc", 5)}] {ends_with("main.pk", ".pk")}\n")
put(f"{index_of_str("banana", "na", 3)} {str_repeat("ab", 3)}\n")
put(f"{str_cmp("a", "b")} {str_cmp("b", "b")} {str_less("b", "a")}\n")
put(f"{int_to_str(-42)} {str_to_int("x1")}\n")
put(f"{is_digit(ord("7", 0))} {is_alpha(ord("_", 0))} {is_ident_start(ord("_", 0))}\n")
b := strbuf_new()
strbuf_add(b, "plan")
strbuf_add(b, "ck")
put(strbuf_str(b)); put("\n")

u64

A 64-bit value is a u16 array of four 16-bit limbs, the lowest first. It is not changed after it is made.

  • u64(n) is the value of the integer n, sign-extended when it is negative. u64_limbs(l3, l2, l1, l0) is made of the 16-bit limbs, and u64_hex("0x...") of a hexadecimal string (up to 16 digits; _ is ignored). u64_to_hex(a) is 0x and 16 digits, and u64_to_int(a) is the signed value of a.
  • u64_add, u64_sub and u64_neg compute modulo 2 to the 64th power. u64_and, u64_or, u64_xor and u64_not work bit by bit.
  • u64_shl(a, k), u64_shr(a, k) and u64_sar(a, k) are the left shift, the logical right shift and the arithmetic right shift by k bits (0 to 63).
  • u64_eq(a, b) tests equality. u64_ucmp(a, b) and u64_scmp(a, b) are -1, 0 or 1 comparing as unsigned and as signed. u64_ult and u64_slt tell whether a is smaller.
  • u64_write_le(buf, off, a) stores the 8 bytes of a into the u8 array buf from off, the lowest byte first; u64_write_be stores the highest first. u64_read_le(buf, off) is the inverse, and u64_bytes_le(a) is a u8 array of the 8 bytes.

r_lib_u64.pk

use("u64")
a := u64_hex("0xffffffffffffffff")
b := u64_add(a, u64(2))
println(u64_to_hex(b))
println(u64_to_hex(u64_shl(u64_hex("0x0123456789abcdef"), 36)))
println(u64_to_hex(u64_sar(u64_hex("0x8000000000000000"), 60)))
println(u64_ucmp(u64(-1), u64(1)))
println(u64_scmp(u64(-1), u64(1)))
buf := u8_array(8)
u64_write_le(buf, 0, u64_hex("0x0102030405060708"))
println(buf[0])
println(buf[7])

getopt

Reads command-line options in the rules of GNU getopt_long. An option is Opt{short, long, takes}: short is a one-character string, long is a string, either may be "", and takes is true when the option has a value. getopt(opts, args, from) reads the array args from the index from (1 for argv(), which skips the program file).

  • The result is Parsed{table, rest}. table maps the name of each given option, long or else short, to its value, which is true for an option without a value; the last one wins. rest is the array of the strings that are not options, in order.
  • The forms are -a, -abc (the same as -a -b -c), -o value, -ovalue, --opt, --opt value and --opt=value. A value may begin with -. A lone - is not an option. After -- every string is in rest. Options and other strings may be mixed.
  • The errors are values, not stops: Unknown{name} for an option that is not in opts, Missing{name} for an option whose value is missing at the end of args, and NoValue{name} for --opt=value on an option without a value. name is the string as written, such as "-x" or "--opt". A long option cannot be shortened.

r_lib_getopt.pk

use("getopt")
spec := [Opt{"a", "all", false}, Opt{"o", "output", true}, Opt{"", "level", true}]
use("list")
args := list_to_array(["prog", "-ao", "out.txt", "x", "--level=3", "--", "-y"])
r := getopt(spec, args, 1)
println(head(r))
opts := arg(r, 0)
println(table_get(opts, "all", false))
println(table_get(opts, "output", none))
println(table_get(opts, "level", none))
rest := arg(r, 1)
println(array_len(rest))
println(rest[0])
println(rest[1])
println(getopt(spec, list_to_array(["prog", "-ax"]), 1))
println(getopt(spec, list_to_array(["prog", "-o"]), 1))

table

table_keys, table_values and table_items ([Tuple{key, value}, ...]) list the entries in an unspecified order. A set is a table whose values are true.

r_lib_table.pk

use("list")
use("table")
use("pretty")
t := table()
table_set(t, 'a, 1)
table_set(t, 'b, 2)
put(f"{table_len(t)} {table_has(t, 'a)} {table_has(t, 'z)}\n")
put(f"{sort((a, b) -> a < b, table_values(t))}\n")
s := set_from_list([1, 2, 2, 3])
put(f"{set_len(s)} {set_has(s, 2)} {sort((a, b) -> a < b, set_to_list(s))}\n")

Output

2 true false
[1, 2]
3 true [1, 2, 3]

error

  • line_col(src, pos) is Tuple{line, column} of the byte position pos, both counted from 1. line_text(src, line) is the line without the newline.
  • loc_at(file, src, pos) is Loc{file, line, column}, and show_loc writes it as file:line:column.
  • error_at(loc, msg) performs Error{loc, msg}. catch_error(f) is Ok{f()}, or Err{loc, msg} when f() performs Error{loc, msg}.
  • show_error(src, loc, msg) is file:line:column: msg, the line, and a ^ under the column.

r_lib_error.pk

use("error")
src := "x := 1\ny := x +\n"
r := catch_error(() -> error_at(loc_at("a.pk", src, 12), "expected an expression"))
println(r)
put(show_error(src, arg(r, 0), arg(r, 1))); put("\n")
println(catch_error(() -> 42))

Output

Err{Loc{"a.pk", 2, 6}, "expected an expression"}
a.pk:2:6: expected an expression
  y := x +
       ^
Ok{42}

pretty

show(x) is the string that print writes, with a list as [a, b]. pretty(x, width) puts a part on one line when it fits in width columns, and otherwise puts one element on each line, indented by two spaces. pprint(x) writes it with the width 60.

r_lib_pretty.pk

use("pretty")
put(show(["a", 'b, F{1}])); put("\n")
put(quote_str("say \"hi\"")); put("\n")
pprint(Node{Node{Leaf{}, "left", Leaf{}}, "root", Node{Leaf{}, "a long right branch", Leaf{}}})

unparse

unparse(t) is a string that the rule expr reads as the tree t. It is made from the grammar in peg_sources. unparse_as(rule, t) does the same for any rule and stops the program when there is no string. unparse_try returns none instead of stopping.

  • An alternative Act{Seq{e1, ...}, Lambda{Tuple{Tuple{l1, ...}}, body}} is reversed when body is a quasi-quotation whose !x are labels, Quote{c}, labels, Tuple{labels} or mexpr(h, args). The tree is matched against the quasi-quotation, the subtrees are put in the labels, and the elements are written in order. A string is written as it is, and a rule by unparse_as(rule, subtree). A label _ can be used for an element that always matches the same string ("+" or Same{}). An element is a string, a rule, or Delimited, Delimited1, Many or Option of a rule.
  • Among the alternatives that match the tree, the one with the most parts of the quasi-quotation that are not !x is used.
  • When an alternative of a stronger rule is placed where a weaker rule is wanted, it is enclosed in the first "(" e ")" of the grammar (the action can be anything). An alternative that is only a rule name connects the rule to the rules it can be, and decides which alternatives need parentheses. An alternative that ends with a weaker rule (while (c) e ends with expr) also needs parentheses, unless the same or a weaker rule is wanted.
  • unparse_custom(owner, spec, tail, f) adds an alternative to the rule owner. f(t) is the string of t or none, spec ranks it against the quasi-quotations, and tail is the last rule of the string or none. unparse writes Do{...} in { } with one expression per line indented by four spaces, and writes If as if (c) a else b. Both are added in this way.
  • The string of a tree that the grammar does not write is a constructor call Head{a, ...}. A symbol that is not an identifier, and a value that is not an integer, a string, a symbol or an M-expression, have no string.

t6_unparse.pk

use("unparse")
t := '(if (n < 0) -n else n * (n + 1))
println(t)
put(unparse(t)); put("\n")

Output

If{Apply{_lt, Tuple{n, 0}}, Apply{_sub, Tuple{0, n}}, Apply{_mul, Tuple{n, Apply{_add, Tuple{n, 1}}}}}
if (n < 0) -n else n * (n + 1)

base

panic(msg) writes msg and stops with status 1. assert(c, msg) calls panic(msg) when c is not true.

File values

use(name) returns the file it loaded as a value. The fields of the value are named by the global variables the file defines. The value of a field is the value of the variable when the file has been loaded. With p := use("bitset"), p.new is the new that bitset defines. The rule of . is the same as that of reading a field of a record, and reading a field that does not exist prints a message and stops the program. The number of fields has no upper limit.

r_lib_use.pk

b := use("bitset")
s := b.new(100)
b.add(s, 3)
b.add(s, 64)
println(b.to_list(s))
println(b.count(s))
println(use("bitset") == b)

Output

Cons{3, Cons{64, Nil{}}}
2
true
  • use returns the same value every time it is called with the same name.
  • The global variables a file defines can be used as they are without receiving the result of use.
  • The fields of a file value are the variables that x := e, f(p, ...) := e and fun f define in the file. A definition added to a variable of another file with f(p, ...) = e is not a field.

Libraries written as a module

When a library is written as a module, the module is called by its name after the library is loaded. If bitset is written as module bitset, it goes as follows.

use("bitset")
s := bitset.new(100)
bitset.add(s, 3)

A helper function in the library stays inside unless it is marked export. To call a helper function in a test, gather it in export module internal { ... }. Adding the following at the end of the body of bitset lets a test check the result of the helper helper with bitset.internal.word(65).

    export module internal {
        export word(i) := helper(i)
    }

Preprocessed libraries

Running the program tools/preprocess.pk with the names of libraries as arguments parses the chosen libraries into M-expressions in advance. It loads each named library as use("name") does, with the libraries it uses, and writes the M-expressions that each library is parsed into to planck/lib/<name>.pkm, one M-expression on each line.

Nothing is evaluated in advance: use reads the M-expressions of planck/lib/<name>.pkm and evaluates them one by one, so the program behaves as if use parsed planck/lib/<name>.pk. Without a usable .pkm file, use parses the library.

A .pkm file is used when the text of the library and the grammar are the same as when the file was written. The grammar is the same when the files planck/init.pk, planck/peg.pk and planck/syntax.pk have the same text, the libraries that have declared rules are the same libraries with the same text in the same order, and no other rule has been declared (peg_version is the same). A file that cannot be read as M-expressions, or that does not end with its last expression, is not used either.

A program that replaces parse or a function that the actions of the rules call is not detected. Removing the .pkm files is always safe. A library with a value that has no text as an M-expression (a function, an array) in its parse result cannot be preprocessed.
