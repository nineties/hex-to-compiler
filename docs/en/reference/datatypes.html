Data types

Types of values, immutability, equality and identity.

Types of values

There are eight builtin types. A user can make new types (user data).

The type of a value is told by head. The pattern x @ Int matches a value whose head is Int. The symbols of the eight builtin type names and of user data type names cannot be the head of an M-expression. Making user data whose type name is the same as a builtin type name or another user data type name is an error.

Immutability

A value is either immutable or mutable. Arrays and plain arrays are mutable. Integers, floats, strings, symbols, M-expressions and functions are immutable. When a user makes user data, the user must specify whether it is immutable or mutable. There is no default.

A mutable value cannot be an argument of an M-expression. Neither can immutable user data that holds a mutable value. Making such an M-expression is a runtime error.

Equality and identity

Equality is tested by a == b (_eq). a != b (_ne) is its opposite.

Identity and is

a is b is true if a and b are identical, and false otherwise. Its negation is written a is not b. It has the same precedence as ==, at the level of the comparison operators. Like the comparisons it does not group, so a is b is c is an error. is cannot be written in a pattern.

  • Identical values are equal, except NaN. NaN is identical to itself but is not equal even to itself.
  • Values of a type that is interned are identical if they are equal to a value of the same type. All types other than float are interned.
  • Values of different types are not identical. 1 == 1.0 is true, but 1 is 1.0 is false.
  • Testing whether values are identical is O(1) except for arbitrary precision integers.

Equality across number types

Integers, floats and complex numbers are equal if the values are the same, even when the types differ. 1 == 1.0 and 1 == complex(1, 0) are true, and the hash is the same.

Where equality is used

  • A pattern that writes the same name twice (f(a, a)) matches only when the two values are equal by ==.
  • The builtin table (table_get, table_set and t[key]) treats two keys as the same if they are identical or equal. A NaN object can be looked up by using that same object as the key. An array or a plain array as the key is an error.
  • hash(x) is an integer of 0 or more. Values that are equal by == give the same value.
