Grammar declarations

::= defines or replaces a rule of the grammar. The syntax of planck is made of the same rules, so a declaration extends the syntax of the following expressions.

::=

name ::= alternative | ... defines or replaces the rule name of the grammar. The rules of the syntax (expr, primary, block, add_expr ..., ident, integer, string) are rules of the same grammar. ... as an alternative stands for the previous definition of the rule.

r_unless.pk

primary ::= 'unless c:expr a:block 'else b:block { `If{!c, !b, !a} } | ...

unless (1 > 2) { put("then\n") } else { put("else\n") }
unless (1 < 2) { put("then\n") } else { put("else\n") }

Output

then
else

An alternative is a sequence of items followed by an optional action { ... }. The items and the action are on the same line as ::= or |.

Items

ItemMatches
"text"the text, after blanks and comments
'wordthe word, not followed by [A-Za-z0-9_]
nospace("text")the text, with no blanks or comments before it
namethe rule
samenothing, when the next token is on the same line as the position
delimited(e, sep), delimited1(e, sep)e separated by sep: zero or more, one or more. The value is Tuple{v, ...}
(a | b ...)a choice
e*, e+, e?zero or more, one or more, optional
&e, !elookahead: e matches / does not match, without consuming
label:ee, and its value is the variable label in the action

Values and order

Alternatives are tried in order (PEG). The value of an alternative is the value of its action, the value of the item when there is one item, or Tuple{v, ...} of the items. e* and e+ give Tuple{v, ...}, e? gives Tuple{} or Tuple{v}.

Results of rules are memoized for each position (packrat parsing). A rule may be directly left recursive (sum ::= a:sum "+" b:term { ... } | term), which groups to the left.

t7_calc.pk

calc ::= a:calc "+" b:term { a + b } | a:calc "-" b:term { a - b } | term
term ::= a:term "*" b:atom { a * b } | atom
atom ::= integer | "(" e:calc ")" { e }

println(calc{| 1 + 2 * (10 - 4) |})
println(calc{| 100 - 20 - 3 |})

println(peg_parse('calc, "6 * 7"))
println(peg_parse('calc, "1 + )"))
println(peg_parse('calc, ")"))

Output

13
77
Tuple{42, ""}
Tuple{1, "+ )"}
Tuple{SyntaxError{"unexpected input", ")"}, ""}

peg_parse

peg_parse(rule, s) parses a prefix of s by the rule and returns Tuple{value, rest}, Tuple{Eof{}, ""} when only blanks are left, or Tuple{SyntaxError{...}, ""}.

Text of a rule

name{| text |} is an expression whose text is read by the rule name when the expression is parsed. There is no space between name and {|.

The text is read only by the rule (its strings, words and rules, with their blanks and comments), not by the tokens of the expressions around it. The rule decides where the text ends, and |} must follow, after blanks. So |} and } that the rule reads, for example in its strings or brackets, are a part of the text. A failure of the rule or a missing |} is a syntax error of the expression, at the farthest position the rule reached in the text.

The value of the expression is the value of the rule, as a constant.

r_calc.pk

calc ::= a:calc "+" b:num { a + b } | num
num ::= integer
println(calc{| 1 + 2 + 3 |})        # 6, computed when this line is read

Output

6

The rule must be defined by an expression that is evaluated before the expression with the text is parsed.

Reading the grammar

peg_sources is a table from a rule name to the parsing expression given to _define_rule, with the actions not evaluated (... replaced by the previous definition). peg_version increases at every _define_rule.

i_sources.pk

use("pretty")
pretty.print(table_get(peg_sources, 'add_expr, none))

Output
