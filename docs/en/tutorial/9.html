9. Scope of variables

Which variable a name refers to is decided from the place where the program is written, before the expression runs. Whether a definition adds a case to a function or hides it is described in chapter 3.

Resolving names

t1_scope.pk

n := 5
read_n() := n
caller() := {
    n := 100
    read_n()
}
println(caller())

x := 1
get() := x
x := x + 1
println(Tuple{x, get()})
x = 10
println(Tuple{x, get()})

Output

5
Tuple{2, 1}
Tuple{10, 1}

Scope is lexical: which variable a name refers to is decided before the expression runs, from the place where the program is written. The body of a function sees the parameters and variables of that function and of the functions around it, and the variables defined before it at the top level. The variables of the caller are not visible. read_n() reads the top-level n, not the n inside caller.

Defining the same name again with := makes a new variable, and the functions made before keep referring to the old one. get refers to the first x, so it does not see the new x that x = 10 assigns.

e_undefined.pk

println("start")
println(later)
later := 2

Output

"start"
undefined variable: later

If a name refers to no variable, the program stops with a message before the expression runs. later is defined on the third line and is not visible to the second line. The first line runs earlier, so "start" is written.

The whole rules are in Scope of variables in the reference.
