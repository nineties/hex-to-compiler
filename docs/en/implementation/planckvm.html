planckvm: execution model and values

planckvm is the bytecode that runs all of planck. An evaluator written in planck translates an expression into planckvm instructions and runs them in an instruction loop. This page and planckvm instructions are the external specification: what the user of the VM and a code generator from planck may rely on. This page covers the machine, the values and the numbers. The design inside an implementation is in planckvm internals.

Execution model

The machine is a register machine. Every instruction reads and writes the registers of the current frame.

NameContents
codeThe instructions and the constant table of one lambda or of one top-level expression. Immutable. Its form is in Bytecode format
registerR[0] to R[nregs-1] of each frame, where nregs is a field of the code. Each holds one value
frameThe state of one call
environmentA place on the heap for the variables that “Where variables live” assigns to it. It is made for a call and has a parent environment
cellOne global variable: an object that holds a value and a name

Register windows

  • The registers of all frames lie on one register stack. The range of the registers of a frame is its window.
  • The window of a lambda called by CALL A B C starts at R[B+1] of the caller. The caller puts the arguments in R[B+1] to R[B+C], so they become R[0] to R[C-1] of the callee without being copied.
  • During the call, R[B] of the caller keeps the called function. The values of the registers above R[B] are lost by the call. A value used after the call is kept below R[B].
  • The first value of a register other than the arguments is unspecified. A register is written before it is read.
  • When a window does not fit the register stack, the program stops with stack overflow.

Where variables live

A variable is decided by where it is written, and it is resolved at compile time to one of the three places below. Name resolution ends at compile time, and at run time there is no state of an undefined variable.

PlaceVariablesAccess
CellGlobal variablesGETGLOBAL SETGLOBAL
EnvironmentThe variables of a function that are (1) referred to from a lambda or the body of a Handle inside it, or (2) assigned, when the same code has any of CALL, TCALL, HANDLE and PERFORMENVGET ENVSET
RegisterThe other variables of a functionWritten directly as operands of instructions
  • A variable is assigned when it is the target of a Set.
  • A call has at most one environment, and only a code with variables in an environment makes it with NEWENV. Every slot starts as none. The current environment of a code that does not run NEWENV is the environment that its lambda keeps.
  • A variable in an environment is resolved at compile time to a depth d (the number of parent links to follow from the current environment) and a slot i.
  • A lambda keeps the current environment of the place where it was made. The environment is shared, so an assignment after the lambda was made is seen by the lambda.
  • When a path can reach a variable in a register without going through its definition, LOADNONE at the entry of the code sets it to none.
  • A global variable is a cell, whose first value is none. Def makes a new cell, and the expressions compiled after it refer to the new cell. The expressions compiled before keep referring to the old one. Set writes the same cell.
  • true, false and none are literals, not variables. They are in no register, environment or cell, and are compiled as constants. Writing one as the target of Def, Set or Declare is a compile error.

Calls

CALL A B C calls f = R[B] with the C arguments R[B+1] to R[B+C]. What it does depends on the kind of f.

fConditionAction
LambdaThe arity of its code is CMake a new frame and run the code from its first instruction
Fusion a | bTry a first, then b when a runs outWhat the chosen function does
BuiltinThe number of arguments fitsNo frame is made and the result is received at once. Only eval makes a code of arity 0 and runs it in a frame as a lambda
ContinuationC is 1Resume
Anything elseStop with not a function

The instructions at the entry of a code match the patterns. When they do not match, NEXT tries the next alternative with the same arguments. The instructions at the entry do not write the registers of the arguments. When the alternatives run out, the program stops with matching failed.

The value of RET in the callee is received according to the instruction that made the call.

Calling instructionHow the value is received
A test instruction (TEST to TGEI)The condition is true when the value is not false, and the rule of the test instructions applies

Any otherPut in R[A]

An instruction with a name in the Builtin column of the instruction table does the action of the table only while the cell of that name holds the builtin. When another value has been assigned to the cell, the instruction places a call above its window, calls that value with the same arguments and receives the result by the table above. An immediate is passed as an integer argument.

Continuations and handlers

  • HANDLE runs its body in a boundary frame. When the body ends normally, its value is the value of the Handle.
  • PERFORM A B follows the callers to the innermost boundary, copies the frames and the registers up to it and makes a continuation k. It then drops what is above the boundary and calls the handler of the boundary with (R[B], k). The result is the value of the Handle.
  • When no alternative of the handler matches, the effect goes to the next boundary outside. Then k is made again as a copy up to that outer boundary, and the inner boundary is in the copy.
  • With no boundary the program stops with unhandled effect: v.
  • Calling k copies the saved frames and registers again above the window of the caller. The handler of the boundary stays installed (deep handlers). The argument of k is put in R[A] of the PERFORM and the run goes on. When the body ends, its value returns to the caller of k.
  • k can be called any number of times.
  • Resuming copies neither environments nor cells, so the variables in them are shared between the resumed copies. The variables in registers are copied by value. A variable in a register is not written after the capture, so a variable defined at the capture has the same value in every copy. An x := e that runs after the resumption defines a separate variable in each copy when x is in a register.

Stopping

A runtime error writes its message to the standard error and ends with status 1. There is no way to catch it. The Error effect of error.at is not an error of this kind; it is an ordinary PERFORM.

Top level

  • One top-level expression is one code of arity 0. The local variables of a block in it follow the rule for the variables of a function and are in the registers or the environment of this code.
  • The loop that reads and runs the expressions is the entry of the evaluator, not an instruction. For each expression it reads the cells of the global variables parse and eval and calls them with the entry code below.
  • The entry code is the two words CALL R0 R0 n and HALT R0. The evaluator puts the function in R[0] and the arguments from R[1], and runs it at the bottom of the register stack.
  • eval(e) runs the compiled code of e as if it had been called.

Values

ArrayA mutable sequence of values'array
Plain arrayA mutable sequence of elements of one of the 14 types below'plain
FunctionLambda, fusion, builtin or continuation'function
InternalEnvironment, cell and code. They are never passed to a program as values
  • Tuple{...}, Cons{x, xs} and Nil{} are M-expressions with a fixed head. true, false and none are literals of the symbols of the same names.
  • The only value treated as false is the symbol false.
  • A string is handled by its whole length, including the 0 bytes. The comparison of EQ, the output of put and print, and STRLEN, _strcat and substr do not stop at a 0 byte.
  • Equality (EQ): numbers are compared by value (see below). Strings are equal by contents, M-expressions by head and arguments recursively, and symbols by identity. Arrays, plain arrays and functions are equal only to themselves.
  • HASH gives equal values the same number. A float equal to an integer, and a complex number whose imaginary part is 0 and whose real part is equal to an integer, have the hash of that integer. Arrays, functions and plain arrays are given a number that stays the same for the object.

Numbers

  • Integers have arbitrary precision. There is one integer type in the language: no integer is out of range, and nothing wraps around or is truncated.
  • A float is IEEE 754 binary64 with rounding to nearest even. A complex number is a pair of floats.
  • ADD, SUB, MUL and DIV look at the types of their arguments, as one instruction each, and take integers, floats and complex numbers. When the types are mixed, the operands are raised to the higher type in the order integer, float, complex, and the result has that type.
  • An integer raised to a float is rounded to the nearest value. An integer above 2^53 loses precision: 2^53 + 1 + 0.0 is the float 2^53. Raising an integer that is beyond the range of floats (about 1.8 x 10^308) is an error.
  • DIV of two integers is the quotient truncated toward 0, and a zero divisor is an error. A division that involves a float or a complex number does not stop on a zero divisor: a float gives an infinity or NaN, and a complex number gives the same rule applied to its components.
  • LT and GE compare an integer and a float by their mathematical values without raising the type. They give false when NaN is involved. A complex number has no order, so LT or GE on a complex number is an error.
  • EQ says that values of different types are equal when their values are the same (1 == 1.0, 1 == complex(1, 0)). NaN is not equal to itself. Complex numbers are equal when both components are equal.
  • Floating-point exceptions do not stop the program.
  • A complex number is made by complex(re, im). There is no literal.
