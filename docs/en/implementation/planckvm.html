planckvm: execution model and values

planckvm is the bytecode that runs all of planck. An evaluator written in planck translates an expression into planckvm instructions and runs them in an instruction loop. This page and planckvm instructions are the external specification: what the user of the VM and a code generator from planck may rely on. This page covers the machine, the values and the numbers. The design inside an implementation is in planckvm internals.

Execution model

The machine is a stack machine. The intermediate values of an expression are pushed on the operand stack of each frame.

NameContents
codeThe instructions of one lambda or of one top-level expression. Immutable
frameThe state of one call. It is pushed on the frame stack
environmentThe place for the variables of one call. It is made for each call
cellOne global variable: an object that holds a value and a name

Code

  • The instructions are a sequence of integers. An instruction is its number followed by its operands.
  • A jump target L and the pc are indices into the instruction sequence.
  • When a code is made it is checked: the height of the operand stack is determined uniquely at every instruction, every jump target is the start of an instruction, and the stack never goes below zero. The maximum height is computed.
  • The height at the failure target L of a MATCH* instruction is 0.

Frames

A frame is the state of one call, pushed on the frame stack. When the frame stack is full the program stops with stack overflow.

Environments and variables

  • A call makes one environment, and every slot starts as none.
  • A variable is decided by where it is written. It is resolved at compile time to a depth d (the number of parent links to follow) and a slot i. Name resolution ends at compile time, and at run time there is no state of an undefined variable.
  • A lambda keeps the environment of the place where it was made. The environment is shared, so an assignment after the lambda was made is seen by the lambda.
  • Resuming a continuation does not copy environments. The resumed copies share the same variables.
  • A global variable is a cell, whose first value is none. Def makes a new cell, and the expressions compiled after it refer to the new cell. The expressions compiled before keep referring to the old one. Set writes the same cell.

Calls

CALL n takes f a1 ... an from the stack. The function f is chosen as follows.

fCondition
LambdaThe arity of its code is n
Fusion a | bTry a first, then b when a runs out
BuiltinThe number of arguments fits. No frame is made and the result is returned at once (only eval makes a frame)
Continuationn is 1. It resumes
Anything elseStops with not a function

When a lambda is chosen, a frame and an environment are made, the arguments are put in the frame and the code runs from its first instruction. The instructions at the entry match the patterns. When they do not match, NEXT tries the next alternative with the same arguments. When the alternatives run out, the program stops with matching failed.

Continuations and handlers

  • HANDLE runs its body in a boundary frame. When the body ends normally, its value is the value of the Handle.
  • PERFORM v follows the callers to the innermost boundary, copies the frames up to it and makes a continuation k. It calls the handler of the boundary with (v, k) and returns the result to the caller of the boundary.
  • When no alternative of the handler matches, the effect goes to the next boundary outside. Then k is made again as a copy up to that outer boundary, and the inner boundary is in the copy.
  • With no boundary the program stops with unhandled effect: v.
  • Calling k copies the saved frames again on top of the caller. The handler of the boundary stays installed (deep handlers). The value of the call becomes the value of the PERFORM in the innermost frame, and when the body ends, its value returns to the caller of k.
  • k can be called any number of times.

Stopping

A runtime error writes its message to the standard error and ends with status 1. There is no way to catch it. The Error effect of error_at is not an error of this kind; it is an ordinary PERFORM.

Top level

  • One top-level expression is one code of arity 0. The local variables of a block in it are in the environment of this code.
  • The loop that reads and runs the expressions is the entry of the evaluator, not an instruction. For each expression it reads the cells of the global variables parse and eval and calls them.
  • eval(e) makes a code of the same form and runs it.

InternalEnvironment, cell and code. They are never passed to a program as values
  • Tuple{...}, Cons{x, xs} and Nil{} are M-expressions with a fixed head. true, false and none are symbols.
  • The only value treated as false is the symbol false.
  • A string is handled by its whole length, including the 0 bytes. The comparison of EQ, the output of put and print, and STRLEN, _strcat and substr do not stop at a 0 byte.
  • Equality (EQ): numbers are compared by value (see below). Strings are equal by contents, M-expressions by head and arguments recursively, and symbols by identity. Arrays, plain arrays and functions are equal only to themselves.
  • HASH gives equal values the same number. A float equal to an integer, and a complex number whose imaginary part is 0 and whose real part is equal to an integer, have the hash of that integer. Arrays, functions and plain arrays are given a number that stays the same for the object.

Numbers

  • Integers have arbitrary precision. There is one integer type in the language: no integer is out of range, and nothing wraps around or is truncated.
  • A float is IEEE 754 binary64 with rounding to nearest even. A complex number is a pair of floats.
  • ADD, SUB, MUL and DIV look at the types of their arguments, as one instruction each, and take integers, floats and complex numbers. When the types are mixed, the operands are raised to the higher type in the order integer, float, complex, and the result has that type.
  • An integer raised to a float is rounded to the nearest value. An integer above 2^53 loses precision: 2^53 + 1 + 0.0 is the float 2^53. Raising an integer that is beyond the range of floats (about 1.8 x 10^308) is an error.
  • DIV of two integers is the quotient truncated toward 0, and a zero divisor is an error. A division that involves a float or a complex number does not stop on a zero divisor: a float gives an infinity or NaN, and a complex number gives the same rule applied to its components.
  • LT and GE compare an integer and a float by their mathematical values without raising the type. They give false when NaN is involved. A complex number has no order, so LT or GE on a complex number is an error.
  • EQ says that values of different types are equal when their values are the same (1 == 1.0, 1 == 1+0j). NaN is not equal to itself. Complex numbers are equal when both components are equal.
  • Floating-point exceptions do not stop the program.
  • A complex number is made by complex(re, im). There is no literal.
