From machine code to planck0

These are the bootstrap stages from a Forth written as a hex dump to planck0 written in sasm.

Each stage builds the next stage using only the earlier stages. The order is pforth, plisp, asm and sasm, plisp2, planck0.

pforth

pforth.xxd is a hex dump. xxd -r -c 8 ignores the annotations on the right. The restored bytes are an executable 32-bit x86 Linux ELF file.

The initial dictionary has only builtin words with one-letter names. k reads a character, t writes a character, f looks up a word from a character, x executes a word, and so on.

The first interpreter only repeats k, f and x. Hello World at this point is as follows.

bootstrap/plisp.fs: The 1st phase interpreter repeats execution

\ The 1st phase interpreter repeats execution of k, f and x.
\ The following line is an example program of planckforth
\ which prints "Hello World!\n"
\ --
\ kHtketkltkltkotk tkWtkotkrtkltkdtk!tk:k0-tk0k0-Q
\ --
\ This code repeats that 'k' reads a character and 't' prints it.
\ Note that ':' (58) minus '0' (48) is '\n' (10).

plisp

plisp.fs is the input to pforth. It begins with a sequence of one-letter words that registers whitespace and newlines as words that do nothing and \ as the word for a line comment (bootstrap/plisp.fs: h@l@h@!h@C+h!k1k0-h@$k:k0). The rest builds Forth by self-extension.

  • The second interpreter. It looks up words by name and has a compile state (bootstrap/plisp.fs: The 2nd Phase Interpreter).
  • The usual Forth words: conditionals, loops, recursion, structures (bootstrap/plisp.fs: Compilers).
  • The third interpreter. It reads a word that is not in the dictionary as a number, and stops with an error if it is not a number (bootstrap/plisp.fs: 3rd Phase Interpreter).

A Lisp interpreter is written in that Forth (bootstrap/plisp.fs: Implementation of PlanckLISP onward). It is written in the order of lists, nodes, the reader and printer, and the evaluator. At the end it reads bootstrap/plisp/init.lisp (bootstrap/plisp.fs: s" bootstrap/plisp/init.lisp" eval-file).

asm and sasm

Both run on plisp. They favor a simple implementation over performance and safety.

asm/core.lisp is an assembler for 32-bit x86. It writes an ELF file directly from a list of S-expression instructions, and puts the header, code and data in one readable, writable and executable PT_LOAD.

bootstrap/asm/examples/hello.s

; hello.s in x86

(entry start)

(label msg)
    (ascii "Hello World!\n")

(const len (- here msg))

(label start)
    (mov %eax 4)   ; SYS_WRITE
    (mov %ebx 1)   ; stdout
    (mov %ecx msg) ; addr
    (mov %edx len) ; length
    (int 0x80)

    (mov %eax 1)    ; SYS_EXIT
    (xor %ebx %ebx) ; status = 0
    (int 0x80)

sasm/core.lisp is the compiler of the structured assembly language sasm. sasm is an untyped C-like language with variables, functions, if and while, and is implemented as an internal DSL of plisp. It does not allocate registers. It emits code that repeats pushes and pops on the stack, and asm turns the code into machine code.

bootstrap/sasm/examples/fib.sv

; fib.sv

(include "std.sv")

(fun fib (n)
    (if (< n 2)
        (return n)
        (return (+ (fib (- n 1)) (fib (- n 2))))
        )
    )

(fun main ()
    (putu (fib 20)) (puts "\n")
    )

plisp2

plisp2.sv is the same Lisp rewritten in sasm. It has these parts, in order.

  • Memory allocation (bootstrap/plisp2.sv: Memory Allocation)
  • Nodes (bootstrap/plisp2.sv: Nodes)
  • The reader and printer (bootstrap/plisp2.sv: Parser and Printer)
  • The evaluator (bootstrap/plisp2.sv: Eval)
  • Builtin functions (bootstrap/plisp2.sv: Primitive Functions)

The build has two steps. First, sasm on plisp compiles plisp2. Then the same sasm, running on the resulting plisp2, compiles bootstrap/planck0.sv.
