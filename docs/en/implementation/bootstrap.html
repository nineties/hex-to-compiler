From machine code to planck0

This page follows the path from a one-page hex dump of Forth to planck0, which is written in sasm.

pforth

pforth.xxd is a hex dump of 201 lines. xxd -r -c 8 ignores the annotations on the right. The restored bytes are an executable ELF file. The current implementation produces a 32-bit x86 Linux ELF.

plisp

plisp.fs is the input to pforth. It begins with a sequence of one-letter words that registers whitespace and newlines as words that do nothing and \ as the word for a line comment (plisp.fs:1–15). The rest builds Forth by self-extension.

  • The second interpreter. It looks up words by name and has a compile state (plisp.fs:335–358).
  • The usual Forth words: conditionals, loops, recursion, structures (plisp.fs:498–1380).
  • The third interpreter. It reads a word that is not in the dictionary as a number, and stops with an error if it is not a number (plisp.fs:1386–1447).

A Lisp interpreter is written in that Forth (plisp.fs:1684 onward). It is written in the order of lists, nodes, the reader and printer, and the evaluator. At the end it reads plisp/init.lisp (plisp.fs:2435). The next stage is an assembler and a compiler, so the choice is a Lisp: it handles syntax trees directly and makes internal DSLs easy.

asm and sasm

Both run on plisp. They are tools for crossing to the next stage. They favor a simple implementation over performance and safety.

asm/core.lisp is an assembler for 32-bit x86. It writes an ELF file directly from a list of S-expression instructions, and puts the header, code and data in one readable, writable and executable PT_LOAD.

asm/examples/hello.s:1–19

; hello.s in x86

(entry start)

(label msg)
    (ascii "Hello World!\n")

(const len (- here msg))

(label start)
    (mov %eax 4)   ; SYS_WRITE
    (mov %ebx 1)   ; stdout
    (mov %ecx msg) ; addr
    (mov %edx len) ; length
    (int 0x80)

    (mov %eax 1)    ; SYS_EXIT
    (xor %ebx %ebx) ; status = 0
    (int 0x80)

sasm/core.lisp is the compiler of the structured assembly language sasm. sasm is an untyped C-like language with variables, functions, if and while, and is implemented as an internal DSL of plisp. It does not allocate registers. It emits code that repeats pushes and pops on the stack, and asm turns the code into machine code.

sasm/examples/fib.sv:1–14

; fib.sv

(include "std.sv")

(fun fib (n)
    (if (< n 2)
        (return n)
        (return (+ (fib (- n 1)) (fib (- n 2))))
        )
    )

(fun main ()
    (putu (fib 20)) (puts "\n")
    )

plisp2

plisp on Forth is too slow for the later stages. plisp2.sv is the same Lisp rewritten in sasm. It has, in order, memory allocation (plisp2.sv:6), nodes (plisp2.sv:54), the reader and printer (plisp2.sv:302), the evaluator (plisp2.sv:586) and builtin functions (plisp2.sv:828).

plisp2 is compiled by sasm on plisp. The same sasm then compiles planck0.sv on the resulting plisp2.

planck0

planck0.sv (2684 lines) is also written in sasm. The page planck0 describes it.
