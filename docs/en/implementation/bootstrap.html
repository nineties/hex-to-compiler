From machine code to planck0

From a Forth in a hex dump to planck0 written in sasm. Each stage rewrites the next one in a higher-level language on top of the previous stage.

pforth

pforth.xxd is a hex dump. xxd -r -c 8 ignores the annotations on the right, and the restored bytes are an executable 32-bit x86 Linux ELF file.

The dictionary starts with builtin words of one-character names only, and the first interpreter repeats k (read a character), f (look up a word) and x (execute it).

bootstrap/plisp.fs: The 1st phase interpreter repeats execution

\ The 1st phase interpreter repeats execution of k, f and x.
\ The following line is an example program of planckforth
\ which prints "Hello World!\n"
\ --
\ kHtketkltkltkotk tkWtkotkrtkltkdtk!tk:k0-tk0k0-Q
\ --
\ This code repeats that 'k' reads a character and 't' prints it.
\ Note that ':' (58) minus '0' (48) is '\n' (10).

plisp

plisp.fs is the input to pforth. It starts with one-character words only and extends itself: an interpreter that looks up words by name, then conditionals, loops and structures. A Lisp interpreter is written in that Forth, and it finally reads bootstrap/plisp/init.lisp.

asm and sasm

Both run on plisp and favor simple implementations over speed and safety. asm/core.lisp is an x86 32-bit assembler that writes an ELF file directly from a list of S-expression instructions. sasm/core.lisp is the compiler of sasm, a C-like language without types. It does no register allocation and generates code that repeats push and pop on the stack, which asm turns into machine code.

bootstrap/sasm/examples/fib.sv

; fib.sv

(include "std.sv")

(fun fib (n)
    (if (< n 2)
        (return n)
        (return (+ (fib (- n 1)) (fib (- n 2))))
        )
    )

(fun main ()
    (putu (fib 20)) (puts "\n")
    )

plisp2 and planck0

plisp2.sv is the same Lisp rewritten in sasm. The build has two steps: sasm on plisp compiles plisp2, and then the same sasm on that plisp2 compiles planck0.sv. Its contents are in planck0.
