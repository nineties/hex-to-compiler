planckvm internals

The design inside an implementation of planckvm. What the user of the VM may rely on is in the external specification: planckvm: execution model and values and planckvm instructions.

Principles

  • The evaluator is a bytecode interpreter: an expression is translated into instructions, and an instruction loop runs them. An expression is not turned into a closure.
  • The evaluator has its own garbage collector, a generational copying collector. It owns the heap of values and the roots.
  • The evaluator does not use the effects, the continuations or the M-expression reader of the host. They are written in planck as parts of the evaluator.
  • The instruction loop does not call itself. The state of the calls of planck is only on the register stack and the frame stack.

Stacks

The evaluator owns two contiguous regions, the register stack and the frame stack. Both are roots of the collector, and when one is full the program stops with stack overflow. The register stack is filled with none at startup.

Calls and returns

  • When CALL A B C chooses a lambda, it saves pc of the current frame and pushes a new frame with base = the current base + B + 1, env = the environment of fn and ret = A. It checks that the window fits up to base + nregs. The arguments do not move.
  • HANDLE A B likewise pushes a frame with base = the current base + B + 2, kind = 1 and reg = A in ret, and runs the lambda R[B] with no arguments.
  • RET A reads the value, drops the frame and gives the value to the caller according to ret of the dropped frame.
  • TCALL B C moves R[B] to R[B+C] to R[-1] to R[C-1] and replaces the current frame. mode and reg of ret are kept, and kind becomes 0. When it calls a builtin, the result is given as by RET.
  • The contents of alts have the form of Fusion below. NEXT chooses, from next in order, an alternative that takes the number of arguments. For a lambda it replaces fn and env of the frame and sets pc to 0. The window does not change. For a builtin the result is given as by RET, and a continuation resumes as by TCALL.
  • When the alternatives run out, it goes to forwarding when kind is 2, and otherwise stops with matching failed.
  • A call for an overwritten cell of a builtin puts the function in R[nregs] and the arguments above it, and goes as CALL does. ret depends on the kind of the instruction: mode is k + 1 for a test instruction, 3 for ASET and PLAINSET, and otherwise 0 with reg = A. The window check uses nregs plus the size of the call.

Checking for an overwritten builtin

The evaluator has one word guard, with one bit for each name of the Builtin column of the instruction table. An instruction with that column first looks whether guard is 0, and looks at its own bit otherwise. The cells of these names are marked, and SETGLOBAL updates the bit when it writes a marked cell (0 when the value is the original builtin, otherwise 1).

Continuations

A continuation is an object on the heap: a copy of a slice of the frame stack and a slice of the register stack. Continuations do not use the effects of the host.

  1. PERFORM A B: it goes down from the current frame to a frame F with kind 1. With no such frame it stops with unhandled effect.
  2. It saves pc of the current frame and makes a continuation by copying the frames from F to the current frame, and the registers from F.base - 2 to R[nregs-1] of the current frame. base in the copy becomes the difference from the start of the slice of registers, and A goes to the field reg of the continuation. This allocation is the S of the instruction.
  3. It drops what is above F and makes a frame at the place of F with kind = 2, the mode and reg of F, and base = F.base. The value sent goes to R[0] and the continuation to R[1], and the handler is chosen with 2 arguments.
  4. Forwarding: it goes down from below this frame to the next frame G with kind 1. With no such frame it stops with unhandled effect. It makes a new continuation of the slice from G to the frame below this one, followed by the slice of the old continuation, and does step 3 for G. The slice of registers of the old continuation continues at F.base - 2, so there is no gap. F.base - G.base is added to base of the frames of the old slice.
  5. Resumption: when the function of CALL A B 1 is a continuation, the argument is read first, the slice is copied to the current base + B + 1 and that position is added to base of each frame. mode and reg of ret of the first frame of the slice (the boundary) come from A of the CALL. The last frame of the slice becomes the current frame, the argument goes to its R[reg], and the run goes on from its saved pc.
  6. When the function of TCALL is a continuation, the argument is read first, the slice is copied to base - 1 of the current frame, and mode and reg of the first frame come from the current frame.

The collector looks at kind and follows only the words that are values. It does not go into the contents of large integers, floats, complex numbers, strings and plain arrays. For a code it skips the instructions and follows the constant table. For a continuation it follows fn, env and alts of each frame, and all registers.

FUSION concatenates the alternatives of R[B] and R[C] into a new fusion.

Generations

  • The collector is a copying collector with a young and an old generation, written in planck as a part of the evaluator. It is not a runtime added to vasm.
  • Allocation is from the young generation. An object that does not fit the young generation is allocated directly in the old one.
  • When the young generation is full, every young object reachable from the roots and the remembered set is copied to the old generation, and the young generation becomes empty.
  • When the old generation is full, it is copied between its two semispaces.

Allocation and safe points

  • An instruction marked S in the instruction table may allocate, and the collector may run when it allocates.
  • The collector runs before the side effects of the instruction. The inputs of the instruction remain in registers during the collection and are updated by it. The instruction reads its inputs again after the collection.
  • Every running value can be reached from the register stack, the frame stack, the environments, the cells or the state of the evaluator. No value lives only in a local of the evaluator. A value that a builtin holds across an allocation is in a temporary slot of the state of the evaluator.
  • The collector does not run in an instruction that allocates nothing (JMP, MOVE, ENVGET and so on). No safe point is placed in the middle of a loop.

There is no table of live registers. An element of the register stack is always a valid value or none. This is kept as follows.

  • At startup every element is filled with none.
  • The collector fills with none the range above this that has been used since the last collection. The top of the range is a word high updated when a window is made.

What is above R[B] of a caller overlaps the window of the callee, and what is below it is a live value or a past value. A past value stays alive until it is overwritten, but it is never a wrong reference. The pc is an index, so a move of the code does not affect it.

The write barrier

The method is a remembered set: a list of old objects. When a reference to a young object is written into an old object whose r is 0, the old object is recorded and r becomes 1. The targets are ENVSET, SETGLOBAL and ASET. A plain array has no references and is not recorded. The initialization of an object allocated in the young generation is not recorded. An object allocated directly in the old generation is recorded when its initialization writes a young reference. A write to the register stack or the frame stack is not recorded, because they are traced as roots every time.

Identity

Arrays, plain arrays and functions have identity (EQ and HASH). It is not held as an address. The first HASH assigns a number to the word for the number in the object (0 is not assigned). A symbol has a number that comes from its name, an M-expression and a string have one from their contents, and a number has one from its value.

Representation of numbers and plain arrays

  • When the result of two integers fits a small integer, the instruction need not allocate. An allocation happens when digits are added, and when the result is a float or a complex number. A result that fits 31 bits is always an immediate.
  • Floats and complex numbers are immutable boxes on the heap. vasm holds a complex number as a pair of floats.
  • The elements of a plain array carry no tag. A plain array holds no references, so the collector does not scan it and writing to it is not recorded. A complex element is two numbers inside the array, not a box.

Partial evaluation

The purpose of planckvm is to partially evaluate an evaluator written in planck and to get an implementation of planck in vasm. The following properties of the design are meant to serve this.

  • The instructions do not change after a code is made, and the register numbers and the differences of jumps are immediate. For a static code the reading of instructions and the choice of the next one can be unrolled, and the indices of registers are static.
  • Pattern matching is in the code that is called. A match can be specialized for each function, and no matcher that walks a data tree is needed.
  • Continuations are copies of frames and use no effects of the host, so the evaluator does not use Perform and does not meet the limit on continuations in planck/lib/pe.pk.
  • A dynamic indirect call goes only to a function reached by CALL. If the set of codes that can be called is closed, each code can become one function.
  • The check for an overwritten builtin only reads the word guard, and it can be folded when guard is static. A global variable is a mutable cell, so a global that is assigned cannot be treated as static.
  • With PLAINGET and PLAINSET, the elements are read and written as numbers without boxes.
