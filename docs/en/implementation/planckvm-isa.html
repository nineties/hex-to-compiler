planckvm instructions

The part of the external specification of planckvm about the bytecode format, the instructions, the builtin functions and the instructions for each feature of planck. See planckvm: execution model and values for the machine and the values, and planckvm internals for the design inside an implementation.

Bytecode format

The basic unit is a 32-bit word. The unit of bytecode is a code: one lambda or one top-level expression is one code. The code of a nested function is in the constant table of the code around it. Bit 0 is the least significant bit.

The fields of a word w are op = w & 0xFF, A = (w >> 8) & 0xFF, B = (w >> 16) & 0xFF, C = w >> 24 and D = w >> 16, where >> is a logical shift. For example, ADD R3 R1 R2 has op = 0x25, A = 3, B = 1 and C = 2, and is 0x02010325.

  • The widened A, B and C have 16 bits, and D has 32 bits. sB and sC become signed 16 bits, and sD signed 32 bits.
  • EXT is used when a register number is over 255 or an index in the constant table does not fit its field. The field of k is not widened.
  • EXT cannot be placed before an instruction of the J format or before itself. A jump goes to the word of EXT, not to the word after it.
  • JMP cannot be widened, so the instructions of a code are limited to a size where the differences fit sJ. Over that is a compile error.

Conditions for a correct code

A code generator keeps the following. The evaluator does not check them.

  • A jump goes to the start of an instruction inside the instructions.
  • The last instruction is one of RET, TCALL, JMP, HALT and NEXT.
  • The word after a test instruction is JMP. The word after an instruction whose name starts with MATCH is NEXT or JMP.
  • Local variables are in registers with smaller numbers than temporary values. At CALL and HANDLE, every live value is below R[B] (HANDLE also keeps R[B] and R[B+1]).
  • The code of the body of a HANDLE does not use TCALL.
  • NEWENV runs once in a code, after every pattern has matched.
  • R[0] to R[arity-1] are not written until the patterns have matched.

A test instruction (TEST to TGEI) makes no value. When the condition is the same as k (true for k = 1, false for k = 0) it runs the JMP of the next word, and otherwise it skips the next word. With NaN, both TLT and TGE are false.

ADD, SUB, MUL, DIV, MOD, ADDI, LT, GE, TLT, TGE, TLTI and TGEI stop when an argument is not a number. For mixed types and the type of the result, see Numbers in the execution model. Of the instructions from HEAD to PLAINSET, those with the T mark stop for an argument of a wrong type or out of range (except for ORD out of range).

An instruction with a name in the Builtin column has S and T like CALL while its cell is overwritten.

Builtins and instructions

Only what is called at a high frequency is an instruction: the constants, variables, control, calls, matching, effects and operators that every run goes through, and the builtins that are called the most. Everything else is a builtin function, and no instruction is added for it. An operation that differs by type is one instruction that looks at the type of its value.

When f of an expression Apply{f, Tuple{...}} is a name of the Builtin column, resolves to its cell and has the right number of arguments, the compiler uses that instruction. The instruction itself handles an overwritten cell at run time, so the compiler does not distinguish it.

The allocations and errors of a machine builtin are covered by the S and T of the CALL that called it. mexpr, substr, _strcat, intern, symname, array, plain_array, plain_len and plain_kind are also errors for an argument of a wrong type or out of range.

The arguments of the bit operations are integers, treated as infinite-width two's complement, negative numbers included.

A builtin that takes a float also takes an integer and raises it to a float. A complex number is an error.

If a PERFORM happens during an eval, the frames inside the eval are ordinary frames and can be copied.

The builtin functions that are in neither the instruction table nor this table are defined by planck code that the evaluator reads before planck/init.pk.

Language features and instructions

Code is generated for each row of the table of the syntax as follows. <e:d> is the instructions that put the value of the expression e in R[d]. t is the smallest free temporary register at that point, and t+1 the one after it.

Register assignment

  • When the pattern of the parameter at position i is a variable in a register, that variable is R[i].
  • The other variables in registers are assigned from R[arity] in order. They are fixed for a code, and are not reused after a block ends.
  • Temporary values use the numbers after the variables, like a stack. They are freed when the evaluation of the expression ends.
  • nregs is the sum of the arity, the number of the other variables in registers and the largest depth of temporary values.

For an operand <e:r>, r is decided as follows. When e is a variable in a register that the evaluation of the later operands does not write, r is the register of that variable and no instruction is needed. Otherwise r is t and the value of e is put there.
