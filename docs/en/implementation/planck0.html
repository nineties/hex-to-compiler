planck0

planck0 reads only M-expressions. It compiles each top-level M-expression to bytecode as it reads it, and runs the bytecode on a virtual machine that keeps its frames on the heap. The source is the single file planck0.sv.

Top level

main prepares the state, reads planck/init.pk, and then reads the program file given as the first argument.

planck0.sv:2597–2609

(fun main (argc argv)
    (init_heap)
    (init_tables)
    (init_symbols)
    (init_compiler)
    (init_vm)
    (init_prims)

    (interpret_file "planck/init.pk")
    (= cmd_argc argc)
    (= cmd_argv argv)
    (if (> argc 1) (interpret_file (get argv 1)))
    )

interpret_file reads a file (planck0.sv:2566–2595). For each expression it calls the global variables parse and eval again through call_global. call_global builds Apply{name, Tuple{arg}}, compiles it and runs it (planck0.sv:2561–2564). Therefore a program that replaces parse has the next expression read by the new parse. The syntax of planck enters by this mechanism.

planck0.sv:2551–2560

; The loop looks up the global variables `parse` and `eval` every time, so
; a program can replace them (Def{parse, ...}, Def{eval, ...}) and the next
; top-level expression is parsed/evaluated by the new definitions. Apply{eval, ...}
; in a program also calls the replaced eval.
;   parse: String -> Tuple{m-expr, rest String}   (initially the builtin parse)
;     When only white space is left, parse returns Tuple{Eof{}, rest} and the
;     loop stops. A replacement parse should pass Eof{} through.
;   eval: m-expr -> any value                     (initially the builtin eval)
; Inside the VM, the builtin eval (PRIM_EVAL) is called through the global
; variable like any other function.

Value representation

A value is one 32-bit word. When the least significant bit is 1, the value is an integer shifted left by one bit. When it is 0, the value is a pointer to an object on the heap. An object has a header word that holds its kind and length.

planck0.sv:69–91

; === data layout (planck0)
; Small integers: tagged with LSB=1. Value is encoded as (val << 1) | 1.
; Heap objects: Identified by LSB=0.
; These objects are preceded by a one-word header containing object-specific information.

; Layout of heap objects.
; m: 1 if the object is mutable
;
;         |        header        |
;         |  27bit | 1bit | 4bit |
; symbol  |      0 |    0 | 0000 | text |
; string  | length |    0 | 0001 | text |
; mexpr   |  arity |    0 | 0010 | sym  | arg1 | .... |
; array   | length |    m | 0011 |
; lambda  |  arity |    0 | 0101 | code | env  |
; prim    |  arity |    0 | 0110 | ptr  | name | kind |
; cont    |      0 |    0 | 0111 | top frame | boundary frame |
; fusion  |      0 |    0 | 1000 | fun1 | fun2 |
; code    |      0 |    0 | 1010 | (see Bytecode VM)
;
;
; Both symbols and mexpr undergo interning,
; enabling O(1) equality testing via pointer comparison.

Symbols and M-expressions are interned. M-expressions with the same structure are one object in memory, so equality is pointer comparison (planck0.sv:329–338).

The heap is a 1 GB region allocated by mmap2 at startup and carved from the front. There is no GC (planck0.sv:36–67).

The M-expression reader

The builtin parse reads four kinds of text: symbols, integers, strings, and Head{...}, where a { follows a symbol directly (planck0.sv:784–874). An M-expression has at most 16 arguments.

planck0.sv:830–862

(fun parse_ (ret raw)
    (= raw (skip_spaces raw))

    (var c (getb raw 0))
    (if (is_symbol_leading_char c) (do
        ; symbol or m-expr
        (= raw (parse_symbol ret raw))
        (= raw (skip_spaces raw))
        (if (== (getb raw) (char "{"))
            (= raw (parse_mexpr ret (get ret) raw))
            )
        )
    (if (is_digit c)
        (= raw (parse_int ret raw))
    (if (&& (== c (char "-")) (is_digit (getb raw 1))) (do
        ; negative integer literal
        (= raw (parse_int ret (+ raw 1)))
        (if (== (gettag (get ret)) IntT)
            (set ret (- 2 (get ret))) ; fixnum(-n) = 2 - fixnum(n)
            )
        )
    (if (== c (char "\""))
        (= raw (parse_str ret raw))
    (if (== c 0)
        (set ret (syntax_error "unexpected end of input"))
        (do
            (set ret (syntax_error "unexpected character"))
            (+= raw 1)
            )
        )))))
    (= raw (skip_spaces raw))
    (return raw)
    )

After the syntax of planck is installed, this reader remains as parse_mexpr.

i_parse.pk

println(parse("1 + 2 * 3\nx := 4"))
println(parse_mexpr("Apply{_add, Tuple{1, 2}} rest"))
println(parse("   "))

Output

The compiler

compile turns an integer or a string into a constant and a symbol into a variable reference, and passes an M-expression to compile_mexpr (planck0.sv:1445–1460).

compile_mexpr dispatches on the head (planck0.sv:1270–1443). The special forms are Apply, Def, Set, Do, If, While, Lambda, Fusion, Quote, QuasiQuote, Handle and Perform. Any other head is a constructor: it evaluates the arguments and builds an M-expression with the same head.

The compiler resolves a local variable to a pair (environment depth, position) at compile time. A top-level Def and an unbound name are global variables, which are looked up in a table at run time. This is why a top-level function can refer to itself.

The virtual machine

The machine has 18 instructions. The design is described in the comments of the source.

planck0.sv:875–948

; === Bytecode VM
;
; planck0 compiles each top-level expression into a code object and runs it
; on a stack-based virtual machine. Every Lambda becomes its own code object.
;
; code object:
;   | header | arity | patterns | nslots | maxstack | ncode | code words ... |
;   patterns: Tuple of parameter patterns (0 for top-level code)
;   nslots:   number of variable slots of the environment
;   maxstack: maximum depth of the operand stack
;   Jump targets are word offsets from the first code word.
;
; environment (internal):
;   | parent env | slot0 | slot1 | ... |
;   Variables are resolved at compile time to (depth, slot) where depth is
;   the number of parent links to follow. An empty slot holds 0, which is
;   never a valid value. Variables are shared locations: closures and
;   continuations refer to the same environment.
;
;   Variables defined by top-level Def, and names that are not bound
;   lexically, are global variables looked up in global_table at run time.
;
; frame (internal, allocated in the heap):
;   | caller | code | pc | env | sp | handler | size | operand stack ... |
;   caller:  the frame which receives the return value (0 for top-level)
;   pc:      address of the next instruction (saved when not running)
;   sp:      byte offset of the stack top from the frame (saved)
;   handler: effect handler if this frame is the boundary of Handle, or 0
;   size:    size of the frame in words
;
; Since frames are not on the machine stack, the VM never calls itself
; recursively and the control state of a computation is just the chain
; of frames from the current frame to the top-level frame.
;
; Instructions (operands follow the opcode):
;   CONST v         push v
;   LOAD d i sym    push slot i of the d-th parent environment
;   STORE d i       store the stack top to slot i of the d-th parent env
;   GLOAD sym       push the global variable sym
;   GDEF sym        define the global variable sym with the stack top
;   GSET sym        update the global variable sym with the stack top
;   POP             discard the stack top
;   JMP off         jump
;   JF off          pop, jump if it is false
;   CALL n          call f with n arguments: [f a1 .. an] -> [result]
;   TCALL n         same as CALL but reuses the caller (tail call)
;   RET             return the stack top to the caller
;   CLOSURE code    push a closure of code and the current environment
;   TUPLE n         [a1 .. an] -> [Tuple{a1, .., an}]
;   MEXPR h n       [a1 .. an] -> [h{a1, .., an}]
;   FUSION          [f g] -> [f|g]
;   HANDLE          [body handler] -> [result]
;                   call the closure body in a new frame marked with handler
;   PERFORM         [v] -> [value given by resume]
;
; Function call:
;   The arguments are matched with the parameter patterns of the callee.
;   Matched pattern variables are written to the slots of a new environment
;   in the order of appearance. For f|g, f is tried first and then g.
;   A frame which is a boundary of Handle is never dropped by TCALL.
;
; Algebraic effects (deep handlers):
;   Handle{body, handler} evaluates body in a boundary frame B with handler.
;   Perform{v} searches the nearest boundary frame B from the current frame
;   and calls handler(v, k) whose result is returned to the caller of B,
;   i.e. it becomes the value of the Handle expression.
;   k is a continuation object (ContT) holding the current frame and B.
;   If the arguments do not match the handler, the next outer handler is
;   tried (effect forwarding).
;   Calling k with a value x copies the frames from the current frame to B
;   (B keeps its handler), links the copy of B to the caller of k, pushes x
;   as the result of Perform and runs the copied frames. Since captured
;   frames are never executed themselves, k can be resumed multiple times.
;   When the resumed body finishes, its value is returned to the caller of k.

Frames live on the heap, not on the machine stack, and the virtual machine does not call itself recursively. The state of a computation is the chain of frames from the current frame to the top level, so a continuation is a pointer to this chain.

Calls and pattern matching

At a call, select chooses the function that matches the arguments (planck0.sv:1616–1644). A Fusion tries the left function and, on failure, the right one. A Lambda compares the number of arguments and then matches the patterns in order.

planck0.sv:1571–1601

(fun match_pat (p v env idx)
    (var t (gettag p))
    (var i 0)
    (var n 0)
    (var h 0)
    (if (== p _S) (return 1)) ; wildcard
    (if (== t SymbolT) (do ; variable pattern
        (set env (+ 1 (get idx)) v)
        (set idx (+ (get idx) 1))
        (return 1)
        ))
    (if (|| (== t IntT) (== t StringT)) (return (values_equal p v)))
    (if (== t MexprT) (do
        (= h (get p 1))
        (if (== h QuoteS) (return (values_equal (get p 2) v)))
        (if (== h _TypeOfS) (do
            (if (!= (typeof v) (get p 3)) (return 0))
            (return (match_pat (get p 2) v env idx))
            ))
        (if (!= (gettag v) MexprT) (return 0))
        (if (!= (get v 1) h) (return 0))
        (= n (get_header_arg p))
        (if (!= (get_header_arg v) n) (return 0))
        (while (< i n) (do
            (if (! (match_pat (get p (+ i 2)) (get v (+ i 2)) env idx)) (return 0))
            (+= i 1)
            ))
        (return 1)
        ))
    (return 0)
    )

match_pat writes the value to the next position of the new environment for a variable, compares equality for a Quote, and checks the kind for a _TypeOf before it matches the inner pattern. An M-expression pattern compares the head and the number of arguments, and recurses on each argument. When no function matches, the program stops with matching failed (planck0.sv:1698–1710).

The builtin eval compiles an M-expression as a top-level expression and runs it in a new frame (planck0.sv:1675–1679).

Builtin functions

init_prims registers the builtin functions in the global table with defprim. defprim takes the name, the number of arguments, the implementing function and the kind (planck0.sv:2459–2467). The operators and the string concatenation are registered under the names that the sugar calls. These names start with _: _add, _sub, _mul, _div, _mod, _lt, _le, _gt, _ge, _eq, _ne and _strcat (planck0.sv:2469–2524). Names without _, such as add and strcat, are not registered. A variable of the same name in a program does not change the meaning of an operator.

Effects

Handle runs its body in a new frame and records the handler in that frame (planck0.sv:1825–1832). Perform follows the chain from the current frame to the callers and looks for a frame that has a handler.

planck0.sv:1842–1864

(fun op_perform ()
    (char[] 8 hargs)
    (var v (vm_pop))
    (var top vm_frame)
    (var b vm_frame)
    (var h 0)
    (var callee 0)
    (save_regs)
    (while b (do
        (= h (get b F_HANDLER))
        (if h (do
            (set hargs 0 v)
            (set hargs 1 (make_cont top b))
            (= callee (select h hargs 2))
            (if callee (do
                (invoke callee hargs 2 (get b F_CALLER))
                (return 0)
                ))
            ))
        (= b (get b F_CALLER))
        ))
    (runtime_error "unhandled effect: " v)
    )

When it finds one, it makes a continuation k, a pair of the current frame and the boundary frame, and matches the handler against (v, k). When the handler does not match, the search continues outward. The value of the handler returns to the caller of the boundary frame and becomes the value of the Handle expression.

Calling k copies the frames from the current frame to the boundary and runs the copy (resume, planck0.sv:1646–1663). The original frames never run, so the same k can be called any number of times (multi-shot continuations).
