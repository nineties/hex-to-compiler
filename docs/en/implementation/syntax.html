Defining the syntax

planck/syntax.pk defines the syntax of planck as rules of the packrat parser and replaces parse in the middle of the file. The syntax is not built into the implementation. It is a part of a planck program.

The file has two parts. Before parse is replaced, the tokens, the functions that the actions call and the grammar of the grammar are written in M-expressions. After it, the rest of the file is read by those rules, and the syntax of planck is declared with ::=.

Tokens

Tokens such as identifiers, integers and strings are written as functions, not as parsing expressions. A token function returns the next position when it reads a token.

planck/syntax.pk: Def{peg_tok_ident

Def{peg_tok_ident, Lambda{Tuple{p}, Do{
    Set{p, Apply{peg_skip_ws, Tuple{p}}},
    Def{q, Apply{peg_inc, Tuple{p}}},
    Def{name, ""},
    If{Apply{peg_is_alpha, Tuple{Apply{peg_char_at, Tuple{p}}}}, Do{
        While{Apply{peg_is_alnum, Tuple{Apply{peg_char_at, Tuple{q}}}}, Set{q, Apply{peg_inc, Tuple{q}}}},
        Set{name, Apply{substr, Tuple{peg_src, p, q}}},
        If{If{Apply{table_get, Tuple{peg_reserved, name, false}}, true,
              If{Apply{_eq, Tuple{q, Apply{_add, Tuple{p, 1}}}},
                 If{Apply{_eq, Tuple{Apply{peg_char_at, Tuple{p}}, 102}}, Apply{_eq, Tuple{Apply{peg_char_at, Tuple{q}}, 34}}, false},
                 false}},
            Apply{peg_fail, Tuple{p}},
            Do{Set{peg_pv, Apply{intern, Tuple{name}}}, q}}},
        Apply{peg_fail, Tuple{p}}}}}}

The words of the table of reserved words peg_reserved and the f of f" are not identifiers (planck/syntax.pk: Def{peg_reserved). A function becomes a rule when it is passed to _define_rule as it is (planck/syntax.pk: Apply{_define_rule, Tuple{Quote{ident}).

The action of a rule is compiled when the rule is defined. Since names are resolved at compile time, the functions peg_* that an action calls are defined before the rule. That is why the definitions of peg_* (planck/syntax.pk: Functions of the syntax sugar) come before the rules of the grammar (planck/syntax.pk: The grammar of the grammar, declared with).

Grammar declarations

The rule syntax_decl reads ::= and turns it into a tree that calls _define_rule. The rules it uses, g_choice, g_alt, g_item, g_suffix and g_primary, are the grammar of the grammar. They are written first, in M-expressions, in the form that a declaration makes (planck/syntax.pk: Grammar of the grammar).

planck/syntax.pk: Apply{_define_rule, Tuple{Quote{syntax_decl}

Apply{_define_rule, Tuple{Quote{syntax_decl}, Quote{
    Act{Seq{ident, "::=", g_choice},
        Lambda{Tuple{Tuple{n, _, e}},
            Do{QuasiQuote{Apply{_define_rule, Tuple{Quote{UnQuote{n}}, Quote{UnQuote{e}}}}}}}}}}}

Apply{_define_rule, Tuple{Quote{g_choice}, Quote{
    Act{Seq{Delimited1{g_alt, "|"}},
        Lambda{Tuple{Tuple{es}}, Do{Apply{peg_choice, Tuple{es}}}}}}}}

Apply{_define_rule, Tuple{Quote{g_alt}, Quote{Choice{
    Act{Seq{"..."}, Lambda{Tuple{Tuple{_}}, Do{Quote{Prev{}}}}},
    Act{Seq{Many1{g_item}, Option{Seq{same, block}}},
        Lambda{Tuple{Tuple{items, act}}, Do{Apply{peg_alt, Tuple{items, act}}}}}}}}}

g_alt rearranges the items and the action of an alternative into Act{Seq{...}, Lambda{Tuple{Tuple{label, ...}}, action}} with peg_alt (planck/syntax.pk: the items and the action of an alternative). The labels become the argument pattern of the anonymous function of the action.

i_decl.pk

use("pretty")
pretty.print('(pair ::= a:integer "," b:integer { (a, b) }))

Output

Apply{
  _define_rule,
  Tuple{
    Quote{pair},
    Quote{
      Act{
        Seq{integer, ",", integer},
        Lambda{Tuple{Tuple{a, _, b}}, Do{Tuple{a, b}}}
      }
    }
  }
}

syntax_decl is the first alternative of expr, so ::= can be written wherever an expression can. A new rule takes effect from the next top-level expression.

Replacing parse

The expressions that an action is written with are the smallest syntax that the rules of planck need: M-expressions, calls, `e, 'e, !e and blocks (planck/syntax.pk: The expressions of an action). The two lines after them switch the syntax.

planck/syntax.pk: Def{parse_mexpr, parse}

Def{parse_mexpr, parse}
Set{parse, Lambda{Tuple{s}, Apply{peg_parse, Tuple{Quote{toplevel}, s}}}}

The M-expression reader remains as parse_mexpr, and parse becomes a function that reads one expression by the rule toplevel. The replacement is a Set, not a Def. load in init.pk has already fixed the variable parse, so a Def would only add a new variable and the libraries that load reads would still be read by the old parse. planck0 looks up parse again for every expression (planck0), so the expressions after the switch are read by the rules above. toplevel reads one expr and checks for one of ;, a newline, or the start of the next expression (planck/syntax.pk: toplevel ::= e:expr).

primary has the alternative ident{expr, ...}, so M-expressions are also read as expressions as they are.

The grammar of the grammar then declares itself again with ::= (planck/syntax.pk: The grammar of the grammar, declared with). A rule that is declared again replaces the rule of the same name, and the rules made by the two forms are the same. After this the rules of planck are written with ::=.

Expressions

The rules are declared from the tightest binding to the loosest, so that each rule refers to rules that are already declared: unary, postfix, mul_expr, add_expr and so on up to ternary, then the patterns, arrow, union, primary and expr (planck/syntax.pk: The rules of planck). A rule that is declared replaces the smaller rule of the same name, which the rules before it were read with. The rules for addition and subtraction are as follows.

planck/syntax.pk: add_expr ::= a:add_expr "+

add_expr ::= a:add_expr "+" b:mul_expr { `_add(!a, !b) }
           | a:add_expr minus b:mul_expr { `_sub(!a, !b) }
           | mul_expr

add_expr is directly left recursive, so it associates to the left. The action is a quasi-quote: !a and !b are the values of the labels, and the action makes Apply{_add, Tuple{a, b}}. The same in minus succeeds only when the next token is on the same line, so a line that starts with -1 is a new expression (planck/syntax.pk: minus ::= same).

An action returns the M-expression that the evaluator receives. 1 + 2 becomes Apply{_add, Tuple{1, 2}}, the same tree as one written directly in M-expressions.

planck/syntax.pk: primary ::= if_expr

primary ::= if_expr
          | 'while "(" c:expr ")" b:expr { peg_while(c, b) }
          | 'handle b:expr 'with h:union { `Handle{!b, !h} }
          | 'perform v:unary { `Perform{!v} }
          | block
          | embed
          | h:ident nospace("{") args:delimited(expr, ",") "}" { mexpr(h, args) }
          | istr_open parts:(istr_text istr_hole expr "}")* last:istr_text istr_close { peg_interp(parts, last) }
          | ident
          | integer
          | string
          | "(" ")" { 'Tuple{} }
          | "(" es:delimited1(expr, ",") ")" { peg_group(es) }
          | "[" es:delimited(expr, ",") "]" { peg_to_list(es) }
          | sugar_primary

The last alternative of primary, sugar_primary, holds match, return, break, continue and for (planck/syntax.pk: sugar_primary ::= 'match).

fun f and f(p, ...) = e are alternatives of the rule expr too, and make Def{f, none} and Set{f, Fusion{f, Lambda{...}}} (planck/syntax.pk: expr ::= syntax_decl). f(p, ...) := e is read as Do{Declare{f}, Set{f, Fusion{f, Lambda{...}}}}, so it adds to f when f is already a variable of the place. The Lambda of the body is made by peg_lambda. A block is only wrapped in Do; the definitions in it are not moved to the top.

Indexing and rewriting

a[i] is an alternative of the rule postfix. The [ follows a with no space, and the parser does not read it when the assignment = follows the ] (planck/syntax.pk: | a:postfix nospace("[") i:index). An alternative of the rule expr turns a[i] = e into a call of _index_set (planck/syntax.pk: | a:postfix nospace("[") i:expr).

The inside of [ ] is the rule index: one expression (planck/syntax.pk: index ::= e:expr). When the function, as in t[p -> e | q if c -> g], has an arm with a guard, _peg_rewrite adds with peg_fuse a last arm that returns peg_skip, so that the function returns peg_skip when no arm applies (planck/syntax.pk: _peg_rewrite,).

_index_get and _index_set are functions that join one Lambda for each kind with Fusion (planck/syntax.pk: a[i] is _index_get(a, i, planck/syntax.pk: a[i] = v is _index_set(a, i, v). A table is selected by the head Table{t} and a list by the heads Cons{x, xs} and Nil{}, so the patterns alone decide the kind. A function f as the index calls subst(t, f) (planck/syntax.pk: subst(t, f) replaces). subst adds to f a last arm that returns peg_skip. A part for which f returns any other value is replaced, and its inside is not tried. For a part for which f returns peg_skip, subst calls itself on each argument.

When a user assigns _index_get = (K{...}, i) -> ... | _index_get, the new kind comes before the original function. The end of planck/lib/vector.pk is written this way.

Translating return and break

return, break and continue are translated to effects. The parser counts each return it reads. When it builds the tree of a function and the count has increased, it wraps the body in a Handle (planck/syntax.pk: peg_lambda,).

i_return.pk

use("pretty")
pretty.print('(f(xs) := { for (x in xs) if (x > 0) return x; 0 }))

Output

Do{
  Declare{f},
  Set{
    f,
    Fusion{
      f,
      Lambda{
        Tuple{xs},
        Handle{
          Do{
            Apply{
              peg_for,
              Tuple{
                xs,
                Lambda{
                  Tuple{x},
                  If{
                    Apply{_gt, Tuple{x, 0}},
                    Perform{Return{x}},
                    none
                  }
                }
              }
            },
            0
          },
          Lambda{Tuple{Return{v}, k}, v}
        }
      }
    }
  }
}

A return x in the body of a for becomes Perform{Return{x}}, and the whole body of the function is wrapped in Handle{..., (Return{v}, k) -> v}. for is a call of peg_for.

Text read by a rule

name{| text |} is read by the rule embed, which is written as a function (planck/syntax.pk: Def{peg_tok_embed). After name and {|, it calls the rule name at that position and then requires |}. The value of the rule enters the tree as Quote{v}.
