Defining the syntax

planck/syntax.pk defines the syntax of planck as rules of the packrat parser and replaces parse at the end. The syntax is not built into the implementation. It is a part of a planck program.

Tokens

Tokens such as identifiers, integers and strings are written as functions, not as parsing expressions. A token function returns the next position when it reads a token.

planck/syntax.pk:27–41

" identifier: [A-Za-z_][A-Za-z0-9_]* except the peg_reserved words and the f of f\"...\" "
Def{peg_tok_ident, Lambda{Tuple{p}, Do{
    Set{p, Apply{peg_skip_ws, Tuple{p}}},
    Def{q, Apply{peg_inc, Tuple{p}}},
    Def{name, ""},
    If{Apply{peg_is_alpha, Tuple{Apply{peg_char_at, Tuple{p}}}}, Do{
        While{Apply{peg_is_alnum, Tuple{Apply{peg_char_at, Tuple{q}}}}, Set{q, Apply{peg_inc, Tuple{q}}}},
        Set{name, Apply{substr, Tuple{peg_src, p, q}}},
        If{If{Apply{table_get, Tuple{peg_reserved, name, false}}, true,
              If{Apply{_eq, Tuple{q, Apply{_add, Tuple{p, 1}}}},
                 If{Apply{_eq, Tuple{Apply{peg_char_at, Tuple{p}}, 102}}, Apply{_eq, Tuple{Apply{peg_char_at, Tuple{q}}, 34}}, false},
                 false}},
            Apply{peg_fail, Tuple{p}},
            Do{Set{peg_pv, Apply{intern, Tuple{name}}}, q}}},
        Apply{peg_fail, Tuple{p}}}}}}

The words of the table of reserved words peg_reserved and the f of f" are not identifiers (planck/syntax.pk:10–25). A function becomes a rule when it is passed to _define_rule as it is (planck/syntax.pk:122–125).

Expressions

The rules run from the loosest binding: expr, union, arrow, ternary, or_expr, and so on up to primary (planck/syntax.pk:144–330). The rules for addition and subtraction are as follows.

planck/syntax.pk:236–242

" a binary - must be on the same line as its left operand "
Apply{_define_rule, Tuple{Quote{minus}, Quote{Seq{Same{}, "-", Not{Tight{">"}}}}}}

Apply{_define_rule, Tuple{Quote{add_expr}, Quote{Choice{
    Act{Seq{add_expr, "+", mul_expr}, Apply{peg_binop, Tuple{Quote{_add}}}},
    Act{Seq{add_expr, minus, mul_expr}, Apply{peg_binop, Tuple{Quote{_sub}}}},
    mul_expr}}}}

add_expr is directly left recursive, so it associates to the left. The action peg_binop turns (left, operator, right) into Apply{_add, Tuple{a, b}} (planck/syntax.pk:129–131). The Same{} before the binary - succeeds only when the next token is on the same line, so a line that starts with -1 is a new expression.

An action returns the M-expression that the evaluator receives. 1 + 2 becomes Apply{_add, Tuple{1, 2}}, the same tree as one written directly in M-expressions.

planck/syntax.pk:308–330

Apply{_define_rule, Tuple{Quote{primary}, Quote{Choice{
    if_expr,
    Act{Seq{Key{"while"}, "(", expr, ")", expr},
        Lambda{Tuple{Tuple{_, _, c, _, b}}, Apply{peg_while, Tuple{c, b}}}},
    Act{Seq{Key{"handle"}, expr, Key{"with"}, union},
        Lambda{Tuple{Tuple{_, b, _, h}}, QuasiQuote{Handle{UnQuote{b}, UnQuote{h}}}}},
    Act{Seq{Key{"perform"}, unary},
        Lambda{Tuple{Tuple{_, v}}, QuasiQuote{Perform{UnQuote{v}}}}},
    block,
    embed,
    Act{Seq{ident, Tight{"{"}, Delimited{expr, ","}, "}"},
        Lambda{Tuple{Tuple{h, _, args, _}}, Apply{mexpr, Tuple{h, args}}}},
    Act{Seq{istr_open, Many{Seq{istr_text, istr_hole, expr, "}"}}, istr_text, istr_close},
        Lambda{Tuple{Tuple{_, parts, last, _}}, Apply{peg_interp, Tuple{parts, last}}}},
    ident,
    integer,
    string,
    Act{Seq{"(", ")"}, Lambda{Tuple{_}, Quote{Tuple{}}}},
    Act{Seq{"(", Delimited1{expr, ","}, ")"},
        Lambda{Tuple{Tuple{_, es, _}}, If{Apply{_eq, Tuple{Apply{arity, Tuple{es}}, 1}}, Apply{peg_first, Tuple{es}}, es}}},
    Act{Seq{"[", Delimited{expr, ","}, "]"},
        Lambda{Tuple{Tuple{_, es, _}}, Apply{peg_to_list, Tuple{es}}}},
    sugar_primary}}}}

The last alternative of primary, sugar_primary, holds match, return, break, continue and for (planck/syntax.pk:1280–1302).

Indexing and rewriting

a[i] is an alternative of the rule postfix. The [ follows a with no space, and the parser does not read it when the assignment = follows the ] (planck/syntax.pk:261–270). An alternative of the rule expr turns a[i] = e into a call of _index_set (planck/syntax.pk:160–161).

The inside of [ ] is the rule index: one expression (planck/syntax.pk:277–279). When the function, as in t[p -> e | q if c -> g], has an arm with a guard, _peg_rewrite adds with peg_fuse a last arm that returns peg_skip, so that the function returns peg_skip when no arm applies (planck/syntax.pk:591–600).

_index_get and _index_set are functions that join one Lambda for each kind with Fusion (planck/syntax.pk:1413–1469, planck/syntax.pk:1498–1550). A table is selected by the head Table{t} and a list by the heads Cons{x, xs} and Nil{}, so the patterns alone decide the kind. A function f as the index calls subst(t, f) (planck/syntax.pk:1334–1381). subst adds to f a last arm that returns peg_skip. A part for which f returns any other value is replaced, and its inside is not tried. For a part for which f returns peg_skip, subst calls itself on each argument.

When a user assigns _index_get = (K{...}, i) -> ... | _index_get, the new kind comes before the original function. The end of planck/lib/vector.pk is written this way.

Grammar declarations

The rule syntax_decl reads ::= and turns it into a tree that calls _define_rule.

planck/syntax.pk:411–415

Apply{_define_rule, Tuple{Quote{syntax_decl}, Quote{
    Act{Seq{ident, "::=", g_choice},
        Lambda{Tuple{Tuple{n, _, e}},
            QuasiQuote{Apply{_define_rule, Tuple{UnQuote{Apply{mexpr, Tuple{Quote{Quote}, Tuple{n}}}},
                                                UnQuote{Apply{mexpr, Tuple{Quote{Quote}, Tuple{e}}}}}}}}}}}}

g_alt rearranges the items and the action of an alternative into Act{Seq{...}, Lambda{Tuple{Tuple{label, ...}}, action}} (planck/syntax.pk:422–432). The labels become the argument pattern of the anonymous function of the action.

i_decl.pk

use("pretty")
pprint('(pair ::= a:integer "," b:integer { (a, b) }))

Output

Apply{
  _define_rule,
  Tuple{
    Quote{pair},
    Quote{
      Act{
        Seq{integer, ",", integer},
        Lambda{Tuple{Tuple{a, _, b}}, Do{Tuple{a, b}}}
      }
    }
  }
}

syntax_decl is the first alternative of expr, so ::= can be written wherever an expression can. A new rule takes effect from the next top-level expression.

Translating return and break

return, break and continue are translated to effects. The parser counts each return it reads. When it builds the tree of a function and the count has increased, it wraps the body in a Handle (planck/syntax.pk:1083–1105).

i_return.pk

use("pretty")
pprint('(f(xs) := { for (x in xs) if (x > 0) return x; 0 }))

Output

Def{
  f,
  Lambda{
    Tuple{xs},
    Handle{
      Do{
        Apply{
          peg_for,
          Tuple{
            xs,
            Lambda{
              Tuple{x},
              If{
                Apply{_gt, Tuple{x, 0}},
                Perform{Return{x}},
                none
              }
            }
          }
        },
        0
      },
      Lambda{Tuple{Return{v}, k}, v}
    }
  }
}

A return x in the body of a for becomes Perform{Return{x}}, and the whole body of the function is wrapped in Handle{..., (Return{v}, k) -> v}. for is a call of peg_for.

Text read by a rule

name{| text |} is read by the rule embed, which is written as a function (planck/syntax.pk:1562–1587). After name and {|, it calls the rule name at that position and then requires |}. The value of the rule enters the tree as Quote{v}.

Replacing parse

The last two lines switch the syntax.

planck/syntax.pk:1568–1570

    Set{p, Apply{peg_skip_ws, Tuple{p}}},
    Def{q, p},
    Def{r, none},

The M-expression reader remains as parse_mexpr, and parse becomes a function that reads one expression by the rule toplevel. planck0 looks up parse again for every expression (planck0), so the expressions after syntax.pk are read in the syntax of planck. toplevel reads one expr and checks for one of ;, a newline, or the start of the next expression (planck/syntax.pk:148–150).

primary has the alternative ident{expr, ...}, so M-expressions are also read as expressions as they are.
